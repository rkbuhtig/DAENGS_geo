# M2 사건 자리에서 진짜 세계가 얼마나 읽히나 — DB 명사는 0/3, 지도 맥락은 6/6

[memory-engine](../explorations/walk/memory-engine.md) §12 가 Walk Capsule 의 event-context 를
"당시 확보 **가능했던** 주변" 이라고 정의했다. 이 실험은 그 "가능했던" 을 가정이 아니라
숫자로 만든다 — M2 의 합성 사건 자리([latent-dwell-synthesis](2026-08-27-latent-dwell-synthesis.md))
에서 **시스템이 실제로 가진 세계 데이터**(DB 의 place·facility, OSM 지형)가 무엇을 돌려주나.

스파이크: `scripts/spikes/territory_paint/world_context_readout.py`

눈으로 보는 표면: **`/world-context`** (dev_console 게이트 뒤). 앱과 같은
`/map/client-config` 로 실제 지도 제공사(네이버)를 띄우고 그 위에 산책 60회의 칠, 심은
자리(A·B·D)와 C 사건, 50m 판정 원과 DB 명사 핀, 시스템이 가진 지형(crossing·park·water)을
겹친다. OSM 타일 폴백이 아니라 **제품이 쓰는 그 지도 위**에서 본다 — basemap 이 보여주는
상호명들은 사람 눈용이고, 측정에는 들어가지 않았다(규약 1·2항).

## 오염 방지 규약 — 실행 전에 적었다

이 실험의 성립 조건이다. 하나라도 어겼으면 결과 전체를 폐기한다.

1. 판단 재료는 **시스템이 가진 것만** — 로컬 DB(`place` 28,284 · `facility` 33,611),
   Overpass 추출(질의·bbox·digest 아래 명기), M2 합성 산출물. 웹 검색·지도앱·작성자
   (사람이든 LLM 이든)의 지역 지식은 어떤 형태로도 안 들어갔다.
2. 결과에 나온 시설 이름·태그를 실제 세계와 대조하거나 정정하지 않는다. "그 자리에 실제로
   무엇이 있는지" 는 이 실험의 관할 밖이고, 확인할 권한이 시스템에 없다.
3. 질문과 판정 기준은 실행 전에 등록했고(아래), 실행 후 옮기지 않았다. 등록 밖에서 관찰된
   것은 **사후 관찰**로 표기한다.
4. bbox 는 M2 의 것을 그대로 썼다 — 지역을 새로 고르지 않았다.
5. 이 실험이 재는 것은 "캡슐에 무엇이 담기는가" 다. "나레이터가 무엇을 말해도 되는가" 는
   문법([memory-engine](../explorations/walk/memory-engine.md) 원칙 10)이 정하고, 여기서
   판정하지 않는다.

## 판단

### 1. 개-주어 자리는 이 상자에서 세계 명사를 못 얻는다 — 낙하 문법이 예외가 아니라 기본이다

A·D 자리 셋 중 셋 다, 50m 도 100m 도 DB 명사가 없다. 이유는 DB 의 정체다 — `facility` 는
KCISA/KTO 문화시설이고 `place` 는 병원·약국이다. **이 시스템은 일반 상권 POI 를 가진 적이
없다.** 카페·편의점·빵집을 몰라서 못 주는 게 아니라, 그 층 자체가 없다.

그러니 [memory-engine](../explorations/walk/memory-engine.md) §12 의 커버리지 구멍 경고와
§16 의 우선순위(`미시 Place 생성 >>> World context 완전성`)가 수치로 선다: **"이 근처" 와
사용자 명명("두부 풀숲")이 기본 경로이고, 세계 명사는 걸리면 좋은 보너스다.** "주인이 지도다"
는 감상이 아니라 이 상자의 측정 결과다.

C04(동물병원 24.1m)는 시스템 자신의 의료 DB 가 걸린 경우다 — 의료 시설 근처의 사건만
명사를 얻는 편향이 있다는 뜻이기도 하다.

### 2. 구조적 정지의 지도 맥락은 실재한다 — 그리고 그 맥락은 A 도 건드린다

B 자리 여섯 곳 전부 crossing 이 13.4m 안에 있다. 교차로에 심었으니 당연한 게 아니다 —
심은 곳은 **보행 그래프의 차수 3+ 노드**고, crossing 은 OSM 이 따로 태깅한 노드다. 이 상자의
OSM 은 그 둘이 겹치게 태깅돼 있다. M4(지도 맥락으로 구조적 정지를 설명)의 재료가 적어도
이 지형에서는 있다.

동시에 경고 하나가 공짜로 나왔다: **A0 도 crossing 22.5m 안이다.** crossing 근접만으로
"이건 구조적 정지" 라고 갈면 A0 같은 자리가 오설명된다. M4 는 근접 하나가 아니라 체류 분포
모양 같은 다른 축과 함께 읽어야 한다 — memory-engine §8 의 "귀속 신호이지 판정이 아니다" 가
지도 쪽에도 그대로 적용된다.

### 3. "국내 OSM 부실" 은 층 단위로 참이다

    미시 원인 층   tree 0 · bench 0 · grass 0     — 없다
    구조 층        crossing 27                     — 있다
    면 층          park 7 (이름 4) · water 1       — 있다

개가 **왜** 멈추는지 설명할 재료(나무·벤치·풀숲)는 이 상자의 OSM 에 하나도 없다 —
memory-engine §7 의 "개가 멈추는 이유는 어느 지도에도 없다" 가 실측이 됐다. 반면 구조 층과
면 층은 있다. 그러니 "OSM 을 쓴다/버린다" 가 아니라 **층별로 갈라 쓴다**: 원인 설명에는
못 쓰고(§7 기각 유지), M4 의 구조 설명과 "공원 안/하천 옆" 수준의 면 명사에는 쓸 수 있다.

### 4. 캡슐 event-context 계약에 주는 것

이 측정이 그대로 `walk-capsule.md` 의 event-context 필드 근거가 된다.

- **상자 하나다.** 대치·도곡 1.4km 상자의 측정이지 "한국 OSM" 의 측정이 아니다. 다른 지형

- Overpass 스냅샷 하나다. digest 가 다르면 비교할 수 없다 (M2 와 같은 규율)
- way 거리는 꼭짓점 최근접 근사 — 과대평가 방향으로만 틀린다. 면 부류만 내부 판정으로 0 이 된다
- probe 는 정답지 좌표다. 실제 시스템의 위치 추정 오차는 안 실렸다 (위 "출처" 의 가정)
- C 는 사건이 각 1 회라 자리 통계가 아니다 — 참고로만 실었다
