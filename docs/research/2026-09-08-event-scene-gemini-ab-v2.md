# 사건 ID 기반 구성 계약과 Gemini 2차 비교

2026-09-08. [첫 구성 비교](2026-09-08-event-scene-gemini-ab.md)의 실패를 바탕으로 출력 계약을 바꾸고 같은 세 조건을 다시 실행했다. **실제 호출 6회, JSON 응답 6/6, 구조 통과 3/6**이다. 본문 작성·지도 좌표 연결·dev/app 이식은 진행하지 않았다.

## 구현한 변경

`editorial_contract.py`는 모델에게 필요한 편집 선택과 시스템이 복원할 필드를 분리한다.

| 구분 | 모델이 반환 | 시스템이 복원·검사 |
|---|---|---|
| A 사건별 | 사건 ID, focus, reason | 시간순 정렬, 장면 ID, 사건 시각, 근거 참조 |
| B 묶음 | 대표·포함·맥락 사건 ID, focus, reason | 단일 소유, 맥락 역참조, 대표 시각, 기록별 원본 범위 |
| 전체 이해·제목 | 문구와 참조 사건 ID | 참조 ID 존재 및 근거 조각 연결; 문구의 진실성까지 보증하지 않음 |
| 생략 | 쓰지 않은 카드 후보의 이유 | 전체 후보 사용 여부, 연결 구간 자동 분류, 누락·모순 검사 |

A/B의 응답 스키마가 다르다. 시각·좌표·scene_id·evidence_ids·중복 결정표를 모델 응답에 노출하지 않는다. 두 모드의 결과는 기존 `SelectionPlan`으로 변환해 상태 저장과 검증에 연결한다. 원본 API 응답은 `calls/*/response.json`, 통과한 변환 결과는 `resolved_plan.json`, 표시 범위와 관측 기록은 `resolved_scene_scopes.json`으로 구분한다.

`included_extent`는 포함 사건의 편집 범위다. 대표 사건 시각이나 행동 지속시간으로 쓰지 않는다. 공유 맥락은 각 사건 참조로 별도 보존한다. 원본 자료의 위치는 여전히 unresolved이며, 좌표를 생성하거나 장소 이름에서 추정하지 않았다.

잘못된 사건 선택을 자동 교정하지 않는다. 중복 소유, 필수 행동의 맥락 전용 처리, GPS 단절 연결, 생략 모순은 거부한다. 유효한 장면의 시간순 정렬과 ID 부여만 결정적으로 수행한다. 제목은 구성에 남긴 사건만 참조하도록 검사한다. 이 제목 범위 검사는 v1보다 명시적으로 강화한 정책이며 이전 통과율과 완전히 동일한 검사 조건은 아니다.

별도 `editorial_experiment.py`가 v2 계약을 사용한다. 이전 실행기는 당시 요청 조건을 보존한다. 공통 실행기의 보고서는 원문 제안과 내부 구성, 제안 개수와 구조 통과 개수를 구분하도록 확장했다. 요청·모델·설정·근거 지문에 더해 변환 코드 지문도 실행 명세에 고정했다. 전용 명령 재개 시 지문이 달라지면 새 실행을 요구한다.

## 비교 조건과 실제 결과

원본은 Gemini 3차 보존 입력의 합성 산책이다. movement/actions/gap의 A/B 쌍에서 구성 모드 외 근거 데이터가 같고, v1과도 근거 해시가 일치함을 확인했다. 모델 `gemini-3.1-flash-lite`, temperature 0.2, 최대 출력 8,192토큰, 카드 상한 7, 호출 순서는 v1과 같다. 단순 계약 수정 외에 묶음의 추가 정보·후반 압축·제목 근거를 명시한 지시도 변경했다. 따라서 특정 개선을 스키마 한 요소의 효과로 분리할 수 없다.

| 조건 | A 사건별 | B 묶음 |
|---|---|---|
| 이동만 | 7장, 구조 통과 | 3장, 구조 통과 |
| 행동 포함 | 7장 제안, 제목 참조 오류로 거부 | 3장 제안, 생략 목록 모순으로 거부 |
| GPS 공백 포함 | 2장, 구조 통과 | 3장 제안, 다른 GPS chain의 맥락 연결로 거부 |

구조 통과는 의미 검증 완료나 사용자 승인이 아니다. 조건별 1회뿐인 탐색이며 성공률의 통계적 추정이나 B의 우월성 검증이 아니다. 통과한 A/B 쌍은 이동 조건 하나다.

| 사용량 | v1 | v2 |
|---|---:|---:|
| 요청 시도 | 6 | 6 |
| 입력 토큰 | 73,867 | 73,108 |
| 출력 토큰 | 12,722 | 5,538 |
| 총 토큰 | 86,589 | 78,646 |
| 미상 사용량 호출 | 0 | 0 |

출력 토큰은 이번 표본에서 약 56.5% 감소했다. 입력 비중이 커 총량 감소는 약 9.2%다. 출력 구조뿐 아니라 실제 문구·선택도 달라졌으므로 고정 절감률로 일반화하지 않는다. 자동 재시도는 없고 6회에서 종료했다. 금액·무료 할당 상태는 별도로 확인하지 않았다.

## 세 실패가 말해주는 것

### 행동 B: 맥락으로 사용하면서 동시에 생략

`e00/e01/e02/e05/e08/e14`를 장면의 맥락에 넣고 omissions에도 redundant로 넣었다. 모두 카드 비대상 연결 사건이며 이번 계약에서는 omissions 대상도 아니다. 변환층은 이를 조용히 삭제하지 않고 거부했다. 모델이 “독립 카드가 없음”과 “구성에서 완전히 미사용”을 혼동하는 문제가 남아 있다.

### 행동 A: 선택과 제목 참조가 어긋남

7개 사건을 선택하고 `e12/e13`은 생략했지만 제목 근거에는 두 사건도 넣었다. 제목 문구 자체가 반드시 거짓이라는 판정은 아니다. 확정된 구성에 제목 근거를 묶는 이번 계약과 어긋난 것이다. 제목 생성 시점을 구성 확정 뒤로 옮길 이유가 생겼다.

### 공백 B: 카드의 맥락을 통해 단절을 연결

후반 장면의 포함 사건은 공백 뒤에 있지만 맥락 `e08`이 공백 전 chain에 속했다. 포함 사건만 확인했으면 놓칠 수 있는 오류다. 현재 검증기는 맥락까지 검사해 `composition cannot join GPS chains`로 막았다. 이로 인해 실제 동선 연결이 생성되지는 않았다.

진단용 메모리 복사본에서 각각 잘못된 생략 항목 제거, 제목의 생략 사건 참조 제거, 다른 chain의 맥락 제거만 했을 때 세 건 모두 구조 검사를 통과했다. **원문 수정·정상 결과 승격·추가 모델 호출은 하지 않았다.** 자동 교정의 안전성을 입증하는 결과도 아니다. 구체적인 대상과 응답 해시는 보존본의 `audit.json`에 있다.

## 편집 품질에서 확인한 점

이동 B는 `e03+e04`, `e05+e06`, `e07+e08+e09`를 세 장면으로 묶었다. 첫 묶음에서 상가 배경과 공원 인근 전환을 함께 읽는 구조는 구현됐고, 시스템은 대표 사건 시간과 묶음의 범위를 분리해 저장했다. 그러나 문구는 여전히 환경 나열에 가깝다.

행동 B는 냄새와 사진을 주변 이동에 묶었지만 마지막 장면에 `e09..e13`을 모아 **17:00–36:00의 19분**을 다시 압축했다. “긴 후반을 몰지 말라”는 지시만으로 편집 품질이 개선되지는 않았다. 다만 고정된 최대 묶음 시간을 제품 정책으로 도입할 근거도 아직 없다.

공백 A는 구조를 통과했지만 공백 전 두 행동만 남겼다. 전체 이해에는 후반 이동이 등장하나 개별 카드는 생략했다. 지도가 전체 동선을 담당한다는 제품 구상에서 이것을 무조건 실패로 볼 수는 없다. 후반에 별도 카드로 남길 새로운 정보가 있었는지를 함께 검토해야 한다.

**의미 과장은 남아 있다.** 이동 A의 “복귀”, 상가가 적음을 “한적한 구간”으로 표현한 부분, 행동 A의 “기념 사진”, 행동 B의 “활발한 탐색”, 공백 B의 “익숙하거나 흥미로운 냄새”와 “추억을 기록하기 위해”는 출처와 별도로 검토해야 한다. 공백 B는 공원 인근 기록을 focus에서 “공원에서의 사진 촬영”으로 바꿨다. interpretations라는 필드에 썼다는 이유로 이런 의미 추가가 허용되는 것은 아니다.

open_questions도 자동 사용자 질문으로 보내지 않는다. 선호·활동성의 영향·돌아온 이유를 묻는 문구에는 확인되지 않은 전제가 섞일 수 있다. 현재는 모델의 잠정 이해 출력으로만 보존한다.

## 판단과 다음 경계

ID 기반 계약은 유지한다. 시각 재작성과 모드 필드 혼용을 제거했고, 정상 내부 구성 3건을 처음 확보했다. 다만 문장 품질과 편집 안정성을 해결한 결과는 아니다.

후속에서는 이번 3개 실패를 회귀 사례로 유지하면서 **선택할 수 있는 사건·맥락의 범위를 입력과 스키마에서 더 명확히 제한하고, 확정된 구성 뒤에 제목·생략 설명을 붙이는 흐름**을 검토한다. 이유가 필요한 판단을 임의의 기본값으로 메우지는 않는다. 통과한 이동 A/B는 시간순 구성 검토 재료로 사용할 수 있지만, 좌표 연결과 본문 작성은 별도 단계다.

## 보존과 검증

[보존본과 비교표](2026-09-08-event-scene-gemini-ab-v2/README.md)에 실제 입력·요청·응답·영수증·통과한 상태·복원 범위·audit를 남겼다. 원래 실행 위치는 워크스페이스의 `outputs/composition-gemini-ab-02`다. `resolved_plan.json`이 없는 거부 결과도 원문은 모두 보존했다.

새 변환층과 기존 선정·묶음·실행기 테스트 54개가 통과했다. 저장 응답 재생 검사를 추가한 뒤 새 변환층·실행기 19개를 다시 통과했다. 실제 실패 3건을 회귀 사례로 추가하고 보고서의 거부 원문 표시를 수정한 뒤 두 테스트 파일 22개가 통과했고, 변경한 Python 네 파일의 Ruff 검사도 통과했다. 전체 저장소 테스트는 실행하지 않았다.

실제 요청 6개는 사전 요청 및 manifest/영수증 해시와 일치했고, 통과한 상태의 시각은 원자료와 일치했다. 본문 장면은 생성하지 않았고 체크포인트는 구성 revision 0까지만 존재한다. 보존 파일 73개는 원래 실행 파일과 바이트 단위로 일치하며 키 형태 패턴 검사에서 노출을 발견하지 못했다. v1 보존본은 변경하지 않았고 v2의 지문 확인도 추가 호출 없이 통과했다.
