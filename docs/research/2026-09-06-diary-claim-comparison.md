# 행동 의미 정규화와 주장별 근거 대조: 3쌍 비교

2026-09-06. [계산 입력 연결 실험](2026-09-06-diary-geo-observed-inputs.md)의 동일한 자료로
행동 표현 정리와 재검토 구조 변경을 비교했다. **세 쌍 모두 근거 대조가 장면을 수정하지
못했다. 추가 호출을 붙이는 것만으로 오류가 줄어든다는 가설은 이번 조건에서 지지되지 않았다.**

## 바꾼 것과 유지한 것

이전 입력에도 행동핀의 `type: sniffing`은 있었다. 이번에는 두 핀에
`normalized_observation: 냄새 맡기`를 추가하고, 조각의 의미에 보호자 원문 메모와 관찰 행동,
더 넓은 해석인 탐색의 차이를 설명했다. `킁킁`이 포함된 원문 메모·핀 시각·좌표는 유지했다.
새 관측 행동이나 동기는 추가하지 않았다. 정규화 전 조각 지문도 남겼다.

GPS·과거 15개 산책에서 계산된 공간 경향·지도 응답 등 나머지 조각은 동일하다.
총 35개 조각, 모델 `gemini-3.1-flash-lite`, 기존 전체 이해·장면 작성 지시도 동일하다.
모델의 샘플링 seed를 고정하지 않았고 같은 정규화 입력으로 초안을 세 번 새로 만들었다.

각 회차의 전체 이해 → 장면 순회 완료 직후를 공통 초안으로 삼아 두 조건을 비교했다.

| 조건 | 공통 초안 이후 실행 |
|---|---|
| 정규화 + 기존 재검토 | 기존 `reconcile` 1회 |
| 정규화 + 근거 대조·수정 | 별도 `claim_audit` 1회 → 대조 결과와 원자료를 전달한 수정 `reconcile` 1회 |

두 번째 조건의 초안은 첫 번째 조건의 저장 응답을 정확히 재생했다. 초안을 다시 생성하지
않았으므로 쌍 안에서 재검토 전 상태는 완전히 같다. 각 조건 3개, 총 6개 최종 보드이며
독립적으로 생성한 초안은 3개다. 이전 비정규화 실행은 과거 비교 자료 1개로만 두었다.

## 근거 대조 계약

전체 이해의 요약·관찰 흐름·해석·질문, 모든 장면의 제목·본문·관찰·해석·질문·연결 문구를
빠짐없이 목록으로 만든다. 모델은 각 항목에 아래 내용을 반환한다.

- 원자료가 확인하는 내용과 추가로 가정한 내용.
- `supported`, `plausible`, `unsupported`, `contradicted`, `not_assertion` 판단.
- 실제 대조한 원자료 ID, 유지·수정·삭제·질문 중 처리와 이유.
- 같은 주장 때문에 영향을 받을 다른 항목 ID.

모든 목록 항목을 정확히 한 번 다뤘는지, 원자료·영향 항목 ID가 존재하는지 코드로 검사했다.
지시에는 특정 사례의 정답이나 금지 단어를 넣지 않았다. 유효한 사건 연결과 공간 경향을
유지하되 근거보다 강해진 주장을 수정하라고 요청했다. 최종 수정 호출은 대조 결과를 무조건
따르지 않고 원자료로 다시 확인할 수 있다.

**목록 항목은 텍스트 필드 단위다.** 본문 한 문단에 여러 주장이 들어갈 수 있고 제목·질문도
포함된다. 따라서 아래 103개를 독립적인 원자 주장 103개나 평가 표본 103개로 세면 안 된다.
또한 대조 모델의 판단은 정답 라벨이 아니다.

## 실제 결과

| 회차 | 모델이 만든 장면 | 대조 항목 | 대조 모델의 처리 | 기존 재검토의 수정 장면 | 대조 후 수정 장면 |
|---|---:|---:|---|---:|---:|
| 1 | 3 | 33 | 전부 유지 | 0 | 0 |
| 2 | 4 | 42 | 전부 유지 | 0 | 0 |
| 3 | 3 | 30 | 전부 유지 | 0 | 0 |

103개 모두 `keep`이었다. 판단은 supported 72개, plausible 14개, not_assertion 17개였다.
unsupported·contradicted는 없었다. 최종 수정 호출 세 번 모두 `replacement_scenes=[]`를
반환했으며, 실제 장면 객체도 공통 초안과 같았다. 요약·전체 이해·확인 사항 일부 문구는 바뀌었다.

정규화한 세 실행과 그 대조 분기에서 마킹이라는 표현은 나오지 않았다. 하지만 이전 입력에도
영문 행동명이 있었고 비정규화 조건을 이번에 반복하지 않았으므로, 정규화 때문에 마킹 오류가
사라졌다고 인과적으로 결론 내릴 수 없다. 아래 다른 비약은 계속 나타났다.

### 1회차: 대조 단계 자체가 시간·장소의 비약을 승인

장면 1은 40초 동안 냄새를 맡았다고 쓰고, 장면 3은 같은 나무에서 50초간 냄새 맡기에
열중했다고 썼다. 원자료의 40초·50초는 비이동 분류 시간이며 핀은 해당 구간 중 한 시점의
관찰이다. 행동 지속시간 전체를 기록한 자료는 없다.

대조 모델은 장면 1 본문을 다음처럼 요약해 `supported / keep`으로 판정했다.

> 07:02:40경 공원 내 나무 밑에서 40초간 냄새 맡기 행동함.

환경 응답이 공원 내부를 증명하지 않는다는 점도 놓쳤다. 나무 재방문에서 심리적 안정감을
얻는다는 장면 3의 해석은 합리적이라는 이유로 유지했다. 최종 수정은 장면을 바꾸지 않았다.

### 2회차: 공간 등장과 행동 목적이 섞인 채 유지

장면 1의 과거 공간 등장은 11/15다. 본문은 이곳이 중요한 정보 갱신 지점으로 확인된다고
쓰고, 해석에는 특정 나무에 집착하며 정서적 안정감을 얻으려 한다고 썼다.
장면 2는 3/15 공간 등장을 20%의 확률로 방문했던 곳이라고 표현하고, 정지에 호흡 조절의
의미를 붙였다. 공간 집계는 그 행동 이력이나 목적을 측정하지 않는다.

대조 후 전체 요약에서는 정서적 안정이라는 문구가 빠졌지만 장면의 해석에는 그대로 남았다.
본문·해석 목록·전체 이해가 일관되게 수정됐다고 볼 수 없다. 왕복 경로를 원형 루프라고
부르는 표현도 장면에 남았다.

### 3회차: 시간순 연결은 유지했으나 동기 추정은 남음

장면은 남쪽으로 갔다 돌아오며 같은 나무에서 두 번 냄새를 맡았다는 순서를 잘 유지했다.
하지만 첫 나무가 강력한 탐색 욕구를 자극한다고 쓰고, 장거리 이동을 보행 훈련의 일환일 수
있다고 해석했다. 마지막에는 시작과 끝에 반드시 확인해야 하는 정보 수집 지점이라고 썼다.

대조 모델은 이 항목들도 유지했다. 최종 확인 사항에는 고정적인 정보 수집 루틴인지
우연한 관심인지 보호자에게 확인해야 한다는 질문이 생겼지만, 장면의 강한 표현은 그대로였다.
이것은 질문 추가이며 원래 주장을 수정한 결과와 구별해야 한다.

## 연결성이 희생됐는가

세 쌍 모두 왕복 순서, 같은 나무의 두 기록, 과거 공간의 반복 등장이라는 연결을 유지했다.
대조 후 장면이 동일하므로 서술이 지나치게 삭제되거나 사건 연결이 사라지지는 않았다.
그러나 올바른 내용과 함께 근거가 부족한 내용도 유지됐으므로 이를 대조 구조의 품질 성과로
세지는 않는다. 평가용 사례·설명은 실행 뒤 사람이 읽기 위한 보고서에 기록했고 모델 입력에는 넣지 않았다.

## 호출·비용·실패

실제 API 시도 31회 = 성공 22회 + HTTP 429 실패 9회다. 초안 재생 13회는 실제 호출이 아니다.
성공 응답의 보고된 토큰 합은 **625,515**, 실제 API 지연 합은 **137.902초**다.
실패 요청의 사용량은 응답 기록에 없으며 이 수치는 전체 작업 시간이나 청구 금액이 아니다.

| 회차 | 기존 재검토 토큰 | 대조 + 수정 토큰 |
|---|---:|---:|
| 1 | 27,677 | 63,702 |
| 2 | 28,584 | 68,303 |
| 3 | 27,315 | 63,379 |

초안 작성 비용을 제외한 마지막 검토 구간만 비교한 수치다. 대조를 붙이면 기존 마지막
검토의 약 2.3–2.4배 토큰을 사용했지만 이번에는 장면 수정이 없었다.

처음 회차들을 동시에 호출하면서 429가 발생했다. 각 프로세스가 즉시 세 번 시도하고 멈춰
실패 9회가 남았다. 이후 순차적으로 완료 단계 다음부터 재개했다. 후속 코드에는 429·503 시
30초 대기 후 재시도를 넣었다. 한 실행의 단계당 시도 한도는 3회이며 수동 재개 기록도 보존했다.
성공 출력이 마음에 들지 않는다는 이유로 다시 뽑거나 실패 기록을 제외하지 않았다.

## 판단과 다음 가설

행동 의미 정규화는 입력 계약을 명확히 하는 작업으로 유지할 수 있다. 그러나 별도 근거
대조 호출을 현재 형태 그대로 제품 단계로 채택할 근거는 이번 결과에서 얻지 못했다.

대조 모델이 문단의 일부 맞는 내용을 요약하고 전체를 supported로 승인하는 사례가 보였다.
`supported_content`에도 원래 비약이 들어갔다. **검토 항목을 다 채우는 것과 실제로 근거를
대조하는 것은 다르다.** 다음 비교 후보는 문단을 개별 주장으로 나누고, 주장마다 원자료의
구체적인 값·필드와 시간·공간·행동 범위를 먼저 대응시킨 후 판정하는 방식이다. 아직 실행한
것은 아니며, 이 방식으로 해결된다고 기록하지 않는다.

같은 모델, 같은 세션 1개, 초안 3개에 한정된다. 다른 모델이나 중립적인 검토 역할의 영향,
여러 산책에서의 재현성을 이번 실험으로 판단하지 않는다. 작성자 공통 지시를 공유한 것이
검토에 영향을 줬을 가능성도 별도 비교가 필요하다.

## 구현·검증·자료

  초안 공유와 두 재검토 조건, 중단 후 재개. 기존 기본 프롬프트는 변경하지 않았다.
- [비교 검증기](../../scripts/spikes/diary_storyboard/compare_claim_runs.py): 3쌍의 동일 입력·초안,
  저장된 실제 지시·대조 요청·수정 입력 전달, 상태 전이와 실제 호출 비용을 대조한다.
- 원문 메모·다른 조각 보존, 본문·질문까지 검토 목록 포함, 항목 누락·잘못된 참조 거부,
  기존 지시 불변을 회귀 검증했다. 의미 정확성을 가짜 모델 테스트로 판정하지 않는다.

로컬 결과는 저장소 형제 경로 `experiments/diary_storyboard_geo/claim-comparison-01/`이다.
`experiment.json`에 입력 지문과 실제 지시를, `normalized_evidence.json`에 변환 입력을,
`pair-01..03-normalized/`·`pair-01..03-audited/`에 요청·응답·단계별 상태·스토리보드를 저장했다.
각 audited 폴더에는 `audit_input.json`·`claim_audit.json`도 있다.
`comparison.json`·`COMPARISON.md`는 자동 집계이며 본 보고서의 의미 평가와 구별한다.
모든 실행은 `awaiting_review`다. 사용자 검토·일기 선택·생성은 하지 않았다.
