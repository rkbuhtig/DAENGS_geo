# 산책 목록에서 여는 지도 일기 시안

> 이 문서는 Geo `185747f` 기반 로컬 실험의 당시 기록이다. 본문의 코드 경로·실행 명령·localhost 주소는 해당 실험 작업 공간을 가리킨다. 이 문서 PR에는 실험 실행 코드와 원천 캐시를 포함하지 않는다. [종합 보고서](2026-09-07-walk-diary-experiment-report.md)에서 최신 검토 결론과 이전 정책을 대체한 단계를, [보존 자료 안내](2026-09-07-walk-diary-evidence/README.md)에서 저장소만으로 확인할 수 있는 범위를 확인한다.

실행: `python -m tools.lab_server --tool walk-cohort --port 8766`

주소: `/walk-diary-preview`

## 화면 흐름

1. 지난 산책 목록에서 날짜와 경로 썸네일로 세션을 고른다.
2. 세션을 열면 해당 경로와 장면을 지도에서 본다. 별도 지도 탭은 두지 않는다.
3. 지도 안의 ‘겹쳐 보기’에서 계절·강수 조건을 고른다.
4. 조건에 맞는 흔적을 배경에 표시하고, ‘겹친 날’에서 여러 세션의 장면을 시간순으로 본다.
5. 다른 세션의 장면을 선택하면 현재 동선과 카드가 바뀐다. 적용한 조건과 배경은 유지한다.
6. ‘열어본 일기로’로 처음 선택한 세션에 돌아간다.

모바일은 지도 아래 장면 패널, 넓은 화면은 지도 옆 장면 패널을 사용한다.
지도상 가까운 장면은 묶어 누를 수 있다. 위치가 없는 장면은 목록에 남기고 좌표를 추정하지 않는다.

### 숫자와 썸네일의 의미 (사용자 정정 반영)

- 지도 숫자는 밀집 개수가 아니라 **해당 산책 안의 시간순 장면 번호**이다. 위치 없는 장면도 순서에 포함하며, 지도·목록·카드가 같은 번호를 쓴다.
- 가까운 현재 산책의 장면은 각 번호 버튼을 나란히 배치한다. 클릭하면 해당 장면을 바로 연다.
- 겹친 다른 산책은 번호 없는 작은 점으로 표시한다. 세션을 선택하면 그 세션의 장면 번호가 활성화된다. 세션 간 번호를 하나의 밀집 개수로 합치지 않는다.
- 출발·도착 표시는 특히 **목록 썸네일에서 산책을 식별**하기 위한 정보이다. 상세 지도 표시도 유지한다.
- 썸네일에는 출발·도착을 우선 배치하고, 이를 가리지 않으며 서로 겹치지 않는 장면 번호만 표시한다. 생략된 번호를 재번호화하지 않는다. 전체 장면 순서는 상세 지도와 목록에서 확인한다.

## 재사용 범위

- 기존 `/walk-cohort-lab/query`의 `example` 합성 자료 8개 세션, 60개 장면.
- 원래 GPS 경로, 스토리보드 facts/sources 및 확인된 scene location.
- 기존 좁은 브러시 `overlap_display`와 횟수 중심 hybrid30 표현식.
- 방문 횟수 로그 강도에 조건 내 비율을 30% 보정하는 기존 실험 설정을 유지한다.
- 현재 세션이 필터 조건에 맞으면 기존 API 정책대로 배경 집합에도 포함된다.

새 HTML은 탐색 구조를 검토하는 로컬 시안이다. 앱 PR이나 API 데이터 정책을 변경하지 않는다.
계절·강수만 필터링하며 지역 조건, 익숙함 판단, 자동 서술은 추가하지 않았다.
Leaflet 및 OpenStreetMap을 사용하므로 지도 로딩에는 인터넷 연결이 필요하다.

## 확인 범위

Playwright로 목록 진입, 장면 열기, 세션 전환 중 배경 유지, 계절·강수 변경,
빈 조건 결과, 위치 없는 장면, 360/390/600/800/1280px 화면 폭을 확인한다.
백엔드 전체 테스트나 네이티브 앱 검증을 대체하지 않는다.

## 목록 페이지·제목·출발/도착 보완

- 시안은 5개씩 페이지를 나누고 최근 날짜순을 유지한다. 일기에서 돌아오면 목록 페이지와 스크롤 위치를 유지한다.
- HTML 시안은 합성 자료를 한 번 받아 화면에서 나눈다. 실제 앱에서는 목록 요약만 페이지 단위로 조회하고 선택한 세션의 상세를 별도로 가져와야 한다. 페이지 표시가 겹침 집계 대상까지 제한해서는 안 된다.
- 산책 대표 제목은 스토리보드 생성 호출의 결과에 `title`을 함께 포함하는 방향으로 한다. 별도 제목 생성 호출이나 목록 조회 시 재생성을 추가하지 않는다.
- 제목과 스토리보드는 같은 revision으로 저장한다. 장면별 제목과 산책 대표 제목은 구분한다. 제목이 아직 없으면 날짜 기반 제목으로 표시한다.
- 대표 제목은 그날 기록에 근거한 짧은 문구로 작성한다. 확인되지 않은 감정, 장소, 익숙함/새로움 판단을 추가하지 않는다. 충분한 특징이 없으면 평범한 제목을 허용한다.
- 현재 시안은 `bundle.title` 표시를 준비하고 기존 합성 자료의 label을 예시 제목으로 사용한다. 실제 LLM 호출, 스키마 변경 및 저장 연동은 아직 하지 않았다.
- 선택한 경로의 첫/마지막 좌표에 작은 점과 ‘출발’/‘도착’을 표시한다. 두 좌표가 12m 이내이면 ‘출발 · 도착’으로 묶는다(시안의 임시 기준).
- 위치가 없으면 출발/도착을 추정하지 않는다. 실제 기록의 시작/종료 시 GPS가 누락된 경우에는 ‘기록 시작/끝’으로 구분하는 정책이 필요하다.
