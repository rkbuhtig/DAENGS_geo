# 2026-09-04 — 실제 주변 자료를 넣은 합성 산책 스토리보드

대상: [산책 스토리보드와 동네 구간](../explorations/walk/storyboard-and-regions.md).
기준 코드: geo `0defc3a` 위의 `scripts/spikes/storyboard_and_regions`.
운영 계약을 채택하는 문서가 아니라 로컬 실험의 관찰 기록이다.

## 질문과 결과

좌표로 지역을 구별하고, 상가·공원·하천 자료를 붙여 시간순 장면을 만들 수 있는가?

**이 지역에서는 가능했다.** SGIS 서울 읍면동 경계와 합성 관측 경로를 겹쳐 동 구간을
계산했고, 기본 산책 13장·공백 산책 13장·Pin 없는 산책 12장의 로컬 HTML을 만들었다.
시작·공원·상권·하천·Pin·게임·끝 장면과 지역 전환을 같은 타임라인에 놓았다.
문장은 근거별 템플릿이며 LLM/음성 합성은 호출하지 않았다.

중요한 발견은 **API 조회 성공이 지역 문맥의 완전함을 뜻하지 않는다**는 것이다.
전국하천표준데이터의 전체 응답을 받았지만 이 지역의 양재천·탄천 항목은 찾지 못했다.
별도 EGIS 하천 형상을 보조 자료로 사용했고, 두 원천을 화면과 receipt에서 구분했다.

숫자는 2026-09-04의 실제 응답에 대한 값이다. 시점 좌표 수는 위도와 경도가 모두 있는
행의 수이며 하천선 수가 아니다. 공원의 예로 늘벗근린공원은 대표점
`37.48928087, 127.0563303`, 자료 기준일 `2026-01-29`였다.
전체 source receipt의 query·captured_at·hash는 로컬 `storyboard.json`에 있다.
원본 응답·API 키·SGIS 신청 개인정보는 Git에 넣지 않는다.

SGIS ZIP의 `.prj`는 ESRI:102080(UTM-K/GRS80), `.cpg`는 UTF-8이었다.
공식 제공 안내의 EPSG:5179와 같은 투영 파라미터를 확인하고 두 표기를 허용했다.
경계의 SHA-256과 기준일은 bundle에 보존한다. 경위도는 WGS84, 공간 판정·거리는 5179,
화면은 단순 축척 지도다. 지도 표시용 단순화는 지역 판정에 사용하지 않는다.

## 시나리오에서 보인 것

- 기본 합성 산책: 기존 Walk 계산기 기준 이동거리 **2,859m**, 약 **38분 49초**.
- 안정적인 동 구간은 도곡1동 → 도곡2동 → 대치1동 → 개포2동 → 개포1동 → 개포4동 →
  도곡2동 순서였다. 마지막 도곡2동은 앞선 구간과 합쳐지지 않는다. 출발점 복귀를 뜻하지 않는다.
- 공백 버전: 995초부터 1,185초까지 관측 공백 **190초**, 계산 이동거리 **2,622m**.
  그 사이의 도로·동 통과·정지를 추정하지 않는다. 공백 때문에 기본판의 개포2동 장면은
  나타나지 않았고, 관측된 다른 위치에서 하천 장면이 선택되었다.
- Pin 없는 버전도 시작·지역·주변 문맥·끝으로 재생됐다. 게임 장면은 스위치로 독립 제거된다.
- 상권 장면은 관측점 반경 125m 안에 있는 **수집된 등록 행**의 업종을 요약한다.
  공원 장면은 대표점까지, 하천 장면은 EGIS 형상까지의 거리를 설명한다.

모든 산책 경유점·Pin 메모·게임 성과는 합성이다. 실제 도로·교량을 따라 걷도록 만든 라우팅
결과가 아니며 사진을 촬영한 적도 없다. 공원과 하천을 화면에 그렸다는 이유로 입장·산책로
이용을 사실로 만들지 않았다. 주변에 있는 것을 장소에 대한 방문 이력으로 승격하지 않았다.

## 구현 경계와 검증

수집 → 최소 필드 projection → 기존 simulator/Walk 계산 → 순서 있는 동 구간 → 장면 편집 →
로컬 HTML 순서다. 완전 수집·0건·partial·fetch_failed·parse_failed 상태를 구분한다.
동일 페이지가 반복되어 전체 건수만 채우는 경우도 partial이다. source cache가 있으면
같은 입력에서 다시 만들 수 있고, 기본 CLI는 외부 요청을 보내지 않는다.

자동 검증은 전용 **17개 테스트 통과**, 새 스크립트 **3개 import 통과**, 해당 경로 Ruff
통과로 한정했다. 범위는 페이지 누락/중복/실패·키 비노출·경계 교점 거리 보존·A→B→A·
공백/chain 유지·경계 불확실·겹친 polygon·수집 범위 완전성·Pin 없는 시나리오 순서다.
전체 테스트나 운영 통합 테스트를 실행한 결과가 아니다.

브라우저에서는 세 시나리오 선택, 하천 출처 구분, 공백 장면, Pin/게임 제거와 재생을
확인한다. 지도선은 `CanonicalTrail.segments` 각각만 그린다. 향후 경계 정확도 평가에는
실기기 관측, 경계선 위 이동, 한 동네 산책과 짧은 스침을 더 넣어야 한다.

## 다음 판단

지역 구별 자체가 불가능해서 구상을 멈출 단계는 지났다. 다음 관건은 지역 분할을 게임 규칙과
동일시하지 않으면서 장면을 잘 선택하는 것이다. 이번 60초 기준은 편집용 임시값이다.
행정동 경계는 기본 지역 이름과 집계 틀의 후보이고, 실제 점령 단위를 확정한 결과는 아니다.

남은 공백은 원천별 지역 커버리지, 경계 revision과 코드 crosswalk, 한 동네 산책 편집,
사진/Pin 증언 정정, 현재 행사 정보, LLM narrator의 근거 제한, 그리고 #85 이후 운영 경로
보관·재구성 범위다. 세 데이터는 행사 피드나 개인 경험의 첫 방문을 제공하지 않는다.

SGIS 신청 시 출처 표시와 완성 결과물 사본 제출 조건에 사용자가 동의했다.
출처는 화면과 이 문서에 표기했다. **SGIS 활용 결과 등록은 아직 제출하지 않았다.**
원본 경계·계정 정보를 포함하지 않는 결과 보고서 또는 공개 결과 URL을 제출 대상으로
준비할 수 있다. 이 문서나 코드의 PR 작성이 SGIS 제출을 대신하지는 않는다.
