# 공간·액션 슬롯에서 스탬프를 찍어 Gemini에 전달한 실험

2026-09-08. 사용자 제안인 독립 후보 집합·슬롯 유지와 교체·정책에 따른 스냅샷을 구현했다. **실제 호출 6/6이 구조 검사를 통과했고, 세 조건에서 각각 7장의 짧은 카드를 작성했다.** 사건과 맥락을 연결하는 부담은 줄었으나 모든 조건에서 카드 상한을 채웠고 의미 과장은 남았다. 제품 적용 또는 서술 품질 승인 결과가 아니다.

## 1. 이전 실험에서 무엇을 바꿨나

[직전 ID 구성 실험](2026-09-08-event-scene-gemini-ab-v2.md)은 모델이 사건을 골라 묶고, 맥락과 생략을 결정하며 제목까지 제안했다. 이번에는 시스템이 스탬프의 중심과 맥락을 먼저 확정한다.

```text
보존 원자료 → 공간 풀 / 액션 풀 → 슬롯의 시점별 상태
                                ↓
                     스탬프 생성·적재 정책
                                ↓
             필수 스탬프 확정 + 추가 스탬프 선택(LLM)
                                ↓
             선택된 스탬프만 제목·한 문장 작성(LLM)
```

모델에게 원자료 전체, 후보별 소유권 결정표, 생략 이유 목록, 이해·해석·질문 목록을 보내거나 반환시키지 않는다. 선택 응답은 추가 스탬프 ID 배열 하나다. 작성 응답은 전체 제목과 스탬프별 제목·한 문장이다. 선택 가능한 ID를 응답 스키마 enum으로 제한한다.

코드는 `stamp_materials.py`와 `stamp_experiment.py`에 별도로 두었다. 기존 v1/v2 실험과 워크트리의 `record_envelopes.py` 작업은 수정하지 않았다. 기록·주변 봉투 계약은 향후 입력 경계이며, 이번 자료에는 그 계약의 관측 좌표가 없으므로 억지로 해당 Record를 만들지 않았다.

## 2. 자료와 전처리 범위

동일한 Gemini 3차 보존 입력의 movement/actions/gap 세 조건을 사용했다. 산책·참가자·행동은 합성이며 공간 설명은 앞선 공공 공간 실험의 파생 조각이다. 공공 API 재조회, 실기기 산책, 원본 GPS 재계산은 하지 않았다. 좌표·날씨·시점·행동 지속시간은 확보되지 않은 항목으로 남겼다.

중요한 제한: 원본 공간 조각은 이미 한국어로 계산된 대표 배경과 전환 문구다. 이번 어댑터는 **그 보존 형식의 제한된 어휘를 명시적인 사전과 문법으로 읽어 딕셔너리로 바꾼다.** 임의의 사용자 문장을 파싱하는 도구가 아니다. 지원하지 않는 행동·장소·관계는 추측하지 않고 거부한다. 실제 운영 입력에서는 구조화된 공간 계산 결과와 직접 연결하는 어댑터가 필요하다.

상가 구성은 장소 유형이고, 공원·하천 이름은 출처의 라벨이다. canonical place ID로 승격하지 않았다. `near`는 인근 관계이며 내부 진입이 아니다. 거리 감소→증가 순서는 `distance_trend.sequence`로 보존한다. 현재 대표 배경만 있는 자료로 동시 공존하는 모든 공간을 복원하지 않는다.

## 3. 슬롯과 스탬프 정책

| 항목 | 이번 고정 설정 | 의미 |
|---|---|---|
| 공간 슬롯 | 3개, 최근 관측 300초 이내 | 같은 키 재확인 시 갱신, 용량 초과 시 가장 오래 갱신된 항목 교체 |
| 액션 슬롯 | 2개, 최근 기록 600초 이내 | 원본 액션 이력은 별도로 보존. 슬롯은 최근 맥락 조회용 |
| 환경 집합 | 자료 없음 | 날씨·빛을 채우지 않음 |
| 스탬프의 공간 | 현재 대표 배경 + 최근의 다른 공간 최대 1개 | 최근 관측과 현재 관계를 구분 |
| 액션 상대 시간 | 액션 스탬프에 직전 액션과의 시간차 | 행동 지속시간이 아님 |
| 공간 상대 시간 | 현재 공간으로 연결된 원본 구간 시작과의 시간차 | 그 사이 계속 체류했다는 뜻이 아님 |
| GPS 단절 | chain 변경 시 활성 공간·액션 슬롯 초기화 | 원본 이력과 이미 찍힌 스탬프는 유지 |
| 찍는 계기 | 원본의 카드 자격이 있는 행동·공간 전환 | 용량 교체 자체로는 찍지 않음 |
| 필수 보존 | required 행동 스탬프를 시스템이 먼저 선택 | 이번 자료의 냄새·사진 기록 |
| 카드 수 | 최대 7, 추가 선택 0개도 가능 | 스탬프 내부 수정과 병합을 모델에 허용하지 않음 |

이 수치들은 첫 탐색 설정이며 최적화한 정책이 아니다. 전환 구간은 구간 끝에 스탬프를 찍어 그 이후의 정보를 미리 읽지 않는다. 실제 처리 시각과 anchor의 원본 구간은 다르다. 사진·냄새는 원래 point 시각을 유지한다.

스탬프는 내용·정책·원본 사건 참조·내용 해시를 가진 독립 스냅샷이다. 풀의 상태가 바뀌어도 기존 내용은 바뀌지 않는다. 단, Python dict 자체가 물리적으로 수정 불가능한 것은 아니며 저장 지문과 재실행 비교로 변조를 확인한다.

### 사진 스탬프의 실제 예

actions의 `stamp:e07`에는 다음이 담겼다.

- 중심 기록: 산책 900초 시점 사진. anchor는 `[900, 900]`.
- 현재 공간: 늘벗근린공원 `near`, 출처 라벨.
- 이전 행동: `e04` 냄새 기록으로부터 300초.
- 공간 관계: `e06`의 원본 공간 구간 시작 780초로부터 120초.
- 연속 체류 여부: `not_established`.
- 출처 사건: `e04/e06/e07`. 이후 `e09` 등 미래 사건은 포함하지 않음.

이 연결은 모델이 계산한 것이 아니다. 전처리에서 만들어진 값이며 스탬프를 선택한 뒤 문장 작성 입력에 전달했다.

## 4. 실제 Gemini 결과

모델은 이전과 같은 `gemini-3.1-flash-lite`, temperature 0.2다. 단계를 줄여 최대 출력은 4,096토큰으로 설정했다. 조건별 선택 1회·작성 1회, 총 6회에서 멈췄고 자동 재시도는 없었다. 처리 순서는 movement 선택/작성 → actions 선택/작성 → gap 선택/작성이다.

| 조건 | 생성 스탬프 | 필수 | 실제 선택 | 선택 토큰 | 작성 토큰 | 합계 |
|---|---:|---:|---:|---:|---:|---:|
| 이동만 | 7 | 0 | 7 | 1,850 | 2,299 | 4,149 |
| 행동 포함 | 9 | 2 | 7 | 2,382 | 2,507 | 4,889 |
| GPS 공백 | 10 | 2 | 7 | 2,690 | 2,362 | 5,052 |
| 합계 | 26 | 4 | 21 | 6,922 | 7,168 | **14,090** |

입력 12,427토큰, 출력 1,663토큰이다. 사용량 미상 호출은 없다. HTTP 응답·파싱·구조 검사 모두 6/6 통과했다. 검사 범위는 선택 ID·필수 기록·개수·카드 대응·시각 복원이며 문장의 의미 정확성은 포함하지 않는다.

직전 v2의 grouped 세 조건은 구성만으로 총 39,534토큰이었다. 이번에는 선택과 짧은 작성까지 총 14,090토큰이다. **과업·자유도·출력 구조가 달라 동일 조건의 품질/비용 대조군은 아니다.** 입력을 다지고 판단 범위를 줄였을 때 작업량을 줄일 수 있다는 탐색 결과로 본다. 제목·본문의 주장 검증, 순회·재검토, 최종 일기 작성까지 포함한 비용은 아니다.

## 5. 기존 실패에 대한 결과

| 기존 문제 | 이번 관찰 | 해석 |
|---|---|---|
| 맥락 사용과 생략 모순 | 모델은 스탬프 ID만 선택, 사용 원본 목록은 시스템이 계산 | 모순을 만들던 중복 출력 책임을 제거함 |
| 생략 사건을 제목 근거로 반환 | 작성기는 선택된 스탬프만 받음. 별도 사건 ID 근거 목록을 쓰지 않음 | 참조 불일치 경로를 제거했지만 문구의 의미 과장은 남음 |
| GPS 공백 너머 맥락 결합 | 모든 스탬프 출처가 동일 chain. 기존 문제였던 e08 연결 없음 | 입력 전에 시스템이 차단함. 모델이 공백 추론을 잘하게 됐다는 증거는 아님 |
| 사진 시각 확장 | 사진 anchor `[900,900]` 유지 | 모델에 시각 편집권이 없음 |
| 후반 19분을 한 카드로 합침 | 스탬프 병합이 없어 해당 구조가 생기지 않음. 각 anchor는 원본 구간 유지 | 고정 구성의 효과. 스탬프 단위 자체가 좋은지는 별도 평가 |
| 너무 많은 공간 카드 | 세 조건 모두 상한 7장 선택 | 선정 품질은 해결되지 않음 |
| 의미 과장 | 기념 촬영·복귀·머무름이 다시 등장 | 짧은 지시와 가공 입력만으로 의미 정확성을 보장하지 못함 |

스탬프 생략과 원본 사건 미사용은 다르다. 예를 들어 공간 스탬프를 독립 카드로 고르지 않아도 사진 스탬프의 배경으로 그 원본 사건이 쓰일 수 있다. 이번 출력은 `omitted_stamp_ids`와 `used_source_event_ids`로 그 차이를 보존한다.

## 6. 실제 문구 검토 — Codex의 사후 검토

**연결 관계를 문장에 반영한 사례:** actions 사진 본문은 “이전 행동 기록으로부터 300초, 공간 이동으로부터 120초”를 언급했다. 필요한 관계가 입력 조각에 있으면 모델이 활용할 수 있음을 보여준다. 다만 `구간 시작`이라는 기준이 `공간 이동`으로 흐려졌고, 초 단위 수치를 그대로 나열해 기록 보고서처럼 읽힌다.

**명확히 남은 의미 문제:** 같은 카드의 제목은 “공원에서의 기념 촬영”이었다. 입력은 공원 인근이고 촬영 목적은 없다. 본문은 인근을 유지했지만 제목이 위치 의미와 목적을 확대했다. movement의 거리 변화 카드에는 “머무르며”가 붙었으나 정지 근거는 없다. 이동·행동 조건의 상가 카드에는 같은 유형의 재등장을 “복귀”로 표현한 부분이 남았다.

**시간 기준의 손실:** movement는 `recent_space_observations.seconds_ago`를 “상가 구간에서 240초 후 ... 이동”처럼 썼다. 해당 값은 스탬프 시점과 이전 공간 관측 시점의 차이이며 이동 소요 시간이 아니다. 계산이 맞아도 문장에 기준 사건이 빠지면 독자가 다르게 이해할 수 있다. 향후 모델에 넘길 관계 필드에서 기준 사건/시점을 더 직접적으로 표현할 필요가 있다.

**반복과 생략:** movement는 모든 공간 스탬프를 선택했다. actions는 앞의 7개를 선택하고 뒤의 거리 감소→증가 등 2개를 생략했다. gap은 뒤쪽 공간 카드도 선택했지만 총 7장이었다. 이번 선택기는 생략 이유를 반환하지 않으므로 실제 판단 이유를 단정하지 않는다. 카드 상한을 줄이면 해결된다고도 결론내리지 않는다.

**추가 정보가 항상 사용되지는 않음:** gap의 사진 본문은 사진과 공원 인근만 언급하고 제공된 상대 시간은 쓰지 않았다. 관계가 있다는 것과 서술에 모두 포함해야 한다는 것은 다르다. 어느 관계가 읽을 가치를 더하는지 다음 평가에서 확인해야 한다.

## 7. 페이지 교체 자체는 어디까지 실험했나

기본 공간 슬롯 3개에서는 용량 교체가 **0회**였다. 300초 만료가 먼저 일어났기 때문이다. 갱신·만료·chain 초기화와 스냅샷 고정은 실행됐지만 이 결과를 LRU 우수성으로 표현하면 안 된다.

공간 슬롯 1개로 동일 입력을 오프라인 재생한 대조에서는 세 조건 각각 용량 교체 5회가 발생했다. 생성 스탬프 ID 목록은 기본 설정과 같았고, 최근 공간을 실을 수 있는 내용은 달라졌다. 이 대조 입력으로 추가 LLM 호출은 하지 않았다. 복수 장소의 동시 공존이 풍부한 원자료를 확보한 뒤 교체 정책과 적재 정책을 따로 비교해야 한다.

## 8. 다음에 확인할 것

슬롯·스탬프 전처리는 유지할 가치가 있다. 구조 책임을 시스템으로 옮겨 입력을 줄였고 세 조건의 읽기용 결과를 확보했다. 다음에는 이번 스탬프를 그대로 두고, **독립 카드와 다른 스탬프의 배경이 반복되는 경우의 선정 정책**, **제목·본문에서 공간 자격과 시간 기준을 잃는 문제**를 좁혀 비교한다. 모델 지시를 계속 늘리는 방식으로 되돌아가지 않는다.

최종 사용자 화면, 실제 지도 위치, 원본 기록·봉투 어댑터, 날씨·시선 자료, 스탬프 수정/삭제·재생성 정책은 이번 실험 밖이다. 관측이 없는 항목을 모델 일반 지식으로 복원하지 않았다.

새 실험 및 재사용 입력 어댑터의 테스트 30개가 통과했다. 명칭·호출 바인딩 정리 후 새 실험 테스트 13개를 재실행해 통과했고 신규 세 파일의 Ruff 검사도 통과했다. 전송 요청은 예정 요청·영수증 해시와 일치했으며 원자료·스탬프 해시, 참조 사건의 시각·chain, 저장 결과 재계산을 대조했다. 전용 명령은 동일 입력의 완료 결과를 재사용하고 실패·중단 호출을 자동 재전송하지 않는다. 전체 저장소 테스트는 실행하지 않았다.

보존 파일 49개는 원래 출력과 바이트 단위로 일치한다. 키 형태 패턴 검사에서 노출은 발견되지 않았고, 이전 두 A/B 보존본도 원래 출력과 일치함을 확인했다. 검증 및 보존 과정에서 추가 모델 호출은 없었다.
