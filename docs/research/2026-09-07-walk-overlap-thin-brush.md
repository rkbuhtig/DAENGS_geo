# 겹친 산책 수와 가는 브러시

> 이 문서는 Geo `185747f` 기반 로컬 실험의 당시 기록이다. 본문의 코드 경로·실행 명령·localhost 주소는 해당 실험 작업 공간을 가리킨다. 이 문서 PR에는 실험 실행 코드와 원천 캐시를 포함하지 않는다. [종합 보고서](2026-09-07-walk-diary-experiment-report.md)에서 최신 검토 결론과 이전 정책을 대체한 단계를, [보존 자료 안내](2026-09-07-walk-diary-evidence/README.md)에서 저장소만으로 확인할 수 있는 범위를 확인한다.

방문 비율의 1/1과 100/100을 같은 진하기로 표시하는 것은 쌓인 흔적을 보는 목적에 맞지
않는다는 검토에 따라 기본 농도를 서로 다른 산책의 겹 수로 변경했다. 원본 방문 비율은
위치 조회의 보조 숫자와 비교 화면으로 보존한다. 익숙함/새로움이나 서술 정책은 추가하지 않는다.

## 농도

완전한 관측으로 명시된 각 산책의 방문 support를 이진화해 한 장으로 다룬다. 체류 시간과
한 산책 안의 반복 통과는 겹 수를 추가하지 않는다. 누락/부분 관측 제외 정책은 이전과 같다.

표시 alpha = `0.72 × log(1 + min(k, 100)) / log(101)`.

k는 가늘게 처리한 산책별 표시 mask의 합이다. 내부에서는 정수 겹 수, 부드러운 외곽에서는
0~1의 기여가 합쳐진 보간값이다. 1/3/10/30/100겹 범례는 이 함수에 직접 대응한다.
1겹 alpha 약 0.108, 3겹 0.216, 30겹 0.536, 100겹 이상 0.72다. 조회 최대값이나 N으로
다시 정규화하지 않으므로 다른 기록이 추가되었다는 이유로 같은 겹 수의 농도가 달라지지 않는다.

100겹 상한과 로그 곡선은 시각 비교를 위한 실험 설정이며 통계적 유의성 문턱이나 실측으로
확정된 최적값이 아니다. 100 이상은 같은 농도이고 정확한 원본 겹 수는 위치 조회로 확인한다.

## 폭

계산용 Hex 반경 8u와 원본 방문 집계는 유지한다. 각 산책의 표시 support를 2m raster에서
약 2m 안쪽으로 줄인다. 전체 합을 줄이는 대신 산책마다 처리해 가까운 경로의 표시가 먼저
하나로 합쳐지는 것을 피한다. 극소 support가 침식으로 전부 없어질 경우 침식 전 support를 쓴다.

번짐 sigma를 단순히 5m→3m로 줄인 첫 시도에서는 셀 굴곡이 다시 보였다. 최종 버전은
sigma=5m 평활화를 유지하고, mask 0.12~0.9 구간을 smoothstep으로 대응해 연한 바깥 자락을
걷어낸다. 즉 부드러운 외곽을 유지하면서 실제 보이는 폭을 줄인다. 원본 Hex에 이미 합쳐져
저장된 구분을 복원한 것은 아니다. 표시 농도와 클릭한 원본 셀의 겹 수는 외곽에서 다를 수 있다.

## 검증

관련 13개 검사(새 브러시 + 기존 방문 통계) 통과 후 외곽 방식을 수정했고, 변경된 브러시
4개 검사를 다시 실행해 모두 통과했다(9.84s). 관련 Python Ruff도 통과했다.

합성 평행 띠에서 두 띠 사이 표시값이 이전 5m 번짐의 절반 미만으로 줄었고, 표시값 0.1 이상
영역도 줄었다. 2겹 대비 20겹이 진해지고, 추가 체류/누락/부분 관측은 겹을 추가하지 않았다.
Windows Edge에서 1회(비율 100%)가 연하게 표시되고, 3/30회에서 농도가 증가하는 것을 실제
캡처로 확인했다. 기존 비율 화면에서는 2/3과 20/30 이미지가 같아 비교 의미도 유지된다.
원본 겹 수+비율 조회, 모바일 지도/카드 동시 표시, 320~1120px 가로 넘침 없음, JS 예외 없음.

실기기 성능·실제 GPS 모집단 검증과 Dev/App 이식은 수행하지 않았다.
기본 화면: `/walk-cohort-lab?population=ratio30`, 한 번 사례: `?population=single`.
