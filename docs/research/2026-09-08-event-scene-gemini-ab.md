# 사건별 카드와 사건 묶음: 실제 Gemini 구성 비교

2026-09-08. 미커밋 LLM층 작업에서 이어간 구성 단계 실험이다. **6개 요청 모두 응답했지만 구조 검사는 0/6 통과했다.** 묶음의 편집 가능성은 보였으나 정상 출력이나 제품 채택 근거로 취급하지 않는다. 본문 작성·지도 연결·app/dev 변경은 수행하지 않았다.

## 무엇을 비교했나

보존된 Gemini 3차 입력의 movement, actions, gap 세 조건을 각각 A(1사건=1장면), B(대표·포함·맥락 사건을 가진 묶음)로 요청했다. 같은 조건의 근거 데이터는 구성 모드 외 동일하고 해시로 확인했다. 산책과 행동은 합성이며 실사용자 산책의 품질 평가는 아니다. 원본 보존본에 좌표가 없어 지도 위치는 unresolved로 남는다.

모델은 `gemini-3.1-flash-lite`, temperature 0.2, 최대 출력 8,192토큰, 장면 상한 7이다. 모드별 지시는 다르며 공통 사실성 지시와 설정은 같다. 조건별 각 1회, 총 6회이며 자동 재시도와 본문 작성 호출은 없다. 실행 순서는 movement A/B → actions B/A → gap A/B다. 반복 평가나 통계적으로 유의한 A/B 검증은 아니다.

`composition_experiment.py`를 추가해 요청 사전 보존, 입력·설정 지문 고정, 계획 단계만 실행, 실패 원문 보존, 중단된 호출의 자동 재전송 방지를 구현했다. 최대 시도는 6회다. 확인된 사용량 100,000토큰에 도달하면 다음 호출을 중단하는 장치는 실제 총사용량의 엄격한 상한이 아니며 실패 호출의 미상 사용량도 0으로 간주하지 않는다.

## 실제 결과

아래 수는 **거부된 원문의 제안 장면 수**다. 승인된 장면은 모든 조건에서 없다.

| 조건 | A 사건별 | B 묶음 | 관찰 |
|---|---:|---:|---|
| 이동만 | 7 | 3 | 전환 나열을 묶었지만 유사한 공간 설명과 복귀 표현이 남음 |
| 행동 포함 | 5 | 3 | 냄새·사진과 주변 이동을 묶음. 후반 19분은 한 장면에 집중 |
| GPS 공백 포함 | 2 | 3 | A는 공백 전 행동만, B는 공백 뒤 이동 묶음도 제안 |

HTTP 200 및 JSON 파싱 성공 6/6, 구조 통과 0/6. 영수증의 입력 토큰 합계 73,867, 출력 토큰 합계 12,722, 총 86,589이다. 사용량 미상 호출은 없다. 무료라는 설명과 별개로 금액이나 계정 과금 여부는 이번 기록에서 확인하지 않았다.

### 호출 계약에서 드러난 문제

A 세 응답 모두 B용 `compositions`를 채워 `individual mode cannot contain grouped composition`으로 거부됐다. 두 모드에 공용 응답 스키마를 제공하면서 individual에서는 불필요한 필드를 없애지 않은 설계 결함이다. 가짜 Provider는 작성자가 알고 있는 규칙대로 응답해서 이 문제를 드러내지 못했다. 모델 능력 부족으로만 해석해서는 안 된다.

B 세 응답 모두 대표 사건 시간 대신 묶음의 전체 범위를 `outline` 시간에 넣어 `scene must preserve representative event bounds`로 거부됐다. actions의 사진은 원본 15:00의 순간인데 반환 개요는 13:00–15:00이었다. 원자료 자체는 변경되지 않았고, 검증기가 체크포인트 생성을 막았다. 편집 범위와 관측 시각을 하나의 필드로 오해하기 쉬운 인터페이스를 개선해야 한다.

첫 오류만 고치면 해결되는지도 메모리 복사본에서 진단했다. A는 묶음 필드만 제거하고, B는 대표 사건 시간만 원자료에서 복원했다. 원문·체크포인트는 변경하지 않았고 성공 응답으로 집계하지 않았다.

| 실행 | 가정한 수정 뒤 첫 검사 결과 |
|---|---|
| movement A | 구조 검사 통과; 의미 정확성 승인은 아님 |
| movement B | 맥락 구성과 선택 결정의 참조 불일치 |
| actions A | 여유 장면 수가 있는데 budget으로 생략 |
| actions B | 구조 검사 통과; 의미 정확성 승인은 아님 |
| gap A | individual에서 금지된 context 전용 결정 |
| gap B | 연결 구간을 connection 대신 redundant로 생략 |

이는 첫 후속 오류 진단이며 모든 결함 목록이 아니다. 같은 관계를 구성표와 결정표 양쪽에 다시 쓰게 한 부담도 보인다.

### 구성과 의미에서 드러난 문제

- **묶기의 가능성:** actions B는 `e03+e04`를 상가 배경과 냄새 기록으로, `e06+e07`을 공원 인근 배경과 사진 기록으로 묶었다. 관측과 편집을 분리하려던 방향에 부합하는 제안이다. 다만 시간 계약을 위반한 원문이므로 정상 장면으로 쓰지는 않았다.
- **과도한 압축:** actions B의 세 번째 장면은 `e09..e13`, 17:00–36:00의 19분을 묶었다. 카드가 적어졌어도 각각의 변화가 읽히는지는 별도 문제다. 3장은 시스템이 강제한 값이 아니라 이번 모델의 제안이다.
- **앞부분 편중과 부정확한 생략 이유:** actions A는 5장만 제안하고 후반 4개 후보를 “최대 장면 수 초과”로 제외했다. 상한은 7이다. gap A도 두 행동 이후를 남기지 않았다. 이를 모델의 실제 사고 원인이라고 단정할 수는 없지만 반환한 설명은 검증 대상이다.
- **근거를 넘는 의미:** actions B에는 “기념 사진”, “활기찬 분위기”, “산책의 정점”이 나왔다. movement B의 전체 이해에는 “산책을 즐긴”이 나왔다. 사진 목적과 감정은 입력에서 확인되지 않는다. 본문을 쓰기 전의 제목·초점·선정 이유에서도 의미 과장이 시작된다.
- **공간 관계의 손실:** movement A/B의 “복귀”는 같은 상가 유형의 재등장을 같은 장소로 돌아온 것으로 읽게 할 수 있다. “거리 변동” 같은 일반 표현은 접근·이탈의 순서를 충분히 전달하지 못한다. gap B의 “공원을 잇는 이동”도 인근 관측을 실제 시설 이용 경로로 확대하지 않았는지 별도로 검토해야 한다.

## 다음 구현 결정

관측은 엄격히 보존하고 장면 구성은 유연하게 한다는 방향은 유지한다. 다만 다음 비교 전에 LLM 출력 계약을 먼저 좁힌다.

1. **모드별 응답 스키마를 분리한다.** A는 선정 사건 ID, B는 대표·포함·맥락 사건 ID를 반환한다. 해당 모드에서 금지한 구조는 스키마에 노출하지 않는다.
2. **확정 가능한 필드는 시스템이 조립한다.** 모델이 원본 시각·좌표·근거 ID 목록을 재작성하지 않게 한다. 사건 ID를 검증한 뒤 원자료에서 복원한다. 장면의 편집 범위와 대표 사건 시각을 별도 값으로 유지하며 행동의 지속시간으로 합치지 않는다.
3. **구성 소유 관계를 한 번만 선언한다.** 선택 결정과 구성표 사이의 중복 참조를 줄이고, 시스템이 파생 소유·맥락 관계를 만든다. 모델은 묶음과 생략 이유처럼 판단이 필요한 내용을 맡는다.
4. **통과한 구성으로 편집 품질을 비교한다.** 행동 보존, 공백 경계, 후반부 누락, 지나치게 큰 묶음, 반복, 새 정보의 유무를 함께 본다. 장면 수 감소를 품질 점수로 대체하지 않는다. 최대 묶음 시간 같은 제품 규칙은 아직 확정하지 않는다.

이번 요청에서는 6회 한도를 유지해 추가 호출하지 않았다. 다음 버전은 새 출력 디렉터리에서 비교하며 이번 실패 원문을 덮어쓰지 않는다. 통과하는 구성 계약을 확보한 다음 지도 검토와 고정 구성의 문장 작성으로 진행한다.

## 보존과 검증

[실험 보존본](2026-09-08-event-scene-gemini-ab/README.md)에 요청·응답·영수증·입력과 진단을 보존했다. `results.json`의 원문과 구조 승인 상태는 별도다. `diagnostic.json`의 가정한 수정 결과는 실제 모델 성공 결과가 아니다. 원래 실행 위치는 워크스페이스의 `outputs/composition-gemini-ab-01`이다.

요청 6개의 사전 보존본·실제 전송본·manifest·영수증 해시를 대조했고 모두 일치했다. 승인 체크포인트는 없다. 네트워크 없이 실행하는 구성 실험·개별 선정·묶음 검사 40개가 통과했다. 실제 모델의 계약 실패를 테스트 통과로 상쇄하지 않는다. 보고서의 제안 수와 승인 수 분리 후 실험 실행기 테스트 5개를 다시 실행해 통과했고, 신규 실행기·테스트의 Ruff 검사도 통과했다. 보존 파일 58개의 키 형태 패턴 검사에서 노출은 발견되지 않았다.
