# 산책 일기 워킹 스켈레톤 실행 기록

2026-09-06. [기획과 아키텍처](../explorations/walk/diary-storyboard-plan.md),
[실험 코드와 실행 방법](../../scripts/spikes/diary_storyboard/README.md).

## 무엇을 구현했나

geo의 `scripts/spikes/diary_storyboard/`에 파일 기반 실행기를 만들었다.
자료 스냅샷 → 전체 이해 → 시간순 장면별 갱신 → 전체 재검토 → 검토 버전 저장 →
생성 여부 선택 → 선택적 일기를 각각 분리했다. 단계별 원자료·이전 상태·모델 출력과
변경 이유를 저장하고, 실패 시 마지막 완료 단계부터 다시 실행한다.

앞선 단일 호출 실험이나 워크스페이스의 `diary_four_inputs/sequential`과 구별되는 점은
원자료 조각 봉투, 계약 검사, 체크포인트 재개, 앞 장면 재검토 요청·교체, 사용자 편집과
생성 입력의 버전 연결, 저장 요청의 정확한 재생까지 같은 실행기에 넣었다는 것이다.

## 입력과 실행 조건

- 모델: `gemini-3.1-flash-lite`. 이전 실험과 같은 모델이며 모델 간 성능 비교는 하지 않았다.
- 입력: 코드의 `fixtures/scenario.json`. 두부의 07:00–07:15, A→B→C→B→A 가상 산책.
- 미시 관측 7구간, B의 냄새핀 2개와 귀가길 메모, 주변 환경·측정 맥락, 과거 공간 출현 B 18/24·C 3/24를 함께 제공했다.
- 과거 공간 수치는 조건·공간 정의·분모를 포함한 합성 입력이다. 실제 geo 계산기를 이번 실행에서 호출하지 않았다.
- 단계마다 전체 자료와 직전 상태를 전달했다. 장면 개수는 모델이 제안했다.
- 사용자 검토는 `actor=simulated`, `reviewer=skeleton-smoke`로 모사했다. 실제 보호자의 검토·수정 효과를 측정한 것은 아니다.

로컬 원문은 이 워크스페이스의 `experiments/diary_storyboard_geo/live-01/`, 재생 결과는
`experiments/diary_storyboard_geo/replay-01/`에 있다. geo 저장소 밖의 실행 산출물이며 레포에
포함되지 않는다. 재현 가능한 합성 입력과 코드는 geo에 있다. 다른 PC에서 저 로컬 산출물이
있다고 가정하지 않는다.

## 실제 실행 결과

| 항목 | 결과 |
|---|---|
| 첫 전체 이해 시도 | HTTP 200/STOP이었지만 장면 2의 시작을 `07:04:00+07:08`로 출력. 세션 시간 범위 검사에서 거부, 상태 미채택 |
| 재개 | `advance`로 다시 전체 이해 호출 후 성공 |
| 장면 구성 | 모델이 3개 제안: 출발·첫 냄새 / C까지 이동·머무름 / B 재방문·귀가 |
| 순차 갱신 | 장면별 별도 호출 3회. 직전 이해와 완성 장면들이 다음 요청에 포함됨을 저장 JSON 대조로 확인 |
| 전체 재검토 | 1회. 수정 장면 0개와 남은 질문 2개를 반환 |
| 검토·선택 | 버전 5와 6에서 실험용 검토 후 skip·generate 양쪽 실행 |
| 생성 안 함 | 각 분기에서 일기 모델 호출 0회, 일기 파일 없음 |
| 생성 | 해당 검토 버전의 스냅샷으로 각 1회 호출. 최종 구현 검증 결과는 버전 6 |
| 저장 응답 재생 | 모델 호출 0회. 이해·장면 3개·재검토·일기 총 6개 요청의 응답 재생. 현재 상태와 최신 두 선택 결과가 원 실행과 동일 |

전체 실제 호출은 **8회, 39,427토큰, 호출 지연 합계 29.835초**였다. 실패한 첫 이해 시도와
개발 중 생성 입력 투영을 수정한 뒤의 추가 일기 실행을 포함한다. 정상 3장면 한 사이클은
이해 1 + 장면 3 + 재검토 1 + 선택 시 일기 1회다. 위 전체 수치를 일반적인 한 사이클 비용으로
읽지 않는다. 검토·편집은 모델 호출을 발생시키지 않는다.

생성 입력 투영을 수정한 이유는 숨긴 장면의 사용자 문구가 검토 메타데이터 안에 남아
전달될 수 있는 경로를 제거하기 위해서였다. 최신 입력에는 포함 장면과 검토 주체·버전만
전달하며, 전체 편집 이력은 상태 파일에 보존한다. 문구 수정 시 기존 모델의 파생 설명이
정정 문구를 덮어쓰지 않도록 생성용 표현도 분리했다.

## 내용에서 확인한 한계

재검토는 원자료와 모순되지 않는다는 이유로 장면 교체가 필요 없다고 응답했다. 하지만
실제 장면에는 ‘심리적 안전 기지’, ‘만족스러운 표정’, ‘아까와는 사뭇 다르게’ 등 자료로
확인되지 않는 심리·표정·전후 행동 차이가 남아 있었다. C에서 공기나 바닥 냄새를 살폈다는
서술도 기록된 행동이 아니다.

최종 일기에도 ‘출발할 때보다 훨씬 여유롭고 차분하게’, ‘충분히 즐겁고 안정된 아침 산책’이
남았다. 공간 출현 비율, 이번 세션의 행동핀과 이동, 환경을 연결하는 과정에서 해석을
과하게 확정하는 문제를 최종 재검토가 해결하지 못했다.

따라서 이 실행은 **단계 실행·상태 전달·검토 버전·선택 분기의 동작을 확인한 결과**다.
새 아키텍처가 기존 실험보다 서술 품질이 좋다거나 사실성을 확보했다고 결론 내리지 않는다.
원자료의 ID가 맞다는 검사와 그 자료가 문장을 뒷받침하는지는 다른 문제다. 모델의 재검토
설명 자체도 평가할 출력이다. 과거 공간 조각을 제거하는 결론으로 바꾸지 않는다.

## 회귀 검증

`tests/test_diary_storyboard_skeleton.py`의 회귀 사례 7개와 발견식 import 검사 8개가 통과했다.
회귀 검증은 상태 전달, 뒤 장면 이후 앞 장면 교체, 실패한 장면부터 재개, 없는 근거 ID 거부,
원자료 변경 감지, 세션 밖 장면 시간 거부, 검토 전 생성 거부, 사용자 편집·숨김 보존,
오래된 버전 거부, skip의 무호출, 같은 생성 요청의 결과 재사용을 다룬다.
테스트 모델은 제어 흐름 검증용이며 LLM 품질의 정답지가 아니다.

```powershell
uv run pytest tests/test_diary_storyboard_skeleton.py tests/test_script_imports.py -k diary_storyboard -q
uv run ruff check scripts/spikes/diary_storyboard tests/test_diary_storyboard_skeleton.py
uv run python -m scripts.spikes.diary_storyboard.verify_run --run ../experiments/diary_storyboard_geo/live-01 --compare-replay ../experiments/diary_storyboard_geo/replay-01
```

마지막 명령은 저장된 요청·응답과 체크포인트를 대조한다. 5개 모델 상태 전이, 4개 선택의
검토 스냅샷, 재생 실행의 최신 상태·결과 일치를 확인했다. `verification.json`에 결과를 쓴다.
최초 잘못된 시간대 응답도 보존하며, 완료 상태로 채택된 응답과 구별해 집계한다.

## 이어서 실험할 경계

실제 geo 계산 결과의 자료 어댑터와 공간 경향 조회 정책, 의미 오류를 실제로 수정하는
재검토 입력·출력, 여러 유형의 산책에서 장면 구성이 유지되는지에 대한 비교가 남았다.
장면 분할·병합, 큰 자료의 전달 비용, 앱·서버 연결은 아직 구현하지 않았다.
