# WalkDiaryRoute 시작·종료 보호와 단순화 측정

## 질문

단일 산책 일기에서 순서 있는 선을 보여 주려면 어떤 최소 파생이 필요한가. 앞뒤 경로 절단,
시작·종료점 공간 보호, 좌표 양자화, 선 단순화가 위치 노출·형태 충실도·크기에 어떤 차이를
만드는지 먼저 잰다.

이 실험은 합성 GPS와 dev payload를 쓴다. 개인정보 안전성이나 보관 기간을 입증하지 않는다.

## 재현

```bash
uv run python -m scripts.spikes.walk_diary_route.report
uv run pytest tests/sim/test_walk_diary_route_privacy.py -q
```

고정 seed, perfect sensor, 5초 간격, 1.2m/s로 세 모양을 비교했다. `mid-walk-home-revisit`는
시작점에서 출발해 160m 이동한 뒤 시작점을 다시 지나 다른 방향으로 끝난다. P95 오차는 공간
보호 후보에서는 보호권 밖 canonical 점만 대상으로 한다. 바이트는 공백 없는 후보 fragment
JSON의 UTF-8 크기다.

## 관찰

1. **경로 거리 절단은 일반적인 시작점 보호가 아니다.** 중간 재방문 경로에서 앞뒤 60m를
   잘라도 선이 시작점 1.79m까지 돌아왔다. 시작과 종료 순서만 보는 정책은 루프·왕복에서 깨진다.
2. **공간 보호는 선을 끊는 연산이어야 한다.** 점만 지우고 양끝을 다시 연결하면 보호권을
   가로지르는 가상 선이 생긴다. 구현은 두 원과 선분의 교차를 잘라 별도 fragment로 만들었고,
   기존 CanonicalTrail chain도 합치지 않았다.
3. **양자화·단순화는 크기와 디테일에는 강하다.** 완전 직선은 101점에서 2점으로 줄었다.
   하지만 이것만으로 시작점 노출은 0m에서 바뀌지 않는다. 개인정보 보호라고 부를 수 없다.
4. **반경은 정보 손실과 바로 맞바뀐다.** 짧고 결함이 있는 checked-in 예제에서는 60m 후보도
   canonical 거리의 32.7%만 남았고 100m 후보는 전부 사라졌다. 한 숫자를 전역 기본값으로
   채택할 근거가 없다.
5. **공간 보호도 익명화가 아니다.** 여러 산책에서 선이 같은 빈 원의 경계로 모이면 그 중심을
   추정할 수 있다. 이 실험은 한 세션의 직접 좌표 노출만 측정했고 누적 공격은 측정하지 않았다.

## 결론

단일 산책 일기 선의 제품 가치는 계속 검증한다. 다만 현재 결과로 서버 영속을 여는 것은
기각한다. 앞으로의 후보는 최소한 공간 보호·fragment 단절·버전·삭제 수명을 가져야 하며,
실제 기기와 반복 산책 누적 평가에서 반경과 보관 기간을 닫기 전에는 private coordinate-bearing
artifact로 취급한다.
