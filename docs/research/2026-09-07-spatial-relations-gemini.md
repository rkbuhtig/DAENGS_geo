## 적용한 정책

시스템이 관측 지점의 숫자를 공간 배경과 거리 변화로 요약하고, 행동 핀을 별도 사건으로 분리한다. 모델은 사건 하나를 장면 하나로 선택한다. 이번 실험에서는 사건 병합을 허용하지 않았다.

| 항목 | 이번 실험 정책 |
| --- | --- |
| 공간 배경 | 공원 대표점 100m 이내 → 하천 형상 100m 이내 → 상가 구성 순으로 대표 배경 선택 |
| 상가 배경 | 반경 125m 등록 상가 40개 이상은 ‘모인 구간’, 10개 이하는 ‘적은 구간’, 중간은 ‘산재한 구간’ |
| 흔들림 억제 | 다른 배경이 2개 관측 후보에서 연속 확인되면 새 배경으로 전환. 확인 후 첫 변화 지점부터 소급 적용 |
| 거리 관계 | 같은 대상의 연속 관측 3개 이상에서 모든 시점 쌍의 거리 변화율 중앙값(Theil–Sen) 계산 |
| 접근/멀어짐 | 처음·끝 거리 차이 절댓값 35m 이상이며 변화율 절댓값 0.25m/s 이상일 때 방향 부여 |
| 지나침 후보 | 최소 거리 지점의 앞·뒤 각각 3개 이상 관측으로 접근 후 멀어짐이 확인되면 ‘거리가 줄었다 다시 늘어남’ |
| 자료 단절 | 최근접 공원 이름 변경, 공간 사실 누락, GPS chain 변경을 가로질러 거리 추세를 연결하지 않음 |
| 이동 사건 범위 | 배경 전환, 행동 핀, GPS 단절, 최대 300초에서 분리 |
| 행동 사건 | 동일한 가상 냄새 핀 10분, 사진 핀 15분을 한 시점의 사건으로 유지. 뒤쪽 이동을 붙이지 않음 |
| 모델 권한 | 3~7개 사건 선택. 행동 사건은 필수 보존. 임의 시간 범위·좌표 작성 및 후보 병합 금지 |
| 근거 인용 | 장면당 행동 1개, 장소 근거 1~3개, 참가자 최대 2개 |

위 수치는 합성 실험용 초기값이다. 실제 GPS 정확도, 보행 속도, 지역별 상가 밀도에 맞춰 보정하지 않았다. 배경 전환에 히스테리시스를 사용하므로 사건의 모든 지점이 동일한 거리/상가 임계값을 충족한다는 뜻은 아니다. 한 구간의 대표 배경이라는 의미다. 행정동 변화만으로 사건을 나누지는 않는다.

‘어디로 향하는 목적’이나 실제 진입은 계산하지 않았다. 공원 대표점 접근과 공원 입장, 하천 근접과 하천 산책로 이용은 별개다. 방향 벡터/하천 접선 비교도 이번 구현에 포함하지 않았다. 거리 관계는 시간순 관측에 기반한 공간 변화다.

## 입력의 형태

모델에는 사건 ID, 관측 시간 범위, 연속 경로 chain, 참가자, 계산된 행동·장소 관계와 각 근거 ID를 전달했다. 예를 들어 ‘양재천까지 거리가 줄었다가 다시 늘어남’, ‘등록 상가가 모인 구간에서 늘벗근린공원 가까운 구간으로 주변 특징이 바뀜’이다.

원시 상가 수, 거리열, 관측 좌표, 계산에 사용한 원자료 ID는 로컬 audit 파일에 보관한다. 공간 전환 근거는 이전 사건 ID까지 추적할 수 있다. 모델이 선택한 사건 ID로 시스템이 대표 관측 좌표를 찾아 지도 핀을 배치한다. 사건 분리 때문에 1~2개 후보만 남는 곳에서는 3개 관측이 필요한 관계를 생성하지 않는다.

## 실제 호출 결과

모델은 이전과 동일한 `gemini-3.1-flash-lite`, temperature 0.2. 입력 구성, 프롬프트, 출력 계약을 함께 변경한 탐색 비교다. 전처리만의 효과를 분리한 통제 실험은 아니다.

| 조건 | 시스템 사건 수 | 장면 수 이전→이번 | 가장 긴 장면 이전→이번 | 입력 토큰 이전→이번 | 성공 호출 시간 |
| --- | ---: | --- | --- | --- | ---: |
| 이동만 | 11 | 4→5 | 13:00→5:00 | 16,542→3,661 | 6.031초 |
| 행동 핀 추가 | 15 | 3→5 | 23:49→5:00 | 16,690→4,426 | 3.641초 |
| 행동 핀+단절 | 18 | 4→5 | 19:04→4:00 | 16,123→4,995 | 4.000초 |

성공 응답 3건의 총 입력 토큰은 49,355→13,082로 약 73.5% 감소했다. 이번 성공 응답의 전체 토큰은 15,675, 호출 지연 합계 13.672초다. 첫 이동 조건 호출은 서버가 응답 없이 연결을 종료하여 한 번 재시도했다. 따라서 생성 요청 시도는 4회이며, 실패한 요청의 사용량과 처리 여부는 확인할 수 없다. `transport-failure.json`으로 별도 보존했다. 위 사용량·지연 합계에 그 실패 호출은 포함되지 않는다.

세 조건 모두 사건/근거 ID, 주체, 시간순, 사건 길이, 행동 보존 검사를 통과했다. **최대 장면 범위 축소와 행동 보존은 시스템 계약의 효과**이며 모델이 스스로 발견한 개선으로 해석하지 않는다. 조건별 성공 출력 1개씩인 합성 실험이므로 일반적인 품질 성공률은 산출하지 않는다.

## 내용 비교

행동 핀 조건은 ‘시작 → 냄새 맡기 → 공원 근처 사진 → 양재천 인근 이동 → 마무리’의 5장면을 생성했다. 사진은 15분 시점으로 분리됐고, 사진 뒤의 이동이 별도 장면으로 다시 나타났다. 이전의 ‘활기차게’, ‘잠시 멈춰’, ‘다정한 사진’ 표현은 이번 원문에 없었다. 이동만 조건의 ‘공원 주변 녹지’, ‘하천 산책로’, ‘산책을 즐긴다’도 이번 원문에서는 사라졌다.

하지만 계산된 거리 관계를 실제 인용한 것은 15개 장면 중 1개뿐이었다. 이동만 조건의 ‘독골근린공원에 가까워지는 경로’다. 행동 핀 조건과 단절 조건에서는 장소 배경과 행정동만 골랐다. 입력에 관계를 제공하는 것과 그 관계를 이야기의 중심으로 선택하는 것은 별개라는 점이 드러났다.

남은 문제:

- 지명과 행정동 이동을 반복하는 문장이 많다. 접근·멀어짐·지나침의 우선순위를 더 검토해야 한다.
- 단절 조건의 ‘기념 사진’은 촬영 목적이 주어지지 않았는데 추가한 수식이다.
- 이동만 조건의 limitations는 구체적 장소명이 없다고 썼지만 입력에는 공원·하천 이름이 있다. 모델의 자기 설명도 검토가 필요하다.
- 마지막 사건을 보고 ‘산책을 마쳤다’고 추론했다. 현재 행동 조각에는 종료가 명시되지 않았다. 시작처럼 종료도 시스템 사건으로 명시하는 편이 낫다.
- 단절 직후 재개 사건을 선택하지 않았다. 없는 경로를 만들지는 않았지만 카드만 읽으면 시간 공백이 약하게 드러난다. 화면의 단절 안내와 지도 공백을 함께 유지했다.
- 행동 핀과 공간 배경 전환으로 짧게 나누면 관계 계산에 필요한 3개 관측이 부족해진다. 다음에는 관계 계산용 관측 창과 장면 표현 범위를 분리해 비교할 필요가 있다.

제목·요약·장면·선정 이유는 모델 원문을 수정하지 않았다. 검토 의견을 별도로 작성하고 출력 SHA-256에 묶었다. 리뷰 파일의 내용과 출력 해시가 다르면 내보내기를 거부한다.

## 구현과 검증

`scripts/spikes/storyboard_composer/episodes.py`: 공간 배경·추세·사건 분리.
`episode_run.py`: 후보 전달, 실제 호출, 구조 검사, 기록.
`episode_export.py`, `episode-audit.js`, `episode-audit.css`: 이전 결과·사건 후보·계산 근거 비교 화면.
`llm.py`는 프롬프트·출력 스키마를 주입받는 선택 인자와 통신 실패 기록만 확장했다. 기존 v1 기본값과 원본 산출물을 유지했다.

원시값과 실제 요청·응답은 작업 공간의 `outputs/storyboard-composer/gemini-02/`. 키는 실행 프로세스 환경 변수와 HTTPS 헤더로만 사용했다. 앱·서버 운영 코드는 바꾸지 않았다.

```powershell
# 실제 호출 시 COMPOSER_GEMINI_KEY를 실행 환경에서 제공한다.
& ../DAENGS_geo/.venv/Scripts/python.exe -m scripts.spikes.storyboard_composer.episode_run --materials ../../outputs/storyboard-composer/materials.json --out ../../outputs/storyboard-composer/gemini-02 --run
& ../DAENGS_geo/.venv/Scripts/python.exe -m scripts.spikes.storyboard_composer.episode_export ../../outputs/storyboard-composer/gemini-02 ../../outputs/storyboard-composer/gemini-01
& ../DAENGS_geo/.venv/Scripts/python.exe -m unittest scripts.spikes.storyboard_composer.test_episodes scripts.spikes.storyboard_composer.test_contract -v
```

표적 회귀 검사 17개 통과. 추세에 필요한 관측 수, 작은 흔들림, 최근접 대상 교체, 공간 사실 누락, 배경 확인, 행동 사건 분리, GPS 단절, 잘못된 사건/근거 인용을 검증했다. 전체 저장소 테스트는 실행하지 않았다.
