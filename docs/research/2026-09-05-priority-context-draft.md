# 우선순위 기반 환경 조회 — 수정 가능한 초안

> 후속 상태: 선택 규칙은 [geo #238](https://github.com/rkbuhtig/DAENGS_geo/pull/238)에서
> 실데이터용으로 추출해 dev/app에 연결했다. 아래는 최초 lab 검증 시점의 기록이다.
> 현재 구현·미확인 범위·다음 작업은 [공간 일기 제작 계획](../explorations/walk/diary-storyboard-plan.md)을 따른다.

이 문서는 행동 핀이 없어도 산책 결과를 제공하기 위한 현재 lab 정책이다.
운영 app/dev에 승격하지 않았으며 기존 공통/행동별 조회 비교보다 우선한다.

## 선택 계약

기본 최소 목표 4구간, 구간 분리 간격 100m, 허용하는 최장 빈 거리 300m, 최대 선택 8구간.
최소 목표·분리 간격·빈 거리 기준은 화면과 JSON에서 바꿀 수 있다.

1. 수용된 액션 핀을 시간순으로 선택한다. 목표를 넘더라도 최대 예산 안에서 우선한다.
2. 동일 반려견의 현재 세션보다 이전인 서로 다른 산책 3개 이상에 이동 기준이 있으면
   평소 대비 이동 변화 후보로 부족한 목표를 채운다.
3. 이번 세션의 이동 속도 기준과 비교한 지속 변화 후보로 더 채운다.
4. 선택 구간이 차지하는 경로 범위를 제외한 가장 긴 빈 구간의 중앙에 가까운 유효 관측점을
   선택한다. 목표를 달성해도 300m를 넘는 빈 구간은 예산 안에서 추가 보충한다.

예를 들어 1km 경로에서 액션이 450~470m에 몰리면 하나로 묶고, 약 750m와 200m를
차례로 보충한다. 누적 수용 이동거리를 사용하며 직선 거리로 앞뒤 경로를 대체하지 않는다.
경로 단절마다 별도 block을 만들고 GPS 공백 위에 좌표를 보간하지 않는다.

같은 block에서 경로 거리와 좌표 거리 모두 분리 간격보다 가까운 후보는 하나로 묶는다.
여러 순위에서 같은 구간이 나오면 선택 이유와 근거를 추가한다. 왕복의 서로 다른 통과는
경로상 구간으로 구별할 수 있지만, 실제 API 캐시는 공간적으로 공유할 수 있다.
빈 거리 계산의 구간 폭은 선택점 전후 분리 간격의 절반이다. 이것은 편집용 경로 커버리지이며
API 자료가 그 구간 전체의 환경을 증명한다는 뜻이 아니다.

짧은 경로·관측 부족으로 목표를 채울 수 없으면 `minimum_met=false`와 사유를 반환한다.
예산으로 긴 빈 구간이 남으면 `coverage_met=false`로 표시한다. 액션 후보가 8곳을 넘으면
나머지 조회 후보를 명시적으로 보류한다. 행동 기록 자체는 삭제하지 않는다.

## 이동 비교는 아직 좁은 대리 지표

현재 과거 비교는 **과거 산책별 이동 구간 속도 중앙값들의 중앙값**이다. 현재 세션 기준도
이동 구간 속도 중앙값이며 최소 5개 구간을 요구한다. 0.5배 미만 또는 1.75배 초과가
20초 이상 연속한 구간을 후보로 삼고, 속도 차이×지속시간 순으로 고른다.
이는 평소의 장소별·시간대별 행동 경향을 구현한 것이 아니다. 앱의 행동 개수 프로필을
개인화 모델로 해석하지 않는다. 향후 비교 가능한 조건과 통계 정책을 교체할 자리다.

브라우저 비교 목록에 새로 저장한 산책은 이동 기준을 함께 저장한다. 기존 저장 항목에
기준이 없으면 비교에 사용하지 않는다. 현재/미래 산책, 다른 반려견, 중복 ID는 제외한다.
가져온 JSON은 명시적인 `reference_walks`로 재현한다. 새 산책을 시작하면 로컬 비교 이력을 쓴다.

자동 조회 지점은 사용자 행동 핀이 아니다. 지도에서는 보라 사각형이며 별도 환경 목록에
나타난다. 행동 프로필의 기록 개수와 근거 ID를 늘리지 않는다. 출력은 장소 배경과 관측된
이동 변화까지만 다루며 킁킁·감정·관심을 추론하지 않는다.

## 실행·비교

[실행 README](../../scripts/spikes/walk_record_lab/README.md)의 서버를 실행한 뒤,
핀 없이 종료하거나 액션을 한쪽에 몰아보고 선택 순서와 보충 전 빈 구간을 확인한다.
`evaluate`는 8개 입력(정상/공백/지연/핀 없음/메모/삭제/반복/과거 대비 변화)에
최소 목표 3·4를 적용한 16개 bundle을 만든다. 과거 대비 변화 예시는 합성 기준이다.

최소 목표 수는 발견한 시설 수나 장면 수를 보장하지 않는다. 선택한 지점에 조회가 실패해도
관측 경로·시간·기록에 기반한 결과는 남는다. 실제 키·원본 자료는 기존처럼 레포 밖에 둔다.

## 검증

선택 규칙 8개를 포함한 관련 테스트 40개와 Ruff를 통과했다. 액션 군집 후 뒷구간/앞구간 보충,
짧은 경로의 목표 미달, 최소 달성 후 긴 꼬리 구간 보충, 예산 초과 보류, 과거 기준의
동일 반려견/과거/중복 조건, 속도 후보 우선순위, GPS 공백 제외를 검증했다.
Chrome headless에서 핀 없는 1km 산책의 실제 환경 조회, 자동 지점의 프로필 제외,
액션 우선순위, 최소 숫자 변경, 합성 과거 기준 활성화를 확인했다. page error는 없었다.
16개 일괄 사례도 로컬 캐시로 실행했다. 실제 사용자·기기 평가와 운영 서버 통합은 별도다.
