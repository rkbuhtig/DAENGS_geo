## 시스템이 만든 조각

- 누가: 보호자와 반려견 두부. 두부는 비교용 가상 참가자 설정이다.
- 무엇을: 후보 지점 직전의 연속 GPS 구간에서 계산한 이동, 세션 시작, 단절 뒤 기록 재개. 현재 입력에는 검증된 체류 구간이 없다.
- 어디서: 후보 좌표에 연결된 SGIS 행정동, 반경 125m 등록 상가 수·업종, 공원 대표점 거리, 하천 형상 거리.
- 선택적 행동: 10분에 ‘두부가 여기서 냄새를 맡았다’, 15분에 ‘여기서 두부와 함께 사진을 찍었다’. 두 조각 모두 가상 사용자 핀이라고 출처에 명시했다.

공간 재료는 앞선 비교와 동일한 공공데이터 캐시다. 산책은 38분 49초 합성 경로이며, 단절 안에서는 16:35–19:45의 GPS가 없다. 공원 내부/하천 산책로를 검증하는 자료는 없다.

각 조각에 독립 ID, 종류, 출처, 관측 후보 ID를 부여했다. 행동에는 subject_ids가 있어 누구의 행동인지 연결한다. 후보에는 시각과 연속 경로 chain, 사용 가능한 세 종류의 조각 ID가 있다. 모델 입력에는 지도 좌표와 기존 수기 스토리보드를 넣지 않았다. 모델이 고른 anchor_id를 로컬 원본 좌표로 연결한다.

## 모델이 하는 일과 시스템이 검사하는 일

모델은 장면 3~7개를 제안하고 각 장면에 대표 anchor_id, 묶은 anchor_ids, who_ids, what_ids, where_ids, evidence_ids, 제목, 본문, 선정 이유를 반환한다. 전체 제목·요약·자료 한계도 생성한다. 참고: Google의 [구조화 출력 문서](https://ai.google.dev/gemini-api/docs/generate-content/structured-output?hl=en).

시스템은 존재하는 ID인지, 누가·무엇을·어디서가 모두 있는지, 행동의 주체가 포함됐는지, 인용 조각이 그 장면 후보에 속하는지, 시간순이며 장면 범위가 겹치지 않는지, 단절을 넘어서 묶지 않았는지, 대표 핀이 장면 안에 있는지 검사한다. 모델이 지도 좌표를 새로 쓰지 않는다.

ID 검사와 문장 의미 검토는 구분했다. 일부러 없는 감정을 넣은 문장도 ID 검사만으로는 걸러지지 않는다는 회귀 사례를 포함했다. 구조 통과 결과를 자동으로 내용 승인 상태로 승격하지 않는다.

## 원문에서 발견한 점

행동 핀을 넣자 냄새 맡기와 사진 촬영이 각각 중심 장면이 됐다. 사용자 기록이 스토리보드 구성을 바꾸는 것을 확인했다. 단절 안은 단절 이전 사진 장면과 재개 이후 이동 장면을 분리했다.

반면 금지 지침을 제공했는데도 다음 표현이 남았다.

- 이동 기록만: ‘공원 주변의 녹지’, ‘양재천 인근 산책로’, ‘산책을 즐깁니다’. 위치 단서를 확인되지 않은 경관·보행로·감정으로 확장했다.
- 행동 핀 추가: ‘활기차게’, ‘잠시 멈춰’, ‘다정한 사진’. 냄새 맡기 핀에 정지 사실이 없고, 사진 촬영 메모에 사진 내용이 없다.
- 사진 장면의 제목은 ‘공원에서’인데 본문은 ‘공원 근처’였다. 제목의 위치 표현도 검토 대상이다.
- 행동 핀 안의 마지막 장면이 15:00~38:49, 25개 관측 후보를 통째로 묶었다. 두 행동은 살렸지만 뒤쪽 약 24분의 공간 변화를 사실상 요약하지 못했다.
- 모델은 필요한 근거만 고르기보다 장면에 묶은 후보의 거의 모든 조각을 인용했다. ID가 많다는 사실이 문장의 근거 충분성을 증명하지 않는다.
- 모델 스스로 감정을 알 수 없다고 limitations에 적었지만 본문·요약에는 감정 표현을 사용했다.

생성 제목·요약·본문·선정 이유는 수정하지 않고 보존했다. 화면의 Codex 검토 의견을 분리했고, 해당 원문 해시와 검토 의견을 묶어 다른 재실행 결과에 이전 평가가 붙지 않도록 했다.

## 판단과 다음 실험

‘누가·무엇을·어디서’를 독립 조각으로 만들고 선택 ID를 반환받는 연결은 작동했다. 다만 1분마다 공간 정보를 평면으로 주면 모델이 큰 시간 구간을 묶고 근거를 과다 인용한다. 한 장면이 무엇을 대표하는지의 범위를 개선해야 한다.

다음에는 원자료 조각을 보존하면서 시스템이 장소/행동 전환을 이용해 짧은 후보 구간을 만들고, 모델은 그 후보를 선택하게 하는 안과 비교하면 좋다. 장면의 ‘중심 행동’과 ‘배경 장소’를 구분하고 문장별로 꼭 필요한 근거만 선택하게 한다. 내용의 사실성 검사도 전체 요약·제목까지 포함해야 한다. 현재 프로토타입을 운영 자동 생성 품질로 판단하지 않는다.

## 파일과 검증

실험 코드: `scripts/spikes/storyboard_composer/llm.py`, `llm_export.py`, `llm-audit.js`, `llm-audit.css`, `test_contract.py`. 기존 지도 viewer에는 선택 장면 이벤트 하나를 추가했다.

실제 산출물: 작업 공간의 `outputs/storyboard-composer/gemini-01/`. 조건별 input/request/response/receipt JSON 및 전체 runs.json을 저장한다. 요청·응답·프롬프트·원본 입력 해시·토큰 사용량을 확인할 수 있다. 인증 키는 호출 프로세스의 환경 변수와 HTTPS 인증 헤더로만 사용했으며 코드·HTML·JSON에 넣지 않았다.

```powershell
# COMPOSER_GEMINI_KEY는 실행 환경에서 제공한다. 아래 명령에 키 값을 넣지 않는다.
& ../DAENGS_geo/.venv/Scripts/python.exe -m scripts.spikes.storyboard_composer.llm --materials ../../outputs/storyboard-composer/materials.json --out ../../outputs/storyboard-composer/gemini-01 --run
& ../DAENGS_geo/.venv/Scripts/python.exe -m scripts.spikes.storyboard_composer.llm_export ../../outputs/storyboard-composer/gemini-01
& ../DAENGS_geo/.venv/Scripts/python.exe -m unittest scripts.spikes.storyboard_composer.test_contract -v
```

동일한 저장 응답이 있으면 입력·프롬프트·모델을 비교하고 재호출하지 않는다. 다른 실험은 새 출력 디렉터리를 사용한다. 검토가 달라지는 새 출력의 화면 내보내기는 새 의미 검토가 필요하다.

오프라인 회귀 테스트 8개 통과. 브라우저에서 조각 필터와 행동 조각 42개 표시, 카드와 지도 선택 동기화, 핀 키보드 선택, 단절 결과 전환을 확인했다. 앱·서버 운영 코드/DB를 변경하거나 실제 사용자 기록을 전송하지 않았다.
