# 복구한 맥락을 사람이 지도에서 읽을 수 있는가

2026-08-26 실험. 재현:

```bash
uv run python -m scripts.spike_persona_year --cache osm.json --json personas.json
uv run python -m scripts.spike_layer_scenes --personas personas.json \
    --cache-sheets sheets.pkl --out layer-scenes.json
uv run python -m scripts.spike_basemap --walks bbox.json --out layer-basemap.json
```

코드는 `scripts/spike_layer_scenes.py`. 갈래는
[territory-paint](../explorations/walk/territory-paint.md).

## 앞 실험과 무엇이 다른가

[셀로판 회수 실험](2026-08-26-cellophane-recovery.md)이 답한 것은 **정보적으로 복구 가능한가**
였고 답은 숫자였다(코사인 −0.999, ε 0.0341). 여기서 묻는 것은 다른 질문이다.

> 그렇게 복구한 정보를 **사람이 지도에서 읽을 수 있는가.**

판정하는 것도 다르다. 앞은 평가기가, 여기는 **눈**이 한다.

## 고정 시나리오인 이유

미리 겹쳐 둔 조합만 실을 거면서 UI 를 임의 태그 조합처럼 만들면 **실제보다 되는 것처럼
보인다.** 가짜 공급자가 설계의 모든 질문에 답해서 데이터의 한계가 안 보였던 결정 #51 의
UI 판이다. 그래서 13 개 시나리오를 `spike_layer_scenes.SCENARIOS` 에 못 박고 뷰어는 그
목록만 보여준다. 문턱도 슬라이더가 아니라 **두 단계 토글**(`전부` / `심만`)인 것이 같은 이유다.

임의 조합 질의는 DB·API 로 갈 때 한다.

## 무엇을 확인했나

뷰어를 1280×900 으로 띄우고 캔버스 픽셀을 직접 재서 확인했다 — "그럴듯해 보인다" 가 아니라
값으로.

### 1. 전체 장면에서 F1 과 F2 는 구별되지 않는다

같은 집·같은 두 경로·같은 연간 횟수, 계절 배정만 반대인 두 사람.

```
F1|F2 전체    왼쪽 지문 400 · 오른쪽 지문 400 · 차이 0
```

캔버스 밝기 지문이 **완전히 같다.** 앞 실험의 "연간 누적 거리 0.0158(ε의 0.5배)" 이
화면에서 이렇게 보인다 — **누적만 저장했다면 여기서 끝이다.**

### 2. 계절 버튼 하나로 갈라진다

```
F1|F2 여름    386 / 373
F1|F2 겨울    373 / 386      ← 정확히 뒤집힘
```

두 판의 값이 자리를 바꾼다. 버튼 하나 차이다.

### 3. 차이 모드에서 부호가 반대로 칠해진다

발산 램프(따뜻함 = 기준 장면 우세, 차가움 = 빼는 장면 우세)로 `여름 − 겨울` 을 그리면:

| | 따뜻한 픽셀 | 차가운 픽셀 | 따뜻함 비율 |
|---|---:|---:|---:|
| F1 | 11,000 | 5,952 | **0.649** |
| F2 | 6,225 | 10,748 | **0.367** |

코사인 −0.999 가 화면에서 **색 반전**으로 나타난다. 숫자를 안 봐도 읽힌다.

### 4. 대조군 A 는 어느 장면에서도 안 변한다

```
A 여름 414 · A 겨울 410 · A 1분기 411
```

패턴을 안 심은 사람은 버튼을 눌러도 그림이 그대로다. **이게 흔들리면 1~3 의 차이도
믿을 수 없다.**

### 5. 얽힌 태그와 분모가 화면에 같이 나온다

```
E 여름∩밤   n =  72
E 여름∩낮   n =  18      ← 분모가 화면에 붙어 있다
```

"여름 낮엔 하천에 안 간다" 를 n=18 에서 읽고 있다는 것이 보인다. 비율을 분모 없이 내지
않는다는 규율([territory-paint §D](../explorations/walk/territory-paint.md))의 UI 판이다.

## 설계에서 고른 것

**두 판이 같은 창·같은 축척을 쓴다.** bbox 를 공통으로 고정했다 — 각자 자기 데이터에
맞춰 확대하면 나란히 놓는 의미가 없다.

**모드 셋을 갈랐다.** `물감`(한 조건의 지도) · `존재`(간 적 있나) · `차이`(방문률 차).
존재와 차이가 다른 질문이라는 것을 UI 에서도 갈라 보여준다 — 여름 90% · 겨울 10% 인 칸은
존재로는 양쪽에 다 있어 사라지고 차이에는 +0.8 로 남는다.

**결과마다 spec 지문을 띄운다.** 판 아래에 `spec 158b3241d6cd` 가 붙는다. 어떤 조건·집계로
만든 그림인지 화면에서 따라갈 수 있어야 한다는 `LayerSpec` 의 취지를 UI 까지 끌고 온 것이다.

## 알게 된 것 — 밝기 지문은 발산 램프에서 못 쓴다

검증을 자동화하면서 걸린 것: 차이 모드에서 두 판의 밝기 합이 416 대 421 로 거의 같게
나왔다. 색이 정반대인데도 그렇다 — 양수 쪽과 음수 쪽이 **밝기는 비슷하고 색상만 다르기**
때문이다. 그래서 부호 검증은 밝기가 아니라 따뜻함/차가움 픽셀 수로 해야 했다.

순차 램프에는 밝기 지문이 맞고 발산 램프에는 안 맞는다. 다음에 이런 검증을 짤 때 다시
밟지 않으려고 적어 둔다.

## 이 실험이 말하지 않는 것

- **사용성 검증이 아니다.** 실제 견주가 이 화면을 이해하는지는 안 물었다. 여기서 판정한
  것은 "심어둔 차이가 화면에서 드러나는가" 까지다.
- **임의 질의가 되는 게 아니다.** 13 개 조합만 미리 겹쳐 두었다. UI 가 그 이상으로 보이지
  않게 만든 것이 이 실험의 설계 조건 중 하나다.
- **등급 문턱을 정하지 않았다.** `전부`/`심만` 두 단계를 눈으로 비교할 수 있게만 해 뒀다.
  등급은 이 화면에서 관찰한 뒤 별도로 정한다.
- **성능.** 장면을 미리 겹쳐 실었다(918KB). 조합이 늘면 이 방식은 안 늘어난다 — 실시간
  질의는 DB·API 단계의 일이다.
