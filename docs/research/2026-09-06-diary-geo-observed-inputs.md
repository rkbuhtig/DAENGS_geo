# 관측 GPS 계산을 스토리보드에 연결한 실험

2026-09-06. [산책 일기 계획](../explorations/walk/diary/plan.md)의 후속 실험이다.
[초기 골격 실행](2026-09-06-diary-storyboard-skeleton.md)의 수기 수치를, 합성 관측 GPS에서
실제 geo 함수로 계산한 자료로 바꿨다. **입력 확보부터 Gemini 스토리보드까지 연결됐지만,
킁킁 기록을 마킹으로 바꾸는 오류는 최종 재검토에서도 남았다.**

## 확보한 자료와 경계

지정된 `forwork` 폴더에서 API 설정은 확인했지만 실제 산책 export는 찾지 못했다.
기존 `scripts.sim.walk` 시뮬레이터로 이번 산책 1개와 과거 15개를 생성했다.
실제 보호자가 걸은 경로나 기록을 확보했다는 뜻은 아니다.

| 자료 | 이번 입력 |
|---|---|
| 이번 GPS | 2026-09-06 07:00:00–07:22:28.085310 KST, S→A→B→A→S |
| 과거 GPS | 직전 15일의 합성 산책. S→A→S 8개, S→A→B→A→S 3개, S→D→E→S 4개 |
| 센서 | 5초 간격, 정확도 입력 3m, 지터 sigma 0.25m. 첫 사례에는 인위적 관측 공백을 추가하지 않음 |
| 행동핀 | 160초·1175초에 별도 작성한 킁킁 핀. 메모는 나무 밑 탐색과 돌아오는 길 같은 나무 밑 재탐색 |
| 환경 | 이전 좌표 실험에서 저장한 실제 Kakao 응답 6개. A·B 각각 주소, 카페, 음식점 검색 |

A는 (37.48928, 127.05633), B는 (37.48430, 127.05400)이다. 직선으로 작성한 경로이며
도로망·보행 가능 여부를 검증하지 않았다. 과거 경로 구성 자체를 실험자가 정했으므로
아래 등장률은 그 구성의 계산 결과이며 자연 발생한 이용 성향의 통계가 아니다.

생성 조건과 정답은 `evaluation/`에 저장한다. 어댑터는 `observations/`의 관측 export와
별도로 작성한 `pins.json`만 받아 계산한다. 생성기의 정답 경로·정지 의도·seed와
`truth_duration_s`가 포함된 사전 계산 bundle은 LLM 입력으로 넘기지 않는다.

## 연결한 계산과 정책

`compute_facts` → 수용된 시간순 경로·거리·시간·측정 상태,
`compute_curve` → 세션 시간 10구간의 움직임,
`extract_observations` → 저속·공백 관측을 계산한다.
연속성과 기존 moving 분류가 같은 구간을 묶어 입력 시간축을 만든다. 이 구간은 최종 장면이 아니다.
기존 저속 후보 기준(1m/s, 3초)을 사용했고 새 행동 분류기나 장면 우선순위를 추가하지 않았다.

과거 공간은 각 관측 경로를 `paint_sheet`로 칠한 뒤 `territory.dwell.read_at`으로 읽는다.
정책은 `fixtures/acquisition.json`에 별도로 둔다.

- 대상: 이번 저속 관측 중심 4개, 행동핀 2개, 수용 경로 양끝 2개. 모두 조회하며 서사 점수로 거르지 않는다.
- 선택: 같은 반려견, 2026-08-07부터 이번 시작 시각 전까지 시작하고 이번 시작 전에 완료된 산책.
- 조건: 추가 태그 없음, 빈 장 포함. 시간대 태그 선택은 `Asia/Seoul` 기준으로 계산한다.
- 공간: 읽기 반경 30m, 붓 반경 8u, `NARROW_STEP`, `min_peak=0`.
- 전달: 등장 산책 수/선택 산책 수, 등장률, 공간에 배분된 관측 초, 등장/선택 산책당 질량,
  이번 반경 내 연속 관측 구간, 정책·원본·계산 지문과 선택한 산책 ID.

같은 산책은 등장 횟수에 최대 한 번 기여한다. 시간 질량은 셀에 배분한 관측 시간이며
실제 정지 시간이나 냄새 맡은 시간이 아니다. 이번 통과 구간도 반경 안 관측점 묶음이며
정확한 원 경계 통과 시각은 아니다. 과거 자료에는 행동 이력이 없다.
이 조건들은 실험용 정책이며 제품의 반경·조회 대상·조각 개수로 확정하지 않았다.

환경은 조회 대상과 기존 조회 중심이 15m 이내일 때 연결한다. 원래 시설 검색의 250m 반경과
중심·수집 시점을 유지하며 현재 GPS 주변에 새로 질의한 것처럼 바꾸지 않는다. 응답의 연락처
등 불필요 필드는 제외한다. 응답 없는 출발·도착 주변 3개 대상은 `no_source`로 남긴다.
주소에 있는 건물명이나 주변 시설은 공원 내부·시설 방문을 증명하지 않는다. 당시 날씨는 없다.

경로 양끝 2개, 과거 공간 조회 8개, 환경 응답 6개와 자료 없음 3개다.

| 07:02:25–07:03:05 | 비이동 | 5.58m |

기존 추출 결과 그대로 전달했으며, 생성기에 지정한 정지 3개에 맞춰 후보를 고치지 않았다.

| 대표 조회 공간 | 등장 / 선택 산책 | 시간 질량 | 이번 반경 내 연속 관측 구간 |
|---|---:|---:|---:|
| A 주변의 첫 저속·재방문·두 핀 | 11/15 | 930.46초 | 2개 |
| B 반환점 저속 | 3/15 | 204.57초 | 1개 |
| 출발·도착 주변 | 15/15 | 733.56초 | 2개 |

수치를 직접 입력하지 않았다. `calculation_audit.json`에 과거 산책별 셀 질량과 조회 기여를
저장해 어떤 산책이 분자·분모에 들어갔는지 추적한다. 관측 export·캐시에서 다시 계산한
자료 조각과 집계 영수증이 저장 결과와 정확히 일치했다.

## 실제 Gemini 실행

모델은 `gemini-3.1-flash-lite`. 기존 단계별 프롬프트를 바꾸지 않고 계산된 `evidence.json`을
전달했다. 전체 이해 1회 → 모델이 고른 장면 6개를 개별 호출 → 전체 재검토 1회로 실행했다.
모델은 반환점 정지와 복귀 이동을 한 장면으로 묶었고 나머지는 입력 시간축과 비슷하게 나눴다.

두 번째 장면에서 HTTP 503이 발생했다. `advance`로 실패한 장면부터 재개했고 이미 완료한
이해·첫 장면은 다시 호출하지 않았다. 자동 재시도 횟수나 모델 결과를 숨기지 않았다.

| 항목 | 결과 |
|---|---|
| 실제 API 시도 | 9회: 완료 8회 + HTTP 503 1회 |
| 보고된 토큰 합 | 217,583. 성공 응답 usage 합이며 실패 요청 사용량은 없음 |
| API 호출 지연 합 | 51.42초. 실패 포함, 전체 작업 경과 시간과 다름 |
| 완료 상태 | `awaiting_review`, revision 7 |
| 재검토 | `replacement_scenes=[]`, 확인 사항 1개 |
| 사용자 검토 / 일기 결정 / 일기 | 모두 미실행 |
| 저장 응답 재생 | 실제 API 호출 없이 8개 단계 재생, 최종 상태 일치 |

## 서술에서 실제로 드러난 문제

1. 장면 2는 핀의 킁킁과 공간 등장 11/15를 읽고, 자신의 존재를 표시하는 정기적 정보 수집
   장소라고 해석했다. 장면 3 본문은 이를 **“늘벗근린공원의 마킹 지점”**으로 서술했다.
   재검토 후 `observed_flow`에도 **“익숙한 나무 마킹”**, **“귀갓길 나무 마킹”**이 남았다.
   관찰되지 않은 행동이 해석을 거쳐 관찰 흐름에 들어간 것이다.
2. 과거 공간 등장은 과거 행동 반복을 측정하지 않는다. 그런데 최종 확인 사항은 11/15를
   근거로 해당 지점이 주요 공간 정보 허브임을 강하게 시사한다고 했다.
3. 지도 응답은 근처 주소·시설인데 본문은 **“공원 내의 특정 나무”**라고 단정했다.
4. 일정한 복귀 속도에서 **“귀가 경로를 완벽히 숙지”**했다고 썼다. 위치·속도 자료는 그
   심리적 해석을 확인하지 않는다. 40초·50초의 비이동 구간도 핀 행동의 지속시간과 구별해야 한다.

왕복 순서, 같은 나무에서의 두 기록, 주요 시간·거리는 읽었다. 하지만 근거 ID가 존재한다는
검사와 모델의 최종 재검토만으로는 주장과 근거 사이 의미의 비약을 막지 못했다.
입력이 달라진 단일 사례이므로 초기 수기 시나리오보다 서술 품질이 좋아졌다고 비교하지 않는다.

## 설계에 반영할 판단

이번에 확보한 진전은 **원본 관측 → 계산·조회 조건 → 조각 → 단계별 주장**의 추적 경로다.
다음 실험은 문제가 된 주장을 그 원자료로 되돌려 검토하고, 수정이 실제 장면과 전체 이해에
반영되는지 확인해야 한다. 과거 공간 정보를 배제하거나 장면 우선순위를 하드코딩할 근거는 아니다.
관측·해석 필드를 나누는 것만으로도 부족하다는 사례가 생겼다.

35개 조각을 매 호출에 반복 전달하면서 토큰 합이 커졌다. 조각별 중복 출처를 공통 참조로
옮기는 방법과 필요한 원자료를 보존하는 호출 구성을 후속 비교할 수 있다. 이번에는 입력을
임의로 줄이거나 유리한 모델 출력만 골라 기록하지 않았다.

## 검증과 재현 자료

[README](../../scripts/spikes/diary_storyboard/README.md)에 실행 명령과 외부 캐시 형식을 기록했다.
코드·recipe·테스트·이 문서만 저장소에 둔다. 키, 실제 응답 원문, 관측과 모델 요청·응답은
저장소 밖 `experiments/`에 있다. 새 환경에서 실제 입력 실행을 재현하려면 해당 캐시가 필요하다.

| 로컬 경로 (`DAENGS_geo`의 형제 `experiments/` 기준) | 내용 |
|---|---|
| `coordinate_narration/cache/` | 실제 지도 응답 캐시 |
| `diary_storyboard_geo/computed-input-02/` | 확정 입력·생성 정답 분리·계산 영수증·재계산 검증 |
| `diary_storyboard_geo/computed-live-01/` | 실제 요청·응답·503·체크포인트·스토리보드·검증 |
| `diary_storyboard_geo/computed-replay-01/` | 동일 요청 재생 결과 |

초기 `computed-input-01`에서 세션 모델의 UTC 정규화로 오전 태그 선택이 어긋날 가능성을
발견했다. 조회 정책의 시간대로 변환한 뒤 칠하도록 고치고 회귀 테스트를 추가했으며,
Gemini에는 수정된 `computed-input-02`를 사용했다.

회귀 검증은 시간 질량 보존, 산책당 등장 중복 방지, 과거 1개 제거 시 분모·분자 변경,
빈 과거와 0회 등장 구별, 반려견·기간·지역 시간대 선택, 생성 정답 차단, 읽기 반경 하한,
환경 부분 응답·자료 없음·불필요 필드 제거와 기존 골격 상태 전이를 다룬다.
저장 데이터의 재계산 일치와 LLM 8개 상태 전이·오프라인 재생도 별도로 확인했다.
