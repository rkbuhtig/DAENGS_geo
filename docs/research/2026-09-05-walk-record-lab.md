# 2026-09-05 — 행동 기록과 공간 배경의 종료 후 비교

[실행 방법과 실험 규칙](../../scripts/spikes/walk_record_lab/README.md).

## 질문

킁킁·배설·짖기와 메모를 받아 산책 종료 후 선별적으로 실제 주변 정보를 붙였을 때,
기록만 / 환경 추가 / 장면 편집이 어떻게 달라지는가? 개인화 정책을 확정하기 전의 비교다.

## 이번에 연결한 범위

기존 `walk-trace-lab` 경로 편집기와 관측·전달 생성기를 재사용했다. 독립 loopback 서버와
비교 화면을 추가했으며 운영 DB/API는 변경하지 않았다. 기록 수정·삭제, 메모,
캐시 기반 환경 조회, 두 정책, 장면 수 조절, 입력 내보내기/가져오기, 합성 반복 산책 집계를 지원한다.

처음 제공된 env의 공공데이터 키는 미등록 오류를 받았다. 별도 공공데이터 문서의 다른 키로
정상 응답을 확인했다. 키·원본·생성 산출물은 저장소 밖에 두었다.

이번 실행에서 강남구 제공 공원 146건(1페이지), 전국 하천 2,558건(3페이지),
예시 중심 반경 250m 상가 128건(1페이지)을 수집했다. 화면에서 기록한 별도 예시 킁킁 핀에는
늘벗근린공원 대표점 약 96m, 반경 125m에 수집된 등록 상가 중 음식 10·교육 2·소매 1이 표시됐다.
이는 합성 위치와 실제 자료를 결합한 결과이며 실제 방문이나 행동 원인이 아니다.

## 14개 합성 비교

장면 수 상한은 시작·끝 포함 5장이다. '환경 있음'은 하나 이상의 공간 사실이 붙은 기록 수다.

| 입력 | 수용/거절 기록 | 장면 | 공통 정책 환경 있음 | 행동별 정책 환경 있음 |
|---|---:|---:|---:|---:|
| 정상 | 4 / 0 | 5 | 3 | 2 |
| 공백·정확도 저하 | 2 / 2 | 4 | 1 | 0 |
| 지연·역순·중복 전달 | 2 / 2 | 4 | 1 | 1 |
| 핀 없음 | 0 / 0 | 2 | 0 | 0 |
| 메모만 | 1 / 0 | 3 | 0 | 0 |
| 첫 킁킁 삭제 | 3 / 0 | 5 | 2 | 1 |
| 다른 날짜의 반복 | 4 / 0 | 5 | 3 | 2 |

이 표는 정책이 다르게 작동함을 확인한다. 환경이 더 많이 붙는 정책이 더 좋다는 근거는 아니다.
정상 산책의 중간 기록 4개 중 하나는 5장 제한에서 생략되지만 프로필 근거에는 남는다.
핀 삭제는 기록과 프로필에서 제외된다. GPS가 없는 순간의 메모는 위치 없이 살아남는다.

## 판단과 다음 실험

이번 지역에서는 공원 대표점과 상가 배경을 붙일 수 있다. 하천 데이터 응답이 정상이어도
근처 하천을 설명할 수 있다는 뜻은 아니다. 표준 시점 좌표와 하천 형상은 서로 다른 재료다.

새로운 API를 늘리기 전에 동일 산책의 세 결과를 직접 비교해 어떤 정보가 기억에 도움이 되는지
판단할 수 있게 됐다. 등간격 장면 선택은 메모나 중요한 순간을 놓칠 수 있으므로 장면 수와
선택 규칙은 아직 제품 정책으로 승격하지 않는다. 관측 정확도가 좋은 위치 튐도 별도 진단에서
드러나므로 이 lab의 나이·정확도 문턱값을 운영 수용 규칙으로 그대로 옮기지 않는다.

다음 근거는 보호자가 직접 눌러보고 결과를 읽은 평가와 실제 기기 기록이다. 실제 서버 동기화,
다견 귀속, 장소 동일성, 개인화 성격 해석, 사용자 만족은 이번 검증 범위에 포함하지 않았다.

## 검증

새 규칙 테스트 13개와 기존 GPS lab·원천 수집 테스트를 합친 32개를 검증 대상으로 삼았다.
Chrome headless에서 기록·메모 저장, 삭제 후 현재/저장 프로필 갱신, 메모 HTML 이스케이프,
JSON 가져오기/내보내기, 정책 변경, 반복 산책 집계, 기존 GPS 편집기 경로 가져오기를 확인했다.
브라우저 page error는 없었다. 실제 API 조회는 자동 테스트와 분리해 수행했다.
