# 경계·상권·공원·하천으로 만드는 장면 비교

> 이 문서는 Geo `185747f` 기반 로컬 실험의 당시 기록이다. 본문의 코드 경로·실행 명령·localhost 주소는 해당 실험 작업 공간을 가리킨다. 이 문서 PR에는 실험 실행 코드와 원천 캐시를 포함하지 않는다. [종합 보고서](2026-09-07-walk-diary-experiment-report.md)에서 최신 검토 결론과 이전 정책을 대체한 단계를, [보존 자료 안내](2026-09-07-walk-diary-evidence/README.md)에서 저장소만으로 확인할 수 있는 범위를 확인한다.

2026-09-07. 실제 공공데이터 캐시 위에 같은 합성 산책을 놓고, 사용할 수 있는 재료를 바꿔 Codex가 제목·장면 선정·본문을 편집했다. 별도 LLM API 호출이나 자동 선정 성능 평가는 수행하지 않았다. 앱·서버 운영 로직과 데이터는 변경하지 않았다.

## 결과 보기

로컬 비교 화면: http://127.0.0.1:8768/?case=all

원본 구현: `scripts/spikes/storyboard_composer/`. 생성 결과: 작업 공간의 `outputs/storyboard-composer/`에 `materials.json`, `comparison.json`, `index.html`, `viewer.js`.

같은 38분 49초 산책의 여섯 편집안, 총 34개 장면. 지도 숫자는 장면 순서이며 핀과 카드를 연결했다. 좁은 화면에서 지도 핀을 누르면 해당 카드로 이동한다. 각 장면에서 선택 이유와 근거 조각을 확인할 수 있다.

| 제공 재료 | 만들어 본 이야기 | 달라지는 것 |
| --- | --- | --- |
| 경계 | 도곡에서 개포를 지나 | 위치와 큰 구성을 잡는다. 짧은 경계 변화들은 한 장면에 묶었다. |
| 상권 | 서로 다른 상가 사이를 걷다 | 상가 수 변화와 업종 구성 차이를 장면으로 선정한다. |
| 공원·하천 | 공원 이름과 양재천을 따라 읽는 산책 | 가까워지는 장소와 거리 변화가 순서를 만든다. |
| 네 재료 | 상가 사이에서 양재천 가까이, 다시 거리로 | 상권 변화에 공원·하천이라는 배경을 붙인다. 경계는 필요한 위치 단서로 사용한다. |
| 네 재료 + 가상 사용자 메모 | 늘벗 가까이에서 남긴 사진 한 장 | 15분 지점의 메모 한 조각만으로 제목과 중심 장면이 바뀐다. 다른 장면과 좌표·순서는 유지했다. |
| 네 재료 + GPS 누락 | 양재천 가까이 남은 두 기록 사이 | 16:35–19:45를 제거하면 가장 가까웠던 17분 장면을 사용할 수 없다. 앞뒤 기록만으로 계속한다. |

## 실제로 발견한 조합

10분 지점의 반경 125m 등록 상가는 98개(소매 33, 음식 27, 보건의료 12). 15분 지점에서는 등록 상가 0개, 늘벗근린공원 대표점 9m, 양재천 형상 138m였다. 상권만 있으면 ‘등록 상가가 없는 구간’인데 공원·하천이 더해지면 ‘상가 구간에서 공원·하천 가까운 구간으로 이어진 흐름’이 된다.

21분 지점에는 상가 85개(소매 25, 부동산 24, 교육 11)가 다시 잡힌다. 앞의 상가 구간과 업종 구성이 다르므로 두 번째 상가 장면에도 남길 이유가 있다. 이 차이는 같은 산책 안의 공간 비교이며 과거 대비 새로움이나 익숙함 판정이 아니다.

양재천 형상까지 거리는 17분 0m, 21분 164m, 30분 23m로 바뀐다. 같은 장소 이름이 반복돼도 거리 변화가 있는 두 구간을 별도 장면으로 구성할 수 있다. 합성 동선과 물 형상의 겹침은 실제 하천 보행로를 이용했다는 검증 결과가 아니다.

공공 공간 정보는 어디서 배경이 바뀌는지 설명하는 데 강하고, 사용자 핀은 그곳에서 무엇을 남겼는지 설명하는 데 강하다. 장면 선정의 중심은 데이터 종류의 수보다 구간의 변화와 사용자 기록에 두는 것이 적절해 보인다. 이는 이번 편집 비교의 관찰이며 사용자 평가로 검증된 결론은 아니다.

## 더 만들 수 있는 시나리오와 필요한 조각

| 시나리오 후보 | 필요한 조각 | 이번 자료로 가능한 범위 |
| --- | --- | --- |
| 상가 사이에서 물가 가까이로 | 시간순 경로 + 상가 수·업종 + 하천 거리 | 현재 비교안에서 구성했다. |
| 같은 동네 안의 다른 배경 | 행정동 + 상권/공원/하천 변화 | 경계가 바뀌지 않아도 장면을 나눌 수 있다. |
| 두 동네를 잇는 다리 | 경계 전환 + 하천 + 교량/보행로 연결 + 연속 경로 | 교량·보행로 자료가 필요하다. 경계와 하천만으로 다리를 고르면 안 된다. |
| 공원을 통과한 산책 | 경로 + 공원 면 경계·출입구 | 현재 대표점 자료는 공원 접근 장면까지만 지원한다. |
| 물가에서 남긴 한 장 | 하천/공원 + 시간·좌표가 있는 사진 또는 사용자 메모 | 가상 메모로 비교했다. 실제 사진 내용은 사용하지 않았다. |
| 걷던 흐름 중 한 번의 머묾 | 시간순 이동 + 검증된 속도·체류 구간 + 사용자 핀 | 앱의 미시적 움직임 정보와 연결할 후보. 쉬었다거나 즐거웠다는 뜻은 사용자 기록이 있어야 붙는다. |
| 비 오는 날의 공원 기록 모아보기 | 세션 날씨·계절 + 공간 맥락 + 장면 인덱스 | 향후 셀로판 검색과 연결 가능. 이번 자료에는 날씨를 추가하지 않았다. |

## 다음 구현에 가져갈 계약

1. 규칙 기반으로 경로의 관측 지점·연속 구간에 공간 사실과 출처를 붙인다. 명확하지 않은 경계는 사실 목록에서 제외한다.
2. 모델에는 경로 전체의 무제한 원자료보다 장면 후보와 근거 ID, 사용자 기록, 구간 전환 정보를 준다.
3. 모델은 후보 ID 중 장면을 선정하고 제목과 본문, 사용한 근거 ID를 반환한다. 지도 좌표는 후보 ID를 통해 시스템이 연결한다.
4. 기록 단절과 자료 미확인은 그대로 남긴다. 장면 수를 채우려고 미관측 장면을 추가하지 않는다.
5. 최종 UI에는 자연스러운 제목·본문을 사용하고, 대표점 거리·상가 수 등 검토용 세부값은 진단 화면에 둔다. 이번 화면은 판단 근거를 검토하기 위한 실험용 문구다.

이번 편집안을 모델의 정답으로 고정할 필요는 없다. 사실 연결·시간 순서·자료 누락은 기계적으로 검사하고, 장면 선택의 납득 가능성과 내용의 유용성은 여러 출력안을 비교해 평가한다.

## 데이터와 재현

- 기존 2026-09-04 `outputs/walk-storyboard/storyboard.json`의 완전/누락 합성 경로를 사용했다.
- 같은 날 `outputs/storyboard-source-cache`에 수집한 공공데이터 캐시를 재사용했다. 새 외부 전송은 없다.
- 경계는 사용자 제공 `bnd_dong_11_2025_2Q.zip`, SGIS 2025-06-30 기준. 수집 영수증과 원본 fingerprint는 생성 JSON에 포함된다.
- 상가 4,647개 캐시에서 반경 125m 조회 범위가 수집 범위 안에 완전히 들어오는 후보만 사용한다. 상가 수는 보행자 수·실제 영업 여부·방문 횟수가 아니다.
- 강남구 공원 자료는 대표점이다. 하천 표준데이터에 양재천·탄천 정보가 없어 기존 EGIS 하천 형상 캐시로 보완했다.
- 원래 관측된 경로 꼭짓점 중 약 1분 간격으로 선택하며 처음·끝·단절 양 끝은 유지한다. 완전 경로 후보 40개, 누락 경로 39개. 새 좌표를 보간하지 않는다.
- 가상 사용자 메모는 `pin` 비교안에만 존재한다. 실제 사용자 기록·사진은 사용하지 않았다.

`materials` 명령은 원본 경로 파일, 캐시 디렉터리, SGIS ZIP을 인자로 받는다. geometry 의존성은 Geo 원래 프로젝트 환경에 임시 추가하며 의존성 명세를 수정하지 않았다.

```powershell
uv run --project ../DAENGS_geo --with shapely --with pyproj --with pyshp python -m scripts.spikes.storyboard_composer.materials --source <원본-storyboard.json> --cache <캐시-디렉터리> --boundary <SGIS-ZIP> --out ../../outputs/storyboard-composer/materials.json
& ../DAENGS_geo/.venv/Scripts/python.exe -m scripts.spikes.storyboard_composer.build --materials ../../outputs/storyboard-composer/materials.json --out ../../outputs/storyboard-composer
& ../DAENGS_geo/.venv/Scripts/python.exe -m scripts.spikes.storyboard_composer.verify ../../outputs/storyboard-composer/comparison.json
```

검증 결과: 6개 안/34개 장면 모두 관측 좌표, 근거 일치, 허용 재료, 시간 순서, GPS 단절 제외 조건을 통과했다. 메모 추가가 다른 장면을 바꾸지 않는지도 검사했다. 브라우저에서 여섯 재료 전환과 지도 핀→카드 연결을 확인했다. 전체 앱 테스트나 자동 LLM 품질 평가는 이 실험 범위에 포함하지 않았다.
