# 행동·글·사진에 주변 API 봉투를 붙인 1·2단위 결과

2026-09-08. [계약](../explorations/walk/diary/record-envelopes.md),
[수집 정책·재현 명령](../explorations/walk/diary/record-envelope-collection.md).

## 무엇을 확인하려 했나

행동뿐 아니라 사용자가 남긴 글·사진을 원본으로 유지하면서, 주변 API 정보를 출처·태그가 있는
봉투로 추가할 수 있는지 확인했다. LLM에 정규화를 맡기거나 일기 문장을 생성하지 않았다.
기존 Geo의 별도 LLM 구성 실험 워크트리는 변경하지 않고, 이번 계약·수집만 main 기준 별도 PR로 묶었다.

강남구 일대 **합성 기록 6개**를 사용했다. 행동 1개, 자유 글 4개, 사진 참조 1개이며 실제
사용자의 산책·감상·촬영 자료가 아니다. 위치 있는 기록은 5개이고 좌표는 3곳이다. 글 하나는
위치가 없고, 하나는 다음 날 작성하여 과거 route 시각에 연결되며, 하나는 작성 시각이 미상이다.
기록과 관측 위치를 정한 뒤 실제 공공데이터 API를 조회했다. 사진 파일 자체는 만들거나 업로드하지 않았다.

## 현재 결과

| 공급자 자료 | 실제 수집 | 기록에 붙인 결과 |
|---|---|---|
| 도시공원 표준자료 | 강남구 제공 자료 146행, 1페이지 | 위치 있는 5개 기록 각각 반경 내 대표점 1개, known |
| 상가 정보 | 좌표 3곳, 77/113/257행, 3페이지 | 거리 재확인 뒤 60/113/257개 후보. 기록별 최대 30개만 반환하여 5개 봉투 partial |
| 하천 표준자료 | 전국 목록 2,558행, 3페이지 | 시점 좌표가 수치로 사용 불가능한 행 2,364개. 반경 내 연결 결과 0개지만 5개 봉투 partial |
| ASOS 시간자료 | 서울 108 관측소, 2026-09-07 15시 질의 1회 | HTTP 403. 위치 있는 5개 기록에 unavailable |
| 위치 없는 글 | 위치 기반 API 호출 안 함 | 4개 자료 종류 각각 not_requested / location_missing |

봉투는 총 **24개**: known 5, partial 10, unavailable 5, not_requested 4.
이 실행에 empty는 없다. 성공한 빈 결과는 모의 HTTP 테스트에서 별도로 검사했다.
공원 대표점까지 거리는 세 지점에서 약 0.1m / 111m / 248m였으며 공원 내부 판정은 하지 않았다.
상가 원천의 202606 기준년월은 provider_metadata로 보존했다. 9월 7일 당시 영업 상태를 뜻하지 않는다.

5개 위치 기록에 자료 4종류를 붙였지만 동일 조건을 공유하여 **조회 그룹 6개, HTTP 요청 8회**였다.
공원·하천 목록과 같은 시간의 날씨는 공유하고, 상가는 서로 다른 3개 좌표를 각각 조회했다.
각 기록의 원본 ID·본문·좌표·시각은 그대로이며, 같은 좌표의 행동과 글도 개별 기록으로 남았다.
다음 날 작성한 글의 날씨 질의도 작성 날짜가 아닌 기록 대상 날짜를 사용했다.

초기 private dotenv의 키로는 6회 모두 403이었다. 사용자가 별도로 제공한 공공데이터 파일의
키로 상가를 진단한 1회는 성공했고, 그 키로 위 8회 수집을 실행했다. 따라서 이번 작업의
데이터 API 호출 총수는 **15회(초기 6 + 진단 1 + 본 수집 8)**다. 키 값은 코드·문서·공개 결과에 없다.
기상청 403의 세부 원인은 확정하지 않았다. 같은 키로 다른 공급자가 성공했다는 사실만으로
기상청 서비스 활용권한이나 URL 문제를 판정하지 않는다.

## 보존한 증거

- [최종 snapshot](2026-09-08-record-envelope-collection/snapshot.json): 합성 원본과 실제 응답에서 선별한 필드, 관계 계산, 상태·출처·시각.
- [공급자 수집 요약](2026-09-08-record-envelope-collection/collection-summary.json): 8회 수집의 질의·행/페이지 수·상태·원본 receipt 해시.
- [최종 조립 영수증](2026-09-08-record-envelope-collection/receipt.json): 실제 수집 응답을 cache-only로 최종 형식에 조립하여 HTTP 0회.
- [재생 영수증](2026-09-08-record-envelope-collection/replay-receipt.json): 위 snapshot을 다시 입력해도 봉투 중복 없이 동일 출력.
- [기록별 상태표](2026-09-08-record-envelope-collection/README.md).

최종 snapshot과 재생 snapshot의 canonical SHA-256은 모두
`10c8394f5b53ad3bd415caaae3507ed0140c41d70690131b4c6debff766ef6b6`다.
최종 조립·재생은 각각 cache 6개를 사용했고 추가 HTTP 호출은 없었다.

공개 snapshot의 payload는 허용 필드만 선별한 응답이며 API 원문 전체가 아니다. 원본 페이지,
기관 연락처 등 불필요한 필드는 저장소 밖 private cache에 보존했다. 공개 자료만으로 계약과
기록별 연결은 검사할 수 있지만, 원본 API 페이지부터의 완전한 재계산에는 해당 cache가 필요하다.
기존 cache가 없는 사람은 본인에게 허용된 키로 명시적으로 조회해야 하고 응답 변경에 따라 결과도 달라질 수 있다.

## 구현과 검사

- 기록·봉투 Pydantic 계약, JSON Schema 출력, 별도 합성/실제 조회용 입력 예시.
- 고정 endpoint, 페이지·총 요청 상한, cache-only 기본값, 명시적 refresh, 실패 응답 cache.
- 원본 응답의 private 보존과 공개 필드 선별. LLM 정규화·서술 없음.
- 참조 버전·소유 범위·좌표·시각 검사. 새 봉투 append와 소비 버전 선택.
- 공급자 관측의 시각과 기록 시각 분리. 강수 빈 문자열을 0으로 바꾸지 않음.

기존 Geo Python 3.12 개발 환경에서 다음 좁은 범위를 실행했다.

```powershell
python -m pytest tests/spikes/diary_storyboard/test_record_envelopes.py tests/spikes/diary_storyboard/test_collect_record_envelopes.py tests/test_storyboard_sources.py -q
```

**57개 통과.** 새 계약·수집 파일과 테스트의 Ruff 검사도 통과했다.
실제 공급자 성공, 자료 누락, 403은 위 실측 기록으로 구분한다. HTTP 모의 성공 테스트가
실제 기상청 연결 성공을 뜻하지 않는다. 전체 저장소 테스트·App 실기기·DB 연결 검증은 수행하지 않았다.

## 이번에 드러난 점과 다음 경계

기록 종류보다 좌표·시각·조회 범위가 공통 수집의 기준이 되어야 한다. 같은 장소에 쓴 글도
행동과 같은 주변 정보를 얻지만 본문은 사용자의 언어 그대로 남는다. 위치 없는 글은 여전히
일기의 재료이며 공간 API를 못 붙인다는 이유로 버릴 필요가 없다.

정보를 수집하는 것과 쓸 만한 공간 관계를 얻는 것은 다르다. 하천 목록은 수집 자체가 성공해도
대부분 시점 좌표가 없고 하천 형상이 아니어서 이번 위치의 하천을 설명할 수 없었다. 이 결과를
‘하천 없음’으로 만들면 이후 LLM 입력과 검색이 틀어진다. 다음 보완은 EGIS 등 하천 형상
원천과의 연결이지, LLM에게 빈 자료를 해석시키는 것이 아니다.

공원·상가 정보도 한도 때문에 반환하지 않은 항목과 전체 후보 수를 함께 남겨야 한다.
주변 30개를 반환했다고 30곳만 존재한다고 표현하지 않는다. 장소 유형·근접과 실제 방문·행동
원인은 다른 사실이다. 기존의 ‘봉투 보존 → 필요한 재료 선택 → 장면 편집’ 경계를 유지한다.

**다음 3단위**는 이 snapshot을 읽어 위치를 재생하며 과거 기록 카드를 보여주는 Geo HTML 실험이다.
하천 형상과 실제 날씨 확보는 별도 원천 보완 과제로 남긴다. 움직임 봉투, SGIS 경계 결합,
근접 후보 API, Dev 저장, App 카드, LLM 소비 연결은 이번 결과에 포함하지 않는다.
