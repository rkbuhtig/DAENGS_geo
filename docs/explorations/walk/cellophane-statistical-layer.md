# 싸인펜·셀로판·통계층 — 산책별 공간장을 보존하고 질문에 따라 읽는 모델

## 한 문장

**싸인펜은 산책 한 번의 관측 시간을 공간에 침착시키는 연산이고, 셀로판 한 장은 그 결과를
산책 단위로 보존하는 영구 표본이며, 통계층은 여러 장의 z축을 방문률·시간 질량·방문당 체류·
공간 이용 분포처럼 서로 다른 질문으로 축약하는 질의다.**

이 문서는 이 세 비유를 하나의 색 효과로 섞지 않기 위한 의미 계약이다. 구현 계약은
[`Cellophane`](../../../app/features/territory/paint.py)과
[Cellophane GeoJSON](../../contracts/cellophane-geojson.md), 영구 저장 경계는
[결정 #69](../../decisions/2026-08-26-walk-permanent-spatial-form.md)가 우선한다.

## 왜 별도 문서가 필요한가

초기 시각 실험은 다음을 한 화면에 넣었다.

```text
고속 = 얇은 선
저속 = 굵고 진한 선
정지 = 얼룩
재통과 = 투명도 누적
여러 산책 = 같은 선을 여러 번 덧그리기
```

직관적인 그림이지만 네 질문을 하나의 채널에 접는다.

- 한 산책에서 **오래 머문 것**과 여러 산책에서 **자주 나타난 것**이 모두 진하기가 된다.
- 속도, 시간, 붓 폭, GPS 불확실성이 선 굵기 하나에 섞인다.
- 여러 산책을 미리 한 장으로 합치면 산책별 경계가 사라져 방문률과 변동성을 다시 계산할 수 없다.
- 속도 히스토그램은 1차원 주변분포라 생활권이 어느 방향과 골목으로 퍼졌는지 보존하지 못한다.
- 렌더링 opacity를 조절해 얻은 진하기가 데이터의 방문률처럼 오해될 수 있다.

따라서 비유를 버리지 않고 **생성 연산·표본 단위·질의 연산·표현**으로 분해한다.

## 용어와 단단한 경계

| 층 | 이 문서의 이름 | 입력 | 출력 | 저장 여부 | 답하는 질문 |
|---|---|---|---|---|---|
| 관측 | GPS fix·canonical Segment | 기기 위치·시각·정확도 | 연속성 경계가 적용된 구간 | 기존 수집 계약을 따름 | 무엇이 관측됐나 |
| 생성 | **싸인펜** | 산책 1회의 canonical Segment | 시간 가중 공간장 | 연산 자체는 저장하지 않음 | 시간이 공간에 어떻게 배분됐나 |
| 표본 | **셀로판 한 장** | 싸인펜 공간장 | `occupancy[walk, cell]`, `peak[walk, cell]` | **산책별로 영구 보존** | 이 산책이 남긴 장은 무엇인가 |
| 적층 | **셀로판 z축** | 같은 계산 세대의 여러 장 | 산책별 경계를 유지한 선택 집합 | 통짜 누적을 저장하지 않음 | 어떤 장들을 비교할 것인가 |
| 통계 | **통계층** | 선택된 장들 | 방문률·시간·조건부 체류·분포·변동성 | 질의 결과 | z축을 어떤 질문으로 읽나 |
| 표현 | 지도·등치영역·보조 통계 | 통계값과 spec | 색·농도·윤곽·텍스트 | 제품 상태만 | 사람이 어떻게 읽나 |

핵심은 다음 두 문장이다.

> **셀로판은 재방문률이 아니다. 셀로판이 산책 축을 보존하기 때문에 재방문률을 계산할 수 있다.**

> **육각형은 제품 의미가 아니라 계산 좌표계다. 뜻은 셀 하나가 아니라 셀 위의 field와 질의에 있다.**

## 진실성 층 — 생성기가 아는 것과 관측자가 아는 것을 분리한다

합성 산책은 정답을 심을 수 있으므로 실제 GPS보다 더 위험하다. 생성기의 의도를 서술기가 읽으면
관측으로부터 추론한 것처럼 보이는 정답 누출이 생긴다.

```text
latent truth
생성기가 심은 경로 선택·정지·행동 상태

observed GPS
센서가 관측한 시각·좌표·정확도

canonical observation
연속성 경계와 거리/시간으로 만든 Segment

derived spatial observation
occupancy·peak·slow/stop 후보·질량 진단

candidate interpretation
신호 대기·탐색·보호자 정지 등 복수의 후보 설명
```

실험 규칙은 다음과 같다.

1. 생성기의 latent truth는 평가기만 읽는다.
2. 싸인펜·셀로판·서술기는 `observed GPS + canonical/derived observation`만 읽는다.
3. 화면은 관측 사실과 후보 해석을 구분한다.
4. `저속 → 정지 → 고속`만으로 행동 원인을 하나로 확정하지 않는다.
5. 회수율은 derived 결과와 latent truth를 **사후 비교**해 측정한다.

예시:

```text
관측 사실
- 21초간 1.0m/s 미만
- 그중 6초간 변위가 거의 없음
- 뒤이어 8초간 속도 상승

후보 해석
- 주변 탐색
- 신호 대기
- 보호자 정지
- 앞선 상대를 따라잡기
```

## 싸인펜 — 관측 시간을 공간에 침착시키는 생성 연산

산책 `i`의 시간에 따른 관측 위치를 `xᵢ(t)`, 계산 셀을 `c`, 붓 kernel을 `K`라고 하면 한 장의
시간 질량은 개념적으로 다음과 같다.

```text
Oᵢ(c) = ∫ K(c, xᵢ(t)) dt
```

현재 Paint v2는 이를 Segment를 일정 간격으로 샘플링하고 각 stamp의 가중치 합을 1로
정규화해 근사한다. 따라서 유효 Segment 전체에 대해 다음 질량 보존이 성립해야 한다.

```text
Σc Oᵢ(c) = Σsegment Δt = source_segment_s
```

### 속도는 물감의 직접 입력이 아니다

같은 10m를 2초에 통과하면 그 주변에 배분되는 시간이 적고, 20초에 통과하면 많다. 속도에
따라 `고속/저속` 분기를 추가하지 않아도 다음이 자연히 나온다.

```text
빠른 통과  → 같은 공간의 dt가 작음 → 옅음
느린 통과  → 같은 공간의 dt가 큼   → 진함
정지       → 위치 변화 없이 dt 증가 → 한 주변에 고임
되짚기     → 같은 산책 안에서 재통과 → 한 장 안에서도 덧칠
```

`10/40/40/10` 속도 테이프와 canonical `moving`·slow 후보는 시뮬레이터·디버거·검증용이다.
기본 Paint 식을 바꾸는 입력으로 쓰지 않는다. 그래야 속도 문턱 양쪽에서 물감이 갑자기 바뀌지
않고, “저속 판정이라 진하고 진해서 저속처럼 보인다”는 순환을 피한다.

### 붓 폭, 물감량, 위치 불확실성을 한 값으로 만들지 않는다

| 값 | 의미 | 현재 상태 |
|---|---|---|
| `BrushProfile` | 제품이 정한 공간 kernel의 단면 | 고정 profile 후보를 세대별로 사용 |
| `occupancy_s` | kernel 주변에 배분된 관측 시간 질량 | Paint v2에서 보존 |
| `peak` | 그 산책에서 셀이 받은 최대 raw 붓 세기 | kernel 정규화와 별도 |
| GPS accuracy | 관측 위치의 불확실성 | 수집되지만 adaptive kernel은 미채택 |

`BrushProfile`과 GPS 오차는 수학적으로 결합할 수 있지만 같은 개념은 아니다.

```text
K_material  제품이 정한 싸인펜 단면
K_sensor    위치 관측의 불확실성
K_effective 둘을 결합해 실제로 배분할 kernel
```

정확도 연동 붓을 채택한다면 `paint_fp`를 바꾸는 계산 세대 변경이다. 현재 고정 붓에서 화면만
GPS 정확도에 따라 넓혀 그리면 저장된 field와 보이는 field가 달라지므로 금지한다.

### continuity gap은 칠하지 않는다

한 사용자 산책에 여러 continuity chain이 있을 수 있다. chain 사이 관측 공백은 시간이 흘렀다는
이유만으로 직선 보간하지 않는다. 싸인펜은 **관측된 유효 Segment**만 칠한다.

## 셀로판 한 장 — 산책별 경계를 보존하는 영구 표본

개념적인 표기는 다음과 같다.

```text
occupancy[walk, q, r]
peak[walk, q, r]
```

실제 구현은 대부분의 셀이 비어 있으므로 산책별 희소 맵이다.

```text
Cellophane
- walk_id
- at
- occupancy: {(q, r): seconds}
- peak: {(q, r): strength}
- paint_version
- grid_version
- radius_u
- profile_fp
- sample_step_m
- paint_fp
```

`walks`는 한 장의 저장값이 아니다. 같은 셀에 대해 선택된 장을 세고 `min_peak`를 적용한
**질의 결과**다. 한 장에 `occupancy`와 `peak`를 함께 남겨야 나중에 “오래 옆을 스침”과
“심부까지 가까이 감”을 다른 조건으로 읽을 수 있다.

### 원좌표 purge 전후의 경계

셀로판은 계산 당시에는 canonical Segment에서 만든 파생물이다. 그러나 [결정 #69]에 따라
원좌표를 purge한 뒤에는 **그 산책에서 남은 영구 공간 측정값**이 된다.

```text
finish 전
canonical Segment → paint_sheet() → 검산 → Cellophane

finish/purge 후
원좌표 없음 → Cellophane만 영구 보존 → 과거 산책 재도장 불가
```

따라서 셀로판을 일반적인 재생성 가능 캐시라고 부르면 안 된다. 붓·격자·샘플 간격·알고리즘이
바뀌면 과거 장을 조용히 새 의미로 읽지 않고 `paint_fp`가 다른 세대로 분리한다. 새 세대는
새 산책부터 쌓이고, 질의는 같은 세대의 장만 고른다.

### 한 장이 지켜야 하는 불변식

1. `occupancy`와 `peak`의 셀 집합이 같다.
2. `occupancy_s`는 유한한 0 이상이며 전체 합이 유효 Segment 시간과 계산 오차 안에서 같다.
3. `peak`는 유한한 `0..1`이고 occupancy 정규화로 의미가 바뀌지 않는다.
4. `paint_fp`가 실제 `PaintSpec`의 fingerprint와 같다.
5. 서로 다른 `paint_fp` 장은 한 질의에서 섞지 않는다.
6. 산책별 장을 통짜 누적으로 대체하지 않는다.
7. 색상·opacity·보간 반경은 저장 계약에 넣지 않는다.

## 셀로판 적층 — z축을 유지한 선택 집합

적층은 `Σ occupancy` 하나를 미리 저장하는 작업이 아니다. 먼저 질의가 장을 고른다.

```text
Selector
- 기간: since / until
- 파생 태그: 시간대 / 요일 / 월 / 계절
- 계산 세대: paint_fp

선택 결과
- selected: 조건에 걸린 장 수
- total: 조건 전 전체 장 수
- sheets: 산책별 경계를 유지한 장 목록
```

같은 장 집합에서도 통계층이 어떤 축으로 줄이느냐에 따라 다른 답이 나온다. 이것이 셀로판을
미리 접지 않는 이유다.

## 통계층 — z축을 읽는 여러 연산

아래에서 `S`는 선택된 같은 세대의 산책 장 집합, `N = |S|`, `Oᵢ(c)`는 산책 `i`의
`occupancy_s`, `Pᵢ(c)`는 `peak`, `τ`는 `min_peak`다.

`τ`로 셀을 거르면 질의 결과의 시간 질량 일부가 제외된다. **Paint v2의 질량 보존은 원래 한
장의 전체 `occupancy`에 대한 불변식이지, `min_peak`를 적용한 집계 결과의 불변식이 아니다.**
방문률·조건부 체류처럼 근접 조건이 질문의 일부일 때만 `τ`를 쓰고, 전체 공간 이용 분포는 우선
`τ = 0`인 raw occupancy를 기본으로 삼는다.

### 1. 총 시간 질량

```text
T(c; τ) = Σᵢ Oᵢ(c) · 1[Pᵢ(c) ≥ τ]
```

선택된 산책 전체에서 그 주변에 총 몇 초의 관측 시간이 배분됐는가. 긴 산책과 반복 방문이
더 큰 영향을 가진다.

### 2. 산책당 방문률

```text
Vᵢ(c; τ) = 1[c가 산책 i의 셀 집합에 있음 ∧ Pᵢ(c) ≥ τ]
R(c; τ)  = Σᵢ Vᵢ(c; τ) / N
```

전체 선택 산책 중 몇 장에서 그 셀이 충분한 붓 세기를 받았는가. 아직 모델 기반 미래 확률이
아니므로 **재방문 확률**보다 **산책당 방문률**이라고 부른다.

`τ`가 바뀌면 질문도 바뀐다.

```text
τ = 0.0   붓 가장자리라도 닿은 장
τ = 0.9   붓 심에 가까이 들어온 장
```

따라서 결과에는 `visited / selected`, ratio, `min_peak`를 함께 둔다.

### 3. 방문했을 때 평균 체류

```text
D(c; τ) = T(c; τ) / Σᵢ Vᵢ(c; τ)
```

그곳에 나타난 산책만 놓고 한 번에 평균적으로 얼마나 많은 시간 질량이 배분됐는가. 분모가 0이면
0초가 아니라 계산 불가다. 평균만으로 꼬리가 긴 체류를 감추지 않도록 중앙값·IQR도 후보로 둔다.

### 4. 산책 간 안정성

각 셀 또는 국소 영역에서 산책별 값을 그대로 사용한다.

```text
모든 선택 산책 기준     median(Oᵢ), IQR(Oᵢ), zero rate
방문한 산책 조건부      median(Oᵢ | Vᵢ=1), IQR(Oᵢ | Vᵢ=1)
시간 변화               최근 창과 기준 창의 rate·median 차이
```

0을 포함한 중앙값은 “평소에도 나타나는가”를, 방문 조건부 중앙값은 “갔을 때 얼마나 머무는가”를
답한다. 두 값을 같은 `median occupancy`라는 이름으로 내지 않는다.

### 5. 전체 시간 비중 기반 공간 이용 분포

```text
U_time(c) = Σᵢ Oᵢ(c) / ΣᵢΣc Oᵢ(c)
```

내 전체 산책 시간은 공간적으로 어디에 배분됐는가. 긴 산책은 실제로 더 많은 시간 질량을
가지므로 더 큰 영향을 준다.

### 6. 산책 동등 가중 공간 이용 분포

산책 `i`의 유효 시간 질량을 `Tᵢ = Σc Oᵢ(c)`라 하고, 이 값이 양수인 기여 산책 수를 `M`이라
하면:

```text
U_walk(c) = 1/M · Σᵢ:Tᵢ>0 [Oᵢ(c) / Tᵢ]
```

한 번 산책을 나가면 보통 어느 쪽에 시간을 쓰는가. 각 산책을 한 장으로 동등하게 취급하므로
긴 산책 하나가 지도를 지배하지 않는다. 관측 시간이 없는 빈 장은 선택 표본 `N`에는 남지만
합 1로 정규화할 수 없으므로 기여 표본 `M`에서는 빠진다. 결과에는 `selected`와 `contributing`을
둘 다 붙인다.

### 같은 진하기를 네 질문으로 풀기

| 공간 패턴 | 방문률 | 방문당 체류 | 읽을 수 있는 관측 |
|---|---:|---:|---|
| 매일 빠르게 지나는 골목 | 높음 | 낮음 | 반복 생활 동선 |
| 한 번 오래 머문 자리 | 낮음 | 높음 | 일회성 장기 체류 |
| 자주 오래 머문 자리 | 높음 | 높음 | 반복 체류 후보 |
| 드물게 스친 외곽 | 낮음 | 낮음 | 탐색 외곽 |

단일 알파나 단일 “진함 점수”로 이 표를 접지 않는다.

## 공간 이용 분포의 50·80·95% 영역

속도 히스토그램은 속도값의 1차원 분포일 뿐 공간 구조를 잃는다. 여러 산책의 중심 통계는 지도와
같은 공간축 위에 있어야 한다.

선택한 비음수 공간 분포 `U(c)`에 대해:

1. 값이 큰 셀부터 정렬한다.
2. 누적 질량이 50%, 80%, 95%가 되는 셀 집합을 각각 구한다.
3. 지도에는 `핵심 50% / 일상권 80% / 외곽 95%`로 표시한다.

이것은 최고밀도영역(highest-density region)에 가까운 **질량 영역**이다. 반드시 하나의 연결된
폴리곤일 필요는 없다. 동쪽 공원과 남쪽 골목이 각각 핵심이면 두 조각으로 나오는 것이 맞다.
화면의 부드러운 윤곽은 셀 집합의 렌더링이지 원자료를 바꾼 새 측정값이 아니다.

같은 `50%`라도 기준 분포가 다르면 뜻이 다르므로 화면에 다음 provenance를 붙인다.

```text
기준: 산책 동등 가중 시간분포
표본: 최근 30회 중 같은 Paint 세대 28회
조정: Raw
min_peak: 0.0 — 시간분포의 raw occupancy
```

### 집 중심 방향·거리 분포는 보조 통계다

극좌표 보조 그림은 유효하다.

```text
각도   집에서 본 방향
반지름 집과의 거리
농도   방문률 또는 시간 비중
```

생활권이 동쪽 200~500m에 집중되는지, 북쪽으로 드물게 멀리 가는지 빠르게 읽을 수 있다. 다만
굽은 도로와 장벽을 잃으므로 지도 위 분포의 대체물이 아니라 보조 통계로만 둔다.

## 집 편향 — Raw를 보존하고 Adjusted를 별도 질의로 만든다

모든 산책이 집에서 시작하고 끝나면 집 주변의 구조적 노출이 가장 높다. 이것은 오류가 아니지만
“선호 공간”으로 읽으면 틀린다.

원칙은 삭제가 아니라 병렬 보존이다.

```text
Raw
실제로 관측된 전체 공간장

Adjusted
출발·도착이라는 구조적 노출을 명시된 규칙으로 조정한 질의 결과
```

초기 Adjusted 후보:

- 첫·마지막 50m 제외
- 첫·마지막 60초 제외
- 집 반경 30m를 기준 영역으로 분리

어느 것도 아직 canonical이 아니다. 조정 규칙은 `LayerSpec`에 드러나야 하고 Raw 장을 덮어쓰지
않는다. 장기적으로는 `관측 방문률 / 집에서 출발하는 경로의 기대 방문률` 같은 보정도 가능하지만
현재 범위가 아니다.

## 표현 계약 — 데이터와 화면 효과를 분리한다

### 한 장: 싸인펜 화면

- 한 산책의 `occupancy_s` field를 연속 농도로 표시한다.
- 속도 등급에 따라 선 폭이나 색을 직접 바꾸지 않는다.
- 정지와 되짚기는 시간 질량이 같은 주변에 더 쌓여 자연히 진해져야 한다.
- `peak`, accepted chain, speed/slow/stop 후보는 디버그 overlay로 켜고 끌 수 있다.
- 화면 opacity는 표시 설정이며 `occupancy_s`의 의미를 바꾸지 않는다.

### 여러 장: 셀로판 화면

- 선택한 통계 metric을 한 번에 하나만 기본 색 채널로 표시한다.
- `방문률 / 총 시간 / 방문당 체류 / 산책 동등 분포`를 같은 “진함” 이름으로 묶지 않는다.
- 표본 수·분모·기간·계산 세대·min_peak·Raw/Adjusted를 항상 표시한다.
- 육각형 경계는 기본 화면에서 숨기되 디버거에서는 원래 셀과 수치를 확인할 수 있어야 한다.
- 수동 “한 획 투명도” 슬라이더를 데이터 노브처럼 취급하지 않는다.

### 분포: 통계 화면

- 선택한 `U_time` 또는 `U_walk`의 50·80·95% 질량 영역을 지도에 표시한다.
- 선택 영역을 누르면 산책별 z축 요약을 보여준다.

```text
최근 20회 중 12회 등장
산책당 방문률 60%
방문한 날 체류 중앙값 18초
IQR 11~32초
최근 5회 중 4회 등장
```

- 속도 히스토그램은 단일 산책 디버거의 보조 패널로 유지할 수 있지만 여러 장 화면의 중심 통계가
  아니다.

## HeatMap은 표현 참고이지 통계 모델이 아니다

[NAVER Maps HeatMap](https://navermaps.github.io/maps.js.ncp/docs/naver.maps.visualization.HeatMap.html)은
가중 지점을 픽셀 반경·불투명도·색상 스펙트럼으로 부드럽게 읽게 하는 표현 참고다. 서버의
물리 미터 기반 Paint와 셀로판 통계를 대신하지 않는다.

현재 Paint가 이미 kernel을 적용해 셀에 시간을 배분한 뒤이므로, 셀 중심을 다시 큰 반경의
HeatMap에 넣으면 이중 확산이 된다.

```text
물리 붓 20m로 이미 배분
→ 화면 HeatMap이 다시 30px 확산
→ 보이는 범위가 계산 범위보다 넓고 zoom에 따라 의미가 변함
```

렌더러 보간은 셀 경계를 감추는 최소 범위로 제한하고 계산 반경인 척하지 않는다.

또한 육각 격자는 도로·건물·하천 장벽을 이해하지 않는다. 원형 kernel이면 반경 안의 건너편
셀도 칠할 수 있다. 장벽을 막으려면 별도의 보행 가능 영역 mask, 도로망 kernel, map-matched
edge 누적이 필요하다. 현재 field를 위치 오차를 포함한 근방 이용장으로 해석한다면 일정한
번짐은 허용할 수 있지만 “육각형이 장벽 문제를 해결한다”고 주장하지 않는다.

## 실험을 섞지 않는다

### 실험 A — 싸인펜 생성 연산 검증

```text
같은 경로
다른 시간 테이프
```

시나리오:

- 일정 속도
- 전체 저속
- 짧은 정지 다수
- 한 번의 긴 정지
- 왕복 재통과
- continuity gap 포함

판정:

- 모든 시나리오에서 질량이 유효 Segment 시간과 보존된다.
- 느림·정지·되짚기의 농도 차이가 속도 등급 분기 없이 시간 배분만으로 생긴다.
- continuity gap을 가로지르는 물감이 생기지 않는다.
- `peak`는 체류 시간 증가와 다른 축을 유지한다.

### 실험 B — 셀로판 z축과 통계층 검증

```text
같은 집
여러 경로
비슷한 전체 행동 비율
```

예시 30회:

```text
공통 현관 구간
    ↓
공통 주 동선
    ├─ 동쪽 루프 45%
    ├─ 남쪽 왕복 30%
    ├─ 북쪽 공원 15% — 방문 시 긴 체류
    └─ 임시 탐색 10%
```

판정:

- 공통 줄기는 방문률이 가장 높다.
- 동쪽 루프는 주 생활권으로, 남쪽은 보조 생활권으로 갈린다.
- 북쪽 공원은 방문률은 낮지만 방문당 체류가 높게 나온다.
- 탐색 가지는 외곽 95%에는 나타나고 핵심 50%에서는 빠진다.
- `U_time`과 `U_walk`이 긴 산책이 포함된 fixture에서 실제로 다른 결과를 낸다.
- 같은 경로를 N번 복제한 알파 테스트만으로 통과 처리하지 않는다.

### 실험 C — 센서 내성 검증

```text
같은 latent 경로·행동
GPS noise seed와 accuracy만 변경
```

판정:

- 총 시간 질량은 보존된다.
- 방문률과 50·80·95% 영역이 허용 범위 안에서 안정적이다.
- 붓보다 큰 지터가 있을 때 위치 정밀도를 과장하지 않는다.
- 서술기는 noise seed나 latent truth를 보지 않는다.

## 현재 구현과 차이

### 이미 있는 기반

- `paint_sheet()` — canonical Segment를 Paint v2 질량 보존 공간장으로 변환
- `Cellophane` — 산책별 `occupancy`·`peak`와 계산 세대 보존
- `stack()` — 같은 세대의 장을 `min_peak` 조건으로 질의 시 집계
- `LayerSpec` — selector·aggregation·projection과 분모 보존
- `rate_field()`·`region_visit_rate()` — 산책당 방문률의 기반
- `spatial_stats.py` — 총 시간·산책당 방문률·방문당 체류·`U_time`·`U_walk`과 계산 영수증
- `highest_mass_regions()` — `U_time`·`U_walk`의 동률을 자르지 않는 50·80·95% 질량 영역
- `population_truth.py` / `population.py` — 같은 집에서 14/9/4/3으로 갈라지는 30회
  evaluator truth와 truth label을 제거한 canonical Cellophane fixture
- `/cellophane-distribution` — 다섯 metric과 질량 영역을 실제 Naver/OSM 지도에서 바꾸어 보는
  dev console 검증 화면. 모집단 generator version·run ID와 Paint 세대를 함께 표시한다.
- [`continuous_brush.py`](./continuous-brush-reference.md) — canonical Segment를 육각형 없이
  정규화된 시간 질량 원으로 읽는 비교용 연속 reference field
- Cellophane GeoJSON — 한 장의 chain·셀·질량 진단 검증 표면

### 아직 없는 것

- 산책별 중앙값·IQR·최근 변화 같은 z축 안정성 readout
- Raw/Adjusted 집 편향 질의 계약
- Paint profile과 센서 불확실성을 분리해 검증하는 실험
- 한 장·여러 장·분포 모드를 구분한 제품 표면

## 구현 순서

1. **완료 —** 통계 이름과 분모 계약을 `SpatialField`로 고정한다.
2. **완료 —** 기존 장을 변형하지 않는 순수 집계 함수로 `visit_rate`, `total_time`,
   `conditional_dwell`, `U_time`, `U_walk`을 만든다.
3. **완료 —** 같은 집에서 갈라지는 결정론적 30회 fixture와 evaluator-only latent truth를
   별도 파일로 만든다.
4. **완료 —** metric별 기대 순위와 50·80·95% 영역 회수 테스트를 작성한다.
5. GPS noise seed만 바꾸는 센서 내성 fixture를 추가한다.
6. **실험 화면 완료 —** 여러 장·분포 dev 화면의 수치를 집계 함수 결과와 대조했다. 한 장과
   제품 화면으로 승격하는 일은 센서 내성 검증 뒤에 남긴다.

UI에서 먼저 색을 고르거나 알파를 조정하지 않는다. 먼저 “무슨 질문의 어떤 값인가”가 코드와
테스트로 고정돼야 한다.

## 기존 결정과 이 문서가 새로 제안하는 것

### 이미 채택됐거나 구현으로 고정된 제약

- 산책 한 번을 독립 Cellophane으로 보존한다.
- 통짜 누적을 영구 저장하지 않고 겹치기는 질의로 한다.
- 원좌표 purge 뒤 집계 셀 맵을 영구 공간 형태로 남긴다.
- `occupancy`는 Paint v2에서 보존되는 관측 시간 질량이다.
- `peak`와 `occupancy`를 한 값으로 접지 않는다.
- 다른 `paint_fp` 세대를 섞지 않는다.
- 육각형은 계산 격자이며 제품 영역 의미가 아니다.

### 이 문서의 탐색 제안

- 통계층의 첫 metric 집합과 정확한 이름
- `U_time`과 `U_walk`의 병렬 제공
- 50·80·95% 최고밀도 질량 영역
- Raw/Adjusted 집 편향 비교
- 한 장·여러 장·분포의 화면 모드 구분
- 싸인펜/셀로판/센서 내성의 세 실험 분리

이 항목들은 측정과 구현 검증 전까지 `exploring`이다.

## 열어 둔 결정

- 제품 canonical `BrushProfile`과 grid radius
- GPS accuracy를 kernel에 결합할지, 결합한다면 세대 수를 어떻게 제한할지
- 방문률의 `min_peak` 기본값과 민감도 표시
- 조건부 체류의 대표값을 평균·중앙값 중 무엇으로 둘지
- 50·80·95% 영역의 셀 연결과 렌더링 보간 규칙
- Raw/Adjusted의 첫 canonical 집 편향 보정법
- 서로 다른 Paint 세대가 공존할 때 기간 비교 UX
- 실제 기기 데이터에서 신뢰할 최소 산책 수

## 리뷰 체크리스트

새 코드·문서·화면은 다음 질문을 모두 통과해야 한다.

- [ ] 생성기의 latent truth를 관측 결과처럼 읽지 않는가?
- [ ] 속도 등급이 Paint 물감량이나 선 폭의 직접 입력이 아닌가?
- [ ] `occupancy_s`의 질량 보존을 유지하는가?
- [ ] `peak`와 시간 질량, GPS 불확실성을 구분하는가?
- [ ] 산책별 장의 경계를 보존하는가?
- [ ] `walks`를 영구 셀 값으로 미리 접지 않는가?
- [ ] 서로 다른 `paint_fp` 세대를 섞지 않는가?
- [ ] 방문률에 분자·분모·`min_peak`가 붙는가?
- [ ] 총 시간과 산책 동등 가중의 질문 차이를 드러내는가?
- [ ] Raw를 지우지 않고 Adjusted를 별도 질의로 만드는가?
- [ ] 50·80·95%가 어느 분포의 질량 영역인지 표시하는가?
- [ ] HeatMap 보간이 Paint kernel을 다시 확산시키지 않는가?
- [ ] 육각형을 도로·건물 장벽 모델로 오해하지 않는가?
- [ ] 화면 opacity를 데이터 값처럼 저장하거나 해석하지 않는가?
- [ ] 같은 경로 복제로 셀로판 통계 실험을 대신하지 않는가?

## 이 문서가 바뀌어야 하는 신호
