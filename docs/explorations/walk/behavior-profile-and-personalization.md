# 행동 Pin에서 상황별 강아지 프로필과 다음 산책으로

이 문서는 2026-09-04 대화에서 나온 **새 설계 후보**다. 사용자는 행동 관련 Pin을 바탕으로
개인화 데이터를 만들고 다음 산책의 미시적 움직임에 맞춰 제안할 수 있는지, 또는 먼저
“이 강아지는 어디에서 어떤 성향을 보여요”를 프로필에 설명할 수 있는지 물었다.

현재 구현은 아니다. 데이터베이스·API·행동 어휘·판정 문턱·보존 기간·Context capability를
채택하지 않는다. 아래 객체 이름과 JSON은 설명용 후보이며 실행 계약으로 가져다 쓰지 않는다.
세션 전체 경위와 다른 컴퓨터에서의 재개는
[인수인계 문서](../../research/2026-09-04-walk-personalization-handoff.md)를 먼저 읽는다.

## 1. 만들고 싶은 경험

사용자는 기록을 남기고, 시간이 지나면 그 기록으로 자기 강아지를 조금 더 구체적으로
설명할 수 있다. 예를 들면 “활발함” 하나를 붙이기보다, 어느 장소·상황에서 어떤 행동을
기록했는지와 그 실제 장면을 함께 본다. 다음 산책에서는 관련 있는 기억을 꺼내 선택에
도움을 준다. 스토리보드는 그 요약의 근거를 다시 보는 표면이 된다.

```text
산책 관측 ──→ 미시 관측 후보 ──→ 실제 제시한 Offer
                                     │
직접 책갈피 / 사후 기록 ───────────────┤
                                     ↓
                          사용자 증언 + 안정 Pin
                                     ↓
                  현재 유효 의미 · 강아지 귀속 · 시간/공간 자격
                                     ↓
                     상황별 행동 근거 묶음 (새 설계 후보)
                         ├─ 프로필에서 반복된 기록 설명
                         ├─ 관련 Pin / 스토리보드로 돌아가기
                         └─ 현재 상황과 대조해 다음 산책 제안 후보
```

프로필 요약과 산책 제안은 같은 근거를 서로 다른 목적으로 읽는다. 다만 제안은 현재 장소의
이용 조건, 사용자 의도, 시간, 알림 부담까지 고려해야 하므로 프로필 표시보다 별도 검증이
더 필요하다. **프로필 요약을 먼저 검증하자**는 것은 이번 대화에서 나온 권장 진행 순서다.
사용자가 최종 구현 순서나 운영 정책을 확정한 것으로 기록하지 않는다.

## 2. 실제 코드와 구상의 경계

| 재료/기능 | 확인한 현재 상태 | 이 구상에서 필요한 일 |
|---|---|---|
| `WalkFacts`, `CanonicalTrail` | 측정 사실과 유효 구간/단절 존재 | 의미를 원래 사실 계약에 추가하지 않고 소비 |
| `AttestedClaim` | `subject_role`, `meaning_code`, `vocabulary_version` 존재 | 어떤 행동 코드가 재사용 가능한지 어휘 정책 필요 |
| `WalkAttestation` | confirmed/rejected/uncertain 및 정정 참조 존재 | Pin별 현재 head를 읽어 긍정 행동 주장 자격 확인 |
| `EpisodePin` | 안정 identity·시각 정밀도·대표점·footprint 존재 | 근거 링크, 사건 중복 방지, 문맥 연결 자격 확인 |
| Pin 정정 | append-only correction과 현재 head 읽기 계약 존재 | 행동 요약·추천 cache 무효화는 새 소비자의 책임 |
| Memory Place | 명시적으로 연결한 여러 산책의 Pin과 biography 존재 | 장소별 행동 기록 조회에 재사용 가능한 경계 검토 |
| `DogProfile` | 외부 프로필을 받아 쓰는 geo 계약 | 자동 요약으로 원본 temperament 등을 덮어쓰지 않음 |
| Context Plane v0 | 닫힌 Atom/Facet/Lens 집합 존재 | 행동 이력은 현재 등록 capability가 아님 |
| 스토리보드 spike | 실제 지역 자료 + 합성 산책/Pin/게임의 HTML | 실제 Pin·개인 이력 adapter는 아직 없음 |
| 행동 프로필 projector | 없음 | 다음 실험의 핵심 후보 |
| 다음 산책 개인화 제안 | 없음 | 프로필 근거를 재사용하되 별도 선택·실행 자격 필요 |
| 자동 행동 인식/학습 모델 | 이번 작업에서 만들지 않음 | 별도 데이터·평가·채택이 필요한 후속 실험 |

현재 `meaning_code`는 형식 검증을 받는 문자열이며, 완성된 행동 ontology가 배선됐다는 뜻은
아니다. 어휘에 없는 값을 LLM이 새로 만들어 수용하는 설계를 전제하지 않는다.

프로필 계약에 있는 자기보고 `temperament`와 `activity_level`, 기록에서 파생한 행동 설명,
특정 행동 모델의 추정치는 각각 출처가 다르다. 같은 필드로 합치지 않는다.

## 3. 입력을 받는 기준

### 3.1 구조화된 증언을 첫 입력으로 삼는다

초기 projector의 입력 후보는 다음을 만족하는 Pin과 현재 유효 Attestation이다.

1. 요청 주체가 접근 가능한 강아지의 세션/Pin이다.
2. 최초 생성 증언부터 이어지는 현재 correction head를 확인했다.
3. 현재 head가 `confirmed`이고 필요한 claim이 있다.
4. claim의 `subject_role`이 강아지에 해당한다. 다견 산책에서는 개별 pet 귀속도 확인한다.
5. 코드와 어휘 버전이 이 projector가 인식하는 행동 목록에 속한다.
6. 질문에 필요한 시간·공간·문맥 자격을 만족한다.
7. 입력 조회 뒤 삭제/정정이 발생했으면 오래된 결과의 게시를 막거나 다시 계산한다.

이것은 **강아지의 실제 행동을 센서로 확정했다는 주장**이 아니다. 보호자가 그렇게 증언한
기록이라는 권위를 보존한다. confirmed도 오입력·사후 기억 오류가 있을 수 있다.

### 3.2 기존 개인 문장 경계를 지킨다

[Context Plane v0](../../contracts/context-plane.md)는 개인 자유 문장·감정·생각을 Context
Bundle, 경향, 프로필 갱신, 다른 산책 판단으로 승격하지 않는다. 다음 경로는 이 문서가
열지 않는다.

```text
일기 자유 메모 전체 → LLM으로 성격 추출 → 다음 산책에 자동 사용
```

“Pin을 기반으로 개인화하자”는 구상을 모든 Pin의 사진·자유 메모·보호자 내면까지 재사용하는
승인으로 읽지 않는다. v0 실험은 명시적으로 선택한 구조화 행동 증언과 필요한 객관적 문맥을
쓴다. 자유 문장에 담긴 행동을 구조화하려면 사용자의 별도 확인과 제품 정책을 설계해야 한다.
현재 계약에서 허용된 것으로 가정하거나 우회용 `private_render_only` capability를 만들지 않는다.

### 3.3 입력 종류마다 다른 취급

| 입력 | 초기 행동 요약에서의 취급 |
|---|---|
| dog + confirmed + 인식 가능한 행동 code | 필요한 문맥 자격을 확인한 뒤 기여 가능 |
| owner claim | 강아지 행동으로 집계하지 않음 |
| joint claim | 강아지 단독 행동으로 자동 분해하지 않음 |
| external claim | 외부 사건으로 분리; 강아지의 성격으로 읽지 않음 |
| uncertain | 긍정 행동 수에서 제외; 불확실한 기록이 있다는 상태는 보존 가능 |
| Offer dismiss / expire / 무응답 | 행동 음성 사례가 아님 |
| rejected Offer | 해당 질문에 대한 응답. 모든 행동의 부재로 일반화하지 않음 |
| 미지원 meaning/vocabulary | 실패 이유를 남기고 의미를 추정해 채우지 않음 |
| 자유 메모·사진 원문 | 이 projector 입력에서 제외 |
| 자동 요약문·이전 추천문 | 새 행동 증거로 되먹이지 않음 |
| 게임 점령·랭킹·점수 | 강아지의 호기심·활동성 증거로 사용하지 않음 |

현재 계약에서 `none/unknown` role은 긍정 `AttestedClaim`을 만들 수 없다. 따라서 위 설계는
임의로 그런 claim을 생성하는 예시를 쓰지 않는다. Pin의 최초 생성 증언과 correction head의
권위를 혼동하지 않는 것이 첫 구현의 핵심이다.

## 4. ‘어디에서’의 해상도

행정동, 공원 이름, 개인 Memory Place, 원천 형상, 사건 footprint는 서로 다른 장소 표현이다.

| 질문 | 적절한 근거 후보 | 과도한 일반화 |
|---|---|---|
| 어느 동네에서 기록했나 | revision이 명시된 동 경계와 사건 공간 자격 | 그 동 전체를 좋아한다 |
| 이 장소에서 반복됐나 | 안정 Memory Place membership와 Pin | 화면 marker cluster가 같은 장소 identity다 |
| 공원 주변에서 기록했나 | 공원 대표점까지 거리·공간 지지 범위·정책 | 공원 안에 들어갔다 / 잔디에서 행동했다 |
| 물가 가까이서 기록했나 | 출처가 있는 하천 형상까지 거리 | 하천 산책로를 이용했다 / 물을 좋아한다 |
| 특정 환경 유형 전반에서 반복됐나 | 여러 장소의 비교 가능한 typed context | 한 공원의 기록을 모든 공원으로 일반화 |

같은 장소에서 네 번 관찰한 경우와 서로 다른 네 공원에서 관찰한 경우는 다른 주장이다.
초기 결과는 `place_specific`과 `context_pattern`을 구분하는 방향을 검토한다. 이 이름들은
후보 분류이며 현재 registry 값이 아니다.

중요하게도 이번 실험의 공원 데이터에는 공원 **대표점**만 있다. 가까운 Pin을 공원 내부의
잔디 행동으로 표현하면 원천을 두 번 넘어선다. 실제 피복 자료나 사용자의 구조화 증언이
없으면 ‘풀밭’ 같은 소재를 새로 붙이지 않는다.

## 5. 시간과 귀속

### 5.1 사건 시각과 확인 시각

다음 시각을 구별해야 한다.

- `event_at`: 행동 사건의 시각. 사후 기록에서는 approximate 또는 unknown일 수 있다.
- `attested_at`: 보호자가 증언을 입력하거나 정정한 시각.
- context의 `source_as_of`/`captured_at`: 자료가 설명하는 기준시점과 확보 시각.
- projection의 `as_of`: 현재 요약을 계산한 기준시점.

오늘 정정한 어제의 Pin을 오늘의 행동으로 집계하지 않는다. 시각 미상의 수동 Pin을 오후
산책으로 임의 분류하지 않는다. 장소 관련 기록은 사용할 수 있어도 낮밤 비교에는 사용할 수
없는 등, 자격은 질문별로 달라진다.

### 5.2 강아지와 보호자의 분리

폰의 움직임은 보통 보호자와 강아지가 함께 움직인 결과다. 멈춤을 강아지의 원인으로
즉시 귀속할 수 없다. 보호자가 통화하거나 신호를 기다리는 반복도 경로에 남는다.

`subject_role=dog`는 귀속의 단서이지만, 여러 강아지가 같이 걷는 경우 어느 개의 행동인지
추가 확인이 필요하다. 현재 단일 dog 세션 가정과 미래 다견 세션을 구별하고, 게임의 단일
`claiming_pet_id` 가계약을 행동 귀속 계약으로 재사용하지 않는다.

보호자별 기록 습관을 읽으려면 실제로 확보되고 재사용이 허용된 귀속 정보가 필요하다.
그 필드가 없을 때 한 보호자가 늘 기록했다고 단정하지 않는다.

## 6. 반복을 계산하는 단위

최소한 아래 세 수를 분리한다.

| 수 | 무엇을 세나 | 주의 |
|---|---|---|
| supporting Pin count | 현재 유효한 관련 Pin identity 수 | 한 사건에 중복 Pin이 있을 수 있음 |
| distinct walk count | 관련 근거가 있는 서로 다른 세션 수 | 같은 날 여러 세션의 상관성은 남음 |
| distinct day/place count | 근거가 분산된 날짜/안정 장소 수 | 날짜·장소 자격이 없으면 계산하지 않음 |

다음 예시는 설계 검증용 가상 데이터다.

| 산책 | Pin | 현재 의미 | 위치 |
|---|---|---|---|
| W1 | P1, P2, P3 | 강아지 냄새 탐색 | 장소 A |
| W2 | P4 | 강아지 냄새 탐색 | 장소 A |
| W3 | P5 | 보호자 통화 | 장소 A |
| W4 | P6 | 강아지 냄새 탐색 | 장소 B |

단순 Pin 기준은 강아지 행동 5개지만, 지지하는 산책은 3개다. W1의 세 Pin이 실제 독립
사건인지 모르면 ‘독립 사건 5회’로 표현하지 않는다. W3은 강아지가 해당 행동을 하지 않았다는
음성 정답도 아니다. 장소 A/B가 같은 유형인지 모르면 환경 유형 일반화도 하지 않는다.

첫 집계의 최소 중복 방지 키 후보는 `(pin_id, effective_attestation_id, claim key)`다.
동일 입력 재전송·같은 Pin의 correction 이력을 각각 새 사건으로 세지 않는다.
여러 Pin이 같은 현실 사건을 가리키는 의미 중복은 별도의 문제다. 첫 버전은 독립 사건 수를
주장하지 않고 Pin 수와 산책 수를 분리해 보여주는 쪽이 단순하다.

## 7. 분모와 관측 편향

### 7.1 Pin 없음은 행동 없음이 아니다

“선택한 Pin 중 70%가 냄새 탐색”은 보호자가 무엇을 기록했는지에 관한 비율이다.
“산책의 70%에서 냄새 탐색을 한다”와 같지 않다. 사용자는 특별한 순간만 기록하거나,
바쁜 날에는 아무것도 입력하지 않을 수 있다.

초기 문구는 “이 조건에서 관련 기록이 서로 다른 N번의 산책에 남아 있어요”를 우선한다.
지원 산책 수가 같아도 전체 선택 기간과 원천 범위가 다르면 같은 결론으로 보지 않는다.

### 7.2 기존 low-motion 부정 판정도 행동 음성 정답이 아니다

[Memory Place biography](../../contracts/memory-place-biography.md)의 judgeable 분모는
노출·capability·drift 자격 아래 **low-motion 관측 여부**를 비교하는 계약이다.
여기서 `not_observed`가 나왔다고 ‘냄새를 맡지 않았다’로 변환할 수 없다.
저속 현상의 관측 가능성과 특정 행동을 알 수 있는 능력은 다른 축이다.

향후 행동 발생률을 말하려면 행동별로 관측 기회와 확인 방식, 미응답 처리까지 정의해야 한다.
‘아무 행동도 없음’ 선택지 하나로 모든 행동에 대한 음성 정답을 만들지 않는다.

### 7.3 제안이 입력 분포를 바꾼다

시스템이 냄새 탐색만 자주 물으면 그 행동 Pin이 늘 수 있다. 개인화 제안으로 특정 장소를
자주 방문하게 된 경우도 기록이 자연 발생한 선호의 표본이라고 보기 어렵다.

기존 `elicitation_mode`, 실제 Offer 이력과 이후 제안 노출 이력이 있는 범위에서 기록 생성
경로를 보존한다. 새로운 origin enum을 선납하기보다 실제 학습/평가에서 필요한 구별을
구체 사례로 확인한다. 요약 → 제안 → 같은 답을 유도 → 요약 강화의 순환을 성향 검증으로
착각하지 않아야 한다.

## 8. 파생 요약의 후보 형태

처음부터 장기 학습 모델이나 독립 프로필 DB를 만들 필요는 없다. 첫 실험은 허용된 입력을
받아 결정론적으로 다시 계산할 수 있는 순수 projector로 충분하다.

```text
selected authorized evidence
→ resolve effective Pin meaning
→ verify dog attribution and vocabulary
→ evaluate context/time/spatial eligibility
→ deduplicate and group
→ counts + evidence references + limits
→ bounded display text
```

### 8.1 설명용 JSON

다음은 **현재 API가 반환하는 값이 아니다.** 새 타입을 논의하기 위한 가상 예다.
수치·코드·정책 버전은 테스트 fixture의 예이며 운영 기본값이 아니다.

```json
{
  "draft_type": "behavior_profile_projection",
  "dog_id": "fixture-dog-A",
  "as_of": "2026-09-04T20:00:00+09:00",
  "window": {"from": "2026-08-01", "to": "2026-09-04"},
  "policy_version": "draft-1",
  "input_fingerprint": "computed-from-selected-evidence",
  "summary_items": [
    {
      "meaning": {"code": "sniffing_example", "vocabulary_version": 1},
      "scope": {"kind": "place_specific", "memory_place_id": "fixture-place-A"},
      "evidence_state": "supported_records",
      "supporting_pin_count": 6,
      "distinct_walk_count": 4,
      "distinct_day_count": 4,
      "behavior_rate": null,
      "display_text": "이 장소에서 냄새를 탐색했다는 기록이 네 번의 산책에 남아 있어요.",
      "evidence_refs": [
        {"pin_id": "fixture-P1", "effective_attestation_id": "fixture-A1-r2"}
      ],
      "limitations": ["selected_records", "no_behavior_absence_denominator"]
    }
  ]
}
```

`evidence_refs`는 예시라 한 개만 표시했지만, 실행용 결과가 된다면 전체 근거를 담거나
완전한 membership를 해석할 수 있는 참조/페이지 계약이 필요하다. 표시용 top-K 링크만으로
6개 Pin 전체 기여의 추적성과 삭제 전파를 만족했다고 할 수 없다.

`input_fingerprint`는 dog/selector/원천 revision/정정 head/문맥 revision/정책 버전 등 실제
사용한 입력을 정규화해 계산한다. caller가 임의 문자열을 넣는 예시 형태를 실행 계약으로
옮기지 않는다. 현재값과 과거 시점 재현을 지원할지는 별도 선택이며, 과거 재현을 주장한다면
당시 존재하지 않았던 미래 정정이나 미래 문맥을 입력에 섞지 않아야 한다.

### 8.2 상태는 하나의 신뢰도 점수로 합치지 않는다

후보 상태는 데이터 없음, 지원 기록 있음, 자료 부족, 문맥 부족, 어휘 미지원, 정정 충돌,
재계산 대기 등이다. 기존 ContextAtom 상태를 그대로 복사한 새 enum을 즉석에서 고정하지
않는다. 실제 실패 fixture로 무엇을 구별해야 하는지 먼저 확인한다.

특히 아래 축은 별도로 드러내는 편이 좋다.

- 증언의 확실성: confirmed/uncertain 및 현재 의미.
- 귀속: 어떤 강아지·보호자·외부 사건인가.
- 공간과 시간의 지지 범위.
- 입력량: Pin 수·서로 다른 산책 수·날짜/장소 다양성.
- 문맥의 확보 상태와 기준일.
- 노출·무응답·기록 선택의 편향.
- 입력 revision과 결과의 최신성.

이 축을 근거 없이 `confidence=0.92` 하나로 압축하면 숫자가 무엇을 보장하는지 설명할 수 없다.

## 9. 프로필 화면의 첫 형태

기존 기본 프로필 아래 **‘산책에서 기록된 모습’** 같은 별도 영역을 제안한다. 보호자가 직접
입력한 성격과 자동으로 갱신되는 기록 요약을 구분해서 보여준다.

한 항목의 구성 후보:

1. 짧은 설명: 어느 장소/상황에서 어떤 행동 기록이 반복되는가.
2. 범위: 선택 기간과 관련 산책 수.
3. 근거 열기: 실제 Pin 목록과 해당 스토리보드 장면.
4. 상태: 아직 적은 기록인지, 위치/시각을 제한해서 읽었는지.
5. 정정 경로: 원본 Pin을 고치거나 현재 설명의 표시를 숨긴다.

| 문구 후보 | 필요한 근거/판단 |
|---|---|
| “이 장소에서 냄새 탐색 기록이 네 번의 산책에 있어요” | 해당 행동의 현재 증언 + 장소 membership + distinct walk count |
| “공원 주변에서 이런 기록이 반복돼요” | 주변이라는 공간 조건과 지원 산책 수; 내부 방문으로 표현하지 않음 |
| “공원에서 더 자주 냄새를 맡아요” | 다른 조건과 비교 가능한 행동별 분모·관측 편향 검토가 추가로 필요 |
| “공원을 좋아하는 성격이에요” | 현재 자료만으로 지원되지 않는 선호/성격 추론 |
| “공원에서 불안해서 멈춰요” | 저속 관측에서 감정·인과를 만들어낸 표현. 사용하지 않음 |

“이 설명 숨기기”는 표시 선호이며 행동이 없었다는 증언이 아니다. “내 강아지와 안 맞아요”도
원본 행동 사실을 자동 수정하지 않는다. 원본 기록 정정과 요약 피드백은 서로 다른 행위로 둔다.
사용자가 별도의 자기소개 문장을 확정한다면 그 문장은 사용자 작성/확정 프로필이고 자동
projector 결과와 수명·삭제·공유 계약을 따로 정해야 한다.

기록이 없을 때도 기본 프로필·일반 산책·스토리보드는 작동한다. 개인화를 사용하기 위해
Pin을 의무적으로 입력하도록 만들지 않는다.

## 10. 다음 산책에 쓰는 세 단계

### 단계 A — 관련 기억을 꺼내기

사용자가 장소를 보거나 산책을 준비할 때, 같은 장소 또는 지원되는 문맥의 과거 기록을
제시한다. “이 근처에서 냄새 탐색을 기록한 적이 있어요”처럼 기억을 돌려주는 수준이다.
가장 먼저 비교할 만한 개인화 소비자다. 대화 중 요청에 응답하는 것과 푸시 알림은 별도다.

### 단계 B — 선택 가능한 제안

사용자가 산책 후보를 고르는 맥락에서 “오늘도 잠깐 둘러볼까요?”처럼 선택지를 붙인다.
현재 접근 가능성·시설 조건·사용자 요청을 확인해야 한다. 등록 공원이라는 이유만으로 현재
영업·통행·반려견 허용을 알고 있다고 가정하지 않는다. 행동 기록은 일반 제약을 무시하는
우선권이 아니며, 확인되지 않은 조건은 미상으로 남긴다.

### 단계 C — 미시 움직임에 맞춘 확인/제안

현재 세션의 합법적으로 사용 가능한 관측 창과 과거 확인된 행동의 특징을 비교한다.
비슷한 패턴을 발견하면 검토 후보로 삼을 수 있다. 후보는 행동 확정이나 자동 Pin이 아니다.

다음 입력이 충분한지 별도로 확인해야 한다.

- 폰 위치와 강아지 행동 사이의 귀속 차이.
- 버튼 입력 지연과 사건 시작/끝의 시간 정밀도.
- 현재 관측의 gap·jump·accuracy·drift 상태.
- 기기/보호자/장소/날씨 차이와 과거 표본의 편중.
- 해당 행동을 확인할 기회가 없었던 구간.
- 산책 중 질문 빈도, 반복 질문, 무응답과 거절 처리.

멈추거나 머뭇거렸다고 해서 ‘냄새 맡는 중’, ‘불안함’, ‘피곤함’으로 자동 확정하지 않는다.
질문 노출 자체가 이후 행동과 기록을 바꿀 수 있으므로 추천 효용과 분류 성능도 따로 평가한다.

## 11. geo, dev, APP, 오케스트레이션

### geo에서 먼저 할 일

허용된 행동 증언 fixture를 입력으로 받아 결과를 재계산하는 projector, 근거별 문구,
반례 fixture와 비교 화면을 만든다. 원천 관측과 표현 사이에서 무엇이 증명됐는지 보여준다.
기존 `DogProfile` 계약과 Context registry를 실험용 dict로 확장하지 않는다.

### dev에 승격할 때 확인할 일

운영 프로필·인증·세션 소유권에 맞춰 읽기 adapter와 갱신/삭제 수명을 정한다. 프로필 원본을
수정할지, 별도 파생 조회를 붙일지 담당 경계를 확인한다. 새 테이블과 batch job이 필요하다는
결론을 먼저 내리지 않는다. 처음에는 요청 시 재계산 또는 제한된 cache도 후보가 된다.

이전 세션에서 확인한 dev 오케스트레이션은 능력 선택·입력 조립·실행·결정적 응답 집계를
제공했다. 당시 Walk 능력은 현재 환경의 산책 적합도였으며, 과거 세션 나레이터나 행동 기억
엔진이 아니었다. 확인 기준 commit과 다음 재확인 위치는 인수인계 문서에 있다.

명확한 프로필 페이지 조회나 산책 종료 후 갱신에 매번 언어 기반 intent routing이 필요한
것은 아니다. 같은 도메인 projector를 직접 호출하고, 대화에서는 별도 능력 adapter로
노출하는 방식이 후보가 된다. 공통 aggregate에 자유로운 강아지 성격 추론을 넣지 않는다.

### APP에서 확인할 일

행동 책갈피 입력, 뒤늦은 확인, Pin 정정, 프로필 카드와 근거 장면 이동을 실제 사용자 흐름으로
연결한다. 지도 marker와 행동 입력 UI가 이미 완성돼 있다고 전제하지 않는다. 다견 산책에서의
주체 선택, 기록하지 않는 사용자, 이동 중 조작 부담도 앱 측 검증 항목이다.

### Context Plane에 붙이는 시점

현재 v0 registry에는 행동 이력 capability가 없다. 필요한 typed payload·provenance·목적 Lens·
권한을 정해 별도 변경으로 채택해야 한다. Journal의 describe용 Bundle을 recommend 권한으로
바꿔 넘기는 식의 우회는 하지 않는다. private note는 새로운 typed 이름을 붙여도 허용되지 않는다.

## 12. LLM을 쓴다면 맡길 범위

LLM 없이 집계와 짧은 설명이 먼저 성립해야 한다. LLM은 허용된 요약 항목의 문장을 다듬거나
이미 선택된 근거를 설명하는 후보가 될 수 있다. 다음을 직접 만들게 하지 않는다.

- 사건 수, 산책 수, 발생률, 비교 분모.
- 새로운 행동 코드와 강아지 귀속.
- 근거에 없는 좋아함·성격·감정·원인.
- 현재 자료가 없는 시설 이용 가능성.
- 기록되지 않은 과거 산책이나 관측 공백의 내용.

출력에 evidence ID가 있다고 의미가 근거 안에 있다는 보장은 없다. 입력 claim과 문장의
일치 여부, 숫자, 시간/장소 범위, 금지된 확대 표현을 별도로 평가한다. 실패하면 결정적
문구나 빈 개인화 결과로 돌아갈 수 있어야 한다. 모델 출력으로 원본 증언을 갱신하지 않는다.

## 13. 정정·삭제·시간에 따른 변화

현재 요약은 파생 view라는 가정으로 먼저 실험한다.

| 변화 | 필요한 결과 |
|---|---|
| dog claim이 owner claim으로 정정 | 해당 강아지 행동 기여 제거 |
| confirmed가 uncertain으로 정정 | 긍정 지지 수에서 제거; 현재 불확실 상태로 읽기 |
| 의미 코드 정정 | 이전 그룹에서 빼고 새 그룹의 자격 재평가 |
| source session 삭제 | 그 세션의 Pin·요약 기여·근거 링크·추천 cache를 제거/재계산 |
| dog/subject 삭제 | 해당 주체의 파생 프로필·index/cache도 수명에 따라 삭제 |
| 문맥 원천 revision 변경 | 과거 snapshot과 현재 재해석을 구별하고 사용한 revision 표시 |
| 그룹/문구 정책 변경 | 원본 증언을 바꾸지 않고 새 policy version으로 재계산 |
| 긴 시간 동안 새 기록 없음 | 오래된 근거의 기간을 드러냄; 현재도 동일 성향이라고 자동 단정하지 않음 |

현재 Pin correction API는 retirement/restore API가 아니다. “Pin 삭제 이벤트가 이미 있다”는
가정으로 구현하지 말고 실제 source session 삭제와 지원되는 lifecycle에서 출발한다.

다견·보호자 변경·성장·환경 변화에 대응할 기간/감쇠 규칙은 미정이다. 30일·8주 등의 기간을
쓰려면 실험 파라미터로 남기고 근거 없이 운영 기본값으로 고정하지 않는다.

이미 확정된 `PublishedJournalSnapshot`은 현재 요약과 다른 불변 수명이다. 현재 요약을
정정했다고 기존 확정본을 임의로 덮어쓰지 않는다. 프로필 확정본이라는 새 객체를 만들 경우
그 삭제/정정/공유 의미는 별도 결정이 필요하다.

## 14. 보관·공유·학습 데이터

프로필 요약도 특정 장소와 반복 행동을 포함하면 생활권 정보를 드러낸다. 원본 좌표를
삭제했으니 자동으로 공개해도 되는 ‘무해한 성격 데이터’라고 보지 않는다.

초기 제안은 해당 강아지에 접근 권한이 있는 주체의 개인 열람이다. 공개 프로필·게임 랭킹에
장소별 행동 근거를 붙이는 기능은 별도 공유 설계가 필요하다. 정확 좌표와 사건 시각을
요약문에 기본적으로 복제할 이유도 없다. 근거 조회는 원본 권한을 다시 확인해야 한다.

학습을 한다면 훈련 dataset·embedding·feature cache에서도 source ID와 삭제 기여 추적이
필요하다. 현재 개인화 제안을 모델 재훈련 승인으로 해석하지 않는다. 첫 projector 단계에는
학습 모델이 필요하지 않다.

[결정 #85](../../decisions/2026-09-03-walk-diary-route-privacy.md)는 geo에서 영구 연속
경로 저장을 열지 않았다. 프로필을 만든다는 이유로 purged 경로를 복원하거나 raw fix 수명을
늘리지 않는다. 존재하는 Pin·증언·허용된 저장 재료로 답할 수 있는 질문부터 고른다.

## 15. 반례와 검증 계획

다음은 **앞으로 작성할 테스트 계획**이다. 이번 문서 PR이 이 테스트를 구현하거나 실행한
것으로 읽지 않는다. 기존 스토리보드 17개 테스트는 행동 개인화를 검증하지 않았다.

| fixture/상황 | 기대 결과 |
|---|---|
| Pin 0개 | 빈 행동 요약, 일반 프로필/산책 정상 동작 |
| 한 산책의 같은 행동 Pin 여러 개 | Pin 수와 distinct walk 수 분리 |
| 같은 Pin 여러 번 입력 | 중복 기여 없음 |
| 정정 전후 증언이 함께 입력됨 | 현재 head만 기여; 이전 의미는 history에만 |
| dog → owner 정정 | 강아지 행동 지원 수 감소 |
| uncertain/미응답/dismiss | 행동 없음의 분모로 세지 않음 |
| 같은 좌표의 다른 강아지 | 주체별 결과 분리 |
| 한 Pin의 joint claim | 강아지 단독 행동으로 분해하지 않음 |
| 잘못된 vocabulary version | 미지원 상태; 유사 코드로 추측 매핑하지 않음 |
| 공원 대표점 가까운 도로 Pin | 공원 주변까지만 설명 |
| gap 중 사건/시각 미상 Pin | 미시 움직임 연결과 시간 조건의 자격 제한 |
| 문맥 fetch_failed | 없는 장소/맑은 날/안전한 곳으로 치환하지 않음 |
| 세션 삭제 | 현재 요약·근거·cache에 이전 기여 없음 |
| 최신 계산 중 correction 경쟁 | 오래된 head로 만든 결과의 게시 방지/재계산 |
| summary 문장을 입력에 재삽입 | 원천 증거로 수용하지 않음 |
| 장면 13장 vs 압축 5장 | 같은 근거를 보존하고 이해도/중복 정도 비교 |
| 여러 날짜·여러 장소의 입력 순서 변경 | 같은 정규화 입력이면 같은 결과 |
| as-of 이전/이후의 정정 | 선택한 현재/과거 재현 정책과 일치 |
| 자기보고 temperament와 기록 요약 불일치 | 한쪽을 삭제하거나 자동 덮어쓰지 않음 |

후속 사용자 검증에서는 “설명이 우리 강아지와 맞는가”뿐 아니라 “왜 그렇게 설명하는지
근거를 찾을 수 있는가”, “오해한 내용을 고칠 수 있는가”, “평범한 산책에서도 부담 없이
기록할 수 있는가”를 확인한다. 만족도와 모델 분류 정확도는 같은 지표가 아니다.

미시 패턴 모델을 검증할 때는 같은 산책의 인접 창이 train/test에 섞이는 누출을 막고,
시간·장소·기기·보호자 차이에 대한 평가 범위를 명시한다. 합성 fixture의 통과는 실제
강아지 행동 인식 성능을 증명하지 않는다.

## 16. 권장하는 다음 작업 단위

### 첫 실험 — 입력과 결과를 나란히 보는 행동 프로필

구체 작업 후보는 아래와 같다. 이 문서는 구현을 수행하지 않는다.

1. 기존 타입을 따르는 여러 세션의 합성 Pin/Attestation fixture를 준비한다.
2. dog/owner/uncertain/정정/삭제/시간 미상을 포함한다.
3. 작은 행동 어휘를 fixture 전용으로 명시한다. 제품 어휘로 등록하지 않는다.
4. 현재 head와 기여 자격을 읽는 순수 projector를 만든다.
5. 행동별 Pin 수·산책 수·근거 목록과 제외 이유를 내보낸다.
6. 프로필 카드에서 근거 Pin과 스토리보드 장면으로 이동하는 로컬 비교 화면을 만든다.
7. 정정 또는 삭제 fixture를 적용한 전후 차이를 보여준다.
8. 지원되지 않는 설명이 나오지 않는지 전용 테스트를 작성한다.

성공 조건은 빈 결과·불확실·정정까지 설명 가능한 요약을 만드는 것이다. 보상·추천 점수·
자동 성격 label·모델 학습·운영 DB를 한꺼번에 넣는 작업으로 확장하지 않는다.

### 이어서 할 실험 — 장면 압축과 관련 기억 회수

동일 산책을 기존 13장과 약 5장으로 비교한다. 5장은 제안된 비교군 크기이지 제품 제한이
아니다. 지역 전환을 모두 장면으로 만들지 않아도 흐름이 남는지 확인한다.
그 다음 프로필에서 실제 근거가 확인된 장소 하나를 골라 다음 산책의 ‘관련 기억’ 카드로
되돌려본다. 실시간 질문과 경로 추천은 그 이후에 별도 소비자로 검토한다.
