# 산책 스토리보드와 동네 구간

산책을 시작·이동·중간 Pin·종료 순서로 이어지는 이미지의 흐름으로 읽는 구상이다.
2026-09-04 논의에서 일기 문장 중심의 접근을 스토리보드로 바꾸고, 점령 게임에도 필요한
지역 구별 정보를 이 흐름의 재료로 사용하는 방향이 나왔다.

이 문서는 구상을 축적하는 탐색 문서다. 아래 타입명·화면·구현 순서는 후보이며, 저장 계약,
지역 공급자, 게임 규칙, API 또는 제품 이관을 승인하는 결정이 아니다. 기존 결정은 유지한다.

2026-09-04에 [시나리오 스토리보드 실험](../../research/2026-09-04-storyboard-regions-spike.md)을
추가했다. SGIS 실제 경계·상가·공원·하천 자료와 합성 산책을 결합해 로컬 HTML을 만든다.
`working-skeleton`은 이 개발 실험을 가리킨다. 운영 나레이터나 경로 영구 보관 구현은 아니다.

## 1. 출발점 — 먼저 흐름이 보이고, 필요한 곳에 말이 붙는다

현재 질문은 “산책 일기를 어떻게 잘 쓰나”에서 다음으로 옮겨간다.

> 시작부터 끝까지 장면을 순서대로 넘겨봤을 때, 우리가 어떻게 걸었는지 전달되는가?

기본 재료는 시작과 끝, 관측된 이동, 시간순 Pin이다. 사진·메모·행동 책갈피는 연결 가능한
경우의 추가 재료이며 이 문서가 해당 기능의 운영 구현을 전제하지 않는다.
나레이션은 장면 설명과 전환을 맡는다. 모든 화면에 문장이나 특별한 사건이 필요하지 않다.

사용자가 쓰는 행위도 장면을 남기고, 사진을 붙이고, 자기 말을 덧붙이거나 고치는 것으로
생각해본다. Pin이 없거나 한 동네에서만 걸은 산책도 기본 재생이 성립해야 한다.

스토리보드가 실제 경로 애니메이션을 포함할지, 대표 이미지·지도 컷으로 구성될지,
사진이 없을 때 무엇을 보여줄지, 자동 재생과 직접 넘기기를 어떻게 제공할지는 열려 있다.
이미지로 표현했다는 이유로 방문·행동·점령 사실을 추가할 수는 없다.

## 2. 논의에서 모인 방향과 아직 검증할 가설

| 구분 | 내용 |
|---|---|
| 사용자 제안 | 시작·끝·중간 Pin의 순서를 가진 스토리보드로 산책을 생각한다 |
| 사용자 제안 | 점령 게임과 동네별 랭킹에 필요한 지역 정보를 스토리보드 소재로도 쓴다 |
| 설계 후보 | 공통 지역 카탈로그를 두고 산책의 지역 흐름과 게임 성과를 별도로 만든다 |
| 설계 후보 | 순서 있는 지역 구간을 보존하고 편집자가 챕터 전환에 사용할지 선택한다 |
| 검증할 가설 | 지역 이름과 전환이 Pin 없는 산책도 다시 볼 만하게 만든다 |
| 검증할 가설 | 주변 문맥과 짧은 나레이션이 화면만으로는 부족한 내용을 보완한다 |

이 표의 제안과 가설은 adopted 결정이나 측정 결과를 뜻하지 않는다.

## 3. 지역의 역할 — 챕터 후보와 위치 표시

지역은 Pin마다 붙이는 이름을 넘어 산책 전체의 공간적 순서를 설명할 수 있다.

```text
산책 한 편
  시작
  A동 구간 — 이동, Pin
  B동 구간 — 이동, Pin, 해당 시점의 게임 성과가 있다면 추가
  A동 구간 — 이동
  종료
```

그러나 지역 구간과 화면 챕터는 1:1로 고정하지 않는다. 같은 동네에서도 공원·골목·하천으로
배경이 바뀔 수 있고, 동 경계를 넘어도 같은 하천길이 이어질 수 있다. 지역명은 위치 표시로
쓰고, 의미 있는 전환만 챕터로 선택할 수 있다.

경계를 잠깐 스친 구간을 화면에서 생략하더라도 관측 결과를 지우거나 다른 지역으로 바꾸지
않는다. 경계 근처 GPS 흔들림의 처리와 화면 전환 수를 줄이는 편집은 서로 다른 단계다.
시간·거리 문턱과 touched/traversed 같은 분류는 아직 정하지 않는다.

### 지역 순서만으로 말할 수 없는 것

| 근거 | 가능한 표현 | 추가 근거 없이 만들 수 없는 의미 |
|---|---|---|
| A → B → A의 관측된 구간 | B동을 지나 다시 A동 구간으로 이어짐 | B가 가장 먼 곳, 출발점으로 귀환 |
| 산책 시작 위치 | A동에서 산책 시작 | 집에서 출발, 집 근처 |
| 보관된 기록에서 지역 첫 등장 | 비교한 기록에서는 처음 나타남 | 생애 첫 방문, 처음 걷는 거리 |
| 특정 지역을 반복해서 지남 | 해당 기록에서 자주 걸은 지역 | 강아지가 좋아하거나 가고 싶어 함 |

출발점 복귀는 시작·종료 위치의 관계로, 가장 먼 지점은 별도 측정으로 확인해야 한다.
과거 기록 비교에는 비교 기간·산책 수·기록 누락과 삭제의 영향을 함께 다뤄야 한다.
표현을 “기록에서 처음”으로 제한해도 실제 첫 방문을 암시하는 배지·연출까지 정당화하지는 않는다.

## 4. 공통 지역 정보와 각 제품의 의미

```text
지역 카탈로그: 체계 ID · 지역 ID · 경계 · 표시명 · revision
                       │
             공간 관계를 구하는 공통 계산
               ┌───────┴────────┐
               ▼                ▼
     산책 지역 구간 판정      게임 지역 판정
     순서·공백·품질 보존     접촉·점령·랭킹의 별도 자격
               │                │
               ▼                ▼
       스토리보드 편집       게임 결과와 시즌 집계
```

공유하는 것은 지역을 구별하는 자료와 중립적인 공간 계산이다. 스토리보드용 경계 평활화나
짧은 구간 생략을 게임의 권위 있는 접촉 판정으로 사용하지 않는다. 지역을 걸었다는 사실,
Site Encounter, Capture 성공, 현재 Claim 상태도 서로 대체하지 않는다.

게임 성과는 독립적으로 성립한 결과를 출처와 함께 선택적으로 배치할 수 있다. 과거 산책의
성과를 현재 점령 상태에서 역산하지 않는다. 게임을 하지 않아도 기본 스토리보드는 유지한다.

점령 Cell/Site, 랭킹 지역, 표시용 동네는 목적이 다르다. 첫 실험은 한 지역 체계로 시작할 수
있지만 그 체계의 종류를 명시한다. 여러 체계의 관계가 항상 단순한 포함 관계라고 가정하지
않는다. 별도 리그 체계나 Memory/Territory 두 편집본을 지금 필수로 만들지는 않는다.

## 5. 첫 재료 후보 — WalkRegionItinerary

Pin의 지역명 목록으로는 출발·중간 이동·재진입 순서를 복구할 수 없다. 산책의 관측된 지역
구간을 시간순으로 읽을 수 있는 별도 결과를 검토한다. 아래는 책임을 설명하는 초안이다.

```text
WalkRegionItinerary [후보, 미구현]
  산책 / 분석 세대 식별
  region_scheme_id / region_catalog_revision
  resolution_policy_version
  ordered entries
    RegionSpan
      구간 식별 / 순서 / 지역 식별 / 사용한 표시명
      시작·끝 offset / 시간 정밀도와 추정 근거
      관측된 거리·시간 / 경계 불확실성
    UnobservedSpan
      관측 공백 / chain 단절 / 이유
    UnresolvedSpan
      관측은 있지만 지역을 판정하지 못한 범위 / 이유
  원천·계산 fingerprint와 생성 이력
```

같은 지역에 재진입한 구간은 구별한다. A동#1과 A동#2를 지역 ID가 같다는 이유로 합치지 않는다.
다만 구간 ID가 재계산을 넘어 안정적인 identity인지, 특정 결과 revision 안의 참조인지는 미정이다.

A동에서 기록이 끊기고 C동에서 다시 잡혔다면 중간을 B동 통과로 채우지 않는다.
지역별 관측 시간의 합이 전체 산책 시간과 같다고 가정하지 않으며 공백·미판정분을 남긴다.
Pin은 시간과 공간 근거로 구간에 연결하고, 불확실하면 억지로 하나의 동네에 배정하지 않는다.

정확 좌표를 빼도 지역 순서와 시간은 개인의 이동에서 파생된 정보다. 내부 재료와 나레이터에
전달하는 최소 정보, 개인 열람과 공유용 표현의 경계를 별도로 정한다. 시작·종료 지역을 숨길
때는 “산책 시작/종료”처럼 처리할 수 있으며 확인되지 않은 “집 근처”로 바꾸지 않는다.

## 6. 보관과 계산 시점 — geo와 운영을 구별한다

[결정 #84](../../decisions/2026-09-03-canonical-trail-consumer-boundary.md)의 geo CanonicalTrail은
finalize 중의 transient 증거다. 원좌표 purge 후 Cellophane만으로 이동 순서를 복원할 수 없다.
geo에서 과거 스토리보드의 지역 순서를 재생하려면 purge 전 필요한 재료를 보존하는 수명 결정이
선행해야 한다. 이 문서가 새 결과를 필수 Capsule 자식으로 추가하거나 궤적 보관을 승인하지 않는다.

[결정 #85](../../decisions/2026-09-03-walk-diary-route-privacy.md)는 단일 산책의 선형 UI 방향을
유지하지만 WalkDiaryRoute의 서버 영속은 열지 않았다. 현재 허용 범위는 dev Lab·fixture replay와
원본 수명을 늘리지 않는 종료 직후 미리보기다. 지역 구간 후보는 이 동선과 별도 형태이지만,
이 문서만으로 저장 자격을 얻지는 않는다. 관련 [동선 탐색](walk-diary-route.md)의 단절 보존과
실제 열람 가치 검증을 함께 참고한다.

운영 dev는 전제가 다르다. 아래 확인 기준의 D-044·D-047은 원본 좌표를 계정 삭제까지 보존한다.
따라서 운영에서는 종료 후 별도 계산도 선택지이며 “finalize에서 만들지 않으면 영원히 불가능”은
아니다. 계산 시점·저장 여부·재시도·실패 격리와 삭제 수명은 실제 채택 저장소에서 결정한다.

재현성은 같은 산책 ID만으로 정의하지 않는다. 같은 분석 입력, 같은 지역 카탈로그 revision,
같은 판정 정책에서 같은 지역 구간 내용이 나와야 한다. 편집본에는 사용한 Pin 증언 revision,
문맥 snapshot, 게임 결과 revision, 편집 정책도 필요하다. 현재 projection의 갱신과 사용자가
확정한 과거 편집본의 보존은 별도 문제다.

## 7. 나레이션과 기존 오케스트레이션의 자리

기존 [memory-engine](memory-engine.md)의 관측·파생·사용자 의미·편집 기억 구분을 이어받는다.
검토했던 WalkNarrativePacket은 이 흐름에서 장면과 근거를 전달하는 후보가 된다.
문장 우선 계약으로 확정하기 전에 화면의 순서와 장면별 재료를 먼저 검증한다.

```text
산책 사실 + 지역 구간 + Pin/증언 + 선택적 문맥/게임 결과
  → 근거를 보존한 장면 후보
  → 선택·묶음·순서·화면별 길이를 정하는 편집
  → 기본 화면과 문구
  → 필요한 장면의 제한된 나레이션
```

저속 관측만으로 행동을 확정하지 않는다. Pin에도 uncertain 증언이 있을 수 있고, Offer를
닫은 행위는 사건이 없었다는 증언이 아니다. Claim ID 연결은 추적성이지 자유 문장의 의미가
근거를 벗어나지 않았다는 증명이 아니다. 결정적 표현과 제한된 나레이션을 같은 재료로 비교한다.

주변 문맥은 전체 산책의 배경과 개별 장면의 상세 배경을 구별한다. 먼저 장면을 고르고 상세
조회를 제한하는 접근은 첫 실험의 범위일 수 있으나, 이동 중 풍경과 경로 전체의 노출 문맥을
영구히 배제하는 원칙으로 고정하지 않는다. 외부 정보가 없거나 실패해도 기본 재생은 가능해야 한다.

dev 오케스트레이션은 능력 선택·입력 조립·실행·결정적 응답 집계를 이미 제공한다.
현재 그 안의 Walk 능력은 현재 환경의 산책 적합도이며 산책 세션 서술 기능은 아니다.
향후 스토리보드/서술 능력을 별도 도메인 기능으로 연결하고, 명확한 종료 후 자동 생성에서는
같은 기능을 직접 호출하는 방향을 검토한다. 공통 aggregate에 자유 합성 역할을 추가하는
것이나, 대화 저장을 장기 기억 활용으로 간주하는 것은 이 구상의 전제가 아니다.

## 8. 먼저 확인할 작은 결과물

지역 체계 하나로 실제 산책의 지역 구간을 읽고, 기존 Pin을 시간순으로 배치해 짧게 넘겨본다.
지역 전환은 필요한 곳에만 표시한다. 지도 이미지·경로 재생의 구현과 보관 자격은 별도 확인한다.

| 사례 | 확인할 것 |
|---|---|
| 한 동네, Pin 없음 | 특별한 사건 없이도 시작·이동·끝이 이해되는가 |
| 한 동네, Pin 있음 | 지역 이동 없이도 장면에 머물 이유가 생기는가 |
| A → B → A | 재진입은 보존하고, 출발점 복귀를 자동으로 주장하지 않는가 |
| 경계 근처 흔들림 / 짧은 스침 | 관측의 불확실성과 편집 생략을 구별하는가 |
| 관측 공백 / 지역 미판정 | 경로와 지역 이동을 지어내지 않는가 |
| 통과만 함 / 독립적으로 확인된 Capture 있음 | 중립 이동과 게임 성과가 화면에서도 구별되는가 |

성공 기준은 지역 이름을 정확히 나열하는 데서 끝나지 않는다. 무음으로도 산책의 흐름이
전달되는지, Pin에 자연스럽게 시선이 머무는지, 나레이션이 실제 정보를 보태는지 확인한다.
스토리보드가 어색하다는 이유만으로 게임 경계를 바꾸지 않고, 원천·판정·편집 중 원인을 구별한다.
이 표 전체의 검증은 아직 완료되지 않았다. 첫 실험은 여러 동을 거치는 합성 경로의 재진입,
Pin 유무, 관측 공백과 게임 표시 유무를 비교한다. 한 동네 산책·실기기 경계 흔들림·사용자
이해도는 남아 있다. 자동 검증과 화면 확인 범위는 연결한 연구 문서에 따로 기록한다.

## 9. 다음 논의에서 채울 빈칸

- 첫 지역 체계의 실제 단위·공급자·경계 품질과 이름의 이해 가능성.
- 사진 없는 산책의 화면 재료, 한 동네 산책의 편집, 자동/수동 넘김과 장면 길이.
- 지역 판정 불확실성, 공백, 짧은 스침과 챕터 전환의 기준.
- geo 실험에서 필요한 보존 범위와 운영 dev의 후속 계산·실패 격리 방식.
- 증언 정정·지역 revision 변경·게임 결과 변경 뒤 현재 화면과 확정본의 관계.
- 개인용 기본 스토리보드에 게임 성과를 얼마나 보여줄지와 공유 범위.

후속 논의는 제안, 반례, 실제 관찰, 채택 여부를 구분해 이 문서에 쌓는다. 측정 결과가 생기면
날짜가 있는 research 문서로 연결하고, 채택할 계약만 별도 결정으로 옮긴다.
