# 영역 칠하기 — 산책 점을 붓으로, 산책 한 번을 셀로판 한 장으로

산책 점에 굵기를 주면 붓이 된다. 지나간 자리가 칠해지고 쌓이면 **자주 가는 영역이 저절로
진해진다.** 면을 그리게 하지도, 궤적이 닫히기를 기다리지도 않는다.

그리고 산책 한 번은 **셀로판 한 장**이다. 조건(계절·시간대·날씨)으로 장을 골라 겹치면
그 조건에서의 행동이 지도로 나온다. 지도는 저장된 진실이 아니라 **질의 결과 뷰**다.

```
산책 이벤트(태그 포함)
        ↓ 조건으로 고르기
해당 이벤트 집합
        ↓ 집계 규칙
공간 × 기간 → 빈도 분포
        ↓ 판정
등급
        ↓ 렌더
색
```

색을 맨 아래 둔다. 이 순서가 뒤집히면 등급이 데이터에 굳어 다시 못 묻는다.

## 여기까지 온 과정 — 네 가지를 버렸다

이 갈래는 "산책 기록을 지형에 담는다"에서 출발해 네 번 방향이 바뀌었다. 버린 것을 남기는
이유는 같은 질문을 다시 안 하기 위해서다.

### 1. 네이버가 지형을 객체로 준다 — 아니다

`CadastralLayer`(지적편집도)는 **래스터 타일**이라 이벤트도 없고 필지 geometry·id 도 못
꺼낸다. `naver.maps.Data` 는 GeoJSON **렌더러**이고 데이터는 호출자가 넣는다. Android SDK 도
같다 — `PolygonOverlay` 로 직접 그리고 `LAYER_GROUP_CADASTRAL` 은 역시 래스터다.

**네이버는 렌더러를 주지 데이터를 주지 않는다.** 면이 필요하면 V-World·공공데이터에서
가져오거나 우리가 만들어야 한다.

### 2. 사용자가 면을 그린다 — [parked](drawn-region.md)

구현과 측정이 있다(`app/geo/region.py`). 접은 이유는 사용자가 **먼저** 그려야 한다는 것과,
원좌표 purge 때문에 나중에 그린 면이 과거 산책을 못 본다는 것이다. 그 문서에 남긴
손익분기 규칙(면 한 변 ÷ 셀 반지름이 실제 비로 4~5배)은 셀 격자를 쓰는 한 계속 유효하다.

### 3. 궤적이 스스로 면을 만든다 — 실측으로 기각

집에서 나가 집으로 오니 궤적이 닫힌 고리일 것이라고 봤다. 실제 도로망에서 간선이 겹치지 않는
고리를 찾으니 **하나도 없었다** — 아파트 단지 안쪽 길이 대부분 막다른 가지다. 그 지형에서
사람은 나갔던 길로 되돌아오고, **왕복 선은 넓이가 0이다.**

그리고 애초에 산책의 시작과 끝은 주인이 정하지 지형이 정하지 않는다. 면은 궤적이 만드는 게
아니라 붓이 만든다.

### 4. 이진 도장 — [측정으로 기각](../../research/2026-08-26-brush-falloff.md)

셀 중심이 붓 반경 안이면 시간을 통째로 주는 방식. 경로 위의 칸과 24m 떨어진 칸이 같은 값을
받아 **모든 칸의 `peak` 이 1.0** 이 된다. 표시를 어떻게 하든 구별할 값 자체가 없다.

### 곁가지: 밴드를 저장값으로 두는 안도 접었다

`10/15/20` 을 셀마다 카운터 3개로 저장하면 사후에 반지름을 다시 고를 수 있다(#59가 시설
밴드에 그렇게 했다). 접은 이유는 **셀이 밴드보다 크면 세 밴드가 같은 칸을 칠해 구별이
사라지기** 때문이다. 대신 셀 중심까지의 **연속 거리**로 물감을 정한다 — 그러면 셀 크기는
값을 어디 보관할지만 정하고 답의 해상도는 정하지 않는다.

## 지금 서 있는 것

`app/geo/paint.py` — 순수함수. 셀마다 세 값을 쌓는다.

| | 뜻 | 왜 하나로 안 되나 |
|---|---|---|
| `occupancy` | 감쇠 반영 물감 총량 | 가까이 오래 = 멀리 아주 오래 |
| `walks` | 문턱 이상으로 칠한 산책 수 (빈도) | 문턱 없이 세면 옆으로 스쳐도 오른다 |
| `peak` | 한 산책에서 받은 최대 세기 | **근접과 빈도를 가르는 축** |

**셋은 산책 한 장(`Cellophane`)마다 따로 남는다.** 미리 접어 칸마다 최대값 하나로 만들면
"한 번 심에 들고 49 번 옆으로 지나감" 이 `walks=50 · peak=1.0` 이 되어 "50 번 다 들어옴" 과
구별되지 않는다 — 이 설계가 막으려던 혼동이 집계 단계에서 되살아난다. 그래서 겹치기(`stack`)는
**질의**이고 문턱(`min_peak`)은 그때 고른다.

`BrushProfile` 이 붓 단면이다. 현재 후보는 계단/연속 × `3·8·20` / `10·15·20`, 그리고 대조군인
이진. 측정 결과 **`3·8·20` 이 갈라내고 `10·15·20` 은 심이 넓어 가장자리를 못 잡는다.**

`app/geo/cells.py` — 앱·서버·적재가 공유하는 육각 격자. `anchors.py` 와 Android
`LocalHexCellIndexer` 가 같은 축좌표를 쓴다. 그 주장은 이제
`docs/contracts/hex-grid-golden.json` 을 **양쪽 테스트가 함께 읽어** 지킨다.

**격자 반지름은 미터가 아니라 단위다.** Web Mercator 라 위도 37.5° 에서 1 단위가 실제
0.79m 다. 처음엔 `radius_m` 이라 부르며 그대로 거리로 썼고, 그래서 `3·8·20` 붓이 실제
2.4·6.3·15.9m 로 동작했다. 지금은 `radius_u` 이고 거리·넓이는 `cells.metres_per_unit` ·
`cells.cell_area_m2` 를 거친다.

## 열려 있는 것

### A. 무엇을 영구히 남기나 — **지금 정하지 않는다**

셀로판을 나중에 다시 만들려면 무언가가 남아야 하는데 원좌표는 finish 직후 purge 된다(#57).
후보가 둘이고, **아직 고를 근거가 없다.**

| | 크기(1.5km 산책) | 재투영 자유 | 민감도 |
|---|---|---|---|
| 단순화 궤적 (Douglas-Peucker) | ~80점 | **완전** — 붓·셀 크기 나중에 변경 가능 | 궤적 그대로. 순서·시각 보존 |
| 셀 맵 + 셀별 시각 | ~200행 | 셀 크기에 갇힘 | 궤적과 거의 같음 |
| 셀 맵, 집계만 | ~200행 | 셀 크기에 갇힘 | **낮음** — 순서가 사라진다 |

**갈리는 축은 "셀이냐 선이냐"가 아니라 "순서를 남기느냐"다.** 단순화는 점 개수를 줄이지
민감도를 줄이지 않는다. 반대로 순서를 버린 셀 맵은 "어디에 있었다"만 남고 "어디를 거쳐
어디로"가 사라진다.

지금 안 정하는 이유: 실사용 업로드는 **#57(보관 기간)과 #58(식별자)이 이미 막고 있다.**
페르소나 데이터에는 프라이버시 이해관계가 없으므로 둘 다 들고 실험할 수 있고, 실험이
필요한 셀 크기·붓을 알려준 **뒤에** 되돌릴 수 없는 경계를 고르는 것이 맞다.

### B. 붓이 좁아지면 GPS 잡음이 표현보다 우세해진다

심을 2~3m로 줄이면 GPS 오차(σ 5~15m)가 심보다 커진다. **금지될 이유는 아니다** — 붓은
특정 주장을 판정하는 자가 아니라 행동 field 를 만드는 kernel 이라 GPS 보다 좁아도 동작한다
(`judgment.py` 의 `unjudgeable` 과는 상황이 다르다). 다만 그림이 실제 행동보다 잡음을 더
보여주게 된다. 안이 둘:

- **정확도에 맞춘 붓** — `accuracy_p50_m` 은 이미 수집한다. 붓 굵기가 그날의 확신을 표현하게
  된다(좁고 진한 = 확실히 여기, 넓고 흐린 = 이 근처). `measured|estimate|unavailable` 과 같은 철학
- **도로망 맵매칭** — 지터가 거의 사라져 2~3m 붓이 의미를 갖는다. 대신 **없는 확신을 만든다** —
  잔디를 가로질렀는데 매핑된 길이 없으면 가장 가까운 길에 붙인다

전자가 싸고 거짓말을 안 만든다. 먼저 해 볼 것.

### C. 등급과 태그 사전 — 데이터가 생긴 뒤

색은 연속 실수가 아니라 **이산 등급**이어야 한다. 이유는 표시가 아니라 소비 쪽에 있다:

- 셀 1,800개 × 실수는 LLM 도구 출력이 될 수 없다. 등급 4~5개 × 영역 몇 개면 된다
- 연속값을 주면 LLM이 없는 비교를 만든다("약간 더 자주"). 등급은 옮겨 적을 뿐 만들 수 없다
- 등급은 문턱을 넘을 때만 바뀌므로 **"여전히 4단계입니다"** 가 성립한다. 연속값은 매번 흔들린다
- **등급이 바뀌는 것 자체가 사건이다** — "이번 달에 이쪽이 앞마당이 됐어요"

다만 구체 문턱과 태그 어휘는 지금 정하지 않는다. 결정 #63 §5가 태그 사전·점수 튜닝을 사용
데이터 이후로 미룬 것과 같은 이유다. 세 값(`occupancy`·`walks`·`peak`)이 남아 있으면 등급은
**언제든 다시 판정할 수 있다** — `encounter.py`(사실) / `judgment.py`(판정) 분리와 같은 구조다.

한 가지만 미리 고정한다: **빈도를 셀 때 `peak` 이 낮은 통과는 세지 않는다.** 축은 빈도 하나로
두되 `peak` 을 입장 조건으로 쓴다. 그래야 길목 옆이 다시 핵심으로 올라오지 않는다.
이것이 `stack(sheets, min_peak=...)` 이고, **장을 산책별로 들고 있어야만 가능하다.**

### D. 비율은 분모와 함께 낸다

"겨울 8/10 = 80%" 와 "겨울 80/100 = 80%" 는 다른 관측이다. `count` · `denominator` · `ratio`
셋 다 남긴다. **판정을 막자는 게 아니라 정보를 잃지 말자는 것이다** — 이 표면은 병원 검색과
달리 틀려도 헛걸음이 생기지 않으므로, 엄밀성으로 진입을 막을 이유는 없다.

## 시간축 — 지금 보존하고, 해석은 늦춘다

24회를 한 장에 합치면 봄에 간 공원과 겨울에 간 골목이 같은 의미가 된다. 그래서 원본은
**산책 하나 = 독립 관측 사건**이어야 하고, `day / week / month / season` 집계는 후처리여야 한다.
계절을 원본 단위로 박으면 7월에만 나타난 변화가 "여름"에 흡수돼 사라진다.

그리고 **1년을 기다릴 필요가 없다.** 시간 맥락은 점진적으로 값을 낸다.

| 시점 | 산책 수 | 검증 가능해지는 것 |
|---|---:|---|
| 1회차 | 1 | 셀로판 한 장 — "오늘 여기 다녔어요" |
| 1주 | ~10 | 겹침 — 늘 가는 길이 보임 |
| 1달 | ~30 | 등급이 의미를 가짐 · **시간대**(아침/저녁) |
| 3달 | ~90 | **요일** 패턴 |
| 1년 | ~700 | **계절** |

그래서 붙이는 순서는 **시간대 → 요일 → 계절**이다. 계절을 1번으로 놓지만 않으면 매 단계가
바로 검증된다.

### 태그는 가질 수 있는 것부터

결정 #51의 교훈이 여기 그대로 적용된다 — 편집 툴 30개를 만들었는데 DB가 답할 수 있는 조건은
셋이었다. 태그도 같은 질문을 먼저 해야 한다.

| 태그 | 지금 되나 |
|---|---|
| 시각·요일·시간대·계절 | **공짜** — `WalkSession.started_at` 파생 |
| 거리·시간·속도·정지 수 | **이미 있음** — `WalkFacts` |
| 일출/일몰 대비 밝기 | **공짜** — 좌표 + 날짜로 계산 |
| 날씨·기온 | 외부 API. Usage Gate 대상, 과거는 소급 조회 필요 |
| 개 컨디션 | **안 됨** — 프로필은 이 레포 소유 아님(#4), 입력 주체도 없음 |

1차는 공짜인 것만. 그리고 #63 §4처럼 **원천 사실과 파생 태그를 분리해서** 남긴다 —
`temperature = 29.4` 는 사실이고 `temp_band = hot` 은 파생이다.

## 레이어 연산

셀로판을 여러 장 겹치는 것 말고도 의미 있는 연산이 있고, 하나로 줄일 이유가 없다.
다만 연산이 **두 종류**라는 것에 주의한다 — 섞으면 조용히 틀린 답이 나온다.

```
존재(support) 연산                 값(빈도·비율) 연산
A ∪ B   한 번이라도 간 곳           visit_rate(A) − visit_rate(B)
A ∩ B   둘 다 간 적 있는 곳          여름 우세 ←→ 겨울 우세 차이 field
A − B   여름에만 가 본 곳
```

**존재 연산만으로는 계절 편향을 못 본다.** 여름 90% · 겨울 10% 로 가는 칸은 `A − B` 에서
사라진다 — 둘 다 support 에 있으니까. 정작 보고 싶은 건 그 80%p 차이인데.

존재 연산은 육각 id 집합 연산이라 **격자 표현에서 공짜**다(궤적 표현은 래스터화가 먼저다).
위 §A를 고를 때 같이 볼 것. 값 연산은 어느 표현이든 겹친 뒤 칸마다 빼면 된다.

첫 렌더가 뭉갠 것은 데이터 성질이 아니라 렌더러 문제였다 — 히트 블롭을 셀 간격의 1.7배로
퍼뜨려 등급 차이를 스스로 지웠고, 등급 구분 없이 모든 칸을 같은 물감으로 칠했다. 연 1,000회
× 산책당 200칸은 시각화가 감당 못 할 양이 아니다.

## 검증됨 (2026-08-26)

`LayerSpec`(`app/geo/layers.py`)과 정답 심은 1년치로 파이프라인 전체를 쟀다 —
[셀로판 회수 실험](../../research/2026-08-26-cellophane-recovery.md). 6 기준 전부 통과.

가장 센 결과는 F1/F2 다. **같은 집·같은 경로·같은 연간 횟수, 계절 배정만 정반대**인 두
사람의 연간 누적 지도가 잡음보다도 가깝고(0.5ε) 계절 조건에서는 코사인 −0.999 로 갈린다.
전체 누적만 저장했다면 두 사람이 구별되지 않는다 — **장 단위 보존이 값을 한다**는 근거다.

그래서 §A 의 후보 중 "셀 맵, 집계만" 이 무엇을 지키는지가 분명해졌다: 지켜야 하는 것은
좌표가 아니라 **산책 단위 경계**다. 통짜 누적 하나로 접으면 그 경계가 사라진다.
