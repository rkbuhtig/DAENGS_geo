# 경로 기반 공간 스토리보드

## 한 줄

산책 중에는 화면을 보지 않는다. 종료 후 시간순 GPS 동선을 확정하고, 실제 통과 순서와 길의 흐름에 모순되지 않는 공간 이미지를 겹쳐 **누군가 사용자와 강아지의 산책을 기록해 준 듯한 스토리보드**를 만든다.

제공사별 기능·한국 커버리지·요금·저장 정책은 날짜가 붙은 [공간 이미지 제공사 조사](../../research/2026-08-19-spatial-imagery-providers.md)에서 분리 관리한다.

## 경험 목표

- 산책이 끝난 뒤 동선을 하나의 선이 아니라 순서가 있는 장면들로 기억한다.
- 같은 장소라도 어느 방향으로, 몇 번째로 통과했는지에 따라 다른 장면이 된다.
- 사진은 사용자의 정확한 시선을 재현하지 않아도 된다. 사용자가 지나온 길과 방향적으로 모순되지 않으면 된다.
- 약간 비스듬한 시점은 자연스럽다. 90도 옆길이나 맥락 없는 역방향처럼 경로에서 이탈한 느낌을 주는 이미지만 거른다.
- 적합한 이미지가 없으면 잘못된 이미지를 억지로 넣지 않는다.

## 비목표

- 이동 중 로드뷰·스토리보드 표시
- 실시간 길안내 또는 사용자의 고개 방향 추론
- GPS만으로 1인칭 시야를 정확히 복원
- 제공사 이미지를 무단 저장·가공하거나 스크린샷으로 자산화
- 첫 단계에서 사용자와 강아지를 이미지 안에 생성·합성

마지막 항목은 공간 장면 선택이 검증된 뒤 별도 갈래로 다룬다. MVP는 **경로와 일관된 공간 장면의 선택·배열**까지다.

## 전체 흐름

```text
산책 중
시간순 GPS 좌표 배치 저장
        ↓
POST /walks/{id}/finish
        ↓
노이즈 정리 · 최종 경로와 누적거리 확정
        ↓
자동 장면 후보 추출 또는 사용자 지점 선택
        ↓
경로 회랑 · 통과 순서 · 대략적 진행 방향으로 이미지 후보 필터
        ↓
WalkPassageScene[] 생성
        ↓
정적 경로 + 이동 순서대로 겹친 이미지 카드
```

공간 이미지 조회는 종료 후에만 한다. 산책 중 배터리 비용은 기존 GPS 수집 외에 늘리지 않는다.

## 좌표가 아니라 통과 사건

장면의 식별자는 `(lat, lng)`가 아니다.

```text
WalkPassage =
  좌표
  + 통과 시각
  + 경로상 누적거리(route_offset_m)
  + 구간의 대략적 진행 방향
```

원형·왕복 동선에서는 같은 좌표를 여러 번 지날 수 있다.

```text
A 좌표, 10분째,  320m 지점, 동쪽 진행
A 좌표, 45분째, 2780m 지점, 서쪽 진행
```

두 기록은 위치가 같아도 서로 다른 `WalkPassage`다. 좌표만으로 중복 제거하지 않는다.

## 경로와 진행 방향

GPS는 연속함수가 아니라 시간순 점의 집합이다. 원본 점을 보존하고, 종료 후 화면과 장면 추출에 쓸 경로를 별도로 정리한다.

짧은 산책 범위에서는 위·경도를 로컬 평면 좌표로 옮겨 경로를 다음처럼 본다.

```text
r(s) = (x(s), y(s))
```

`s`는 출발점부터의 누적거리다. 순간적인 GPS 점 두 개 대신 현재 지점 앞뒤 10~30m 구간으로 접선을 근사한다.

```text
v(s) ≈ r(s + Δs) - r(s - Δs)
heading = atan2(v.x, v.y)
```

북쪽 0도, 시계방향 기준이라 `atan2(dx, dy)` 순서다. 실제 구현에서는 정확한 소수점 방위보다 구간이 대체로 어느 방향으로 이어지는지만 필요하다.

정지 중이거나 이동량이 GPS 정확도보다 작으면 진행 방향을 만들지 않는다. 직전 값을 억지로 복사하기보다 해당 점을 장면 후보에서 제외하거나 정지 장면으로 별도 처리한다.

## 경로 회랑과 방향 필터

동선을 폭이 없는 선이 아니라 좌우 여유를 가진 `route corridor`로 본다.

```text
┌──────────────────────────┐
│       실제 산책 동선 →   │
└──────────────────────────┘
```

이미지 후보는 다음 순서로 거른다.

1. 촬영 좌표가 장면 지점의 검색 반경 안에 있는가
2. 촬영 좌표가 경로 회랑과 가깝거나 시야가 경로를 향하는가
3. 이미지의 방향이 해당 구간의 길 흐름과 크게 어긋나지 않는가
4. 같은 촬영 시퀀스나 파노라마가 연속 장면에 반복되지 않는가
5. 촬영일·화질·출처 표시 조건을 충족하는가

사진 방향과 경로 방향 차이는 넓은 허용각을 가진 보조 점수다.

```text
delta = abs(((photo_heading - route_heading + 180) % 360) - 180)
```

초기 가설은 다음과 같고 실제 표본으로 조정한다.

```text
0°~45°    우선 후보
45°~70°   허용 후보
70° 이상  기본 제외
```

이 값은 사용자의 시선을 맞히기 위한 임계값이 아니다. 경로와 무관한 옆길·역방향 이미지를 제거하기 위한 시작점이다. 360도 파노라마라면 촬영 지점은 유지한 채 경로와 자연스러운 시야를 선택할 수 있다. 평면 사진은 제공된 촬영 방향과 맞는 경우에만 쓴다.

## 장면 후보

### 자동 생성

다음 사건을 먼저 후보로 잡는다.

- 처음 방문한 길 또는 구역
- 진행 방향이 크게 바뀐 곳
- 의미 있게 머문 곳
- 평소 경로와 갈라지거나 다시 합쳐진 곳
- 공원·하천·병원 같은 실제 랜드마크 인접 지점

후보가 부족할 때만 누적거리 간격으로 보충한다. 가까운 후보는 합치고 짧은 산책은 3~5장, 긴 산책은 6~8장 정도를 초기 가설로 둔다.

### 사용자 선택

사용자가 종료 화면의 경로를 누르면 가장 가까운 실제 `WalkPassage`로 스냅한다. 해당 통과 사건의 위치·순서·방향으로 이미지 후보를 찾고, 적합한 후보가 있으면 스토리보드에 삽입한다.

같은 지도 좌표를 두 번 지났다면 좌표만으로 하나를 고르지 않고 시간 또는 경로상 위치를 함께 보여준다.

## 결과 화면

- 위쪽에 전체 정적 경로를 둔다.
- 아래쪽에 `route_offset_m` 순서로 이미지 카드를 겹쳐 놓는다.
- 카드를 넘기면 지도 위 해당 통과 지점을 강조한다.
- 경로의 임의 지점을 눌러 장면을 추가할 수 있다.
- 정적 이미지가 없고 인터랙티브 파노라마만 있으면 카드에서 제공사 뷰어를 연다.
- 촬영일과 제공사 출처를 항상 표시한다.
- 제공사 이미지는 당일 촬영물이 아니므로 `이 지점 주변의 기록 이미지 · 2022-11 촬영`처럼 표현한다.

## 데이터 모델 초안

```text
WalkPassage
- id
- walk_id
- route_offset_m
- occurred_at
- lat
- lng
- route_heading_deg | null
- reason                 # interval | turn | stop | new_area | user_pick

WalkPassageScene
- id
- passage_id
- order
- provider
- provider_scene_id
- camera_lat
- camera_lng
- source_heading_deg | null
- distance_from_route_m
- captured_at | null
- attribution
- viewer_url | null
- state                  # ready | no_match | policy_blocked
```

이미지 바이너리는 기본 저장 대상이 아니다. 제공사 정책에 따라 장면 ID·메타데이터·표시 URL만 저장하고 클라이언트에서 허용된 방식으로 불러온다.

## 세션 엔진과의 경계

- 위치 수집과 경로 확정은 산책 세션 엔진 책임이다.
- 장면 후보·이미지 매칭·스토리보드 상태는 종료 후 파이프라인 책임이다.
- 이미지 제공사 호출 실패가 산책 완료·보상 확정을 실패시키면 안 된다.
- `POST /walks/{id}/finish`가 장면 생성까지 기다릴지, 경로만 반환하고 비동기 생성할지는 미결이다.
- 기존 `MapProvider`는 정적 지도와 지오코딩 책임을 유지한다. 채택 시 공간 이미지는 별도 `SceneProvider` 경계를 검토한다.

## 프라이버시와 정직한 표현

- 출발·종료 좌표는 집 주소일 가능성이 높다. 시작과 끝 일정 거리의 장면 후보 제외 또는 좌표 절삭이 먼저다.
- GPS 원본과 단순화 경로의 보관 기간을 구분한다.
- 제공사 사진을 사용자가 그날 본 장면이라고 단정하지 않는다.
- 향후 사용자·강아지 합성 장면을 만들면 `산책 경로를 바탕으로 재구성한 장면`이라고 표시하고, 원본 이미지의 가공 허용 범위를 별도로 확인한다.

## 검증 계획

### 경로 표본

- 원형 경로: 출발·도착이 겹침
- 왕복 경로: 같은 길을 반대 방향으로 통과
- 교차 경로: 같은 좌표를 다른 시각·방향으로 여러 번 통과
- 정지 포함 경로: 방향이 정의되지 않는 구간 존재
- 골목과 큰길이 섞인 경로: 인접하지만 다른 길의 이미지가 후보로 들어옴

### 측정

- 경로 회랑 안 이미지 발견률
- 방향 필터 통과율
- 같은 시퀀스 중복률
- 촬영일 분포
- 장면 하나당 제공사 호출 수와 비용
- `내가 지나온 길처럼 느껴지는가`에 대한 사람 평가

정밀한 방위 오차보다 마지막 체감 평가가 우선이다.
