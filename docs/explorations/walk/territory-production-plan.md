# 산책 점령 게임 — 제작 계획

2026-09-05 작업 대화에서 합의한 제작 방향과 작업 순서를 기록한다. 기획의 큰 틀은 이
계획을 기준으로 닫고, 지도에서 플레이 가능한 한 사이클을 먼저 만든다. 이 문서의
`implementation: draft`는 1·2단계 기반과 로컬 지도 연결을 작성했고 촬영·온라인 연결이
남아 있다는 뜻이다. API·DB 필드의 최종 계약은 각 구현 PR에서 정한다.

## 구현 진행 — 2026-09-05

1단계 모델·액션·판정 기반은 아래 PR에서 확인한다. 머지·배포 상태는 링크 대상 PR에서
읽고, 검증 결과는 해당 단계 작업 시점의 기록으로 남긴다.

1단계에서는 기존 장소 조회·산책 추적·방문 인증 API를 바꾸지 않았고, DB·실제 카메라·온라인 공유·시즌은

**2단계 지도 연결:** [APP #140](https://github.com/SAJOYO/DAENGS_APP/pull/140).
서비스의 실제 세션 ID·참여견과 현재 위치를 연결하고, debug 빌드에서 점유 표시·대상 범위·
Pin 영역표시를 제공한다. 점유는 메모리 페이크이며 대표견은 첫 참여견을 기본값으로 표시한다.
사진을 요구하는 영역의 탈취는 아직 안내만 한다. 화면의 접근 판정은 로컬 피드백이며
온라인 canonical 접촉 인증을 대신하지 않는다.

2026-09-05 로컬 Gradle 실행으로 타겟 테스트 47개(실패/skip 0)와 `assembleDebug` 통과를
확인했다. 실제 보행·진동·기기 배치는 연결된 기기가 없어 미검증이다. 상세 체험 절차는
[APP 연결 문서](https://github.com/SAJOYO/DAENGS_APP/blob/6d2025d/docs/territory-map-actions.md)를 본다.

다음 작업은 **3단계 실제 촬영과 페이크 사진 판정**이다. 같은 점령 시도에 사진을 붙여
미인증 점유를 강화하고, 새 세션의 인증 탈취까지 한 사이클을 이어간다.

## 1. 제작 기준이 되는 게임 규칙

- 전봇대 등 기존 `TerritorySite`에 접근해 강아지의 **영역표시**를 한다.
- 사진 없이도 점유할 수 있다. 사진 인증이 있는 점유가 더 높은 우선권을 갖는다.
- 인증 점유를 빼앗으려면 새로운 산책 세션에서 그 장소에 가서 사진을 다시 인증해야 한다.
- 한 세션에서 여러 장소를 점령할 수 있지만, 같은 장소를 여러 번 점령할 수는 없다.
- 이미 만든 점령에 사진 인증을 추가하거나 인증 실패·통신 장애를 재시도하는 것은 같은
  시도의 진행으로 다룬다. 새로운 점령 횟수로 세지 않는다.
- 다견 산책의 참여견 목록과 영역표시의 주체를 구분한다. 참여견 중 대표견 한 마리를
  선택하고 점령 시도에 그 ID를 남긴다. 강아지 수만큼 점령 기회를 늘리지 않는다.
- 산책 중 촬영과 비동기 판정을 제공한다. 확인 중에도 산책을 계속할 수 있다.
- 온라인 시즌은 여러 장소의 점유를 정기 정산하고, 누적 점령 점수와 정산 시점의 최대
  동시 점유 기록을 구분하는 기존 방향을 이어간다.

같은 곳에서 세션 종료·시작을 반복하는 행위는 다른 장소를 확보할 기회를 포기하는
기회비용이 있다. 이번 제작에는 별도 이탈·재진입 의무나 최소 이동·대기 조건을 추가하지
않는다. 여러 장소를 확보하는 시즌 구조 안에서 실제 플레이를 보고 판단한다.

기존 [점령지 게임](territory-site-game.md)의 사진 필수 흐름은 이 계획에서 **미인증 점유 →
인증 강화**로 확장한다. [시즌 점령전](territory-season-scoring.md)의 최신 유효 인증에 의한
소유권 교체와 정기 정산 방향은 유지하되, 미인증 점유를 포함한 세부 점수 정책은 아직
확정하지 않았다. 기존 문서의 모든 탐색이나 계약을 일괄 채택하는 변경은 아니다.

## 2. 구조: 공유 점유·내 접근·점령 시도를 분리

다음은 역할을 맞추기 위한 모델 초안이다. 필드명과 저장 형태는 구현 시 기존 모델에 맞춘다.

| 구성 | 주요 정보 | 책임 |
|---|---|---|
| `TerritorySite`와 점유 정보 | 안정적인 장소 ID, 좌표, 미점유/점유, 점유 강아지 ID, 인증 여부, 점유 시각, 상태 버전 | 모두가 공유하는 장소와 현재 점유 상태 |
| 세션의 대상별 접근 판정 | 세션 ID, 장소 ID, 접근 불가/접근 중/점령 준비, 거리·불가 이유 | 지금 내가 이 대상에 영역표시를 할 수 있는가 |
| `ClaimAttempt` | 시도 ID, 세션 ID, 장소 ID, 대표견 ID, 행동한 사용자 ID, 접촉·촬영 참조, 처리 상태 | 영역표시와 인증 추가·재시도를 하나의 흐름으로 추적 |
| 지도 표시 모델 | 위 세 구성의 조합 | 점유자·인증 여부와 내 액션 가능 상태를 함께 표현 |

‘다른 강아지가 인증 점유 중’과 ‘나는 점령 준비 완료’는 동시에 성립한다. 따라서 점령
준비를 공유 점유 상태의 대체 값으로 넣지 않는다. 사진 판정 결과도 점유 상태에 직접
대입하지 않고, 점령 규칙을 통과한 결과로 점유를 갱신한다.

대표견은 점령 시도에 고정해서 남긴다. 대표견 선택 UI와 산책 중 변경 여부는 첫 제작을
막는 별도 기획 과제로 키우지 않는다. VLM의 강아지 검출과 등록 개체 식별은 구분한다.

접근 판정은 산책의 검증된 위치·접촉 근거를 소비한다. 지도 표시 토글은 산책 수집을
바꾸지 않는다. [CanonicalTrail 소비자 경계](../../contracts/canonical-trail-consumers.md)에
따라 Cellophane 색·밀도나 일기 표시 경로에서 점령 근거를 역산하지 않는다.

## 3. 사용자에게 보이는 한 사이클

```text
산책 시작 · 참여견과 대표견 설정
→ 지도에서 점령지 확인
→ 접근하면 대상과 액션 가능 상태 강조
→ Pin의 영역표시 액션
   ├─ 사진 없이 점유 가능한 경우 → 미인증 점유
   │                                → 선택적으로 사진 인증 추가
   └─ 인증이 필요한 탈취 → 같은 세션에서 현장 촬영
→ 사진 저장 · 확인 중 (산책 계속)
→ 인증 성공과 점령 자격 확인
→ 인증 점유 표시
```

미인증 점유의 인증 강화는 그 점유를 유지하며 처리한다. 다른 강아지의 인증 영역을
탈취하는 동안에는 기존 점유자를 유지하고, 확정 결과를 받은 뒤 바꾼다. 확인 중·재촬영·
재시도 대기를 구분하되 세부 예외 설계로 첫 플레이 제작을 늦추지 않는다.

## 4. 제작 단계와 완료 기준

### 1단계 — 공통 데이터와 액션 구조

**담당: APP·Dev.** 기존 장소 조회, 산책 세션, 사진 판정 경로를 대조해 재사용 지점을
확인한다. 공유 점유, 내 접근 판정, 점령 시도를 분리하고 앱과 서버가 주고받을 모델을
맞춘다. 세션·장소당 하나의 점령 시도에 인증 추가와 재시도를 연결한다.

산출물은 모델·액션 정의와 공통 예시 데이터다. 미점유, 미인증 점유, 인증 점유,
다른 강아지의 영역에 접근, 인증 확인 중을 같은 구조로 표현할 수 있으면 완료다.

### 2단계 — 산책 지도에서 액션 연결

**담당: APP.** 기존 지도에 점령지 표시 토글을 우선 붙인다. 이는 첫 구현 방식이며
최종 모드 UX를 확정하는 결정은 아니다. 점유자·인증 여부를 표시하고, 근접하면 범위와
대상을 강조한다. Pin의 영역표시를 선택된 대상의 액션으로 연결한다.

산출물은 예시 점유 데이터로 동작하는 지도 화면이다. 실제 산책에서 장소 확인 → 접근
상태 변화 → 대상 확인 → 영역표시까지 이어지고, 표시를 꺼도 산책이 계속 기록되면 완료다.

### 3단계 — 실제 촬영과 페이크 판정으로 플레이 완성

**담당: APP.** 사진 없는 점유와 실제 카메라 촬영을 붙인다. 판정은 교체 가능한
인터페이스 뒤의 페이크 구현으로 성공·부적합·지연·장애를 재현한다. 다른 강아지의
점유 데이터를 포함해 인증 강화와 탈취가 지도에 반영되는 과정을 만든다.

**첫 제작 묶음은 1~3단계다.** 완료 기준은 직접 걸으면서 전봇대에 접근해 영역표시하고,
사진으로 인증을 강화하거나 다른 강아지의 영역을 빼앗는 한 사이클을 앱에서 체험하는
것이다. 이 단계의 점유 변경은 로컬/페이크이며 온라인 공유나 실제 VLM 검증 완료로
표현하지 않는다.

### 4단계 — 서버 저장과 온라인 공유

**담당: Dev·APP.** 임시 점유 공급자를 서버 API로 교체한다. 서버가 접촉·촬영 근거와
점유 우선순위, 새 세션에서의 인증 탈취, 세션당 장소별 한 번 규칙을 적용하고 점유를
확정한다. 앱은 확정 상태를 지도에 반영한다. 재전송은 같은 시도로 처리한다.

산출물은 저장·조회·영역표시·인증 결과를 연결한 온라인 흐름이다. 두 계정으로 같은
장소의 점유·탈취가 공유되고, 앱을 다시 열어도 서버 상태가 유지되면 완료다. 기존
사진 판정이나 방문 기록 구현이 있다면 재사용하되, 방문 기록을 공유 소유권과 동일시하지 않는다.

### 5단계 — 시즌 점수와 실제 사진 판정

**담당: Dev·APP.** 점유 변경 기록과 정기 정산을 연결하고 지역별 누적 점령 점수·최대
동시 점유 기록을 표시한다. 시즌 경계에서 점유·점수를 초기화하는 기존 방향을 반영한다.
사진 판정은 실제 공급자로 연결하고 현장 촬영 샘플로 확인한다. 두 작업은 4단계의
계약이 안정된 뒤 병행할 수 있다.

산출물은 이동 → 영역표시 → 인증 → 공유 점유 → 시즌 점수까지 이어지는 흐름이다.
점수는 촬영 버튼에서 즉시 더하지 않고 정산 규칙으로 산출한다. 시즌·정산 테스트와
실제 사진 성공·실패 경로를 확인하면 완료다.

## 6. 구현 단계에서 좁혀갈 항목

큰 기획을 다시 여는 목록이 아니라, 해당 기능을 연결할 때 정할 세부 항목이다.

- 사진 없는 점유끼리 충돌할 때의 처리: ‘탈취 불가’는 아직 확정 규칙이 아니다.
- 미인증 점유의 시즌 점수 반영 여부: ‘인증만 점수 인정’도 아직 확정 규칙이 아니다.
- 접근 반경·위치 품질 기준, 복수 후보의 대상 선택과 촬영 유효 시간: 근접 UX에서 조정한다.
- 지연된 인증과 동시 요청의 순서: 온라인 연결 단계에서 소유권 갱신 계약으로 정한다.
- 시즌 길이·정산 주기·지역 단위: 시즌 구현 단계에서 기존 점수 문서와 함께 정한다.

완료할 수 있다.
