# 산책 장면과 일기 생성 기획

**하나의 장면을 혼자 읽어도 완성된 서브 일기로 만든다.** 사용자가 그 순간을
돌아볼 수 있도록, 장면의 중심과 그 순간에 사용할 수 있는 재료로 납득 가능한
서술된 그림을 만든다. 장면 생성에는 전체 세션을 먼저 이해하는 LLM 단계가 필요하지 않다.

2026-09-12 사용자 결정으로 기획을 변경했다. 긴 산책에서는 전체 입력과 장면 사이의
연결 추론이 부담과 오류 가능성을 키우며, 개별 장면의 서술만으로도 제품 가치를 만들 수
있다는 판단이다. 이는 작업 방향의 채택이며 장면 품질·비용·지연의 검증 완료 선언은 아니다.

이 문서가 현재 기획의 기준이다. 자료의 계산 정의·확보 범위는
[자료 카탈로그](evidence-catalog.md), 구현과 과거 실험의 위치는 [일기 입구](README.md)에서 찾는다.
기존 전체 이해 → 순차 장면 갱신 → 전체 재검토를 필수로 둔 기획과 후속 아키텍처·청사진은
폐기했다. 당시 실행 코드와 날짜별 결과는 재현 자료이며 현재 기획의 필수 단계가 아니다.

## 먼저 완성할 결과

장면의 중심은 사용자가 남긴 행동·메모·사진 또는 시스템이 선정한 관측·경로 지점이다.
사진은 이미지가 실제로 제공됐는지, 관측은 기기의 움직임인지, 메모는 사용자의 어떤
원문인지 구별한다. 출처가 다른 중심을 같은 행동으로 취급하지 않는다.

장면은 앞 장면을 읽거나 산책 전체의 줄거리를 알아야 이해되는 문장이 되어서는 안 된다.
다른 장면과의 연결을 만들기 위해 장면 자체의 완성을 미루지 않는다. 지도와 목록에 장면을
순서대로 놓는 일은 시스템이 맡는다. 표시 순서를 모델의 서사 재료로 전달할 필요는 없다.

장면 수와 장면의 완성도는 별개다. 재료가 적은 장면은 짧을 수 있고, 사용자 기록이 풍부한
장면은 그 내용을 충분히 살릴 수 있다. 모든 장면을 같은 분량·문장 수·시설 수로 맞추지 않는다.

## 장면과 전체 일기의 책임

| 결과 | 생성에 필요한 재료 | 책임 |
| --- | --- | --- |
| 개별 장면 | 해당 장면의 중심·원문과 적격한 공간·환경·동선 재료 | 그 장면 안에서 초점과 표현을 선택해 완성된 서브 일기를 작성 |
| 전체 일기 | 사용자가 채택·편집한 장면, 각 장면의 원본 근거, 필요할 때 별도로 참조하는 저장된 세션·동선 자료 | 여러 장면을 한 편으로 구성하는 별도 생성 |

전체 일기의 추가 자료는 원래 세션과 동선에 연결해 보관하고 그 생성 단계에서 참조한다.
장면 작성 입력에 미리 모두 넣거나, 전체 일기 작성을 장면 생성의 선행 조건으로 두지 않는다.
전체 일기의 호출·구성·분량 정책은 후속으로 정한다.

전체 일기는 완성된 장면 문장만을 사실의 원본으로 삼지 않는다. 표현상 생략하거나 강조한
선택이 새로운 관측 사실이 되지 않도록 원본 근거를 함께 참조한다. 장면 사이에 기록 공백이
있으면 전체 일기에서도 그 사이의 연속 행동이나 인과를 만들어 채우지 않는다.

## 시간은 판정과 표시에서 쓰고, 장면의 자유 추론 재료로 주지 않는다

기록의 시각은 원본에 보존한다. 시스템은 그 시각으로 자료의 유효성, 동선의 연속성,
대상 기록과의 대응, 저장 버전과 지도 표시를 확인한다.
**이 내부 판정에 필요한 정보와 장면 작성자가 읽을 정보는 별도다.**

| 정보 | 시스템·원본에서의 용도 | 장면 작성 입력의 기준 |
| --- | --- | --- |
| 시계 시각·날짜·시간대 | 원본 보존, 당시 자료 연결, 화면 표시 | 시간만으로 밤 풍경·계절감·체감을 추론하도록 제공하지 않음 |
| 시작 후 경과·종료까지 남은 시간·세션 총시간 | 세션 관리와 필요한 집계 | 초반·후반, 잠깐·오래, 서두름·피로의 근거로 제공하지 않음 |
| 장면 순번·앞뒤 장면·전체 장면열 | 정렬과 원본 연결 | 앞 장면에서 계속 이어진다는 이야기를 만들도록 제공하지 않음 |
| 관측 support·조회 시각·유효 구간·단절 | 적격성 판정과 근거 재현 | 원시 시간 필드 대신 적격한 재료의 의미와 한계를 전달 |
| 사용자 원문 안의 시간 표현 | 사용자가 실제 남긴 기록 | 원문을 보존하며 다른 사건의 시간이나 인과로 확장하지 않음 |

정확한 숫자도 그 순간의 체감이나 풍경을 보증하지 않는다. 같은 시계 시각이라도 계절과
실제 환경에 따라 다르게 느껴지며, 같은 세션의 인접 장면 사이에 몇 시간의 공백이 있을 수
있다. 단절 표시와 금지 프롬프트를 붙이는 것만으로 전체 시간열의 전달을 정당화하지 않는다.

자료가 현재 장면에 속하는지는 코드가 먼저 판정한다. 직전 구간에서만 성립하는 관측을
현재 순간의 사실로 옮기지 않는다. 시간 관계를 제거하면 뜻이 바뀌는 재료는 장면 입력에서
제외하거나 적격한 의미로 투영할 수 있는지 검토한다. 시간 필드만 지우고 다른 장면의 행동을
남기는 것은 이 경계를 충족하지 못한다.

실제로 확보한 환경 관측은 유효한 공간·시간 범위를 확인한 뒤 사용할 수 있다. 시계 시각으로
날씨·밝기·분위기를 대신 만들지 않는다. 원본 메모의 시간 표현을 삭제하거나 시스템의
유효성 검사를 없애는 기획 변경도 아니다.

## 슬롯에 남길 재료와 문장에서 쓸 재료

슬롯은 **그 장면을 이해하고 그리는 데 사용할 수 있는 근거를 남기는 자리**다.
공간·환경·동선은 유효해지는 조건이 다르므로 나눈다. 파트가 존재한다고 모든 파트를 채우거나
선정된 자료를 모두 문장에 언급해야 하는 것은 아니다.

| 재료 | 남기려는 내용 | 적재·제외와 해석의 경계 |
| --- | --- | --- |
| 중심 기록 | 사용자 행동·원문·사진 또는 선정한 관측·경로 지점 | 주변 자료가 없다고 중심을 버리지 않음. 사용자 기록과 기기 관측의 출처 유지 |
| 공간 | 그 지점을 알아보고 장면을 구체화하는 위치·공간 관계 | 대상 위치·거리의 기준·자료 시점·출처 확인. 등록 시설을 방문·영업·과거 풍경의 증거로 바꾸지 않음 |
| 환경 | 그 장면에 적용할 수 있는 실제 관측 | 관측의 대상 지역·유효 범위 확인. 미확보·낡음·다른 시점이면 제외 |
| 동선 | 그 장면을 설명할 수 있는 검증된 움직임·형태 | 같은 연속 구간과 대상 대응 확인. 공백을 넘기거나 상대 저속을 감속·휴식·강아지 행동으로 바꾸지 않음 |

조건을 통과한 후보가 용량 때문에 빠진 것과, 자료가 없거나 부적격한 것은 구별해 보관한다.
선정된 근거와 모델이 실제 사용한 근거도 구별한다. 근거 ID·버전·역할을 포함하는 고정
스탬프는 어떤 자료로 장면을 썼는지 재현하기 위한 연결이다.

슬롯은 장면마다 재계산하는 스냅샷으로도 성립한다. 작업 중 자료의 교체·만료가 실제 장소의
진입·이탈이나 새 사건을 뜻하지 않으며, 이미 공개된 장면을 교체할 권한도 주지 않는다.
용량·반경·시간 문턱과 순위 방식은 구현 정책이다. 기존값 재사용과 새 임시 정책을 명시하고,
이번 기획 변경만으로 숫자를 바꾸거나 제품 원칙으로 승격하지 않는다.

## 사실의 범위와 서술의 자유

장면의 목표는 읽었을 때 하나의 순간이 납득되는 것이다. 근거보다 강한 사실이 만들어질
입력과 해석을 제거하면서, 모델에는 시선·강조·문장 구성·리듬·생략을 선택할 여지를 준다.
사실의 근거를 지키는 일과 객관적인 관찰 보고 문체로 쓰는 일은 같지 않다.

‘대표 시설 하나와 거리’, ‘배경 한 줄 뒤에 원문’ 같은 구성을 품질 기준으로 고정하지 않는다.
시설을 언급할지는 장면에 도움이 되는지로 판단한다. 원문을 저장 상태 그대로 보존하는 것과
원문을 중심으로 자연스러운 읽기 흐름을 만드는 것을 함께 만족해야 한다.

공간을 위에서 조망하는 3인칭 묘사는 사용할 수 있다. 행위까지 외부 관찰자의 보고로 바꾸면
사용자 경험과의 거리가 생긴다. 공간 묘사의 시점과 행위 주체의 경험을 구별하며, 본문 전체를
기계적으로 1인칭 또는 3인칭 하나로 통일하는 것으로 해결하지 않는다.

행위의 주체와 내용은 기록에 맞춰 쓴다. 자연스러운 문장을 위해 주어를 생략할 수 있지만,
보호자·반려견·기기를 서로 바꾸지 않는다. 기기 위치가 모였다는 관측을 ‘나는 쉬었다’나
‘강아지가 쉬었다’로 번역하지 않는다. 반대로 관측의 한계를 지키겠다는 이유로 모든 본문을
‘확인되었다·관측되었다’로 통일하지도 않는다. 적절히 서술할 근거가 없다면 과장해 채우지 않는다.

행동 원본과 공간·환경·동선은 자료 구조에서 구별한다. 사용자에게 보여주는 장면은 그 재료로
구성한 하나의 완성된 글이다. 자료의 분리가 별도 문단 두 개나 고정된 앞뒤 접합을 요구하지 않는다.
본문 필드·원문 표시·편집 계약의 구체적 변경은 구현 단계에서 정한다.

## 준비·공개·편집

사용자 경험은 **산책 종료 → 준비 → 동선·세션 정보·장면이 묶인 결과 열기 → 수정**이다.
기본 보드는 AI 없이도 읽을 수 있어야 하며, 준비 예산 안에 도착한 유효한 서술만 최초 결과에
반영한다. 빠르게 준비되면 바로 공개하고 늦으면 기본 내용으로 확정한다.

새로고침은 조회다. 재진입이나 편집 중인 화면 때문에 생성을 반복하지 않는다. 늦은 AI
응답으로 공개본을 바꾸지 않으며 사용자 수정은 자동 생성보다 우선한다. 전체 일기의 후속
생성도 공개된 개별 장면이나 사용자 편집을 자동으로 교체하지 않는다.

10초는 앞서 둔 초기 준비 예산이며 최적값이 검증된 수치는 아니다. 슬롯을 모두 채우거나
더 많은 자료를 기다리기 위해 준비 시간을 무한히 늘리지 않는다. 문서의 이 원칙과 각 제품
구현의 실제 제한 시간을 구별한다.

## 구현 반영과 다음 확인

이번 변경은 기획 문서의 변경이다. 기존 실행기의 `understanding`, 전체 장면열, 원시 시간
필드, `background + original` 조립이 이 문서 수정으로 사라지는 것은 아니다.
입력 투영·프롬프트·출력·앱 연결을 각각 새 기준에 맞춰야 한다.

| 문서·자료 | 읽는 목적 |
| --- | --- |
| [Geo 장면 조립](scene-pipeline.md) · [행위와 배경](action-background.md) | 중심·출처·적격한 배경을 준비하는 기존 오프라인 구현 |
| [Geo 작성 투영 실험](how-writing.md) | 당시 시간·순서를 포함한 입력의 비교 기록. 새 장면 입력 계약으로 복사하지 않음 |
| [DEV 슬롯](https://github.com/SAJOYO/DAENGS_dev/blob/dev/docs/walk/diary-part-slots.md) · [생성](https://github.com/SAJOYO/DAENGS_dev/blob/dev/docs/walk/diary-generation.md) | 서버의 현재 계약·조립·수명주기와 기획의 차이를 확인 |
| [APP 생성·표시](https://github.com/SAJOYO/DAENGS_APP/blob/dev/docs/walk-diary-generation.md) | 원문·본문·지도·편집이 연결되는 현재 구현을 확인 |

다음 비교는 같은 장면 중심과 적격한 근거를 고정하고, 전체 세션·다른 장면·원시 시간
메타데이터를 서술에 제공하지 않는 입력으로 수행한다. 코드가 판정에 사용한 원자료는 별도로
남기고, 실제 전송한 입력·프롬프트·응답을 함께 보여준다.

확인할 것은 장면 하나의 완결성, 원래 기록의 중심성, 자연스러운 공간·행위 서술,
근거를 넘는 시간·행동·인과의 부재다. 긴 세션·관측 공백·희소 자료·사진·메모는 각각 실제
확인 범위를 밝힌다. 인용 ID 검사 통과를 문장 품질의 완료로 보고하지 않는다.

선정 방식·본문 분량·모델·호출 묶음·비용 최적화는 결과로 정한다. 의미상 장면이 독립이라는
결정만으로 ‘장면마다 HTTP 요청 하나’나 새 서버·큐·저장소를 필수 구조로 만들지 않는다.
