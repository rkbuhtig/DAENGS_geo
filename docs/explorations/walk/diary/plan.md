# 산책 일기 계획

**이번 산책 세션에서 어떤 일이 일어났는지가 이야기의 중심이다.**
LLM이 전체 세션을 먼저 이해하고, 시간순으로 장면을 하나씩 채우면서 이해를 갱신한다.
보호자가 스토리보드를 검토·편집하고 완료본을 저장한 뒤, 별도 요청으로 일기 생성 여부를 결정한다.
전체 이해와 순차 갱신은 이미 정한 제작 흐름이다. 제품 미구현을 이유로 기획 미정으로 돌리지 않는다.

미시 동선, 이번 산책의 거시 흐름, 환경, 행동핀, 과거 공간 경향을 함께 읽는다.
과거 공간 경향도 조건·분모·의미를 가진 조각이며, LLM이 이번 세션에서의 관련성과 쓰임을
판단한다. 과거 공간 경향을 미리 배제하거나 단순 배경으로 역할을 고정하지 않는다.
이 문서는 제작 방향·흐름·구현·다음 작업을 맡고, 값·계산 정의·확보 범위·추출 정책은
[자료 카탈로그](evidence-catalog.md)가 맡는다. 실행 결과는 연결된 날짜별 실험 기록에 남긴다.

2026-09-06 첨부 원문 **「산책 일기 기획.md」(303줄)**를 기존 계획과 통합했다.
Geo 구현 위치는 `bb8baf5` 기준으로 확인했다. 아래 DEV·APP 상태는 원문과 기존 계약의
2026-09-06 확인 범위이며, 이번 정리에서 운영 저장소 최신 상태를 재검증한 것은 아니다.

### 설계한 아키텍처

```text
이번 산책 자료 + 과거 공간 경향 조회 정책·계산
  → 시간·공간·출처·측정 상태를 가진 자료 조각 스냅샷
  → 전체 이해: 시간적 사건 흐름·사건 사이 연결·잠정 해석·장면 개요
  → 장면 순회: 현재 장면 작성 + 전체 이해 수정 + 앞 장면 재검토 요청
  → 전체 재검토: 원자료 대조, 필요한 장면 교체, 남은 확인 사항
  → 보호자 검토·편집·완료본 버전 저장
  → 생성 여부 선택: 스토리보드 보관 / 해당 검토본으로 일기 작성
```

첫 전체 이해는 이후 장면을 맞춰야 하는 확정 줄거리가 아니다. 사건 연결과 해석을 이후
자료 확인에 따라 수정한다. 과거 공간 경향도 이 과정에서 다른 조각과 함께 읽는다.
각 위치의 주변 정보를 따로 문장으로 바꾸는 것으로 전체 세션 이해를 대신하지 않는다.
장면의 수·경계·재료별 우선순위·분량·병합 방식을 제품 규칙으로 고정하지 않았다.
기존 selector의 조회 지점 수나 한 실험의 장면 수를 최종 정책으로 가져오지 않는다.

| 경계 | 책임과 계약 |
|---|---|
| 자료 생성 | 미시 관측, 이번 세션 전체 흐름, 환경, 행동핀, 과거 공간 경향을 준비한다. 추출 정책이 공간·기간·조건·지표·분모를 소유하고 LLM이 서사적 쓰임을 판단한다. |
| `evidence_snapshot` | 조각 `id`, `kind`, 이번 세션과의 `session_links`, `value`, `meaning`, `provenance`, `measurement_status`. 실행 동안 원자료를 유지한다. |
| `understanding` | `summary`, 근거를 참조하는 `observed_flow`·`interpretations`, `open_questions`. 장면을 읽으며 바뀌는 잠정 이해다. |
| `outline`·`scenes` | 시간순 장면 개요, 장면 문구, 관측·해석·미확인 사항, 앞 장면과의 연결. 모델이 처음에 장면 개요를 제안한다. |
| 갱신 결과 | 현재 장면과 전체 이해, `change_reason`, `evidence_ids`, 다시 볼 앞 장면 ID를 반환한다. 이전 설명이 원자료를 대체하지 않게 둘 다 전달한다. |
| 변경 이력 | 단계마다 전체 상태와 변경 이유·근거·영향 장면을 저장한다. 앞뒤 버전을 대조해 무엇이 바뀌었는지 확인한다. |
| 최종 재검토 | 원자료·장면·이해·재검토 요청을 대조하고 필요한 장면을 교체한다. 해결되지 않은 사항은 사용자 검토에 남긴다. |
| 검토·생성 | 검토는 모델 호출 없이 사용자 편집을 별도 저장한다. 생성 요청은 검토된 특정 버전과 입력 스냅샷에 묶인다. |

과거 공간 경향의 세부 계산 계약은 값·단위·조회 공간·기간·조건·분자/분모·품질·추적 정보를
갖춰야 한다. [추출 정책과 조각 계약](evidence-catalog.md#과거-공간-경향을-llm의-조각으로-만드는-정책층과-계약)에
세부 항목을 둔다. 현재 실험은 아래 조회 정책을 실행하고 조건·집계 결과·원본 지문을 조각에 보존한다.

### 실제 구현된 골격

- Pydantic 입출력 계약과 자료 조각 어댑터. 초기 `scenario.json`은 수치를 직접 작성한 시나리오이며, 새 `acquisition.json`은 GPS 생성과 조회 조건을 정의한다.
- 기존 시뮬레이터로 이번 산책 1개·과거 15개의 관측 GPS를 생성하고, 관측 export만 실제 `compute_facts`·`compute_curve`·`extract_observations`에 전달한다. 생성기의 의도·정답은 평가 폴더에 분리한다.
- 과거 관측 경로를 `paint_sheet`로 칠하고 `read_at`으로 이번 위치 주변을 읽는다. 공간 등장률·시간 질량·분자/분모·현재 통과 구간·정책과 계산 지문을 보존한다.
- 별도로 작성한 합성 행동핀과 저장된 실제 Kakao 지도 응답 6개를 연결한다. 원래 환경 조회 중심·반경·수집 시점과 자료 없음 상태를 유지한다.
- 전체 이해 1회 → 모델이 정한 장면마다 별도 호출 → 전체 재검토 1회. 각 호출에 원자료와 직전 상태를 전달한다.
- 원자료 지문, 단계별 상태 버전, 변경 이유·근거·영향 장면, 요청/응답·모델·사용량·오류 기록.
- 중단 시 마지막 완료 단계부터 재개. 자료 또는 프롬프트가 바뀌면 별도 실행을 요구한다.
- 원자료 ID, 장면 ID, 시간 범위와 시간순서의 구조 검사. 검증 실패 결과를 다음 상태로 채택하지 않는다.
- 마지막 재검토에서 장면 교체 가능. 원본 장면은 이전 버전에 남긴다.
- CLI로 검토·문구 편집·숨김, 검토 버전 확인, 생성 안 함/생성 요청. 실제 검토와 실험용 검토 입력을 구별해 저장한다.
- 같은 검토 버전의 완료된 생성 결과 재사용. 사용자 편집 보존, 숨긴 장면 제거, 생성 입력의 검토본 지문 저장.
- 저장 요청과 정확히 일치하는 응답의 오프라인 재생 및 읽기용 Markdown 출력.
- 행동핀의 원문을 유지하며 관찰 의미를 정규화하는 실험 어댑터, 동일 초안에서 기존 재검토와 별도 근거 대조 후 수정을 비교하는 실행기·검증기.

### 구현 선택과 아직 남은 것

이번 추출 정책은 저속 관측 중심·행동핀·경로 양끝을 모두 조회 대상으로 삼는다. 같은 반려견의
지정 기간 내 완료된 과거 산책을 선택하고, 반경 30m·붓 반경 8u·빈 장 포함·조건 필터 없음으로
읽었다. 시간대 조건은 `Asia/Seoul` 기준이다. 값은 fixture에 둔 실험 조건이며 제품의 추출
정책이나 장면 우선순위로 확정하지 않았다. 원본 관측으로 조각과 집계 영수증을 다시 계산해
일치 여부를 검증할 수 있다. 실제 기기 기록·운영 조회 연결은 아직 없다.

이 골격은 한 프로세스가 파일 상태를 소유한다. 운영 작업 큐·DB·앱 UI·서버 동기화는 붙이지
않았다. 모든 단계에 전체 자료를 전달하므로 큰 세션의 입력 크기와 비용은 후속 검증 대상이다.
첫 개요의 장면 수·경계는 이번 실행 동안 유지하며, 순회 중 분할·병합·재배치는 미구현이다.
재검토는 한 번 실행한다. 반복 횟수·종료 정책을 제품 정책으로 채택한 것은 아니다.

원본 정정 시 영향받은 장면만 재생성, 사용자 편집 후 의미 재검토, 사용자 재생성 옵션은 후속 작업이다.
현재 원자료 변경은 새 run으로 비교하고 기존 편집·검토본을 보존한다.

**구조 검사 통과는 의미의 정확성을 뜻하지 않는다.** 실제 실행에서는 재검토 모델도
근거가 부족한 심리·표정 서술을 그대로 두었다. 프롬프트·검토 입력·출력 계약을 바꾸며 이
문제를 실험할 기반을 만들었으며, 사실성 해결이나 제품 완성으로 기록하지 않는다.
계산 입력을 연결한 후속 실행에서도 `킁킁`이 `마킹`으로 바뀌고, 공간 등장 11/15가 행동 습관의
근거로 확대됐다. 재검토는 장면을 교체하지 않았다. 과거 공간 조각을 제거하는 대신, 주장의
근거가 실제로 그 의미를 지지하는지 대조하는 재검토 구조를 후속 실험 대상으로 삼았다.

후속 3쌍 비교에서는 냄새 맡기로 의미를 정규화하고, 본문·관찰·해석·전체 이해·질문을
항목별로 원자료에 대조한 뒤 수정하도록 했다. 대조 모델은 103개 텍스트 항목을 모두 유지로
판정했고 세 번 모두 장면 수정이 없었다. 정지 시간과 행동 지속시간의 혼동, 심리적 동기·
장소 범위의 비약도 남았다. 추가 대조 호출은 실험 구현이며 제품 정책으로 채택하지 않았다.

## LLM이 함께 읽을 재료

| 재료 | 앞서 정리한 역할 |
|---|---|
| 시간순 동선 | 이번 산책의 위치·시간·이동 흐름을 제공 |
| 행동 기록 | 킁킁 / 배설 / 짖기를 보호자가 관찰해 남김. 배설에서 마킹 의도를 추정하지 않음 |
| 특별한 순간 | 시각과 가능한 위치를 가진 자유 메모 |
| 행동 핀 | 특정 시각·위치의 관찰을 보태고, 종료 후 주변 환경을 읽을 위치의 근거가 됨 |
| 자동으로 선정한 위치·구간 | 환경과 이동 양상을 읽기 위한 후보. 사용자가 남긴 행동 기록으로 세지 않음 |
| 위치의 환경 | 그 장면의 배경을 제공. 가까운 시설의 존재를 방문·행동 원인·감정의 근거로 바꾸지 않음 |
| 과거 공간 경향 | 다른 조각과 함께 LLM이 파악하고, 이번 세션과 각 장면에서의 관련성·쓰임을 판단할 자료 |

버튼 입력 수는 기록된 관찰 수다. 실제 행동의 총횟수나 기록하지 않은 행동이 없었다는 증거가 아니다.

행동 핀을 남기지 않은 산책도 시간순 동선과 확인 가능한 배경을 재료로 삼는다. 특별한 사건이 반드시 있었다고 만들지 않는다.

2026-09-06 원문 기준 사진은 앱에 저장 기능이 있지만, 현재 행동 동기화·장면 분석·AI 입력에 자동으로 포함되는 재료로 보지 않는다. 다른 개와 인사는 기존 기획에서 기본 행동 버튼에 포함하지 않았다.

## 보호자가 검토하고 고치는 단계

LLM이 전체 흐름을 읽고 장면을 갱신한 뒤, 보호자가 구성을 확인하고 고칠 수 있도록 한다. 스토리보드 검토 완료와 최종 AI 일기 생성 사이에 보호자의 결정을 둔다. 검토 완료 자체가 일기 생성 요청은 아니다.

| 조작 | 의미 |
|---|---|
| 원본 행동·메모 수정 또는 삭제 | 기록 자체의 정정. 현재 분석과 집계에 반영해야 함 |
| 이번 구성에서 장면 숨김 | 이번 출력에 포함하지 않는 선택. 원본 행동을 삭제하는 것과 다름 |
| 장면 문구 편집 | 분석 원본과 구분해 보호자가 수정한 문구를 보관 |
| 검토 완료 | 포함한 장면과 근거를 완료본으로 저장 |
| AI 일기 생성 요청 | 완료한 구성으로 한 편의 일기를 만드는 별도 요청 |

새 분석이 도착해도 사용자 편집과 이미 저장한 완료본을 자동으로 덮어쓰지 않는다. 원본이 바뀌면 편집을 보존한 채 재확인이 필요한 상태를 구분한다.

geo의 LLM 골격은 제품 API에 연결하지 않았다. 검토본 서버 동기화와 다른 기기 복원,
일기 생성·열람의 제품 연결, 운영 DB 적용·실기기 전체 흐름 확인이 남아 있다.
기존 규칙 selector의 세부 수치는 그 구현을 설명하는 값이며 새 LLM 장면 정책으로 가져오지 않는다.

제품의 요청·응답과 저장 동작은 [실데이터 이식 계약](../../../contracts/walk-storyboard-live.md),
[장면 교환 v2](../../../contracts/walk-storyboard-candidates-v2.md),
DAENGS_dev·DAENGS_app의 `docs/walk-storyboard-live.md`에서 확인한다.

## 아직 정하지 않은 일기 정책

장면을 어떤 기준으로 나누고 고를지, 순회 중 합치거나 나눌 수 있을지, 무엇을 얼마나
서술할지, 공간 경향을 어느 장면에 어떤 표현으로 보탤지는 아직 확정하지 않았다.
자료 조각이 있다는 이유만으로 장면 우선순위나 성격·감정 해석을 정하지 않는다.

## 다음 작업

1. 항목별 대조가 전부 유지로 끝난 원인을 검토한다. 문단 안의 주장을 나누고 원자료의 값·필드·시간·공간·행동 범위에 대응시킨 후 판정하는 구조를 다음 비교 후보로 둔다. 아직 효과를 검증한 구현은 아니다.
2. 핀 없음·관측 공백·왕복·재방문 등 여러 산책과 사용자 편집 사례로 확인한다. 합성 자료와 별도로 실기기 관측·환경 자료를 확보해 같은 경로에 연결한다.
3. 추출 대상·조건·반경을 바꿔 조각의 의미와 분모가 보존되는지 확인하고, 환경 조회 자료의 범위를 넓힌다.
4. 실험 결과를 바탕으로 장면 경계 갱신, 큰 입력의 비용, 제품 API·저장·앱 연결을 구체화한다.
