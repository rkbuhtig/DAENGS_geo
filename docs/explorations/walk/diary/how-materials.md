# HOW 풀에 넣을 움직임 재료

**HOW는 정제된 동선의 움직임 형태이고, WHERE는 공간 소속·관계와 그 변화다.**
이 작업은 HOW 후보를 만드는 단계다. 공간 경계 통과, 장소 진입, 상권 전환을 HOW로 분류하지 않는다.
이 추출기 자체는 LLM 호출·슬롯 교체·스탬프 생성을 하지 않는다.
후속 [HOW 스탬프 조립](how-stamps.md)이 산책 종료 후 기록 중심과 제한된 직선 맥락을 구성한다.

## 이번 구현

[how_materials.py](../../../../scripts/spikes/diary_storyboard/how_materials.py)는
`HowSource → 기존 compute_facts → CanonicalTrail → HOW 조각`을 계산한다.
`extract_how(trail, policy)`로 이미 계산된 공용 동선을 직접 받을 수도 있다.
운영 `app` 코드와 기존 스탬프 실험을 수정하지 않았다. 현재 HOW 정책은 Geo 실험 디렉터리에 있다.

1. 기존 계산기가 거른 좌표·시간 역행·GPS 단절·명시적 pause 경계를 유지한다.
2. HOW용 정확도·비현실적인 구간 속도 검사를 추가한다. 거절한 양쪽을 다시 잇지 않는다.
3. 좁은 범위에 일정 시간 머문 후보와 시간 간격을 두고 본 이동량을 계산한다.
4. 체류 내부의 흔들림을 관측 대표점 하나로 줄이고, RDP로 작은 형태 변화를 단순화한다.
5. 충분히 긴 구간의 직선 형태·좌우 방향 전환·방향 반전·직전 구간 되짚기를 추출한다.

대표점과 단순화 꼭짓점은 모두 실제 입력의 `client_seq`를 참조한다. 새 좌표를 만들어 핀으로 쓰지 않는다.
형태 계산용 평면 근사는 짧은 산책을 위한 로컬 좌표계다. 표시용 형태 거리와 기존 산책의 이동거리·동선 offset은 별도 값이다.
원본 GPS·앱 표시 동선을 이 실험이 덮어쓰지 않는다.

## 만들어지는 조각

| kind | 의미 | 추가 조건 |
| --- | --- | --- |
| `local_stay` | 좁은 범위에서 관측된 머무름 | 범위·시간·최소 표본 수와 낮은 시간 간격별 이동량 |
| `straight_run` | 해당 해상도에서 직선에 가까운 이동 구간 | 충분한 길이, 원래 점들의 선분 이탈 거리 확인 |
| `turn` | 앞뒤 긴 구간의 뚜렷한 진행 방향 변화 | `left`, `right`, `reverse`; 양쪽 구간 길이·각도 근거 |
| `retrace` | 직전 큰 구간을 되짚는 형태 | 방향 반전 + 돌아오는 관측점들이 직전 선분의 허용 폭 안에 있음 |

직선 구간과 회전은 서로 배타적인 분류가 아니다. 하나의 큰 모서리에서 앞·뒤 직선 조각과 회전 조각을 함께 만들 수 있다.
머문 뒤 꺾이는 경우도 체류와 회전을 함께 남긴다. 이 후보들을 몇 장면에 실을지는 스탬프 정책의 책임이다.

모든 조각은 `axis=how`, `status=candidate`, `subject=recording_device`다.
`support`에는 원본 시각·시퀀스 구간·canonical chain·추가 HOW 단절 구간이 있고,
`anchor`에는 원본 대표점의 시각·좌표·동선 offset이 있다. `metrics`에는 판정에 사용한 수치,
`quality`에는 관측 수·정확도·정확도 미상 표본 수를 남긴다.
`ref`는 원본 해시·기존 계산 버전·HOW 정책·재료 내용에 연결된다.
강아지의 행동이나 보호자가 그렇게 움직인 이유를 추정하지 않는다.

## 초기 문턱값

이 값은 **합성 동선에서 확인한 초기 정책**이며 실기기 최적값이 아니다.

| 항목 | `how-geometry-v1` 기본값 |
| --- | --- |
| HOW 입력 정확도 상한 | 20m; 정확도 미상은 별도 표기 |
| HOW 입력 구간 속도 상한 | 4m/s; 초과 시 HOW 연속열 분리 |
| 형태 단순화 허용 폭 | 8m와 해당 연속열 정확도 중앙값 중 큰 값 |
| 국소 체류 | 관측 범위의 바운딩 박스 대각선 20m 이내, 30초 이상, 5점 이상 |
| 체류의 이동량 보조 조건 | 약 10초 간격의 관측점 사이 거리 합 / 구간 시간 ≤ 0.4m/s |
| 직선 구간 | 40m 이상이며 단순화 허용 폭의 2배 이상 |
| 뚜렷한 회전 | 앞뒤 각 30m 이상이며 허용 폭의 2배 이상, 방향 차이 45° 이상 |
| 방향 반전 | 방향 차이 150° 이상 |
| 되짚기 | 앞뒤 각 40m 이상, 돌아오는 점들이 직전 선분에서 10m 또는 단순화 폭 이내 |

체류 구간은 이 공간·시간 해상도에서의 관측 창이다. 접근·출발의 일부가 포함될 수 있어 실제 정지 시작·종료를 확정한 값이 아니다.
구간 샘플링 기반 이동량도 원시 속도나 행동 지속시간과 같지 않다. 바운딩 박스 기준은 회전 불변의 정밀 체류 영역 추정이 아니다.

## 회전의 시각과 판정 가능 시각

90초 지점에서 꺾여 180초까지 이어지는 동선을 보고 회전을 판정했다면:

```text
anchor.at       = 꺾인 곳의 원본 관측 시각 (예: 90초)
support         = 방향을 계산한 앞뒤 관측 범위 (예: 0~180초)
판정 가능 시각  = support.ended_at 이후
```

회전에 180초가 걸렸다는 뜻이 아니다. `time_meaning=observed_support_window`로 남긴다.
이 방식은 완료된 산책을 읽는 배치 추출이며 실시간 검출기가 아니다.
나중에 지도가 어느 지점을 강조할지는 anchor를 쓰고, 온라인 슬롯에 언제 들어갈 수 있는지는 자료 가용 시점을 따로 본다.

`query_how(catalog, at=..., chain_index=..., lookback_s=...)`는 해당 시점까지 관측이 완료됐고
최근 범위에 해당하는 후보만 돌려준다. 대표 시점만 보고 미래 구간의 회전을 먼저 내보내지 않는다.
조회 결과에는 수치·시간·근거 참조가 있고 좌표 배열은 없다. 이 조회 자체가 후보의 카드 선택이나 스탬프 생성은 아니다.

## 실험 결과와 발견한 실패

[how_demo.py](../../../../scripts/spikes/diary_storyboard/how_demo.py)에 좌표·시각을 결정론적으로 만드는 합성 10조건이 있다.
원점은 실제 사용자와 무관하며 모든 입력을 mock으로 표시한다. 소스 JSON·계산 JSON·SVG·검토 HTML을 함께 저장한다.

| 합성 조건 | 최종 검출 |
| --- | --- |
| 직선 + 작은 좌표 흔들림 | 직선 1, 회전 없음 |
| 뚜렷한 우회전 / 좌회전 | 각각 직선 2, 해당 방향 회전 1 |
| 제자리 + 좌표 흔들림 | 국소 체류 1, 회전 없음 |
| 머문 뒤 우회전 | 직선 2, 국소 체류 1, 우회전 1 |
| 같은 구간 되짚기 | 직선 2, 반전 1, 되짚기 1, 체류 없음 |
| 평행한 다른 쪽으로 돌아오기 | 직선 2, 우회전 2, 되짚기 없음 |
| 완만한 방향 변화 | 직선 조각 2, 큰 회전 없음 |
| 짧은 꺾임 | 현재 크기 문턱을 넘는 조각 없음 |
| 모서리에서 GPS 공백 | 서로 다른 chain의 직선 2, 공백을 넘는 회전·체류 없음 |

첫 구현은 **왕복 끝부분을 체류로 오인**했다. 좁은 공간에 30초 이상 들어오는 왕복 창이 범위·시간 조건을 만족했기 때문이다.
그 창을 대표점 하나로 압축하면서 되짚은 거리도 약 80m에서 69.78m로 줄어들었다.
이를 맞는 결과로 받아들이지 않고 시간 간격별 이동량 조건을 추가했다. 같은 입력에서 오인이 사라졌고,
실제 체류 fixture와 머문 뒤 회전은 유지됐다. 테스트에 두 조건을 함께 남겼다.
이 사례는 “정제 후 모양만 읽기”에서도 체류 압축 정책이 다른 움직임의 모양을 훼손할 수 있음을 보여준다.

## 실행·검증

```powershell
uv run python -m scripts.spikes.diary_storyboard.how_demo --out ../diary-lab/how-materials-01
uv run pytest tests/spikes/diary_storyboard/test_how_materials.py tests/walk/test_walk_facts.py -q
```

출력 `index.html`에서 동선과 표시 지점을 보고 ‘계산된 재료’를 펼쳐 원자료 참조·수치를 읽는다.
`{case}/source.json`이 입력, `{case}/how.json`이 HOW 후보 카탈로그, `report.json`이 조건별 수량이다.
기존 출력 디렉터리를 덮어쓰지 않는다.

최초 표적 검사 31개 중 왕복 회귀 1개가 실패했고, 나머지 30개는 통과했다.
수정 후 영향받은 HOW 검사 18개를 다시 실행해 모두 통과했다. 기존 산책 계산 검사 13개는 첫 실행에서 통과했으며 수정하지 않았다.
표적 검사는 방향 부호, 작은 흔들림, 짧고 완만한 꺾임, 체류·회전 공존, 왕복과 평행 이동,
GPS 공백·정확도 거절·속도 이상치, 표본 간격 변경, 참조 보존·시간대·자료 가용 시점을 포함한다.
실제 기기·실제 산책 정확도, 전체 저장소, LLM 문구 품질을 검증한 결과는 아니다.

## 다음 경계

- 카탈로그와 WHEN·WHAT의 원본 참조 연결은 [후속 조립](how-stamps.md)에서 구현했다. WHERE 전환과의 결합은 남아 있다.
- 산책 종료 후 스탬프별 직선 맥락 용량을 별도 정책으로 두었다. 실시간 HOW 슬롯의 만료·교체 전략은 후속이다.
- 실제 보존 동선 어댑터와 실기기 표본으로 해상도·체류·큰 회전 문턱을 검토하기.

완만한 곡선의 누적 회전, 여러 모서리를 지나 돌아오는 경로의 되짚기, 국소 반복 이동·배회는 아직 분류하지 않는다.
대표 공간 라벨·경계 통과는 WHERE에 남는다. 이 자료를 원좌표가 있는 단계에서 계산·보존하는 운영 연결도 별도 작업이다.
