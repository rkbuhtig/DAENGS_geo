## 과거 공간 경향을 LLM의 조각으로 만드는 정책층과 계약

과거 공간 경향은 조회 조건에 따라 다른 결과가 나온다. 어떤 조건으로 어떤 공간 경향을 뽑을지 정하는 정책층과, 계산 결과를 LLM이 해석할 수 있는 조각으로 전달하는 계약이 필요하다.

이번 세션의 위치·구간·기록을 기준으로 정책층이 조회 공간·기간·조건을 정하고,
해당 산책의 셀로판·공간 관측에서 지표를 계산한다. 조건·수치·근거·측정 상태를 가진
조각을 만든다. 장면 작성에는 그 장면에 적격한 의미만 투영하며, 전체 일기에서 필요한
자료는 별도로 참조한다. 이 계산 계약이 전체 세션 이해나 장면 순회를 요구하지 않는다.

### 정책층이 정할 것

| 정책 대상 | 정해야 할 내용 |
|---|---|
| 추출 계기와 대상 위치 | 이번 세션의 어떤 위치·구간·기록을 기준으로 과거 공간을 조회할지 |
| 공간 범위 | 한 좌표의 주변, 특정 영역, 경로 주변 등 무엇을 같은 공간으로 읽을지 |
| 과거 산책의 선택 조건 | 대상 반려견, 기간, 이번 세션과의 시간 경계, 날씨·낮밤 등의 조건 |
| 계산할 공간 경향 | 방문 비율, 공간 이용 비중, 국소 시간 질량, 조건별 분포 차이 등 어떤 질문을 계산할지 |
| 비교 조건 | 비교하는 경우 어느 공간·기간·조건을 비교 기준으로 삼을지 |
| 관측 품질과 분모 | 빈 장·관측 공백·측정 세대 차이를 어떻게 다루고, 어떤 산책을 계산에 포함할지 |
| 조각 구성 | 같은 위치의 여러 지표나 겹치는 결과를 어떻게 묶어 전달할지 |

이 층은 조회와 계산의 기준을 소유한다. 제품의 수치 문턱·조회 기간·반경·조각 개수는 아직 정하지 않았다. 실험에는 저속 중심·핀·경로 양끝, 지정 기간, 30m 읽기 반경·8u 붓·빈 장 포함·Asia/Seoul 시간대 조건을 fixture로 두었다. 장면 작성자는 해당 장면에 사용할 수 있도록 투영된 조각 안에서 표현상 쓰임을 판단한다.

### 보존할 조각 계약과 작성용 투영

아래는 공간 경향 전용 계약에 보존할 정보다. 이 봉투 전체를 장면 LLM에 전달하지 않는다.
시간이나 범위를 생략하면 잘못된 뜻이 되는 자료는 그대로 투입하지 않고 작성 적격성을 검토한다.
geo 골격에는 공통 자료 조각 봉투를 구현했고,
현재는 관측 GPS에서 실제 계산한 값과 실험 조회 조건을 `provenance`와 `value`에 보존하고
원본에서 재계산해 검증한다. 모든 지표를 포괄하는 제품 스키마는 후속 설계 대상이다.

| 계약 항목 | 담을 내용 |
|---|---|
| 조각 식별 | 조각 ID, 종류, 계약 버전 |
| 이번 세션과의 연결 | 어느 위치·구간·기록을 기준으로 추출했는지 |
| 공간 정의 | 실제 조회한 중심·반경·영역·경로 범위 등 |
| 조회 조건 | 대상 반려견, 기간, 조건 필터, 조회 기준 시점 |
| 계산 결과 | 지표 이름, 값, 단위, 정규화 방식 |
| 결과의 근거 규모 | 선택한 산책 수, 관측이 기여한 산책 수, 지표별 분자·분모 |
| 비교 근거 | 비교 결과라면 양쪽 조건·값·표본 규모 |
| 결과의 의미 | 예를 들어 실제 시설 출입 횟수인지, 붓이 닿은 공간의 등장 비율인지 구별할 설명 |
| 측정 상태 | 정상 계산·자료 없음·관측 부족·부분 결과·실패 등을 구별할 상태와 사유 |
| 추적 정보 | 참조한 자료, 추출 정책 버전, 측정·집계 버전과 계산 조건의 지문 |

예를 들어 ‘자주 가는 곳’이라는 문구로 집계를 대체하지 않고, **어떤 영역을 어떤 기간·조건으로 조회했으며 선택 산책 중 몇 회에서 어떤 방식으로 나타났는지**를 원본 조각에 보존한다. 이 범위를 유지하면서 장면 또는 전체 일기에 쓸 수 있는지는 각 작성 입력에서 판단한다. ‘자주’라고 부를 기준이나 최종 표현을 이 예시로 확정하지 않는다.

### 기존 구현과 연결되는 부분

2026-09-06 원문이 확인한 dev의 공간 일기 조회에는 이미 산책 선택 조건, `visit_rate`·`walk_utilization`, 분자·분모, 조회 영수증과 계산 세대 정보가 있다. geo에는 국소 영역 읽기와 더 다양한 공간 지표가 있다. 이 계산과 조회 계약을 활용할 수 있다.

geo 실험에 **이번 세션에서 어떤 공간 질문을 만들지 정하는 추출 정책**과 **그 조회 결과를 이번 세션의 위치·구간·기록과 연결해 LLM에 전달하는 조각 계약**을 연결했다. 국소 원형 조회를 대상으로 한 구현이며, 지도용 field 응답만으로 조각 계약 전체가 완성됐다고 보지는 않는다.

## 이번 산책 안에서 순서대로 읽을 수 있는 조각

| 조각 | 꺼낼 수 있는 값 | 일기에 전달할 수 있는 내용 |
|---|---|---|
| 시간순 위치 | 좌표, 시각, 순번, 연속 구간 번호 | 어떤 위치가 먼저·나중에 관측됐는지 |
| 두 관측점 사이의 구간 | 양 끝 좌표·시각, 거리, 시간 차이 | 어느 위치에서 어느 위치까지 관측이 이어졌는지 |
| 구간 속도 | 구간 거리 ÷ 시간 차이 | 해당 구간의 평균적인 이동 속도. 정확한 순간 속도와 구분 |
| 정지 이벤트 | 시작·끝 시각, 지속시간, 대표 좌표, 관측점 수, 정확도 | 현재 계산 기준에서 정지로 잡힌 구간과 위치 |
| 저속 관측 구간 | 시작·끝 시각, 지속시간, 대표 좌표, 연속 구간 번호 | 어느 시점·위치 주변에 저속 관측이 이어졌는지 |
| 저속 구간의 이동거리 합 | `path_m` | 그 후보 구간 안에서 관측 좌표를 따라 움직인 거리 |
| 저속 구간의 시작·끝 거리 | `net_m` | 구간을 거치며 시작점에서 얼마나 멀어졌는지 |
| 저속 구간의 퍼진 범위 | `span_m` | 대표 중심 주변에서 관측점이 얼마나 퍼져 있는지 |
| 저속 구간의 측정 조건 | 관측점 수, 정확도 중앙값, 단절 경계 인접 여부 | 후보를 해석할 때 함께 볼 측정 근거 |
| 관측 공백 | 공백 시작·끝 시각, 경과 시간, 양 끝 위치의 거리 | 언제부터 언제까지 중간 움직임을 알 수 없는지 |

`path_m`, `net_m`, `span_m`은 같은 저속 후보에 함께 붙어 있다. 길게 전진한 후보와 좁은 범위에서 움직인 후보를 비교할 재료로 사용할 수 있다. 이 값만으로 냄새 맡기·탐색·불안 같은 행동 의미가 확정되는 것은 아니다.

dev는 원본 좌표를 보존한다. 분석 중 생성되는 모든 segment가 별도 영속 배열로 저장되는 것은 아니므로, 전체 구간열이 필요하면 원본에서 재계산한다. app에는 완료 동선의 구간 속도를 계산하고 선택한 경로 지점에서 표시하는 구현이 있다.

|---|---|---|

셀로판만으로는 이번 산책 안의 방문 순서·진행 방향·왕복 횟수를 복구할 수 없다. 이 정보는 시간순 위치와 구간 자료에서 읽는다.

## geo에 구현돼 있어 가져다 쓸 수 있는 추가 계산

아래는 2026-09-07 Geo 기준 코드에서 확인한 계산이다. dev/app에 모두 연결된 기능이라는 뜻이 아니다. geo의 계산 함수 또는 서비스 구현을 활용할 수 있는 조각이다.

## 아직 사용할 수 있는 결과로 세지 않는 것

기기 속도는 app에서 수신하지만 현재 원본 저장·서버 전달에는 빠져 있다. 속도 정확도를 활용한 추정, 종료 후 스무딩, 가감속 추정, 속도별 경로 색상은 추가 구현·검증 대상이다. 현재 확보된 조각과 혼동하지 않는다.


## Geo에서 확인한 계산·연결 근거

| 근거 | 확인할 경계 |
|---|---|
| [facts](../../../../app/features/walk/facts.py), [모델](../../../../app/features/walk/models.py) | accepted/moving 거리·시간, moving 평균 속도, canonical point·segment·gap |
| [미시 관측](../../../../app/features/walk/observation.py) | `path_m`은 지터를 포함한 구간 거리 합, `net_m`은 양 끝 변위, `span_m`은 중심에서 가장 먼 점까지의 거리. 행동 판정값이 아님 |
| [측정 영수증 생성](../../../../app/features/walk/capsule.py), [영수증 계약](../../../../app/features/spatial_diary/contract.py) | 점의 수·품질·공백을 계산 결과와 함께 전달 |
| [공간 통계](../../../../app/features/territory/spatial_stats.py), [공간 일기 조회](../../../../app/features/territory/spatial_diary.py) | 선택 산책과 기여 산책의 분모, 빈 장, 계산 세대와 조회 영수증 |
| [Geo 어댑터](../../../../scripts/spikes/diary_storyboard/geo_adapter.py), [조회 recipe](../../../../scripts/spikes/diary_storyboard/fixtures/acquisition.json) | 어떤 질문을 실제로 계산해 자료 조각에 넣는지 |
| [자료 계약](../../../../scripts/spikes/diary_storyboard/contracts.py), [재계산 검증](../../../../scripts/spikes/diary_storyboard/verify_acquisition.py) | 자료 ID·이번 세션 연결·값·의미·출처·측정 상태와 재계산 지문 |
| [환경 캐시 어댑터](../../../../scripts/spikes/diary_storyboard/cached_environment.py) | 원래 조회 중심·반경·수집 시점과 현재 연결 위치를 구별 |

특히 Geo의 `visit_rate`는 선택 산책 수를 분모로 삼고, `walk_utilization`은 시간 질량이
양수인 각 기여 산책을 합 1로 정규화한 뒤 기여 산책 수로 평균한다. 따라서 빈 장이 있을 때
두 분모를 같은 숫자로 간주하지 않는다. `time_utilization`은 전체 시간 질량을 분모로 삼는다.
저속·정지 지속시간도 보호자가 기록한 행동의 지속시간과 구별한다.
세션 곡선의 `still_s`는 정지 후보 시간으로, 정지 이벤트의 지속시간 문턱을 적용한
`WalkFacts.stop_s`와 다르다. 시간 10구간은 현재 계산기의 선택이며 일기의 장면 개수가 아니다.

## 원문이 참조한 외부 구현과 실험
