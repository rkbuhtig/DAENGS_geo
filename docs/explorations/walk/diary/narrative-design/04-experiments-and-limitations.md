# 실험과 실패 기록

**이전 호출 성공이나 구조 검사 통과를 최신 서술 기획의 검증 완료로 이어받지 않는다.**
첨부 파일에서 확인한 과거 응답, 작업을 이어받아 여기서 실행한 응답, 사용자가 붙여준 다른
환경의 보고를 구별한다. 실제 모델 문장은 [출력 원문 모음](07-model-outputs.md)에 따로 남긴다.
이번 문서 작성 중 새로운 API·LLM 실험은 실행하지 않았다.

## 1. 근거와 확인 범위

| 기록 | 확인한 것 | 확인했다고 말할 수 없는 것 |
| --- | --- | --- |
| 첨부 `scene-context-comparison.zip` | run-01–03, narration-04–07의 저장 입력·프롬프트·응답·검사 기록 | 이 문서 작성 중 우리가 동일 요청을 다시 실행했다는 주장 |
| 앞선 대화 H119의 에이전트 설명 | 초기 장소 전용 입력과 대표 시설 제한을 사용했다는 보고 | 설명만으로 모든 초기 요청의 원본을 독립 검증했다는 주장 |
| 여기서 저장한 run-08–13 | 실제 HTTP 생성 요청과 확보 응답 또는 실패 | 응답 없는 요청의 공급자 처리·청구 상태, 운영 앱 연결 |
| 사용자 제공 Windows 호출 기록 | 다른 실행 환경에서 네 API가 성공했다는 보고 | 여기서 같은 데이터가 반환됐다는 주장 |
| 여기서 저장한 네 API 진단 결과 | 각 요청에서 502 HTML을 받음 | 인증키가 틀림, 공급자가 모든 환경에서 중단됨 |

첨부 DB·원래 사용자 식별자·정확한 동선 전체를 문서 저장소로 복사하지 않는다. 이 기록에는
설계 판단에 필요한 문장과 필드 구조, 결과 범위, 재현 파일 이름·해시를 남긴다.

## 2. 같은 산책에 실제로 있던 재료

기준 산책은 2026-09-10 한국시간 20:47:24–20:52:35의 저장 보드다. 이 시각은 실험 식별을
위한 기록이며 **현재 장면 LLM에 전달할 입력 예시가 아니다.**

전체 보드에는 시작·종료 경계와 세 경로 보충 지점, 동선 집중 관측 장면으로 여섯 장면이 있다.
서술 대상은 위치가 있는 중간 네 장면이었다. 이 표본에는 사용자 사진·메모와 환경 근거가 없다.
풍부한 행동 핀·특별한 순간·여러 반려견 행위자 사례를 검증한 표본으로 일반화하지 않는다.

네 장면의 부가 재료는 시설 12건, 주소 참고 4건, 상대 저속 동선 배경 1건이었다.
동선 집중은 중심이고 상대 저속은 별도 배경이다. 둘은 같은 사실이 아니다.
`original`의 ‘산책길의 이 지점을 지났다’와 ‘이 구간에서는 동선이 한곳에 모였다’는 자동
기본 문구다. 사용자가 직접 쓴 특별한 순간 원문으로 취급하지 않는다.

## 3. 시간과 ‘몇 번째 장면’은 실제로 어떻게 들어갔나

첨부 run-03의 `writer-input.json` 최상위 키는 다음과 같다.

```text
revision
display_timezone
scene_sequence
scenes
```

`scene_sequence`에는 시작·중간 네 장면·종료 순서로 여섯 항목이 들어 있다. 각 항목은
`scene_id`, `kind`, `event_at`을 갖는다. 생성 대상 `scenes`에는 각 장면의 `original`,
`center`, `evidence`가 있으며, `center`에도 `event_at`, `time_basis`와 관측 정보가 있다.
경로 지점에는 `continuity_block`, `observed_route_m` 같은 계산 자료도 들어 있었다.

따라서 모델은 **전체 배열의 순서와 각 시각, 경계 종류를 읽을 수 있었다.** 숫자형 ‘세 번째’
필드 하나가 있어야만 순서를 추론할 수 있는 것은 아니다. 이 확인은 모델 내부에서 실제로
어떤 신호를 사용했는지 입증하는 것이 아니라, 그런 판단이 가능한 입력이 있었다는 뜻이다.

후속 narration-04–07에는 `walk_position`, `card_context`, `writing_materials` 등의 설명이
추가되거나 사용됐다. run-09에는 `reading_facts`의 경과 시간·관측 경로 위치 설명도 들어갔다.
‘산책 시작 후 약 1분’은 그 실제 응답에 나타났다. 시간·순서가 슬롯 용량 밖의 중심 맥락으로
들어갔다고 해서 서술에 영향을 주지 않는 것은 아니다.

현재 결정에서는 이 시간열·경과·앞뒤 맥락을 새 장면 작성 입력으로 복사하지 않는다.
내부 원본·적격성 판정과 모델 투영을 나눠야 하는 이유가 이 실험에서 구체적으로 드러났다.

## 4. 장면 서술과 행동 서술은 당시 어떻게 합쳐졌나

run-01–03의 모델 응답은 장면별 `background`와 `evidence_ids`였다. 당시 표시 경로는
생성 배경 뒤에 기본 `original`을 붙이는 방식이었다.

```text
표시 본문 = background + 줄바꿈 + original
```

즉 **모델 출력과 원문은 실제로 구별돼 있었고, 조립된 하나의 본문으로 표시했다.** 하지만
이는 사용자가 요청한 장면 서술과 행동 서술을 각각 완성된 표현 역할로 설계했다는 뜻이 아니다.
자동 기본 문구를 뒤에 붙이는 것만으로 원문 중심의 읽기 흐름이 보장되지 않았다.

반면 narration-04–07과 여기서의 run-08–13은 비교용 전체 `body`를 반환하도록 했다.
사용자에게 보여준 문장을 단순히 설명 편의로 두 필드에서 생략한 것이 아니라, 실험의 출력
계약 자체가 바뀐 경우가 있다. 기존 제품의 `background`에 그 `body`를 그대로 넣으면 원문이
중복되거나 기존 검증·편집 계약과 충돌할 수 있으므로 호환 패치라고 보고하지 않았다.

인칭 혼용도 구조적 연결과 표현 선택을 함께 봐야 한다. 배경은 지역을 설명하고 기본 원문은
주어가 생략된 행위·관측 문장을 붙이므로 서로 다른 시선이 이어질 수 있었다. 그러나 문법적
주어 생략만으로 화자가 보호자인지 반려견인지 확정되지는 않는다. 모델이 그 차이를 의도적으로
설계했다는 증거도 없다. 현재는 [서술 역할 기준](02-narration-contract.md)으로 다시 평가한다.

## 5. 첨부 run-01–03: 시설 문구로 좁아진 세 번의 결과

| 실행 | 출력에서 확인한 특징 | 판단 |
| --- | --- | --- |
| run-01 | 번화한 거리·상점가·식당 밀집 중심, 여러 시설명 | 실제 근거보다 강한 공간 성격. 산책 장면보다 지역 소개에 가까움 |
| run-02 | 각 시설 하나와 거리. ‘산책로를 이어가고’가 남음 | 구성은 좁아졌고 공간 과장은 남음 |
| run-03 | ‘현재 장소 자료에는 … 등록돼 있다’가 세 장면에 반복 | 사실 범위를 알리는 문구에 가까우며 자연스러운 장면 서술의 개선 완료가 아님 |

이전 에이전트는 run-03을 별도 앱의 비교용으로 적용했다고 보고했다. 이것은 실제 사용자
품질 승인이나 이 Work에서 재검증한 제품 적용이라는 뜻이 아니다. H119의 대화와 저장 응답을
대조하면, 보고된 문장이 실제 `background`에 존재하는 것은 확인할 수 있다.

핵심 실패는 두 가지였다. 처음에는 산책 중심을 충분히 주지 않은 장소 전용 과제로 좁혔고,
그 뒤에는 오류를 줄이려고 대표 시설과 문장 틀을 강제했다. 글의 목적과 표현 선택이 사라진 채
정확한 시설 설명만 남았다. 정확성과 자연스러운 서술을 함께 평가해야 한다.

## 6. 첨부 narration-04–07: 독립 장면을 말했어도 입력 경계는 달랐다

첨부 ZIP에는 앞선 대화의 세 번 외에도 네 번의 후속 응답과 프롬프트가 들어 있다.
각 receipt는 원본 불변·장면/인용 구조 통과를 기록하면서 의미 품질은 구조 검사로 정하지
않는다고 명시한다. 이 문서에서는 응답 문장을 다시 읽어 다음 문제를 구별했다.

| 실행 | 프롬프트에서 바뀐 것 | 실제 출력의 한계 |
| --- | --- | --- |
| narration-04 | 시설 변환 대신 전체 `body`, 원래 중심·산책 흐름 사용 | ‘걷기 시작했다’, ‘산책로’, ‘계속해서’ 등 출발·길 종류·연속성 확장 |
| narration-05-standalone | 단독 작은 일기 목적과 `card_context` 설명 | ‘천천히’, ‘차분하게 밤공기’, ‘익숙한 길목’, ‘불빛’, ‘주변을 살피며’ 등 없는 양상·감각·행동 |
| narration-06-grounded | 논픽션, 중심/시간/선택 근거를 읽는 순서로 정리 | 시설 목록과 관측 보고가 다시 많아지고 ‘산책로’가 남음 |
| narration-07-revision | 이전 초안을 출발점으로 다듬음 | ‘산책을 시작했다’와 ‘계속 걸었다’가 남고, 동선 집중 중심이 상대 저속으로 대체됨 |

`standalone`이라는 실행 이름과 독립 장면이라는 지시만으로 최신 기획을 구현한 것이 아니다.
당시 입력에는 전체 시간순 맥락이 남아 있었다. narration-07 프롬프트의 ‘사용자가 더 낫다고
평가한 초안’이라는 표현도 그 실행의 지시문이며, 이 문서가 최신 품질 승인을 선언하는 근거로
삼지 않는다. 비교 선호와 제품 채택은 다른 판단이다.

이후 같은 원문·중심·선택 근거를 고정하고 전체 본문 서술을 비교했다. 실제 생성 HTTP 요청은
여섯 건이며 응답 확보 세 건, 시간 초과 두 건, HTTP 429 한 건이다.

| 실행 | 변경 | 결과 | 호출부터 처리 종료까지 |

이 시간은 네트워크 연결·대기·처리를 포함하는 해당 실험 환경의 경과다. 모델 자체의 추론
시간이나 Android 준비 시간과 같지 않다. 이 적은 표본으로 모델 우열·운영 실패율·지연 분포를
결론 내리지 않는다. 시간 초과 요청이 공급자에서 끝났거나 청구됐는지는 여기서 확인하지 못했다.

run-08/09는 구조 검사를 통과했지만 의미 문제가 남았다. run-12는 존재하지 않는 근거 ID를
인용해 구조에서도 실패했다. **네 장면 모두 사실 범위와 서술 품질을 만족하는 한 세트는
확보하지 못했다.** 이 결과를 제품 코드·앱·발행본에 적용하지 않았다.

### 7.1 run-09에서 실제 사용한 잘못된 방향

다음은 당시 실제 프롬프트의 일부다. 현재 지시가 아닌 **철회된 실험 입력의 증거**다.

> 각 장면의 reading_facts에는 코드가 center와 저장된 시각을 풀어 쓴 사실이 있다. scene_center의 중심을 먼저 이해하고, time_in_walk 또는 related_observations와 관계지어 장면을 구성한다.

그 결과 중 하나는 다음과 같다.

> 산책 시작 후 약 1분이 지나 역삼동의 한 지점을 지났다.

이 표현을 당시에는 시간 활용으로 분석했으나, 이후 사용자 지적으로 **시간 맥락을 늘리는
방향을 현재 장면 생성의 개선안에서 철회**했다. 오래된 비교 보고서 마지막의 ‘중심·시간 관계를
읽기 좋은 형태로 전달’이라는 다음 작업도 그대로 이어받지 않는다.

run-08→09에서는 입력 설명과 프롬프트를 함께 바꿨으므로 효과를 둘 중 하나로 분리할 수 없다.
run-09→10/11의 모델 비교도 응답 누락 때문에 우열을 판단할 수 없다.

## 8. 실제 지정 API 실험과 중단

사용자의 요구는 실제 API의 필드를 받아 한 좌표의 서술 골격에 분류하고, 다른 좌표에도 같은
분류가 적용되는지 확인하는 것이었다. 실제 지정 API가 아닌 대체 재료로 이 요구를 충족했다고
보고하면 안 된다.

### 8.1 중단된 대체 시도

처음 기존 환경 키로 시도한 공공 요청들은 502였다. 이어 Kakao에 세 좌표의 주소·공원 검색·
카페·음식점을 조회한 열두 요청은 실제 응답을 받았다. 도곡동·역삼동·성수동 좌표에서 서로 다른
결측·검색 결과·페이지 범위를 확인했고, 과거 공공 스냅샷도 참고했다.

**Kakao 조회는 실제 호출이었지만 사용자가 요청한 지정 공공 API 실험의 대체로는 거절됐다.**
과거 스냅샷은 재생 자료이지 새 좌표의 실제 호출 결과가 아니다. 이 결과를 최신 서술 골격의
검증 성과나 사용자가 채택한 수집 경로로 기록하지 않는다. 다음 에이전트는 임의로 이 경로를
재개하지 않는다.

### 8.2 사용자가 제시한 다른 환경의 성공 보고

사용자는 Windows에서 상가·도시공원·하천의 데이터 1건과 SGIS 토큰→시도 목록 조회가
성공한 로그를 붙여줬다. 보고된 전체 건수는 당시 조회 범위에 대해 상가 서울 554,092,
공원 18,202, 하천 2,558, 시도 17이었다. 현재 전국 현황이나 여기서 검증한 통계로 쓰지 않는다.

키의 URL 인코딩과 SGIS 새 도메인에 관한 확인도 포함됐다. 이 보고는 다른 실행 환경에서
호출이 가능했다는 근거다. 이 Work 환경의 요청이 성공했다는 증거와 합치지 않는다.

### 8.3 새 인증 정보로 여기서 재확인한 결과

2026-09-12 12:59:52 UTC 부근에 시작한 네 요청은 다음과 같다. 인증 정보는 결과 파일에
노출하지 않았고, 키·토큰은 이 저장소에 넣지 않는다.

| API | 비밀값을 제외한 요청 범위 | 직접 받은 결과 | 경과 |
| --- | --- | --- | --- |
| 상가 반경 | 경도 127.052, 위도 37.487, 250m, 첫 페이지 1건 | HTTP 502, `Connection refused` HTML | 12.07초 |
| 도시공원 | 첫 페이지 1건 | HTTP 502, 같은 HTML 오류 | 16.10초 |
| 하천 | 첫 페이지 1건 | HTTP 502, 같은 HTML 오류 | 24.13초 |
| SGIS 인증 | 새 `mods.go.kr` 호스트의 인증 요청 | HTTP 502, 같은 HTML 오류 | 20.11초 |

공공 데이터 키는 전달받은 URL 인코딩·줄바꿈 형태를 정규화해 사용했다. 정상 JSON이나
인증 오류 코드를 받지 못했으므로 키 유효성 또는 공급자 전체 상태를 판정할 수 없다.
SGIS는 토큰을 받지 못했으므로 후속 데이터 요청도 실행하지 않았다.

이후 사용자의 중단 지시에 따라 추가 대체 실험을 하지 않았다. 현재 기획 문서화는 이 실패를
없었던 일로 하거나 실험 성공을 선언하는 작업이 아니다.

## 9. 이 기록으로 말할 수 있는 결론

- 좋은 서술에는 글의 목적과 장면 중심이 실제 모델 입력에 있어야 한다.
- 금지 표현을 지우면서 시설 한 줄로 좁히는 것은 목표를 달성한 개선이 아니다.
- 구조·인용 검사 통과는 의미 품질의 충분조건이 아니다.
- ‘독립 장면’이라고 지시하면서 전체 시간열을 주는 입력은 최신 기획과 다르다.
- 기기 관측 위주의 이 표본은 특별한 순간과 풍부한 행동 기록의 품질을 검증하지 못한다.
- 지정 공공 API 실제 응답 → 같은 골격의 좌표 간 분류 → 실제 LLM 서술 연결은 아직 남아 있다.

이제 필요한 것은 이 한계를 숨기는 새 설계도가 아니라, [재개 지침](05-agent-handoff.md)에
따라 실제 재료와 실제 문장이 함께 보이는 비교다.
