# 근거·슬롯·실제 API

슬롯의 목적은 **현재 장면을 이해하고 서술하는 데 사용할 수 있는 재료를 남기는 것**이다.
공간·환경·동선이라는 파트 이름이나 3/1/1이라는 숫자가 기획의 목적은 아니다.
원칙의 형성은 [대화 전개 3–7절](01-decision-history.md), 글에서의 사용은
[서술 기준](02-narration-contract.md)을 함께 읽는다.

## 1. 두 종류의 구분을 섞지 않는다

**공간·환경·동선**은 자료의 성질과 유효 조건에 따른 파트 구분이다.
**어디서·누가·무엇을·어떻게·환경 α**는 서술에 필요한 의미의 구분이다.
각 의미를 별도 슬롯 객체 하나로 구현해야 한다거나 두 구분이 같은 표라는 결정은 없다.

| 원천·파트 | 서술에 기여할 수 있는 의미 | 자동으로 얻을 수 없는 의미 |
| --- | --- | --- |
| 장면 중심 기록 | 누가·무엇을, 실제 기록에 따라 어떻게 | 기록되지 않은 감정·의도·원인 |
| 참여 대상·행동 행위자 | 누가 | 각 참여자가 모든 핀의 행동을 했다는 사실 |
| 공간 | 어디서, 위치를 알아보는 단서 | 실제 진입·방문·시야·분위기 |
| 환경 | α | 행동 원인, 개인의 체감·감정 |
| 검증된 동선 | 기기의 움직임이라는 무엇을, 그 형태라는 어떻게 | 반려견의 특정 행동·휴식·목적 |

사용자 기록과 선정된 중심은 주변 후보와 슬롯 자리를 두고 경쟁하지 않는다.
특별한 순간은 매 기록을 별도 장면으로 보존하며 공간·환경만 보조한다. 이 예외를 무시하고
일반 동선 슬롯까지 붙이는 공통 파이프라인을 설계하지 않는다.

## 2. 원자료에서 문장까지 각 단계가 정하는 것

| 단계 | 정하는 내용 | 실패·누락의 뜻 |
| --- | --- | --- |
| 확보 | 실제 공급자 응답·사용자 기록·기기 관측이 있는가 | 호출 실패, 빈 응답, 페이지 미수집 등. ‘해당 현상이 없다’와 다르다 |
| 후보화 | 어느 원본의 어떤 주장과 적용 범위인가 | 필드 의미·좌표계·단위 등이 불명확하면 후보 의미를 꾸미지 않는다 |
| 적격성 | 이 장면에서 이 역할로 사용할 조건을 만족하는가 | 실패와 판정 불명을 구별한다 |
| 동일 주장·충돌 정리 | 실제 중복인가, 양립하지 않는 같은 주장인가 | 같은 시설 종류나 대상 ID만으로 합치지 않는다 |
| 용량 선정 | 적격 후보가 예산을 넘을 때 어떤 것을 담는가 | 적격하지만 용량 때문에 제외된 결과다 |
| 스탬프 고정 | 이 장면이 어느 근거·버전·역할·정책을 채택했는가 | 재현 연결이 불완전하면 생성의 근거를 추측하지 않는다 |
| 작성 입력 투영 | 모델이 이 장면에 대해 읽어야 할 의미는 무엇인가 | 내부 판정 자료와 자유 서술 재료를 구별한다 |
| 서술 | 채택 근거 중 무엇을 어떻게 표현할 것인가 | 선택적 생략은 정상이다. 사실의 범위를 넘는 표현은 실패다 |
| 공개 | 어떤 결과를 사용자가 읽고 수정하기 시작하는가 | 공개 후 작업용 자료가 바뀌어도 본문을 자동 교체하지 않는다 |

이 표는 책임 설명이다. 새 서비스 아홉 개나 아홉 번의 호출을 만들라는 아키텍처가 아니다.
기존 코드가 여러 책임을 함께 처리해도 근거와 결과가 구별되고 목적을 만족하면 재사용한다.

## 3. 각 파트가 지키려는 것

| 파트 | 기획상 목적 | 원본 근거 | 적재·제외 조건 | 허용되는 해석 | 실패 시 남는 결과 |
| --- | --- | --- | --- | --- | --- |
| 중심 | 어떤 순간을 남긴 것인지 잃지 않는다 | 행동 핀·자유 서술·사진 참조·선정 관측·실제 경로 지점 | 원본 종류와 버전 확인. 사용자 기록을 주변 자료 부족·예산으로 버리지 않음 | 그 원본이 실제 기록한 내용 | 중심과 기본 표시. 특별한 순간은 사용자 본문 자체 |
| 공간 | 장면 위치와 공간 관계를 구체화한다 | 실제 조회한 등록점·주소·형상·명시 집계 | 현재 위치 대응, 자료 종류, 거리 기준·단위·버전 확인. 다른 좌표 관계·불명 형상·확인 안 된 의미는 제외 | 등록점과의 거리, 해당 주소, 검증된 형상 관계 등 각각 성립한 범위 | 공간 부가 설명 없이 장면 유지 |
| 환경 | 그 순간에 적용되는 실제 환경을 보탠다 | 관측 종류·지역·대상 구간·단위가 있는 응답 | 장면에 대한 공간·시간 적용 확인. 예보와 관측 구별. 미확보·범위 불명·부적격은 제외 | 실제 관측이 설명하는 지역·범위의 환경 | 환경을 비워둠. 시계로 날씨·밝기를 대체하지 않음 |
| 동선 | 현재 장면에서 설명 가능한 움직임을 보탠다 | 정제 구간·관측 계산 결과·원본 연결 | 같은 대상·검증 구간·단절 여부·위치 대응·관측 의미 확인. 시간 제거 시 의미가 달라지면 제외 또는 적절한 투영 검토 | 기기의 적격한 움직임·형태 | 동선 설명 없이 중심 유지. 관측을 새 행동으로 채우지 않음 |

## 4. 공간 조건은 ‘근처’ 한 단어로 끝나지 않는다

### 4.1 위치와 관계의 기준

후보가 어떤 좌표를 기준으로 조회됐는지, 그 좌표가 현재 장면의 확정 위치인지 확인한다.
위치가 없는 사용자 기록에 임의로 세션 시작점이나 가장 가까운 다른 장면의 위치를 붙이지 않는다.
잠정 위치를 허용하는 별도 정책이 없다면 확정 위치처럼 사용하지 않는다.

공간 객체 원본을 재사용하는 것과 과거 좌표에서 계산한 관계를 복사하는 것은 다르다.
A에서 공원 P까지 80m였어도 B에서의 거리는 B를 기준으로 다시 계산해야 한다.
조회 캐시·TTL은 데이터 재사용 정책이지 현재 좌표 관계의 증명이 아니다.

### 4.2 거리 종류를 구별한다

| 값 | 실제로 뜻할 수 있는 것 | 뜻하지 않는 것 |
| --- | --- | --- |
| 등록 지점까지 거리 | 장면 좌표와 데이터에 등록된 대표 점의 거리 | 공원 경계·입구·건물 외벽까지 거리, 진입·방문 |
| 형상까지 거리 | 확인한 선·면과 좌표 사이의 정의된 거리 | 형상을 확보하지 않았는데 추정한 산책길 관계 |
| 검색 반경 | 후보 조회의 범위 | 각 후보의 실제 거리 |
| 지역 집계 범위 | 어떤 행정구역·격자에 대한 통계인가 | 장면 주변 몇 m의 전수 관측 |
| 거리 필드 부재 | 거리 정보가 없음 | 거리 0m |

필드명이 `distance_m`이라고 모든 자료를 등록점 거리로 분류하면 안 된다. 반경·대표점·형상
거리·집계를 같은 숫자 척도로 줄 세우는 것도 의미가 다르다. 같은 종류 안에서 비교하거나
다른 종류를 다루는 명시 정책을 별도로 둔다. 비교 정책을 현장 서술의 사실로 넘기지 않는다.

### 4.3 API 검색 결과가 풍경을 보증하지 않는다

주변 음식점 목록만으로 번화함·상점가·혼잡함을 확정하지 않는다. 검색어 ‘공원’ 결과가
공원 지형만을 반환한다고 가정하지 않는다. 상호명에 ‘공원’이 포함되거나 주차장·관리 시설이
검색될 수도 있으므로 실제 응답 종류를 읽어야 한다.

현재 등록 자료가 과거 산책 당시에 같은 시설이 존재·영업했고 실제 눈에 보였다는 증거도 아니다.
자료 시점이 허용하는 참고 수준을 유지한다. ‘현재 자료에는 등록돼 있다’는 한계를 인용 상세에서
설명할 수 있지만 이를 모든 장면 본문의 고정 문장으로 만들지는 않는다. 본문에 도움되지 않으면
그 자료를 언급하지 않는 선택도 가능하다.

## 5. 환경 조건은 조회 시간과 관측 시간을 구별한다

응답을 오늘 받았다는 사실은 오늘의 관측이나 장면 당시의 관측이라는 뜻이 아니다.
대상 지역·격자, 관측 항목과 단위, 실제 설명하는 시점·구간, 자료 종류를 함께 봐야 한다.

- 관측·예보·구간 누적·지역 평균을 같은 사실로 쓰지 않는다.
- 세션 출발 때의 날씨를 모든 장면의 날씨로 전파하지 않는다.
- 시간 범위가 없는데 임의의 ±5분 같은 범위를 만들어 정당화하지 않는다.
- 지역의 구간 누적 강수 0을 사진을 찍던 정확한 지점에서 비가 한 방울도 안 왔다는 직접 관측으로 바꾸지 않는다.
- 적격성을 위해 사용한 원시 시간은 내부에 남긴다. 서술 입력에 날짜·시계·전체 순서를 다시 싣지 않는다.

환경이 비어 있어도 장면은 성립해야 한다. 공원이라는 이름으로 맑음·시원함·나무 그늘을,
시계 시각으로 밤 풍경이나 계절감을 채우지 않는다. 사용자 체감과 공급자의 지역 관측도 구별한다.

## 6. 동선 조건과 현재 장면 우선의 변경

동선 관측은 검출 단계와 장면에 적용하는 단계를 구별한다. 검출기가 ‘상대적으로 느림’을
산출했다면 슬롯 조건이 이를 ‘감속’으로 바꿀 수 없다. 이동 관측이 잘 계산됐어도 장면과
다른 검증 구간이거나 중간에 허용되지 않은 간선·공백이 있으면 현재 맥락으로 쓸 수 없다.

과거에는 같은 연속 구간의 ‘직전 30초’ 같은 관측을 별도 사건으로 늘리지 않고 현재 기록의
맥락으로 제공하는 실험이 있었다. 같은 세션이라는 조건만으로는 부족하며 검증 구간·원본
연결·관측 종료와 기록 시각의 관계까지 확인하려는 목적이었다.

**현재는 그 과거 정책을 그대로 작성 입력에 이식하지 않는다.** 사용자가 시간순 맥락을 장면
생성에서 제거했기 때문이다. 직전 관측이라는 뜻을 지우면 현재 사실로 오독되는 재료는
현재 순간에 속하는 것처럼 평탄화하지 않는다. 현재 장면에 적격한 의미로 투영할 수 있는지
판정하고, 그렇지 않으면 그 용도로 제외한다. 구체적 투영은 후속 구현·검증 사항이다.

같은 검증 구간 ID 하나가 중간 연결의 품질을 모두 증명하는 것도 아니다. 중간에 제외된
간선이나 관측 공백이 있는지 확인해야 하는 이유는, 두 자료를 이어 서술할 때 발생하는
없는 연속성을 막기 위해서다. 현재 정책은 그 연속성을 모델에 자유롭게 추론시키지 않는다.

## 7. ‘없음’과 ‘쓰지 않음’을 나누는 조건 체계

| 상태 | 의미 | 문장·검토에서의 처리 |
| --- | --- | --- |
| 미확보 | 조회·수집하지 못함 | 현상이 없다고 쓰지 않는다 |
| 부적격 | 명시 조건을 위반함 | 해당 용도의 후보에서 제외한다 |
| 판정 불명 | 조건을 평가할 필수 정보가 없음 | 통과로 추정하지 않는다. 부족한 항목을 기록한다 |
| 중복 | 같은 원본·주장임을 확인함 | 대표와 보존한 출처를 남긴다 |
| 충돌 | 같은 적용 범위·의미의 값이 양립하지 않음 | 근거 있는 해결 정책이 없으면 해당 주장 사용을 보류한다 |
| 용량 초과 | 적격하지만 예산에서 밀림 | 자료가 없거나 틀렸다고 보고하지 않는다 |
| 선정 | 스탬프에 담겼음 | 전부 언급할 의무는 없다 |
| 서술 생략 | 선정했지만 본문에서 안 씀 | 표현 선택으로 평가한다 |
| 생성 실패 | 형식·근거·품질·시간 등의 기준을 못 맞춤 | 기본 결과와 원본을 남긴다 |

조건은 실행 가능한 판정 함수와 인자로 표현할 수 있어야 한다. 예를 들어 원본 버전 대응,
좌표 유효성, 같은 검증 구간, 특정 의미의 거리 상한은 계산 가능한 조건이다.
‘이 장면에 흥미롭다’라는 이름만 있는 조건은 구현된 판정이 아니다.

정책 표현식 언어·범용 룰 엔진·관리자 화면을 먼저 만드는 것은 필수가 아니다. 기존 함수로
판정하고 비교 기록에 조건·실제값·문턱·결과·사유를 남길 수 있으면 우선 목적을 검증할 수 있다.

## 8. 중복·충돌·예산을 구별하는 이유

같은 카페 종류 두 곳은 중복이 아니다. 같은 장소라도 주소 사실과 형상 관계는 다른 근거다.
같은 대상 ID가 같은 관측·범위·주장을 뜻하지 않으며, 다른 출처가 같은 숫자를 냈다는 이유만으로
하나를 지우지 않는다. 묶어 표현한다면 연결한 출처를 보존한다.

조회 시각이 최신이라는 이유만으로 충돌한 값 중 하나를 진실로 고르지 않는다. 자료의 수정
버전과 출처 권위, 범위·단위·측정 의미가 실제로 비교 가능한지 확인한다.

적격 후보가 용량 안에 들어오는데 미리 ‘대표 하나’만 남기면 표현 여지를 다시 좁히게 된다.
예산 초과 때 쓰는 기준과 적격성 조건을 구별하고, 카페 감점·공원 보호·유형별 의무 할당 같은
가치판단을 제외 규칙으로 숨겨 넣지 않는다. 필요하다면 실제 결과로 별도 정책을 결정한다.

전수 검증한 표가 아니며, 사용자가 정한 최적 정책도 아니다. 일부 결과는 첨부 스탬프와 대조할

임시 정책인지와 바꾼 이유를 밝힌다. 이번 문서화는 이 숫자를 조정한 작업이 아니다.

## 10. 스탬프와 수명

작업용 후보는 재조회·재판정·만료·예산 변경으로 달라질 수 있다. 특정 장면이 사용한 스탬프는
근거 ID·버전·사용 역할·대상 연결·판정 정책을 재현할 수 있어야 한다. 고정 스탬프가 있다는
것은 생성 문장을 마음대로 다시 써도 된다는 뜻이 아니다.

다음 세 가지는 별개다.

1. 같은 원자료를 캐시에 보관하는 수명.
2. 해당 원자료가 현재 장면의 슬롯에 적격한 수명·범위.
3. 사용자가 읽고 수정하기 시작한 공개 결과의 보존.

슬롯에서 빠졌다고 원자료나 사용자 기록을 삭제하지 않는다. 슬롯 교체를 장소 이탈·새 사건으로
해석하지 않는다. 정책 재생은 개발 검증에 쓰며, 공개본 자동 교체의 트리거로 사용하지 않는다.

## 11. 실제 API가 제공하는 것부터 분류해야 한다

현재 지정된 공급자와 호출 확인의 범위는 다음과 같다. **이 표의 분류 목적은 향후 실제 응답을
읽을 때의 질문이며, 여기서 새 데이터 행을 성공적으로 확보했다는 뜻이 아니다.**

| 지정 API | 사용자 제공·이번 확인의 범위 | 서술 골격에 대해 확인할 질문 | 아직 증명하지 못한 것 |
| --- | --- | --- | --- |
| 소상공인시장진흥공단 상가(상권)정보 | 다른 환경의 상가 조회 성공 보고. 여기서는 반경 조회 502 | 상호·업종·주소·등록 위치 등 실제 반환 필드 중 어디서에 쓸 수 있는 것은 무엇인가? | 지정 좌표의 실데이터 필드·결측·페이지 범위와 현재 골격 적용 |
| 전국도시공원정보표준데이터 | 다른 환경의 1건 성공 보고. 여기서는 1건 조회 502 | 실제 응답이 대표점·시설 속성·형상 중 무엇을 주는가? | 공원 내부·둘레길·그늘 등의 공간 관계가 실제 응답에서 성립하는지 |
| 전국하천표준데이터 | 다른 환경의 1건 성공 보고. 여기서는 1건 조회 502 | 실제 위치 정보가 점·구간·행정 소재·형상 중 무엇인가? | 좌표와의 거리 계산이나 하천변 경로 서술이 가능한지 |
| SGIS | 다른 환경의 토큰 및 시도 17건 조회 성공 보고. 여기서는 인증 요청 502 | 사용할 데이터 API가 행정구역·통계·형상 중 무엇을 주며 어느 범위인가? | 인증 성공만으로는 장면 좌표의 배경 자료 확보를 증명하지 못함 |

호출할 데이터셋 이름만으로 실제 반환 필드 목록을 확정하지 않는다. 특히 하천 표준데이터가
이름상 하천이라고 해서 좌표에서 선형까지 거리를 바로 계산할 수 있다고 가정하지 않는다.
SGIS 토큰 발급과 시도 목록은 연결 진단의 의미가 있지만 산책 장면의 서술 재료 검증을 대신하지 않는다.

### 11.1 기록해 둔 엔드포인트

- 상가 반경 조회: `https://apis.data.go.kr/B553077/api/open/sdsc2/storeListInRadius`
- 도시공원: `https://api.data.go.kr/openapi/tn_pubr_public_cty_park_info_api`
- 하천: `https://api.data.go.kr/openapi/tn_pubr_public_river_info_api`
- SGIS 인증: `https://sgisapi.mods.go.kr/OpenAPI3/auth/authentication.json`

SGIS의 새 호스트는 앞선 확인에서 [공식 기본 API 안내](https://sgis.mods.go.kr/developer/html/newOpenApi/api/dataApi/basics.html)와
대조했다. 이 목록은 2026-09-12 진단에 사용한 주소다. 데이터 조회 단계에서는 실제 응답과
해당 데이터 API의 계약을 다시 확인한다. 인증키·토큰·서명된 요청 URL은 이 문서나 저장소에 넣지 않는다.

### 11.2 좌표 A를 보고, 같은 분류로 B를 본다

실험을 재개할 때는 요청 좌표·실제 요청 범위·응답 범위를 고정해 남긴다. 전국 첫 1건 조회가
성공했다고 그 행이 A의 주변이라는 뜻은 아니다. 페이지 일부를 받았다면 지역 전체의 현황으로
일반화하지 않는다. 조회 결과 0도 검색 범위·분류·페이지 한계를 확인하기 전에는 시설 부재가 아니다.

첫 좌표에서 각 필드를 다음 열로 분류한다.

| 기록할 열 | 목적 |
| --- | --- |
| 공급자·엔드포인트·응답 필드 경로 | 어디서 실제로 받은 값인지 확인 |
| 실제 값·단위·대상 범위·결측 | 원자료가 무엇을 말하는지 보존 |
| 현재 좌표와의 검증된 관계 | 그 장면에 적용 가능한지 판정 |
| 어디서/누가/무엇을/어떻게/α 또는 내부·비사용 | 문장 재료인지 판정용 정보인지 구별 |
| 허용되는 표현의 강도 | 등록점·형상·지역 집계를 바꿔 말하지 않게 함 |
| 제외 사유·미확보 항목 | 없는 재료를 숨기지 않음 |

그 분류 기준을 고정하고 다른 좌표에 적용한다. 두 번째 좌표의 결과가 빈약하다고 기준을
몰래 바꾸지 않는다. 바꿔야 한다면 A에도 같은 기준을 재적용해 차이를 설명한다.
좌표 수나 반경의 최적값은 아직 확정하지 않았다. 적어도 서로 다른 좌표에 같은 분류가 적용되는지
보자는 것이 사용자의 요구다.

마지막에 실제 앱의 참여 대상·행동·동선 자료를 합쳐 서술 골격을 만든다. 공공 API가 주지 않는
누가·무엇을을 가짜로 채워 공공 데이터의 성과처럼 보이지 않게 한다. 별도 가정 사례를 비교할
수는 있지만 실제 API 실험을 대신할 수 없고 가정임을 명시해야 한다.

## 12. 현재 남은 것은 실데이터와 문장 사이의 검증이다

이번 최신 골격으로 지정 공공 API 응답을 A·B에 적용하고 실제 모델 출력까지 만든 성공
사례는 아직 없다. 기존 자료 카탈로그, 예쁜 예문, Kakao 대체 호출, 과거 스냅샷은 각각 참고
범위가 다르다. 사용자가 중단시킨 대체 실험을 현재 검증 완료로 이어받지 않는다.

다음 결과는 이 문서의 표를 채운 실제 값과, 그중 모델에 정말 전달한 의미, 실제 생성 문장이
함께 보이는 것이어야 한다. 조건을 더 많이 구현했다는 보고만으로 이 연결을 대신하지 않는다.
