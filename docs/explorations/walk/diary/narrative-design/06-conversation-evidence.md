# 대화 근거와 결정 원장

이 문서는 결론의 출처를 되짚기 위한 색인이다. 전체 대화를 무차별 복사하지 않고 관련 구간과
결정 문장을 연결했다. API 키·토큰·개인 경로·DB·무관한 기능 대화는 게시 자료에 포함하지 않는다.

## 1. 자료 범위와 읽는 방법

### H: 첨부된 이전 대화

- 업로드 이름: `scene-context-comparison.zip`.
- 내부 대화: `scene-context-comparison/share-origin-conversation.txt`.
- 형식: `===== 001 user =====`와 같은 번호·역할 경계. 120개 메시지.
- 해당 텍스트 파일 SHA-256: `06d74ff7b5ab5387d3a6c26d89953d71c636d03deb715c138c4096b74a574266`.

이전 대화에는 사용자가 다른 에이전트와의 대화를 통째로 붙여 넣은 긴 `user` 메시지가 있다.
그 안의 에이전트 제안을 모두 사용자가 확정한 지시로 취급하지 않는다. 아래에서는 직접
사용자 질문·수정과, 인용된 에이전트의 설명·제안을 나눠 읽었다.

일부 도구 출력은 원본에서 생략·가림 처리돼 있다. 가려진 호출 결과를 복원하거나 보이지 않는
발언을 추정하지 않는다. 현재 대화에 붙여진 추가 맥락도 중간 생략을 명시하고 있으므로,
이 묶음은 **확보한 대화·첨부 원문·직접 확인한 파일**의 범위에 근거한다.

### U: 현재 이어받은 대화의 사용자 발언

아래 U 번호는 이 문서 묶음을 위해 순서대로 부여한 색인이다. 앱의 원래 메시지 ID가 아니다.
날짜는 이 문서 작성 기준인 2026-09-12이며 개별 발언의 정확한 시각을 만들어 붙이지 않았다.

### 실행 파일과 저장소

실제 파일을 확인한 사실과 다른 에이전트가 실행했다고 보고한 사실을 구별한다.
첨부 실행 파일은 당시 입력·응답의 증거이며, 이 문서 작성 중 같은 호출을 다시 했다는 뜻이 아니다.
코드 기준도 커밋과 확인 범위를 기록한다. 과거 PR 검토 발언을 현재 main 상태로 읽지 않는다.

> 하지만 이 과정이 룰베이스로 이루어져야 한다는 사실이야 그러면 조건이 필요해 지금 네가 이걸 걸러낸건 판단의 영역이고 지금부터는 융통성 있는 조건 시스템이 들어가야해

### 최신 판단을 바꾼 직접 문장

U03 — 시간과 장면에 관한 사용자 발언 중 발췌:

> 이 시간적 정보는 도중에 끊겨 장면 사이에 몇시간의 간격이 생기는 경우가 생기는데 이 사이에 시간 정보를 판단할 근거로 들어가게 되는 일이 한번이라도 생기면 엄청난 오류가 생기는거임

> 이 장면 생성 자체가 하나의 서브 일기고 완성된 제품으로 나와야 되는거야

> 3인칭의 위에서 바라보는 공간적 서술 자체는 괜찮거든? 근데 행위 자체를 3인칭으로 서술해버리면 거기서 이질감이 확 생겨버리는거지

U05 — 장면 우선으로 기획 변경:

> 하나의 장면이 더 우선임 굳이 전체 세션을 이해할 필요는 없어

> 이전 기획이 겹칠거 같으면 과감하게 삭제해도 될거라 생각

U07 — 특별한 순간과 행동 핀:

> 후자는 자유 서술이라 무조건 장면을 따로 할당해줘야 되고 그냥 그 순간의 공간, 환경 정보만 제공해주고 서술 쪽을 아예 관여하지 말자

> 행동 핀쪽은 그냥 강아지의 행동 서술이라 전지적 시점의 서술이 아닌 더 가까운 느낌의 서술이 들어가야해

U09 — 지금 우선할 작업:

> 행동 핀에 나중에 누가 했는가 를 넣는건 어렵지 않으니까 어떻게 서술을 넣을지만 생각해

> 어디서, 어떻게, alpha 이런 슬롯을 모으는데 주력했으면 그냥 저걸 갈아끼웠을때 똑같이 일관성을 가진 서술 구조를 짜라는건데

U10 — 빠진 의미의 복구:

> 내가 화나서 그냥 어떻게로 뭉뚱그렸는데 무엇을도 들어가야 하는거다

U11 — 실제 자료를 확인하는 순서:

> 네가 하나의 좌표를 따서 그 정보를 읽어들이고 실제로 정보들이 어떤 골격에 들어가야 할지 분류를 먼저 해본 다음 다른 좌표에도 마찬가지로 적용이 가능한지 확인해야 하는거야

U12 — 대체 실험 중단:

> 헤이 스탑, 실제 api가 아니면 테스트하는 의미가 없으니까 하는거 접어

여기서 ‘실제 API’는 문맥상 사용자가 요청한 공급자의 실제 호출이다. 이후 대체 Kakao 호출이
실제였다고 설명해도 사용자 요청을 충족한 것으로 되돌릴 수 없다. 같은 발언에 붙여진 다른
환경의 로그는 보고된 성공이지 현재 도구의 반환값이 아니다. 인증 정보는 인용에서 제외했다.

U14 — 문서화 범위:

> 그냥 여기 대화를 싹읽어서 도달하게 된 흐름까지 다 읽고 보여주는걸로 해라, 그러면 문서 하나가 아니라 여러개를 만들어야겠지
