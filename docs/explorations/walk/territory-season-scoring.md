# 시즌 점령전 — 정기 점수와 최대 동시 정복

> 이 문서는 채택된 제품 결정이나 구현 계약이 아니다. 점령지의 현재 상태를 온라인으로
> 공유하고, 정해진 시각마다 그 상태를 점수로 읽는 시즌 게임 가설을 정리한다. 시즌 길이,
> 정산 간격, 지역 체계와 동점 처리는 아직 미정이다.

## 한 문장

**유효한 강아지 사진 점령이 완료되면 점령지의 현재 주인이 바뀌고, 정해진 정산 시점마다
그 점령지를 들고 있는 강아지가 1점을 받는다. 시즌 누적 점수와 한 번의 정산에서 기록한
최대 동시 점령량은 서로 다른 지역 랭킹으로 읽는다.**

```text
검증된 산책 접촉
→ 세션 내 강아지 사진·판정·사용자 증언
→ 유효한 점령
→ 점령지의 현재 주인 교체
→ 시간 또는 날짜 단위 정산
   ├─ 현재 점령지 수를 시즌 점수에 더함
   └─ 현재 점령지 수가 최고면 정복 기록 갱신
→ 지역별 점령 랭킹 / 정복 랭킹
→ 시즌 결과 봉인
→ 다음 시즌은 중립 게임판에서 다시 시작
```

## 1. 점령 증거와 시즌 점수판을 분리한다

[점령지 게임 탐색](territory-site-game.md)은 다음을 맡는다.

- 검증된 산책이 어느 점령지에 접근했는가.
- 사진이 같은 산책 세션 안에서 촬영됐는가.
- 사진에서 강아지가 충분히 보이는가.
- 사용자가 어느 점령 기회에 자기 강아지로 서명했는가.
- 촬영·판정·finalize·개인정보의 경계는 무엇인가.

이 문서는 그 결과로 **유효한 점령이 확정된 뒤**만 다룬다.

```text
territory-site-game.md
= 점령을 어떻게 믿을 것인가

territory-season-scoring.md
= 현재 점령 상태를 어떻게 점수와 시즌 결과로 읽을 것인가
```

기존 탐색의 연결망·포위·내부 해금은 삭제된 아이디어가 아니다. 다만 현재 온라인 시즌
가설에는 필요하지 않으므로 개인형·후속 게임 후보로 보류한다.

## 2. 용어

| 이름 | 뜻 |
|---|---|
| 점령 | 유효한 사진 점령으로 점령지의 현재 주인을 바꾸는 사건 |
| 점유 | 현재 그 점령지를 들고 있는 상태 |
| 점령 점수 | 각 정산에서 들고 있던 점령지 수를 시즌 동안 더한 값 |
| 정복 기록 | 한 번의 정산에서 동시에 들고 있던 점령지 수의 시즌 최고값 |
| 시즌 | 점령 상태와 두 성과를 경쟁한 뒤 초기화하는 기간 |
| 지역 | 같은 랭킹에서 비교할 점령지 묶음 |

```text
점령은 사건이다.
점유는 현재 상태다.
점수는 정산 시점의 상태에서만 생긴다.
```

시즌 종료 순간의 지도만으로 우승자를 정하지 않는다. 마지막 지도는 마지막 장면이고,
시즌 성과는 이미 완료된 정산 기록에서 나온다.

## 3. 온라인 지도에는 현재 상태만 노출한다

점령지 하나의 공용 상태는 처음에는 두 가지면 충분하다.

```text
neutral
controlled(claiming_pet_id)
```

유효한 새 점령이 확정되면 가장 최근에 확정된 점령자가 현재 주인이 된다.

```text
중립 Site
→ 말매의 유효 점령
→ 말매 점령 상태

말매 점령 Site
→ 초코의 유효 점령
→ 초코 점령 상태
```

같은 강아지가 자기가 가진 점령지를 다시 인증해도 점령지 수는 늘어나지 않는다. 재방문은
개인 기록으로 남길 수 있지만 점수는 정산 때만 발생한다.

공용 지도에는 고정 점령지 위치와 현재 상태만 표시한다. 실제 촬영 좌표, 정확한 촬영 시각,
원본 산책 경로와 사진 원본은 공용 점령 상태가 아니다.

## 4. 정산은 현재 점령지 수를 한 번 센다

정산 간격은 시간 단위나 날짜 단위가 될 수 있다. 계산 규칙은 같다.

```text
ScoringTick at T

1. T 시점의 활성 점령지를 지역별로 읽는다.
2. 현재 주인별 점령지 수를 센다.
3. 그 수를 이번 정산 점수로 기록한다.
4. 시즌 점령 점수에 더한다.
5. 기존 정복 기록보다 크면 최고값을 바꾼다.
```

v0에서는 활성 점령지 하나가 정확히 1점이다. 점령지 종류, 사진 품질, 강아지 수,
이전 시즌 성적에 따른 가중치는 두지 않는다.

```text
말매가 현재 7곳 점령
초코가 현재 4곳 점령
콩이가 현재 1곳 점령

이번 정산
말매 +7
초코 +4
콩이 +1
```

정산 뒤 누군가 점령지를 빼앗아도 이미 받은 점수는 바뀌지 않는다. 새 주인은 다음 정산부터
그 점령지가 생산하는 점수를 받는다.

## 5. 점령 점수와 정복 기록

### 점령 점수

점령 점수는 각 정산 점수의 합이다.

```text
occupation_score
=
Σ controlled_site_count at each scoring tick
```

### 정복 기록

정복 기록은 한 번의 정산에서 받은 점수의 최고값이다.

```text
conquest_peak
=
max controlled_site_count at one scoring tick
```

예:

| 정산 | 말매 | 초코 |
|---|---:|---:|
| 13시 | 3 | 0 |
| 14시 | 3 | 8 |
| 15시 | 3 | 0 |

```text
말매
점령 점수 = 3 + 3 + 3 = 9
정복 기록 = 3

초코
점령 점수 = 0 + 8 + 0 = 8
정복 기록 = 8
```

따라서 점령왕은 말매, 정복왕은 초코가 될 수 있다.

```text
점령왕
= 시즌 동안 정산 점수를 가장 많이 쌓은 강아지

정복왕
= 단일 정산에서 가장 많은 점령지를 동시에 가진 강아지
```

정복을 순간 지도 조회값으로 계산하지 않고 완료된 정산 점수의 최고값으로 계산한다.
그러면 두 성과가 같은 단순한 정산 원장을 공유한다.

## 6. 지역별 두 랭킹

초기에는 종합 점수 없이 두 랭킹을 따로 보여 준다.

```text
A동 점령 랭킹
1위 말매  1,460점
2위 초코  1,328점
3위 콩이    974점
```

```text
A동 정복 랭킹
1위 초코  최대 31곳
2위 말매  최대 24곳
3위 콩이  최대 19곳
```

둘을 바로 합치지 않는다.

- 점령 점수는 정산 점수의 합이다.
- 정복 기록은 정산 점수의 최대값이다.
- 사용자가 어떤 플레이로 순위가 올랐는지 바로 이해할 수 있다.
- 두 지표가 실제로 다른 플레이를 만드는지 먼저 확인할 수 있다.

첫 경쟁은 서로 다른 지역을 전국 한 줄로 비교하기보다 같은 지역 게임판 안에서 순위를 낸다.
시즌 중에는 `site_id → region_id` 매핑과 활성 점령지 목록을 바꾸지 않는다.

지역 체계는 행정동·법정동·별도 리그 격자 중 아직 정하지 않았다. 공통 지역 정보는
[산책 스토리보드와 동네 구간](storyboard-and-regions.md)과 함께 검토하되, 스토리보드의
편집용 지역 구간을 게임 점령 판정으로 사용하지 않는다.

## 7. 비동기 사진은 과거 점수를 다시 쓰지 않는다

첫 시즌 가설에서는 사진 촬영 시각으로 점령을 소급하지 않는다.

```text
사진 촬영
→ uploading / evaluating
→ 아직 점령 상태 변화 없음
→ Assessment와 Attestation까지 완료
→ 현재 주인 교체
→ 이후 처음 도래하는 정산부터 점수 획득
```

예:

```text
13:58 촬영
14:00 정산
14:01 점령 확정
15:00 정산
```

- 14:00 점수는 14:00의 이전 점령견이 받는다.
- 새 점령견은 15:00 정산부터 받을 수 있다.
- 이미 끝난 14:00 점수를 다시 계산하지 않는다.

이 단순화는 네트워크와 모델 지연이 정산 경계의 결과에 영향을 줄 수 있다. 실제 채택 전에는
판정 지연 p50·p95와 정산 직전 촬영의 실패율을 측정한다. 시즌 종료 뒤 완료된 옛 사진이
다음 시즌의 점령권을 자동 생성해서도 안 된다.

## 8. 시즌은 점수와 권력만 리셋한다

시즌 길이는 격주 또는 달력 월을 첫 후보로 둔다. 정확한 길이는 미정이다.

```text
시즌 시작
→ 모든 활성 점령지 중립
→ 점령 점수 0
→ 정복 기록 0

시즌 진행
→ 유효 점령으로 현재 주인 변경
→ 정기 정산으로 점수와 최고 기록 갱신

시즌 종료
→ 마지막 예정 정산 완료
→ 지역별 점령·정복 순위 봉인
→ 다음 시즌은 다시 중립
```

리셋되는 것:

- 현재 점령지 주인.
- 시즌 점령 점수.
- 시즌 정복 기록.
- 현재 지역 순위.

리셋되지 않는 것:

- 산책 기록과 Cellophane.
- 허용된 Encounter·Capture·Assessment·Attestation 증거.
- 사용자가 개인 기록으로 남긴 사진과 추억.
- 지난 시즌의 최종 점수·순위·배지.

과거 증거를 새 시즌 점령으로 자동 복사하지 않는다. 이전 시즌 우승자가 다음 시즌 점령력이나
추가 점수를 얻지 않는 것을 v0 원칙으로 둔다. 장기 보상은 칭호·꾸미기·기록처럼 경쟁 조건을
바꾸지 않는 형태를 우선한다.

## 9. 싸인펜·셀로판과 점수판을 섞지 않는다

```text
CanonicalTrail
  ├─ 산책별 Cellophane
  │    어디를 어떻게 걸었는가
  │
  └─ Territory Site consumer
       Encounter + Capture + Assessment + Attestation
       → 현재 점령 상태
       → 정산 점수
       → 지역 랭킹
```

Cellophane의 `occupancy`, `peak`, 방문 횟수와 진하기는 점령 점수나 정복 기록이 아니다.
공개 지도에서 인접한 점령지를 같은 색 면처럼 보여 줄 수는 있지만, 그 렌더링이 추가 점수나
걷지 않은 공간의 소유권을 만들지 않는다.

시즌 결과를 지난달 셀로판처럼 보관하는 연출은 가능하다. 그것은 산책 Cellophane 원판이 아니라
별도의 시즌 결과 표현이다.

## 10. 최소 객체 스케치

아래 이름은 책임을 설명하기 위한 후보이며 DB·HTTP 계약이 아니다.

```text
TerritorySeason
  season_id
  starts_at / ends_at
  scoring_interval
  ruleset_version
  status

SeasonSiteControl
  season_id
  site_id
  controller_pet_id | null
  claimed_at
  source_attestation_id

RegionScoreTick
  season_id
  region_id
  scored_at
  claiming_pet_id
  controlled_site_count

RegionSeasonStanding
  season_id
  region_id
  claiming_pet_id
  occupation_score
  conquest_peak
  conquest_peak_at

SeasonResultSnapshot
  season_id
  region_id
  finalized_at
  occupation_ranking
  conquest_ranking
  ruleset_version
```

`SeasonSiteControl`은 온라인 지도에서 읽는 현재 상태다. `RegionScoreTick`은 완료된 정산 기록이고,
Standing은 그 기록을 합계와 최고값으로 읽은 결과다. 점령 증거 객체를 이 테이블들에 합치지 않는다.

## 11. 초기 불변식

1. 한 시즌의 한 점령지는 한 시각에 최대 한 `controller_pet_id`만 가진다.
2. 마지막으로 확정된 유효 점령이 현재 주인을 바꾼다.
3. 사진 판정과 사용자 증언이 완료되기 전에는 공용 점령 상태가 바뀌지 않는다.
4. 점령 자체는 직접 점수를 지급하지 않는다.
5. 정산 시점의 현재 점령견만 해당 점령지의 1점을 받는다.
6. 완료된 정산 점수는 이후 점령이나 늦은 판정으로 소급 수정하지 않는다.
7. 점령 점수는 정산별 `controlled_site_count`의 합이다.
8. 정복 기록은 정산별 `controlled_site_count`의 최대값이다.
9. 같은 강아지가 자기 점령지를 다시 인증해도 점령지 수와 즉시 점수는 늘지 않는다.
10. v0에서는 모든 활성 점령지의 정산 가치가 1로 같다.
11. Cellophane이나 산책 거리에서 점령 점수를 직접 만들지 않는다.
12. 시즌 종료는 과거 증거를 삭제하지 않고 현재 점령권과 시즌 성과만 초기화한다.
13. 지난 시즌 증거와 우승 보너스가 다음 시즌 점령권을 자동 생성하지 않는다.
14. v0에는 점령 점수와 정복 기록을 합친 종합 랭킹이 없다.

## 12. 먼저 비교할 선택지와 측정

정산 간격:

- 매시간: 하루 안 점수판이 자주 움직이지만 정산 경계를 지나치게 의식할 수 있다.
- 몇 시간마다: 변동과 피드백 사이의 중간값이다.
- 매일: 가장 단순하지만 정산 직전 점령이 몰릴 수 있다.

시즌 길이:

- 격주: 리셋과 신규 유입을 빨리 검증할 수 있지만 시즌 피로가 커질 수 있다.
- 달력 월: 이해하기 쉽지만 중간 유입 사용자가 오래 불리하다고 느낄 수 있다.

측정할 것:

- 한 산책에서 유효 점령까지 완료하는 점령지 수.
- 기존 점령지를 빼앗는 비율과 자기 점령지 재촬영 비율.
- VLM 지연 때문에 다음 정산을 놓친 비율.
- 시간·일일 정산에서 점령 시점이 어떻게 달라지는가.
- 정산 직전 점령 쏠림이 생기는가.
- 점령 점수와 정복 기록의 상위권이 실제로 다른가.
- 시즌 중간 유입 사용자가 순위 변화를 만들 수 있는가.
- 격주와 월간의 재참여율·피로·신규 진입 감각이 어떻게 다른가.
- 지난 시즌 결과와 배지가 리셋 상실감을 보완하는가.

## 13. 연결망·포위는 현재 온라인 계획에서 보류한다

현재 가설은 다음으로 좁힌다.

```text
권위 있는 온라인 상태
= 점령지별 현재 주인

온라인 경쟁
= 정기 정산 점수와 지역 랭킹

면처럼 보이는 영역
= 인접한 현재 점령지의 UI 표현
```

연결망·포위는 향후 다음 중 하나로 다시 검토할 수 있다.

- 공개 점수에 영향을 주지 않는 개인 산책 업적.
- 시즌 특별 미션.
- 일부 지역에서만 여는 별도 규칙전.
- 단순 Site 경쟁이 전략 부족으로 판정됐을 때의 후속 실험.

## 14. 채택할 때 나눌 결정

1. **점령 상태 전이** — 어떤 Attestation이 언제 `SeasonSiteControl`을 바꾸는가.
2. **정산 규칙** — 간격, 경계 시각, 중복 방지와 완료 tick의 불변성은 무엇인가.
3. **점령·정복 랭킹** — 두 지표, 지역 체계, 동점과 공개 범위는 무엇인가.
4. **시즌 수명** — 시작·종료·초기화와 지난 시즌 결과 보관은 무엇인가.

그 전에는 DB migration, 점령 write API, scheduler와 공개 leaderboard를 구현된 제품처럼
`overview.md`나 계약에 올리지 않는다. 첫 spike는 현재 점령 상태와 정산 시각 목록만 입력받는
순수 projector로 만들고, 시간·일일 정산과 격주·월간 시즌을 같은 fixture에서 비교한다.
