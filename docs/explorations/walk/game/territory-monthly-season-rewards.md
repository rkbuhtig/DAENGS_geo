# 점령 게임 — 인증 차등 보상과 월간 시즌 합의

2026-09-09 사용자와의 기획 대화를 기록한다. **합의된 방향·수치와 미결 항목을 구분한
후속 구현 기준**이다. `exploring`은 아래 미결 설계가 남았다는 뜻이며, 합의한 내용을
다시 미정으로 돌리는 표기가 아니다. `implementation: none`은 이번 차등 보상·시즌당
보상 제한·월간 자동 전환의 상태다. 기존 점령·인증·시즌 계산 기반까지 없다는 뜻은 아니다.

이번 문서화는 코드·DB·서버 설정을 변경하거나 게임을 활성화하는 작업이 아니다.
**게임은 OFF로 유지하고 정책 구현·검증 후 개발 서버에서 실험한다.**
예전 실험의 100점·시간당 10점·매 변경 보너스·7일 시즌을 이 기획의 확정값으로 읽지 않는다.

## 1. 목표와 합의 근거

새 영역을 넓게 확보하고, 확보한 영역을 오래 유지하는 즐거움을 함께 보상한다.
집에 돌아온 뒤에도 보유의 가치가 남아야 한다. 인증된 영역을 반복해서 뺏는 행동이나
두 사람이 같은 장소를 주고받는 행동이 개척보다 유리한 보상 구조는 피한다.

대화에서 사용자가 정한 핵심은 다음과 같다.

- 미개척된 곳의 획득 보상을 더 주고 이미 인증된 곳의 탈취 보상은 낮춘다.
- 시즌 단위로 개인이 같은 자리에서 얻는 획득 보상은 한 번으로 제한한다.
- 최초 미인증 점령자는 이후 인증으로 획득하면 누적 100점까지 차액을 받는다.
- 4시간 뒤 적립을 끊는 안은 채택하지 않는다. 장시간 산책과 넓은 정복의 가치를 유지한다.
- 한국 시간 달력 월로 결산한 다음 다음 시즌을 자동으로 시작한다.

여기서 **시즌당 한 번은 획득 보너스에만 적용**한다. 보유 시간 점수까지 100점으로
제한하거나, 보너스를 소진한 장소의 재탈취·시간 적립을 막는 뜻이 아니다.

## 2. 점령·인증·보호 규칙

기존 [인증 우선 정책 v2](../../../territory-policy-v2.md)를 유지한다.

| 대상의 현재 상태 | 사진 없는 점령 | 다른 강아지의 사진 인증 점령 |
|---|---|---|
| 빈 영역 | 미인증 점령 가능 | 인증 점령 가능 |
| 미인증 영역 | 다른 주인에게서 탈취 불가 | 즉시 탈취 가능 |
| 인증 영역, 10분 보호 중 | 탈취 불가 | 보호 종료 전 차단 |
| 인증 영역, 보호 종료 | 탈취 불가 | 새 사진 인증으로 탈취 가능 |

- 보호는 서버에서 인증이 확정된 시점부터 10분이다. 종료 시각과 같으면 도전 가능하다.
- 자기 미인증 영역의 인증 강화도 그 인증 시점부터 보호한다.
- 이미 인증된 자기 영역을 재촬영해 보호를 연장하거나 새 획득 보너스를 받지 않는다.
- 같은 산책에서 재도전할 수 있지만 새 도전·사진과 현재 상태에 대한 서버 검증이 필요하다.
- 촬영 허가는 소유권 예약이 아니다. 지연 판정·동시 탈취는 확정 시점의 버전·시즌을 검증한다.

## 3. 획득 보상

아래 표는 해당 시즌·장소에서 보상 자격을 아직 소진하지 않은 경우다.
각 행동을 할 때마다 무조건 지급하는 표가 아니다.

| 행동 | 지급 | 상태 |
|---|---:|---|
| 빈 영역 최초 미인증 점령 | 20점 | 합의 |
| 빈 영역 최초 인증 점령 | 100점 | 합의 |
| 자기 미인증 영역 인증 강화 | 80점 추가, 누적 100점 | 합의 |
| 남의 미인증 영역 최초 인증 탈취 | 100점 | 합의 |
| 남의 인증 영역 최초 인증 탈취 | 위 인증 획득보다 낮게 | 방향 합의, **50점은 제안값** |

앞의 네 행동은 유지하기로 했다. 따라서 남의 미인증 영역 탈취와 빈 영역 인증 점령은
동일한 100점이다. 모든 종류의 탈취를 개척보다 낮게 만드는 규칙으로 해석하지 않는다.
사진 인증은 기존 주인의 점수를 이전하는 행위가 아니다. 새 주인에게 자기 지급 자격에 따라
보상을 주며, 이전 주인은 이미 정산된 점수를 잃지 않는다.

### 시즌당 1회와 인증 차액

보상 원장에 같은 수혜자·장소·시즌의 지급 이력을 남긴다. 빼앗기거나 산책을 종료하거나
날짜가 바뀌어도 이력은 유지한다. 같은 요청을 재전송해도 지급이 늘지 않아야 한다.

| 순서 | 지급 | 누적 획득 보상 |
|---|---:|---:|
| 최초 미인증 점령 | +20 | 20 |
| 빼앗김 → 미인증 재점령 | +0 | 20 |
| 자기 영역 인증 강화 또는 빼앗긴 뒤 인증 재점령 | +80 | 100 |
| 이후 재점령·재인증 | +0 | 100 |

처음부터 인증 획득 보상 100점을 받은 경우에는 재탈취로 추가 지급하지 않는다.
최초 미인증 보상의 차액 지급은 새로운 최초 보상이 아닌 **남아 있는 인증 보상 자격의
소진**이다. 이미 받은 금액·최초 지급 종류·차액 소진 여부를 함께 판별할 수 있어야 한다.

**미결:** 인증 영역 최초 탈취에 제안값 50점을 지급한 뒤 보상을 종료할지, 다른 경로의
추가 지급 가능성을 둘지는 확정하지 않았다. 이전 답변의 “50점이면 이후 보상 종료”는
제안이며 합의로 승격하지 않는다. 이를 결정하기 전 `100 - 기지급액`을 모든 상황에
일괄 적용하면 안 된다.

**미결:** 사용자가 말한 “개인”의 보상 제한 단위를 강아지로 할지 회원으로 할지 결정해야 한다.
점수의 표시 주체는 강아지다. 현재 코드의 pet 단위 키를 그대로 제품 결정으로 채택하지 않는다.
회원 기준이면 강아지를 바꿔 지급 한도를 우회하거나 차액을 중복 수령하지 못하도록
수혜 강아지와 회원의 보상 자격 관계도 명시해야 한다.

## 4. 보유 시간 점수와 동시 보유 계수

보유 시간 점수는 획득 보너스와 별도로 실제 보유 구간 동안 적립한다.
빼앗기면 해당 영역의 적립이 멈추고, 되찾으면 재개한다. 기존 적립분은 유지한다.
4시간 적립 상한이나 새벽 시간대 감점은 채택하지 않았다.

합의한 계수 구조는 각 영역에 순번별 계수를 주는 방식이 아니라 합계에 동일 계수를 주는 것이다.

```text
계수(N) = min(1 + max(0, N - 1) × 0.1, 2)
구간 시간 점수 = 구간 길이(시간) × Σ(각 점수 대상 영역의 시간당 기본점수) × 계수(N)
시즌 총점 = 지급된 획득 보너스 + 보유 시간 점수
```

여기서 N은 계수 계산에 포함할 영역 수다. 인증·미인증 중 무엇을 N에 포함할지는 미결이다.
예를 들어 동일하게 시간당 5점인 점수 대상 영역 두 개를 한 시간 유지하면
`(5 + 5) × 1.1 = 11점`이다. **5점은 계산 예시이지 확정 배점이 아니다.**

- 보유 수·인증 상태가 바뀌기 전 구간을 먼저 정산하고 이후부터 새 속도·계수를 적용한다.
- 과거 점수를 새 계수로 소급 증액하지 않는다. 획득 보너스에는 계수를 곱하지 않는다.
- 인증 전 시간을 인증 배점으로 소급 환산하지 않는다.
- 미인증·인증의 시간당 배점과 미인증 영역이 계수에 기여하는 방식은 아직 미결이다.
  미인증 2점·인증 10점은 제안값이고, 기존 코드의 시간당 10점도 새 정책의 확정값이 아니다.

새벽 및 경쟁이 적은 지역의 장기 보유 이점은 남는다. 이를 완전히 없애는 대신,
반복 보너스 제한과 획득/시간 점수 비율을 함께 검증한다. 강아지별 제한만으로 다계정
어뷰징까지 해결됐다고 주장하지 않는다.

## 5. 월간 시즌과 자동 전환

**합의:** `Asia/Seoul` 기준 매월 1일 00:00부터 다음 달 1일 00:00 미만까지 한 시즌이다.
고정 30일이 아니며 월별 일수와 연도 변경을 따른다. 서버에는 경계 시각을 UTC로 저장할 수
있지만 월 경계의 계산 기준은 한국 시간이다.

- 첫 실험 시즌만 실제 활성화 시각부터 다음 달 1일 00:00까지 짧게 운영한다.
  과거 월초부터 점수를 소급 생성하지 않는다.
- 이후 시즌은 월초 경계로 자동 전환한다. 예: 10월 시즌은
  `[2026-10-01 00:00 KST, 2026-11-01 00:00 KST)`다.
- 이번 문서의 날짜는 설명·기록일이다. 첫 시즌을 지금 활성화하도록 예약하는 뜻이 아니다.

전환 순서는 다음과 같다.

1. 종료 시각까지만 이전 시즌 점수를 정산한다.
2. 최종 점수·순위·기록을 확정해 보존한다. 동네별 비교 범위나 칭호 정책까지 확정하는 뜻은 아니다.
3. 이전 시즌 점령 주인·인증·보호를 해제해 중립 게임판으로 돌린다.
4. **이전 시즌 결산이 성공한 뒤에만** 새 시즌을 0점으로 시작한다.
5. 새 시즌 ID로 자리별 최초 보상 자격을 새로 계산한다. 이전 이력은 삭제하지 않는다.

산책 기록·사진은 시즌 변경 때문에 삭제하지 않는다. 해당 데이터의 기존 보존 정책은 유지한다.
지난 시즌의 늦은 사진 판정이 새 시즌 점령·점수를 만들면 안 된다.
집계 작업이 늦어져도 달력상의 시즌 경계는 실제 작업 실행 시각으로 밀리지 않는다.

### 자동 전환 구현에서 지켜야 할 조건

- 결산·중립화·시작을 재시도해도 중복 정산·중복 시즌·중복 초기화가 없어야 한다.
- 전환 중 실패하면 미결산 상태에서 새 시즌 점령을 받지 않는다. 정상화 후 안전하게 재개한다.
- 스케줄러를 중복 실행해도 활성 시즌은 하나이며 새 시즌 데이터가 재시도로 지워지지 않는다.
- 시즌 경계에서 점령 쓰기·사진 callback·정산의 순서를 일관되게 처리한다.
- 게임 OFF를 자동 전환 작업이 임의로 ON으로 바꾸면 안 된다.
- 여러 달 중단한 뒤 누락 월을 어떻게 기록할지, 전환 지연 구간의 요청 응답은 후속 운영 설계에서 닫는다.
  멱등성 키·잠금·트랜잭션 및 복구 방식은 여기서 구현 완료로 표시하지 않는다.

## 6. UI 및 범위

선택하거나 가까이 접근한 전봇대의 범위를 표시한다. 주인 카드에서는 강아지 사진·이름과
그 강아지의 점수를 한 묶음으로 읽히게 한다. 내부 식별자는 유지하지만 ID 문자열을
사용자에게 주된 이름표로 노출하지 않는다. 동일 이름이어도 실제 주체는 ID로 구분한다.
공유 점령 상태와 개인 산책·사진 원본의 공개 범위를 혼동하지 않는다.

전봇대 북마크·알림은 후속이다. 이번 보상·시즌 기획이 북마크 테이블·한도·알림 트리거를
확정하거나 구현하는 범위로 확대되지 않는다. 순위 범위와 칭호는
[기존 검토 계약](../../../contracts/territory-ranking-titles.md)을 별도로 닫아야 한다.

## 7. 기존 코드와의 차이 및 후속 작업

2026-09-09 소스 대조 기준: GEO `c8d0cb1`, DEV `ca61bd1`.
GEO의 `app/features/territory_game/policy.py`와 DEV의
`backend/src/daengs_backend/services/activity_core/game_policy.py`는 다음 실험 기본값을 갖는다.
인증 차등 획득·차액 지급·시즌당 1회 보상·월간 자동 시작은 이번에 구현하지 않았다.

| 항목 | 기존 코드/기반 | 이번 기획의 후속 변경 |
|---|---|---|
| 획득 보상 | 점령/탈취 각각 100점, 자기 인증 강화 0점 | 20/100·인증 차액·탈취 차등 |
| 반복 보너스 | 매 변경 또는 강아지·장소별 UTC 하루 1회 옵션 | 시즌당 1회 및 차액 지급 원장 |
| 미인증 시간 점수 | 포함/제외 옵션, 기본 포함 | 등급별 배점·계수 기준 확정 후 확장 |
| 보호 | 인증 v2 기반 존재 | 기존 규칙 유지 |
| 시즌 | 명시적 생성 및 종료 계산·기록 보존 기반 | 한국 시간 월간 자동 전환·실패 복구 |

DEV 주인 요약 API [#360](https://github.com/SAJOYO/DAENGS_dev/pull/360)는 별도 API 작업이다.
API 배포와 인증 v2 마이그레이션 적용이 새 보상 정책의 구현·게임 활성화를 뜻하지 않는다.
2026-09-09 개발 테스트 앱의 인증된 조회에서 회원 확인은 200,
현재 시즌·주인 요약은 503 `activity_disabled`로 확인했다. 이후 상태는 다시 조회해야 한다.

후속 순서:

1. 인증 영역 탈취 금액/최초 지급 후 처리, 시간 배점/계수, 회원·강아지 제한 단위,
   미개척의 정의(현재 중립 vs 시즌 최초 점령)를 확정한다.
2. 점령 판정·보상 자격/계산·정산 저장의 경계를 유지하며 정책 버전을 설계한다.
   진행 중인 시즌의 기존 규칙을 덮어쓰지 않는다. DB 마이그레이션 필요 범위는 원장 설계 후 판단한다.
3. GEO에서 정책과 월간 전환을 검증한 뒤 DEV·APP에 각각 필요한 변경을 승격한다.
4. 개발 서버에서 설정·워커·스케줄러와 앱 액션 활성화를 맞추고 작은 실험 시즌을 연다.

최소 검증 시나리오는 20→80→0, 최초 인증 100→재탈취 0, 소유권을 잃어도 유지되는 지급
이력, 두 참여자의 반복 교환, 동일 요청/동시 인증의 중복 지급 방지, 인증 전후 구간 정산,
보유 수 변화와 2배 상한, 월말·윤년·연말 경계, 첫 단축 시즌, 실패 후 전환 재시도,
늦은 사진 판정과 새 시즌 데이터 보존이다. 미결 정책에 대한 기대값은 확정한 뒤 작성한다.
