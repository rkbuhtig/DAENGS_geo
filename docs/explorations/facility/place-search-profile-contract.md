# 시설 검색 반려견 선택 계약 초안 v1

이 문서는 웹 UI와 향후 Kotlin/검색 서비스 사이의 계약 초안이다. 기존 API에
다견 필터가 구현됐다는 뜻이 아니다. 이번 구현 범위는 선택 UI와 ID 상태 보존이다.

## 화면과 식별

- 검색창·2행 카테고리 아래의 필터 줄에 반려견 선택을 거리·조건과 함께 배치한다.
- 이름으로 표시하고 여러 마리를 선택한다. 동일 이름도 허용하며 식별은 dogId로 한다.
- 프로필 공급자가 전달할 최소 항목: dogId, displayName, avatarUrl(nullable).
- 선택 상태: `{version: 1, selectedDogIds: string[]}`. ID는 중복 없이 보존한다.
- 선택하지 않은 상태는 프로필 기반 조건 없음이다. 모든 반려견을 암묵적으로 선택하지 않는다.
- 프로필 없음/로딩/읽기 실패/삭제된 ID는 구분한다. 오류를 동반 불가로 표현하지 않는다.
- 검색 모드·카테고리 전환으로 반려견 선택을 변경하지 않는다.

웹의 보리(demo-bori)·초코(demo-choco)는 가상 프로필이며 실제 계정 데이터가 아니다.
선택해도 기존 응답을 재평가하거나 제거하지 않는다. 화면에 '검색 미연동'을 표시한다.

## 향후 검색 연결

프로필 공급자는 선택 ID를 해당 사용자가 접근 가능한 최신 프로필로 해석한다.
평가용 스냅샷에는 dogId, profileRevision, sizeClass, weightKg, ageMonths를 둔다.
없는 값은 null이며 이름·품종으로 체중 등을 추정하지 않는다. 평가된 프로필 버전을
응답에 돌려줘 프로필 수정 이전의 결과와 혼동하지 않게 한다.

검색 요청의 초안 필드:

```json
{
  "profileContext": {
    "version": 1,
    "selectedDogIds": ["dog-id-1", "dog-id-2"]
  },
  "categoryScope": {"mode": "all", "kinds": []}
}
```

categoryScope.mode=all은 모든 업종, mode=selected는 kinds에 명시한 업종이다.
기타는 selected + kinds=["etc"]이며 전체보기와 다르다. 기존 서버 kind 파라미터에
문자열 all을 그대로 보내는 계약이 아니다. 클라이언트 어댑터가 API 지원 범위에 맞춰 연결한다.

## 다견 평가 원칙 제안 — 서버 구현 전 확정 필요

- 선택한 각 반려견을 각각 평가하며 가장 큰 한 마리로 대체하지 않는다.
- 한 마리라도 확인된 불일치면 전체 동반 조건 불일치, 불일치 없이 미상이 있으면 확인 필요,
  모두 평가 가능하고 충족해야 전체 조건 충족으로 표시한다.
- 개별 크기·체중 조건 통과가 동반 마릿수 제한까지 통과했다는 뜻은 아니다.
- 정보 미상 결과의 기본 포함 여부와 명시적 제외 필터는 별도로 결정한다.
- 프로필 기본값, 사용자의 직접 조건, AI 제안은 출처를 보존한다. AI가 선택한 반려견이나
  그 신체 정보를 조용히 덮어쓰지 않는다. 조건 충돌은 사용자에게 보여준다.
- 응답에는 반려견별 평가와 집계 이유를 둔다. UI는 판정 근거 없이 '모두 입장 가능'을 만들지 않는다.

프로필 API 경로, 인증, 초기 기본 선택, 선택 저장 범위, 미상 제외 정책은 이 초안에서 확정하지 않는다.
