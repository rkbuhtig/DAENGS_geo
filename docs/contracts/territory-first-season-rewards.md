# 첫 시즌 보상 계산 계약 — 1단계

제품 정책은 [월간 시즌 보상 합의](../explorations/walk/game/territory-monthly-season-rewards.md)를 따른다.
`app/features/territory_game/first_season_rewards.py`는 DB·HTTP에 의존하지 않는 계산 경계다.
**계산 코어만 구현했으며 운영 점령 서비스 연결·DB 마이그레이션·게임 활성화는 하지 않았다.**

## 버전과 기존 데이터

`RewardRules.version = first-season-rewards-v1`에 기본 목표 20/100, 탈취 20,
시간당 2/10을 고정한다. 같은 버전의 숫자를 임의로 변경할 수 없다.
기존 `certified-protection-v2`의 `Rules`, `Score`, 저장 형식과 계산은 그대로 유지한다.
새 버전을 기존 `Rules`에 넣으면 거절되므로 기존 PostgreSQL 어댑터로 잘못 실행되지 않는다.
DEV 연결 단계에서 시즌의 새 정책 스냅샷과 명시적인 버전 분기를 추가해야 한다.

## 기본 보상·탈취 보상

- `BaseRewardKey(season_id, member_id, site_id)`: 회원 기준 자격. 강아지·날짜는 키가 아니다.
- `BaseEntitlement.paid`: 기본 기지급액 0/20/100만 저장한다. 탈취·시간 점수를 넣지 않는다.
- `RewardEvent`: 인증된 서버가 확정한 행동과 당시 이전 주인의 회원·인증 상태.
  회원 ID는 클라이언트 입력이나 강아지 이름이 아니라 서버가 조회한 관계에서 얻는다.
- `ACQUIRED`: 빈 곳 또는 다른 강아지로 소유권 획득. 주인이 있으면 사진 인증이 필요하다.
- `CERTIFIED`: 자기 미인증 영역 강화. `RENEWED`: 현재 인증 등급 그대로 유지, 보상 0.
- 만료된 곳은 이전 주인이 없는 `ACQUIRED`로 전달하되 회원의 기존 원장은 보존한다.

`plan_reward`는 `RewardPlan`을 반환한다. `receipt.base_points`와 `takeover_points`는
별도 항목이며 지급 대상은 `receipt.event.pet_id`다. 이전 강아지의 점수는 수정하지 않는다.
같은 회원의 강아지 변경에는 기본 차액만 지급하고 탈취 보너스를 주지 않는다.
다른 회원의 미인증/인증 주인에게서 탈취하면 매번 20점이다.

| 기본 기지급 | 이번 인증 탈취 | 변경 후 기본 원장 |
|---|---:|---:|
| 0 | 기본 100 + 탈취 20 | 100 |
| 20 | 기본 80 + 탈취 20 | 100 |
| 100 | 기본 0 + 탈취 20 | 100 |

### DEV가 반드시 보장할 트랜잭션

1. 기존 시즌 잠금 순서를 유지하고 `(season_id, event_id)` 영수증부터 조회한다.
2. 재시도는 저장된 요청의 불변 식별자와 현재 요청을 비교한다. 현재 주인으로 과거 사건을
   재구성하지 않는다. 정상 재시도에는 저장된 `RewardEvent`와 영수증을 사용한다.
3. 신규 이벤트는 현장·사진·10분 보호·시즌·소유권 버전·만료 검증을 통과해야 한다.
4. 회원 원장을 잠그고, 실제 행이 처음 생긴 경우에만 0으로 초기화한다.
5. 소유권 변경, 이전 보유 구간 정산, 새 원장, 강아지별 기본/탈취 점수,
   보상 내역과 영수증을 **동일 트랜잭션**으로 저장한다. 어느 하나 실패하면 모두 롤백한다.

원장에는 `UNIQUE(season_id, member_id, site_id)`, 영수증에는
`UNIQUE(season_id, event_id)`가 필요하다. 계산 함수만 호출한다고 동시 요청의 중복 지급이
막히지는 않는다. 다음 단계에서 실제 DB 잠금·충돌·롤백을 검증한다.

재시도에서 `existing_receipt`를 전달하면 `replayed=True`, `credit_points=0`이다.
영수증의 원래 지급 내역은 응답/감사를 위해 그대로 반환한다. **그 과거 금액을 다시 더하지 않는다.**
20점 영수증을 나중에 재전송해도 이미 100점까지 올라간 원장을 20점으로 되돌리지 않는다.
서로 다른 정상 탈취 이벤트에는 기존 반복 횟수·일일·회원 쌍 한도를 추가하지 않는다.

## 시간 정산

`HoldingScore`는 강아지별 미인증/인증 보유 수를 별도로 가진다.
`settle_holding`은 `미인증 수 × 2 + 인증 수 × 10`을 구간 길이에 곱한다.
정수 `holding_units`와 기존 `POINT_DENOMINATOR`를 사용해 소수점 구간을 보존한다.
`whole_points`는 표시용이며 구간마다 반올림해서 저장하면 안 된다.

인증 강화 전에 기존 미인증 구간을 먼저 정산하고 수를 바꾼다. 예를 들어 미인증 1시간 뒤
인증 1시간은 2 + 10 = 12점이다. 미인증 3곳·인증 2곳의 1시간은 26점이고 계수는 없다.

이 함수는 **보유 수가 일정한 유효 구간**을 받는다. 개별 장소 만료 시각을 알지 못하므로
지연된 워커의 현재 시각을 그대로 넘기면 안 된다. 호출부가 소유권 변경·인증 강화·만료·
시즌 종료 시각에서 나눠 호출해야 한다. 72시간 만료/현장 연장과 월간 경계 처리는 후속이다.
