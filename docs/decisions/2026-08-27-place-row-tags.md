# 태그는 행에 달린다 — 카테고리가 버린 차이를 복원한다

[결정 #65](2026-08-26-place-first-discovery.md) §5 는 태그·AI 의미 검색을 "사용 데이터가
생긴 뒤" 로 미뤘다. 이 결정은 그 보류를 **부분 해제**한다 — 저장 구조와 근거 등급까지만
정하고, 사전 확정과 런타임 의미 검색은 계속 보류한다.

## 왜 지금인가

`kind` 후보군 안의 쏠림이 정렬로 풀리지 않는다.

- `cafe` 812곳에서 애견 전용(슈가파인 애견카페)과 개 동반 가능(아트살롱)이 구분되지
  않는다. "오늘은 얘가 주인공" 과 "내가 커피 마시는데 개도 데려감" 은 다른 외출이다.
- `travel` 1,632곳에서 멍비치 강릉(개 전용 해변, 크기별 공간분리, 유료)과 삼척해수욕장이
  같은 값을 받는다.
- 반려견 놀이터 43곳이 공원 539곳에 묻혀 있다.

이 차이들은 원천 category 가 버린 것이고, `kind` 를 아무리 잘 정규화해도 복원되지 않는다.
**태그의 목적은 카테고리를 설명하는 것이 아니라 카테고리가 버린 차이를 복원하는 것이다.**

근거는 [태그 재료 측정](../research/2026-08-27-tag-material.md)이다.

## 결정

### 1. 태그는 개별 행의 속성이다 — `kind` 상수 태그는 만들지 않는다

`kind` 전체에 같은 태그를 붙이면 그 `kind` 안에서의 정보량이 정확히 0 이다. `shopping`
8,647행에 `#들름` 을 붙여도 뭉치에 라벨이 하나 더 붙을 뿐 갈라지지 않는다.

따라서 태그의 채택 기준은 **분할력 × 의도 연결 × 신뢰도** 셋을 함께 본다. 분할력만
보면 안 된다 — `#이름길이짝수` 는 완벽하게 반반으로 가르지만 검색에 쓸모가 없다.

`kind` 를 횡단하는 역할 어휘(개가 주인공인가 / 사람 볼일에 동반인가)는 `kind` 함수라도
가치가 있지만, 그것은 §2 의 질의층에서 정의한다.

### 2. 저장은 두 층이고, 상황 의미는 저장하지 않는다

| 층 | 예 | 저장 |
|---|---|---|
| FACT | 컬럼 투영 — 주차 · 동반구역 · 크기제한 | 행에 저장 |
| DERIVED | 이름·원문 파생 — 놀이터 · 해수욕장 · 애견전용 · 목줄 | 행에 저장 |
| CONTEXTUAL | 비 오는 날 갈 곳 · 노령견에게 좋음 | **저장 금지. 질의 시 합성** |

경계 기준은 하나다. **태그의 참이 방문자·상황에 의존하면 질의층, 장소에만 의존하면 저장층.**

`#비오면딱` 을 행에 박으면 폭우와 이슬비, 차 있는 견주와 없는 견주에게 같은 답이 박제된다.
이것은 `app/discovery/state.py` 가 규칙 파생 긴급도를 상태에 남기지 않는 이유와 같다 —
"한 번 걸린 오탐이 세션에 눌어붙으면 사용자가 내릴 방법이 없다".

CONTEXTUAL 은 사라지는 것이 아니라 자리를 옮긴다. `"비 오는 날" → pet_zone:indoor + …`
같은 합성 규칙 자체를 검수된 질의 사전으로 두면 상황 판단도 감사 가능해진다.

### 3. 태그마다 근거 등급을 기록한다

```
source_column    컬럼 값의 투영            parking=true → amenity:parking
restriction_map  restrictions 원문 매핑표   "케이지 이용" → access:carrier_required
name_rule        이름 규칙                  "○○ 반려견놀이터" → feature:dog_park
llm              분류기 판단                 "개라다이스" → 애견 시설
```

등급이 다르면 신뢰도가 다르다. 같은 값으로 취급하면 이름 추론이 원천 사실인 척한다.

**근거를 기록해야 하는 이유는 태깅이 판단을 포함하기 때문이다.** 이 레포는 이미 판단하고
있다 — `KCISA "반려동물용품" → pet_shop` 도 사람의 분류 판단이고, 원천은 `pet_shop` 이라고
말한 적이 없다. `app/place/source_catalog.py` 가 그 판단을 `source_category` 원문 보존 +
`mapping_version` + 불일치 시 adapter 거부로 책임지듯, 태그도 같은 규율을 받는다.

### 4. 조건부 제한은 플랫 태그로 표현하지 않는다

`restrictions` 유정보 1,740행 중 무판단 파싱이 안전한 것은 654행(38%)뿐이다. 나머지는
적용 대상·구역이 조건부다.

```
"대형견 입마개, 목줄" → [
  {code: leash_required,  applies_to: all},
  {code: muzzle_required, applies_to: size>=large},
]
```

`applies_to` 없이 `#목줄 #입마개` 로 눕히면 소형견 보호자에게 없는 제한을 보여준다.
이 구조가 `pet_size_class` 의 85% 가 `any` 라서 크기 필터가 후보군을 거의 못 줄이는
문제(431 → 429)의 실제 해법이다.

매핑의 단위는 **291개 문자열**이다. 사람이 전수 검토할 수 있는 양이므로 표로 만들어
커밋한다.

### 5. `indoor`/`outdoor` 는 동반 구역이다 — 환경 태그로 읽지 않는다

동반 불가 2,794행이 예외 없이 `indoor=f, outdoor=f` 다. 이 컬럼은 시설이 실내인지가
아니라 **반려동물이 들어갈 수 있는 구역**을 말한다. 태그 이름도 `environment:*` 가 아니라
`pet_zone:*` 이어야 한다.

이 컬럼으로 "실내 시설" 을 판정할 수 없다. 개 동반 가능한 문화시설은 거의 전부 야외
구역만 허용이라, 환경 태그로 읽으면 비 오는 날 질의에서 정반대 답이 나온다.

### 6. 태그 부재는 거짓이 아니라 미상이다 — 구조화 축이 계속 권위다

```
parking=true   → amenity:parking 태그 있음
parking=false  → 태그 없음, 구조화 값은 false
parking=null   → 태그 없음, 구조화 값은 unknown
```

태그만 보면 "불가" 와 "미상" 이 구분되지 않는다. [결정 #68](README.md)의 3상태 평가와
`PlaceResult.facts` 가 권위이고, 태그는 그 사실을 탐색하기 쉽게 투영한 표현이다.

의미 태그를 적용한 응답은 **태그별 known/unknown 계수를 함께 반환한다**
(`PlaceSort.coverage` 와 같은 형식). KTO 9,692행은 행 사실이 0 이므로, 이 계수가 없으면
"그런 곳이 아님" 과 "모름" 이 섞인 채 통째로 밀린다.

### 7. 태그 스냅샷이 데이터 버전이다

```
태그 생성        비결정적일 수 있다 (LLM·임베딩·사람 검수)
승인된 스냅샷    고정. (tag, evidence, rule_version, generated_at, source_snapshot)
런타임 검색      결정론
```

`KIND_MAPPING_VERSION`(매핑을 바꾸면 그 변경에서 전체 재분류)과 `JUDGMENT_VERSION`
(사실은 그대로이므로 언제든 재판정)이 이미 같은 모양이다. 규칙이 바뀌면 배치만 다시
돌린다. 파생 자리도 선례가 있다 — `app/ingest/pet_axes.py` 가 "저장된 값의 함수" 로
축을 재파생하며 원천을 다시 호출하지 않는다.

### 8. 임베딩은 발견 도구다 — 자동 분류 경로를 열지 않는다

측정 결과 이름 임베딩은 정규식을 이기지 못했다. `#개주인공` 앵커의 top50 은 정규식이
찾은 것과 100% 같았고(추가 가치 0), 그 밖에서 찾은 것은 **고양이 카페**였으며(개·고양이
미구분), 정규식이 잡은 언어유희 137곳(개라다이스 · 개토피아)은 놓쳤다.

**앵커 문장 → kNN 으로 태그를 자동 생성하는 설계는 검토했고 기각한다** (precision@300
19%). 브랜드명 벡터는 카테고리 설명문 근처에 가지 않는다.

남는 자리는 하나다 — **군집·최근접 이웃으로 태그 후보와 사전 항목을 발견하고, 사람이
승인한 뒤 규칙·매핑표로 정식 태깅한다.** 실제로 휴게소 부설 놀이터, `-독` 활동 계열,
`kind=shopping` 안의 약국이 이 방식으로 나왔다.

임베딩 결과를 사람 승인 없이 저장하는 경로는 어느 `kind` 에서도 열지 않는다.

### 9. 레인 배정

| kind | 주력 | 임베딩 |
|---|---|---|
| travel | 유형어 규칙 (~25어) | 누락 유형 발견 |
| cafe | restrictions 매핑표 + LLM 잔여 | 없음 (이름 반복성 8%) |
| shopping | 브랜드표 (상위 200 = 63%행) | 표 작성 시 후보 제안 |
| pet_shop · grooming · boarding | 컬럼 투영 | 없음 |
| hospital · pharmacy | 태깅하지 않는다 | 없음 |

`pharmacy`·`hospital` 은 재료도 없고 쪼갤 이유도 없다 — 거리와 영업 여부면 충분하다.

## 첫 어휘 **후보** (확정 아님)

구현 결정에서 확정한다. 지금은 측정에서 나온 것을 장부에 올린다.

| 축 | 재료 | 근거 등급 |
|---|---|---|
| 유형 (놀이터 · 해수욕장 · 목장 · 휴게소 · 출렁다리 · 전망대 · 케이블카 · 휴양림 …) | 이름 유형어 | name_rule |
| 활동시설 (운동장 · 수영장 · 마당) | 유형어 + `-독` 계열 + restrictions | name_rule + llm |
| 물놀이 | 해수욕장 · 계곡 · 풀 | name_rule |
| 자연 / 인문 | 유형어 2분 | name_rule |
| 애견 전용 | 이름 + `pet_exclusive`(276행) | source_column + name_rule |
| 동반 구역 | `indoor`/`outdoor` | source_column |
| 동반 조건 (목줄 · 케이지 · 안기 · 마리수 · 추가요금) | restrictions 291 매핑표 | restriction_map |
| 이동 중 쉼 (휴게소) | 유형어 | name_rule |

`#무료`·`#유료` 는 **후보에서 뺀다** — 입장료 컬럼이 존재하지 않는다.

## 이 결정이 하지 않는 것

- **태그 사전을 확정하지 않는다.** 위는 후보다. 사전 자체는 문서가 아니라 코드
  (`app/place/tags.py` 류)에 버전과 함께 두며, 문서에 박으면 두 벌이 되어 어긋난다.
- **venue 접기를 정하지 않는다.** `shopping` 의 좌표 뭉침(김포아울렛 171행)은 공간
  쏠림이라 태그로 풀리지 않는다. parent venue 관계는 별도 결정이다.
- **LLM 노드가 어느 레포에 앉는지 정하지 않는다.** [결정 #53](2026-08-24-agent-parallel-response.md)의
  팀 경계 질문과 함께 미결이다. 이 결정이 고정하는 것은 태그 계약이며, 그 계약이 곧
  인터페이스가 되어 노드가 어느 쪽에 앉든 같은 형식을 채운다.
- **런타임 의미 검색 레인을 열지 않는다.** #65 §5 의 나머지 보류는 유지한다. 기본 결과는
  계속 사실 기반이고, 의미 태그는 사용자가 적용하는 제안층이다.
- **`kind` 를 태그로 덮지 않는다.** `travel` 인 반려견 놀이터는 `kind=travel` 을 유지하고
  태그가 추가로 붙는다 (#65 §2).

## 기존 결정과의 관계

- #65 §5 의 보류를 저장 구조·근거 등급까지 부분 해제한다. 사전 확정과 의미 검색 개방은
  계속 보류다.
- #68 의 3상태 평가가 태그보다 권위다. 태그 부재는 불가가 아니다.
- #62 의 `truncated`, #65 의 `sort.coverage` 와 같은 이유로 태그 커버리지 계수를 낸다 —
  조용히 자르거나 미상을 거짓으로 접지 않는다.
- #67 §5 에 따라 새 최상위 패키지를 만들지 않는다. 태그는 분류 정책이므로 `place` 도메인이
  소유한다 (`source_catalog.py` 가 "분류 정책의 유일한 자리" 인 것과 같은 근거).
- #53 의 "LLM 이 꺼져도 기능 집합은 줄지 않는다" 를 유지한다 — 태그는 스냅샷으로 저장되어
  LLM 없이도 검색된다.
