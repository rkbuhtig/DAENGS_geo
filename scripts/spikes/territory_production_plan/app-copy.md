# 산책 게임 앱 화면 웹 검토판

`app-copy.html`은 판정 실험 `index.html`과 같은 `claims.mjs` 및 공통 TSV를 사용하면서,
Android 산책 화면의 배치 안에서 게임 UI를 조작하는 검토판이다.
소속 탐색은 [점령 게임 제작 계획](../../../../docs/explorations/walk/territory-production-plan.md)이다.

## 플레이 후 개선 — 지도 위 대상과 행동을 우선

초기 카피 [PR #234](https://github.com/rkbuhtig/DAENGS_geo/pull/234)를 직접 조작했을 때
큰 설명 카드와 산책 버튼이 지도 높이의 약 48%를 차지했고, B에 접근하면 대상과 내 위치가
카드 뒤에 가려졌다. 버튼끼리 겹치지 않는다는 검사만으로는 플레이 가시성을 확인하지 못했다.
현재 화면은 이를 고친 **웹 개선안**이며 아래 변화는 아직 Kotlin에 반영하지 않았다.

- 대상 설명을 작은 하단 액션 영역으로 줄였다. 게임 표시 중 일시정지·내 위치는 보조 크기로
  낮추고 상시 ‘기록 중’ 안내를 접는다. 오류와 사용자가 발생시킨 안내는 유지한다.
- 빈 장소는 영역표시를 주된 버튼으로, 사진 바로 촬영은 카메라 아이콘으로 제공한다.
  미인증 점유 후에는 인증 촬영, 부적합 후에는 재촬영을 주된 버튼으로 바꾼다.
  확인 중·인증 완료에는 비활성 큰 버튼을 남기지 않는다. 무사진 점유 규칙은 그대로다.
- 선택한 장소 주변에 접근 링·거리·점유 말풍선을 표시한다. 접근 링은 거리 기반 시각 피드백이며
  체력/점수나 온라인 인증 증거가 아니다. 위치가 불확실하면 준비 상태를 표시하지 않는다.
- 장소를 전봇대 형태로 표시하고 점유에는 발자국을 붙인다. 미인증은 황색, 인증은 녹색이다.
  영역표시·인증 강화·탈취 후 2.4초간 대상 말풍선에 결과를 보여 주고 평상시 표시로 돌아간다.
  짧은 링 효과는 reduced-motion 설정에서 애니메이션을 끈다. 다른 장소의 지연 결과는 사진 목록에 남는다.
- 실제 HUD/하단 컨트롤이 차지한 영역을 계산해 **선택 대상과 현재 위치가 남은 지도 공간에
  들어오게 SVG 카메라를 맞춘다**. 지도 표현만 이동/축소하며 장소 좌표·접근 거리·점령 판정은 바꾸지 않는다.
  가로 화면에서는 카드와 보조 버튼 사이의 공간을 사용한다.

검사는 320·390px 및 가로 화면에서 A/B/C의 멀리·가까이 이동을 각각 조작하고,
대상·내 위치·접근 말풍선이 HUD/버튼/카드에 가려지지 않는지 확인한다.
세로 게임 화면의 하단 점유 높이는 지도 높이의 28% 이내를 회귀 기준으로 삼는다.
2026-09-05 Edge에서 동일한 390×844 미인증 점유 장면을 재측정했을 때 지도 높이 771px 중
하단 UI가 371px(48%)에서 173px(22%)로 줄었다. A에서 B로 이동하는 장면과 좁은 화면,
가로 화면의 대상·내 위치 노출을 스크린샷으로 확인했다.

## 가져온 코드

기존 앱 카피코드는 Geo의 **시설 검색 웹 검토판 [PR #232](https://github.com/rkbuhtig/DAENGS_geo/pull/232)**,
`experiment/place-ui-web@7aee8c8ec6586c9e2048edacb5fbc3a1f67a5ce0`에 있다.
작업 당시 main에 없는 별도 브랜치였으므로 그 PR을 변경하거나 전체 검색 기능을 반입하지 않았다.
프레임·색상·상태바·제스처 바를 필요한 범위로 옮겨 `app-copy.css`에 출처를 남겼다.
시설 검색판처럼 바깥 조작판과 앱 화면을 분리하고 키 없는 SVG 지도를 사용한다.

산책 UI 원본은 APP `2e14d0d52a913b462099dabb1a31836fb3727871`([PR #142](https://github.com/SAJOYO/DAENGS_APP/pull/142))이다.

## 실행과 조작

Geo 루트에서:

```powershell
uv run python -m http.server 8766 --bind 127.0.0.1 --directory scripts/spikes/territory_production_plan
```

[앱 화면 열기](http://127.0.0.1:8766/app-copy.html). 기존 [판정 실험](http://127.0.0.1:8766/index.html)도 유지한다.

1. 앱 프레임 안에서 참여견을 고르고 **산책 시작**한다. 행동 기록 버튼과 HUD를 확인한다.
2. **점령지 보기**를 누른다. 앱 구현처럼 행동 기록 자리에 점령 카드가 나타난다.
   별도 세션이나 별도 지도 화면을 만들지 않는다.
3. 바깥 조작판의 **가까이 이동**으로 접근한다. Pin으로 빈 장소를 미인증 점유한다.
4. **영역표시 인증 촬영**으로 카메라 화면을 열고 샘플을 촬영한다. 취소는 시도를 만들지 않는다.
   촬영 대상은 카메라를 열 때 고정한다. 뒤에서 지도 대상을 바꿔도 다른 장소에 인증을 붙이지
   않는다. GPS나 실제 위치를 바꾸면 원래 촬영 대상에 대한 접근을 셔터에서 다시 판정한다.
5. 확인 중 다른 장소로 이동하거나 표시를 숨긴다. 화면 위 사진 상태에서 결과를 확인한다.
   부적합은 현장 재촬영, 장애는 같은 사진으로 재시도한다.
6. **잠시 멈춤 → 산책 종료 → 다음 산책 준비**로 새 세션을 만들 수 있다.
   점유와 판정 대기열은 유지하며 산책 시간·거리·행동 기록은 새로 시작한다.
   보리의 인증 영역을 만든 뒤 다음 산책에서 두부만 참여시키면 새 사진으로 탈취할 수 있다.
7. 빠른 화면 검토는 **두부의 인증 영역 탈취 → 선택 장면으로 새 연습**으로 시작한다.
   이 조작만 점유·대기열을 초기화한다. 판정 대기 중 초기화해도 이전 결과가 새 장면에 쓰이지 않는다.

가로 보기는 넓은 브라우저에서 제공한다. 모바일 너비에서는 세로 프레임을 유지한다.
320·360·390px에서도 버튼을 조작할 수 있도록 프레임 너비를 줄이며 높이는 844px 기준이다.

## 현재 앱과 다른 부분

이 화면은 Compose 소스에서 출발해 플레이 피드백을 반영한 HTML/CSS이며 **픽셀 단위 복제나 APK 실행 화면은 아니다**.

- 지도·날씨·시각·참여견은 합성 값이다. 실제 지도 키·위치·카메라 권한을 요청하지 않는다.
  내 위치는 안내만 표시하고 홈 이동은 검토 범위 밖으로 명시한다.
- 게임 표시 토글에 따른 기존 행동 도크 숨김은 현재 APP 동작을 따른다. 게임 표시 중에도
  행동 도크를 함께 제공할지는 이 복사판에서 새 정책으로 확정하지 않는다.
- 사진 상태는 지도와 겹치지 않게 **한 줄 요약 → 목록 열기**로 표시한다. APP #142의
  최대 120dp 목록과 다른 검토안이며 아직 Kotlin에 역반영하지 않았다.
- 카메라는 샘플 미리보기와 셔터 UI이며 실제 파일/VLM을 사용하지 않는다.
  판정 선택기는 실험용 바깥 패널에 둔다. 가로 카메라는 버튼 도달성을 확인하는 웹 배치다.
- 일시정지·종료 결과는 관련 게임 흐름을 검사하기 위한 간략한 대응이다. 홈·전체 산책 일기·
  종료 회고 카드 전체를 복사하지 않는다. 행동 버튼은 화면에서 건수와 안내만 남긴다.
- 아이콘은 문자/이모지 대체품이다. 실제 폰트 배율·시스템 인셋·Naver SDK 마커·사진 저장·
  회전/백그라운드 생명주기·보행·진동은 Android 기기에서 확인해야 한다.
- 미인증 무사진 경쟁과 동시 점유 충돌 순서, 점수 정책은 추가로 확정하지 않는다.

## 화면 검사

```powershell
uv run scripts/spikes/territory_production_plan/browser_check.py --channel msedge --app-copy
```

Edge가 없으면 [기존 실행 문서](README.md)의 Playwright Chromium 경로를 사용한다.
검사는 임시 localhost 서버를 열고 완료 후 닫는다. OS 임시 폴더의 `territory-play-lab/copy-*.png`에
프레임 스크린샷을 남긴다. `--output`으로 위치를 바꿀 수 있다.

- 공통 TSV 20단계와 접근·충돌 6개를 같은 모듈에서 실행한다.
- 다견 참여, 행동 기록과 점령 분리, 토글, 준비/접근 불가, 무사진 점유, 인증 강화,
  취소/오래된 위치 셔터 차단, 새 세션의 인증 탈취, 부적합·재시도, 복수 장소를 조작한다.
- 표시 숨김·이동·산책 종료 뒤에도 판정이 완료되는지 확인한다.
- 조회 중/빈 결과/오류, 위치 권한 없음/모의 위치/오차/오래된 위치에서 촬영을 막는지 확인한다.
- 320·360·390px 및 가로 프레임에서 HUD·게임 카드·산책 컨트롤의 겹침과 가로 넘침을 검사한다.
- 촬영 화면과 부적합/재시도/탈취/가로·좁은 촬영 오류 화면을 캡처하여 육안 확인한다.

화면 검증 결과는 웹 대응 구현의 결과다. APK/CameraX 검증 통과로 기록하지 않는다.
