# 산책 기록 → 선택적 공간 배경 → 결과 비교 lab

기존 GPS lab의 시나리오 생성기·관측·전달 시각을 재사용하는 **로컬 연구 도구**다.
운영 app/dev, DB, 개인정보 프로필 정책은 변경하지 않는다. Docker, DB, LLM, SGIS 파일 없이
실행한다. 실제 공공데이터 조회는 선택 사항이다. 기존 GPS 편집기의 지도는 온라인 OSM을 쓴다.

## 실행

geo 루트에서 Python 3.12 환경을 사용한다. 운영 `.env` 전체를 로드하지 않고 지정 파일에서
`DAENGS_DATA_GO_KR_SERVICE_KEY` 한 항목만 읽는다. 파일과 원본 캐시는 저장소 밖에 둔다.

```powershell
.venv\Scripts\python.exe -X utf8 -m scripts.spikes.walk_record_lab.server --cache-dir C:/private/walk-lab/cache --env-file C:/private/walk-lab/private.env --port 8768
```

`http://127.0.0.1:8768`을 연다. `--env-file`을 생략하면 캐시만 사용한다. API 키는 HTML,
응답, 다운로드, URL에 제공하지 않는다. 서버는 loopback에만 바인딩하며 다른 Origin의
POST와 외부 Host를 거절한다. 운영 서버의 라우터에는 등록하지 않았다.

1. 기본 동네 산책에서 재생하거나 시간 슬라이더를 옮겨 행동·메모를 기록한다.
   `예시 행동·메모 채우기`는 현재 입력을 합성 예시로 교체한다.
2. 필요하면 접힌 **기존 GPS lab**에서 경로·센서 조건을 작성하고 가져온다.
   기본 편집기와 새 lab은 독립 시나리오이므로 명시적으로 가져온다.
3. 수정·삭제 후 `산책 종료 · 결과 만들기`를 누른다. 체크했을 때만 없는 캐시를 조회한다.
4. 기록만 / 환경 추가 / 장면 편집을 비교한다. 공통·행동별 정책, 장면 수를 바꿔본다.
5. 종료 후 기록 수정·삭제도 결과와 현재 프로필을 갱신한다. 환경 재계산은 캐시만 사용한다.
6. 비교 목록에 산책을 저장하고 `같은 경로의 다음 산책`을 시작하면 경로·입력을 복사해
   다른 ID와 다음 날짜로 만든다. 저장된 같은 ID는 갱신되며 중복 산책으로 세지 않는다.
7. 실험 JSON은 시나리오·탭·현재 결과·비교 이력을 내보낸다. 가져오기는 시나리오·탭·정책을
   다시 계산하며 결과나 과거 비교 이력을 신뢰해 복원하지 않는다. 동일 재현에는 원본 캐시도 필요하다.

## 관측과 출력 규칙 (미채택 실험값)

- 탭 시각까지 **도착한 GPS 중 수집 시각이 가장 최신인 표본**을 사용한다. 역순·중복 전달이
  위치를 과거로 되돌리지 않는다. 모션의 `sniff-and-go`는 행동 핀을 생성하지 않는다.
- GPS 나이 15초 초과, 정확도 미상/50m 초과는 행동 저장을 거절한다. 메모는 위치 없이 남는다.
  거절된 탭은 실험 기록으로 보이지만 장면·프로필·환경 조회에는 들어가지 않는다.
  이 규칙은 앱 전체 위치 수용 로직의 복제나 제품 계약 확정이 아니다.
- `evaluation_only.anchor_errors`만 GPS 수집 시점의 합성 정답과 오차를 비교한다. 진실 좌표는
  핀·환경·프로필에 사용하지 않는다. 보고 정확도가 좋아도 위치 튐은 통과할 수 있고 진단에 드러난다.
- 킁킁/sniffing, 배설/excretion, 짖기/barking, 메모/note. 메모에서 행동을 추출하지 않는다.
  lab ID와 단일 합성 반려견 귀속은 실험용이며 운영 UUID/다견 API의 완전한 전송 어댑터가 아니다.
- 공통 정책은 세 행동 모두 공간 배경, 행동별 정책은 배설을 경과 시간·수용 이동거리로 처리한다.
  경과 거리는 산책 종료 후 수용 구간을 기준으로 계산하며 GPS 공백을 메우지 않는다.
- 상가는 핀 반경 125m, 조회는 중심 반경 250m. 조회 원이 핀의 125m 영역 전체를 포함하면
  재사용한다. 첫 핀 삭제 후에도 기존 캐시의 공유 영역을 재사용한다. 최대 8개 상가 중심,
  각 질의 최대 6페이지, 추가 공원·하천 2질의다. 전체 GPS에 대해 환경을 조회하지 않는다.
- 공원은 **서울특별시 강남구 제공 자료만** 수집한다. 대표점 250m 이내를 표시하며 입장/경계를
  판정하지 않는다. 다른 지역은 경로 편집 가능하지만 공원 커버리지는 보장하지 않는다.
- 하천은 전국 표준데이터의 `bgngPstnLat/bgngPstnLot` 시점 좌표 250m 이내만 비교한다.
  하천 전체 형상·산책로 이용 판정이 아니다. 기존 EGIS 보조 형상·SGIS 동 구간은 사용하지 않는다.
- 실패/부분 수집/캐시 없음은 근거 상세에 유지한다. 항목 없음은 시설 부재가 아니다. 실패 캐시도
  자동 재조회하지 않는다. 갱신하려면 해당 캐시를 별도 보관하고 명시적으로 다시 수집한다.
- 장면 수는 시작·끝을 포함한다. 중간 기록은 시간순 등간격으로 선택하는 비교 기준이며 중요도
  점수는 없다. 생략 ID를 반환하고 기록/프로필 근거는 보존한다. 핀 없는 산책은 시작·끝 2장이다.
- 프로필은 기록 개수와 기록이 남은 산책 수. 반복 주변은 첫 기록 기준 50m의 간이 묶음이다.
  실제 행동 횟수, 행동 부재, 장소 선호, 원인, 사회성·성격을 추론하지 않는다.
- `source_revision`은 산책과 수용된 입력, `result_revision`은 환경 근거·출력 정책까지 반영한다.

## 시나리오 일괄 실행

```powershell
.venv\Scripts\python.exe -X utf8 -m scripts.spikes.walk_record_lab.evaluate --cache-dir C:/private/walk-lab/cache --out C:/private/walk-lab/cases --env-file C:/private/walk-lab/private.env --fetch
# 이후 오프라인 재실행: --env-file과 --fetch 생략
```

정상 / 공백·정확도 저하 / 전달 지연·중복 / 핀 없음 / 메모만 / 삭제 / 반복의 7개 입력에
공통·행동별 정책을 적용한 **14개 bundle**과 `report.json`을 만든다. 각각 UI에 가져올 수 있다.
합성 경로는 실제 도로 라우팅을 보장하지 않는다. 원본 공공자료는 캐시에만 남고 결과에는
근거별 최소 공개 필드와 수집 시각·fingerprint를 남긴다.

```powershell
.venv\Scripts\python.exe -m pytest tests/sim/test_walk_record_lab.py tests/sim/test_walk_trace_lab.py tests/test_storyboard_sources.py -q
.venv\Scripts\python.exe -m ruff check scripts/spikes/walk_record_lab tests/sim/test_walk_record_lab.py
```

자동 테스트는 네트워크를 사용하지 않는다. 실제 키의 유효성·실기기 GPS·사용자 가치 검증은 별개다.
